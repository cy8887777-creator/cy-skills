# PRD-Lite 规范（prd-spec）

全局一份（`docs/prd/`），基于②全量布局清单的整体理解产出。
**三层结构**，逐层可独立审核。

## 层 1：站点地图（sitemap.md）

页面关系/信息架构：模块 → 页面 → 层级；入口关系（哪些页面互达）。
从全量 §0 叙述 + §1 结构推断——**此层是跨页推断的合法位置**
（盘点是单图视角，PRD 是全局视角）。

## 层 2：功能逻辑（functional.md)

- 业务规则：如 订单状态机（待付款→支付→已购 / 取消→已失效）、
  游览流程（选场馆→游览→讲解→结束）、权限规则（角色差异）、
  地理围栏、会员权益；
- 每页 `states` 枚举：该页要实现的状态（默认态必含；空/加载/错误
  态按 PRD 列出——**未枚举 = 只做默认态**，防状态爆炸）。
  此枚举是④整合同页状态站对账状态图的依据；

## 层 3：每页行为清单（behaviors.md)

按页分组：`页id | 触发 | 行为（跳转目标/弹窗/状态变化）| 依据`。
- 行为必须溯源（引用层 1/层 2 条目或页面可见元素）；
- 目标页面必须存在于 manifest（不存在 → 进 gap 流程，不凭空接线）。

## 与单页技能的关系

- 层 2 中**影响页面结构的规则/状态机**在⑤⑦⑧写码站动工前生效
  （如订单状态机决定订单页有无"取消"钮）；
- **纯交互行为（点哪去哪）不在本层设计**——后置管线⑨交互接线：
  全站页面完成后基于代码事实统一接线（单图视角猜全局行为 = 事故源）；
- 人审点：层 1 全审 + 层 2 业务规则审 + 层 3 抽查（模块内跳转扫过，
  跨模块跳转逐条）。
