# 各站执行细则（references）

每站：输入 → 动作 → 产出 → gate → 子代理编排。执行会话按当前站读对应节。
激活协议（一幕制）见 SKILL.md「激活协议」节——唯一权威在彼处。

站序总览：①盘点 → ②视觉盘点+gap → ③PRD-Lite → ④整合同页状态 →
⑤典型页高保真制作 → ⑥提取设计系统 → ⑦主力页高保真制作 → ⑧铺量
小循环 → ⑨交互接线+自测 → ⑩集成验收。
并行结构：⑤只依赖②的复杂度画像，与③④并行跑；**⑥等④+⑤**
（tokens/组件提取仅依赖⑤可先行，典型页 TSX 转换须等④归并冻结
——"信息齐备后才转"）；⑦等④+⑥。

## §0 环境前置（一次性）

```
python scripts/setup-env.py        # 幂等：pip 依赖 + playwright chromium + 模型下载
<python> flow-front-ui-line-cy-img-to-code/scripts/doctor.py --full   # 验证 READY
cd <工程目录> && npm install
```
- 模型文件：isnet(170MB)+u2net 下载到技能 `models/` 或 `I2C_BG_MODEL` 指定路径；
- setup-env 失败逐项报告（pip / 浏览器 / 模型 URL 分开报）；
- 工程脚手架（npm/Vite/路由壳骨架）为确定性工作，②盘点进行时即可并行搭好。

## §1 盘点（页面清单，零看图）

输入依赖：图包目录**必须来自激活协议第二幕的需求确认**（用户上传
或指定路径）——禁止自行扫描/搜索/猜测任何目录。未获得路径 = 回到
激活协议追问，禁止执行本站。

输入：图包目录。
动作：`scripts/intake.py <图包目录> <工程目录>`：
- 解析命名 `^(\d+)-(.+?)(?:\s*[–-]\s*(\d+))?\.(png|jpg)$`
  → 图 id = `p<编号零填充3位>-<状态>`；同编号图仅标 `group` 分组提示
  （**不在本站合并**——文件名不可信，真实归并在④整合同页状态站，
  PRD states 背书后执行，见 §4）；
- 「弹-」前缀 → `type: 弹窗`；图高/宽 > 2.2 → `long_page: true`；
- 产出 `pipeline/pages.manifest.json` + 按 `templates/plan-template.md`
  生成 `pipeline/PLAN.md` 初稿（全部 pending）。
gate：全量解析、零未知命名 → 人工确认清单 → 冻结。

## §2 视觉盘点 + gap 审计

编排：**子代理分批**（每批 8-10 张，独立上下文），主会话只持轻状态
（manifest + 汇总行 + gap 报告，禁收全量文档）。
子代理 prompt = `templates/inventory-prompt.md`（角色/单图视角纪律/
四章节格式/回报一行式）+ 该批图清单。
- 产出 `inventory/<页id>.md`（§0 叙述 / §1 结构 / §2 素材 / §3 画像）
- 回报行：`页id | 素材数 | 复杂度档 | 策略建议 | 质量标记`
主会话汇总：策略分布 + **三方 gap 审计**（功能清单×图包×盘点，若有
功能清单；无清单 → 领域常识推断 + 精度降级声明）→ `pipeline/gaps.md`。
gate：全量覆盖 + 人工过策略标签与 gap 处置 → 冻结。
**冻结后所有页面写码免看原图**——布局文档是唯一视觉源。

## §3 PRD-Lite 功能逻辑

编排：PRD 子代理（产品经理角色，见 agent-roles.md）。
输入：全量页文档的 §0（叙述）+ §1（结构）章节 + manifest +
**synthesized 推导文档草稿**（②gap gate 裁决补页后，主会话按功能
清单立即生成——先有草稿供 PRD 使用和完善，不要等 PRD 反推）。
输出（落 `docs/prd/` + `docs/sitemap.md`）：
- 站点地图（页面关系/信息架构，**含「入口契约」固定节**——root/tabbar/
  登录/支付返回落点，逐条"入口 → 落点路由"；⑨冒烟第 0 步与
  route-audit redirect 判据的唯一真值，规则见 templates/prd-prompt.md）
- 功能逻辑（业务规则/状态机，含每页 `states` 枚举——④归并的依据）
- 每页行为清单（触发 → 目标/规则引用）
- 结构影响标注（哪些规则影响哪些页面的结构，供写码站消费）
gate：页面 id 全覆盖对账 → 人工审业务规则与行为描述 → 冻结。
**纯交互行为（点哪去哪）不在此设计**——后置⑨交互接线（全站页面
事实上设计，优于单图视角猜测）。

## §4 整合同页面的不同状态（PRD 后，有据归并）

输入：manifest 的 `group` 分组 + ③PRD 每页 states 枚举 + 组内各图
布局文档（§1 结构）。
动作：逐 group 对账——**PRD 状态机 × 组内状态图**：
- 状态图 ↔ state 一一标注（哪张图是初始态/错误态/成功态…）；
- PRD 枚举了、图包没有的状态 → 记缺失（进 gap 报告，实现时按 PRD
  推导，不阻塞）；
- 布局相同仅细节/状态异 → 归并为同一路由页的多状态（每状态保留
  布局文档，实现时该路由组件内多状态渲染）；
- 布局不同 → 保持独立页（同编号不强行合并）；
- 疑似错误重复 → 人工裁决。
产出：**status_map**（机器可读状态映射：每路由页
`{default: <默认态源图>, states: [{id, source, trigger}]}`——默认态
唯一权威，⑤基座选图/⑥转装核对/⑧验收对照全以它为源）+ **角色字段**
（1008-04：每路由页 `role: tab_landing/secondary/modal_host/terminal`
+ `required_exits: [{intent, expect_url_contains?}]`——出口完整性的
机器真值，⑨exits-audit 消费；二级页必有 nav-back、tab 落地页必有
tab 全件、弹层宿主必有开与关、合法终止页标 terminal 豁免；角色判定
依据 sitemap 层级 + PRD 页面角色，逐页可追溯）+ **入口声明**
（1009-06：`entry_declarations: [{entry, target}]`——root/tabbar 各
tab/登录成功/支付完成返回的落点，来自③sitemap「入口契约」节人审
结论的机器化；⑨冒烟第 0 步与 route-audit redirect 判据的唯一机器
真值源）+ 归并结果（图数 → 路由页数）更新 manifest + PLAN.md。
**③→④对账步（1009-06/19）**：冻结前将 sitemap「入口契约」节与
entry_declarations 逐条比对，不一致不得冻结；冻结后任一侧变更须
重新确认+同步（留痕），对账可重复执行。
gate：归并结果人工确认（**含逐页 role/required_exits 过目**）→ 冻结路由页清单。
依据：文件名归并是猜的（2026-09-30 修正）——归并必须基于 PRD
状态语义 + 内容对比。

## §5 典型页面高保真制作（与③④并行）

选页：按②复杂度画像降序取 top 2-3 张（全项目最难/最具代表性形态，
无论是否 tabbar 页——如地图页/首页）。
**基准态规则**：多状态页的基座/平铺稿必须用 **status_map 默认态**
源图；弹窗/遮罩/异常态禁止做基座（其素材只作条件渲染参考）——实测
选弹窗态做基座 = 40+ 处连锁修复且未收敛。
**临时输入（与③④并行的合法性来源）**：仅源图——单页技能状态机
自足，不消费 PRD/归并结果；选页涉及同编号组时只做组内默认状态图
（其余状态等④归并后，⑥转换时补齐）。
逐页走 `flow-front-ui-line-cy-img-to-code` 完整状态机 → 高保真页成品（HTML）。
gate：逐页与源图对齐（verify 断言链 + 独立裁判）。
**只做页，不做沉淀不转 TSX**——tokens/组件库下一站统一提取；
HTML→TSX 的唯一时机在⑥（本站产物暂不进工程，归并/PRD 变化
不引发返工——转换发生在所有信息齐备之后）。

## §6 提取设计系统（依赖⑤+④）

从典型页成品中抽取（从"页"到"系统"的抽象跃迁）。
**三层完备性盘点（1008-18——判据=重复度，非清单枚举）**：
- **值级**：`src/tokens.ts`（色板/字体/圆角/间距实测值 → CSS 变量）
- **元素级**：`src/components/` 叶子组件（NavBar/TabBar/胶囊/卡片/列表行/
  表单项/弹窗/空态/按钮组/统计条——从典型页真实出现的元素泛化）
- **结构级**：**页面壳 PageChrome**（状态栏/导航/胶囊/内容区 slot/home
  indicator 整套）+ **布局骨架**（列表页/表单页/详情页三类，按 sitemap
  页面角色归并）——凡同结构在 ≥2 页出现必须组件化；⑦⑧拼壳一律用
  结构级资产**禁自造**（实测：结构级缺失 → 4 写手各造壳 8+ 文件、
  导航高度两版、选中色两版，⑩抽样 6 major 中 3 个壳漂移——结构漂移
  的正解是组件化让漂移无处发生，事后扫描抓不住结构）
- **视口档（1010-04/C-09）**：壳规格按 PLAN device_profile 定三档
  （phone_portrait 375x812 / tablet 820x1180 / landscape 1280x800）；
  非手机档与宽屏场景用**兜底壳**——画布居中 + 外背景，禁裸错乱；
  全站壳同档同规格，禁跨页漂移
- **输入补强（F 系列，1009-02 闭环）**：⑥输入不得只看 2 张典型页——
  **②盘点阶段的「跨页公共元素登记」**（逐图登记 tabbar/导航/胶囊/空态/
  按钮组等多图重复元素的实例与规格）经④归并**汇总对齐成全局组件
  spec**，⑥以该登记为输入。实证：tabbar 出现在 5 张图、携带两种选中态
  实锤与凹口跟随细节，散在 5 个单页产物中无人汇总——⑥只看典型页，
  p046 的"我的"选中样例直到用户验收报 bug 才被发现（单图视角的管线
  天然看不见跨页公共元素，图包越脏页越多这个盲区越贵）
- 工程接线（路由壳/mock 约定/tokens 引入）
- **典型页转换进工程**：⑤的 HTML 成品按 templates/page-loop-prompt.md
  五步转 TSX（**本站 gate 在④之后**——同编号组页按④归并结果在
  转换时补齐其余状态，不在④前抢跑）——组件库的活样例，⑦⑧写码
  的参照物
产出：**设计系统预览页**（tokens + 全部组件一页陈列）。
gate：模具人工确认（预览页过目）——此后所有页面的模板，错误放大
数十倍，必须人背书。

## §7 主力页面高保真制作

主力圈定（strategy-rules.md）：排除⑤典型页后，tabbar 直达页必
主力；高频使用页必主力；其余按盘点复杂度评估。
逐页：**复用⑥设计系统**，走 `flow-front-ui-line-cy-img-to-code` 第 2-5 步完整
状态机（标注以盘点稿为初稿）→ 转 TSX 组件（任务书见
templates/page-loop-prompt.md 精绘 模式：去壳/JSX提取/mock外置/
data-intent注入/等价验证五步）→ 1-2 轮与源图精炼。
**转装 gate 含素材含字检查**（1008-15）：高权重背景素材转装前查
UI 烘焙字（状态栏/按钮/时间戳），检出送 REVIEW——单页技能素材
链路的兜底收货防线（规则在 coder-prompt 禁止段）。
gate：逐页与源图对比通过（等价验证截图留档）+ 素材含字检查留痕。

## §8 其他页面铺量小循环（结对流水）

剩余直写页：按布局文档 + tokens + 组件库直写 TSX（不看原图，
布局文档是唯一视觉源）。

**结对流水编排**（写手与质检员配对，逐页即审，不攒批）：
- 写手（N 个并行 = 激活协议参数）连续写页：写 → build → 对照 →
  checkpoint 回填 PLAN.md → 完成即进裁判队列，**不停等**继续
  下一页；
- 裁判（1-2 个常驻，与写手数解耦——审的速度跟得上写即可）滞后
  1-2 页跟进：逐页审"源图 vs 成品截图"并排（任务书 =
  templates/judge-prompt.md），行式 verdict + findings；
- blocker/major → 精确清单进回修队列，写手优先修（定点替换）→
  **新裁判复检**（无历史，纯看图）；minor → 记 PLAN 偏差列，不修；
- 同页 2 轮仍有 blocker/major → 降级后置，不卡流水线；**降级须带批准
  标记**（PLAN 状态列"降级后置+批准:来源"——plan-recon 终验识别，
  1009-15/23）；
- **禁止写码会话自评代替裁判**——铺量失败模式是"模板理解偏 →
  错误复制整批"，结对第 1 页即拦截。

⑤⑦精绘页不走本节——它们在单页技能第 5 步内已有逐页裁判
（flow-front-ui-line-cy-img-to-code `references/judge-guide.md`），严重度语言
与本站一致（两份任务书、一套口径）。
**批末 style-lint 伴随**（scripts/style-lint.py）：tokens 外样式
字面量扫描（颜色/字号/族越界即报告）——跨页漂移防线落成可执行
检查。

## §9 交互接线 + 自测

a. 脚本 `scripts/extract-intents.py`（或内联）：扫描全站
   `data-intent` / button / a / input → 交互清单（页/元素/文本/类型）。
b. 模型全站接线：按页面语义 + PRD-Lite 业务规则定 跳转/弹窗/状态
   变化；**业务规则冲突的交互不接**（如未购会员 → IM）。
c. AI 自测：交互清单逐个遍历（点击可达/目标渲染/无报错）。
   分类处置：可修（接线错/笔误）自修复测；**结构性缺失**（目标页面
   图包不存在且无功能清单依据、未走④补页规则）→ 悬空保留占位 +
   记入已知问题清单（不硬连、不造页）；**synthesized 补页（gap 规则
   产出的有依据缺图页）视为已存在目标，正常接线**——悬空与补页的
   分界在 gaps-and-quality.md 缺失行。
gate：自测遍历全过或全部分类完毕。

### 探索式旅程（自测补充，1008-05）

`scripts/explore-walk.py`：从 `/` 出发机器游走——每步从当前页**可见**
data-intent 选未点过的物理点击（跳过 capsule-*/app-toast 系统件），
断言无 404/白屏/console 错；游走后对访问过的非 terminal 页做**死端
检查**（必须有返回/关闭/切换出口）。三条纪律：
- **可复现**：seed+逐步路径+覆盖数落盘，禁止"跑过即过"；
- **terminal 豁免**：合法终止页按④role 字段豁免死端判定（消费
  exits-audit 的同一份真值）；
- **定位=补充**：主流程冒烟验证设计者路径，游走**发现**想象外断链；
  出口完整性以 exits-audit 角色断言为准（1008-04）——游走发现的
  问题必须回流为确定性 fixture 才算闭环，不允许"游走过了"当结论。

## §10 集成验收

**验收维度矩阵（1009-08——查什么；怎么裁见「质检裁定协议」）**：
每维=断言手段+真值来源+覆盖方式，⑩报告**按维度出结论**：

| 维度 | 断言手段 | 真值来源 | 覆盖 |
|---|---|---|---|
| 结构正确性 | route-audit（redirect 判据）+ exits-audit 两态（1009-14） | ④冻结清单（1009-06 唯一真值） | 全查 |
| 内容正确性 | texts 断言（1009-04）+ 裁判逐字（1008-16） | inventory/源图 | 机器全量+裁判抽样 |
| 行为正确性 | e2e 冒烟（首访第 0 步 1009-02）+ 探索游走（1009-05）+ 独立接线裁判（1009-23） | behaviors 主流程标记+入口契约 | 主流程全查+游走发现 |
| 视觉保真 | 裁判看图（1007-07/首访分支/旅程连贯 1008-06） | 源图 | 抽样声明（1007-25） |
| 补页可用性 | 裁判**产品验收官分支**（1010-03：结构/美观/功能三维；功能判据=交互入口齐备且语义完整，1012-03）+ **交互有效性=⑨遍历证据** | 推导布局文档+PRD（无源图，结论口径=产品标准**非源图对比**）+ ⑨自测报告该补页交互遍历结果 + exits-audit 该补页 route verdict 在册（1012-03「在案」定义——点击无反馈=FAIL；真实增量在非出口类交互，声明出口 exits-audit 本就物理点击） | **synthesized 页全查**——无源图页不因此免验 |
| 一致性 | style-lint（--stack 1009-16）+ 跨页聚类（1009-05） | tokens+PageChrome（1009-02） | 批末全扫（**范围含⑨合议新增/补全页**，1010-05——补页晚于⑧批末，不显式纳入即漏扫）；**⑨有新增/补全页 → ⑩全扫前必须重跑 style-lint**（1009-01/15/17 三层时序断言使⑧批末旧报告自动失效，1012-04——能扫到≠跑过，重跑是规定动作） |
| 可维护性 | DOM 真实性（1009-18）+ mock 外置 lint（1007-05） | coder 契约 | lint 全查 |

各维度断言工具运行结束落**证据索引**（1009-17）；⑩报告按**本工程
版本下各工具最新有效 verdict** 出结论（1009-01）——缺行/FAIL =
⑩ FAIL。

**验收视口（1010-04/C-09）**：四验收脚本（e2e-smoke/exits-audit/
route-audit/explore-walk）以 `--viewport` 按 PLAN device_profile 档

### 交付清场（1008-03，⑩检查单三项——实测三漏全过⑩）

- **(a) 脚手架/占位页退役**：root 不得落非业务页——按 sitemap
  「入口契约」root 落点断言（e2e 冒烟第 0 步 + route-audit
  redirect 判据背书）；脚手架自检页删除或重定向，禁"加探针让
  audit 放行"式绕过（篡改断言预期比漏检严重，发现即人工 gate）。
- **(b) 中间产物清场（1009-07 未知文件报告制）**：交付根目录与 src/
  按已知类匹配（构建配置与产物/src 声明资产/pipeline 管线产物/docs），
  **匹配外文件逐个报告 + 人工裁决**（清理或留档），不自动 FAIL——枚举
  点名追不上发明。点名仅为历史举例：单页技能 preview-*.html 与
  __preview_* 转 intermediates、临时截图/自测脚本（_shot*/_verify* 类）、
  死代码（退役组件/占位页文件）、dev 调试目录；已知类清单按工程类型
  可扩展。
- **(c) 数字终态一致且可核验**：交付报告出具后工程**再有任何改动**
  → 重跑全部验收脚本、重出数字；报告数字区标注最终验收产物的
  文件名+mtime（或工程内容 hash），审阅者可 diff 核验"数字=最终
  工程态"——不靠执行端"记得重跑"（实测：报告 16:55 写 58/58，
  17:23 重跑 57/58 FAIL，报告未更新照常交付）。**机器化载体
  （1012-05）**：出具报告时点执行 `plan-recon --freeze-fingerprint`
  落盘 src 指纹（与证据落账时点合一）；交付 gate 以 `--final
  --require-frozen` 核对（不一致=FAIL，逼重跑重出数字；两开关
  互斥防自洗）。

### 交付纪律（硬规则）

- **FAIL 不许解释成 PASS**：审计工具原始输出（含全部 FAIL 行）原文进
  交付报告附录；对 FAIL 的重述逐条引用证据并标"重述"；数字区引用
  脚本产物路径可 diff。
- **已知问题分级**：cosmetic（可带）/ **major（阻断：必修；有实测修法
  当场应用）** / missing（走悬空分诊）。归因过可修性门——有已知检测/
  修复手段的不得归"需设计侧"。报告禁含"有修法未应用"的 major。
- **补全清单**：固定章节——补了哪些壳元素/页面/交互、依据（产品常识/
  PRD 推导/已有复用）、位置。与已知问题清单并列。
- **工具修订**（1010-02）：管线执行中就地修复过验收工具的，交付报告
  单列一节逐条披露——四件套：改了哪个脚本/修了什么/影响哪些站的断言
  口径/判定依据（根因+复现）；技能侧下轮复审追认或否决，否决则工具
  恢复原语义或重修+受影响断言重跑+数字更正。
- **报告读者规范**（1008-10——报告写给"拿项目的人"不是写给管线，
  实测用户"看不懂/不详细/该解决的留给我"）：三段式——
  ①**5 分钟跑起来**（命令+入口+环境要求）；
  ②**验收路径清单**（每条入口→操作→**预期落点**，用户照着点）；
  ③**已知限制与真待拍板分离**（见 1008-11 分诊）。
  硬规则：**禁内部编号**（OI-6/GAP-5/④2:1 裁决/status_map 等管线
  黑话必须写人话，改写范式："三张设计稿的支付倒计时互相矛盾
  （12:00:00/23:59:59/12分02秒），我统一取了 23:59:59——不同意
  告诉我，改一个 mock 字段的事"）；已知问题写全四件——**在哪/
  长什么样/怎么改/修复代价**，"额度用尽记档"式一句话不算交代。

### checkpoint（⑨后⑩前）

Spec/Standards 双轴审查：**关键流程全查**（PRD 主流程标记）+ 其余按
模块抽样，报告**声明抽样清单与比例**——区分全查结论与抽样结论，
禁止把抽样写成全站 PASS。

## 质检裁定协议（UDP，全管线——1009-22）

> 全管线每站的复核/审查/质检/语义判断点，统一挂本协议。查什么=验收维度
> 矩阵（§10），怎么裁=本协议。**判断类型决定复核强度**：确定性工具的正常
> PASS 不开对审/仲裁；语义灰区与高影响判断（造页/落点指派/定级边界/冻结
> 决定变更）才走完整流程。

### 四要素

1. **判断携带对照物**：任何质检判断（工具 FAIL/裁判 findings/gate 结论/
   agent 决策）必须引用对照物（卡面条款/契约/源图/§0 叙述/行为清单），
   禁裸判断。**依据缺失是合法判断结果**——输入无业务信息时登记缺口与
   推断入账本，禁找弱相关材料凑证据。
2. **对审独立**：复核者只看**同一份原始依据和产物**独立出结论——不看
   首位判断者的结论（防锚定）；两份结论对表，一致→执行/登记，分歧→
   仲裁（此时仲裁者才看双方论据与结论）。
3. **分歧升级路径 + 不变量**：分歧可判定"测试基准错/工具误报/实现错"，
   但修正相应输入或工具后**必须重跑生成新结果——账本裁定不得覆盖原始
   退出码**（1007-16 底线的协议化）。仲裁涉及超大成本/原则冲突 → 用户
   终裁；用户不在线 → 依赖该裁定的工作挂起记 pending_review（其他独立
   任务继续），**受影响功能与主流程不得报全绿**，交付时列明待裁决项/
   受阻范围/未执行验收；**仲裁 agent 不得代用户改业务原则**。
4. **账本备案（decisions.md，append-only）**：只记**有裁量的推断、分歧、
   例外、降级、用户推翻**（机器结果归证据索引 1009-17，不重复）。每项：
   `ID | 类型（推断/分歧/例外/降级/推翻）| 问题 | 候选项 | 默认选择 |
   依据版本 | 影响范围 | 裁定 | supersedes`。交付报告置顶「语义推断区」；
   用户随时翻、可推翻（定点重跑）。

### 协议边界四条

1. 判断类型决定复核强度（见首段）——普通检查不加双 agent；
2. **原始 FAIL 不可覆盖**——账本裁定不得改判退出码，改判唯一途径=
   修正输入/工具+重跑；
3. **账本只记裁量**——机器结果进证据索引；
4. **冻结产品决定的变更权限在用户**——合议/仲裁一致也不能改变已审冻结
   决定（gap 裁定/冻结路由/行为依据），冲突方案记**变更待审**。

### 参与度联动（1009-24：激活参数「参与度」×协议行为）

激活表单「参与度」（三档，替代原暂停点密度+失败页处置两问）→ 协议行为：

| 参与度 | 合议一致 | 合议分歧 | 原则冲突/超大成本 | gate |
|---|---|---|---|---|
| 全自动放手 | 执行+账本 | AI 仲裁→执行+账本 | 挂起 pending_review | 紧凑（四处 gate 默认裁决） |

用户不在线：挂起不阻塞其他任务；交付列明待裁决项；回来定点续跑。

## 失败处置规则链（1009-09，全管线统一）

> 失败相关规则（诚实报告/分级/根因门/忽略审计/抽样声明/冻结终审）的
> 统一裁定程序。分类学 severity（blocker/major/minor/cosmetic）× 归因域
> （写码/接线/素材/设计/上游技能）× 可修性（有修法/无修法/超预算）为
> **描述维度**——处置按以下**优先级规则链**裁定（顺序即优先级，首个
> 命中的规则生效）：

1. **用户叫停**：用户明确表示停止/接受现状 → 立即冻结交付（铁律 3，
   优先于一切修复纪律），未决问题如实进交付报告；
2. **根因门**：任何修复轮第一动作=复现+定位根因并报告，禁"改一版试试"
   （1007-19）；
3. **分级处置**：blocker/major 必修（有实测修法当场应用，1007-17）；
   minor/cosmetic 记档可带；
4. **降级/冻结**：修复额度用尽 → 冻结终审（1008-11：~30 分钟级定点修
   优先；仍冻结须给"留档代价>修复代价"理由）→ 显式降级状态须**批准
   标记**（plan-recon 终验识别，1009-15）；
5. **忽略豁免**：逐条理由+有本地处理器佐证才允许（1007-11），审计进报告；
6. **报告诚实不变量**：贯穿全链——原始 FAIL 不得被解释成 PASS（1007-16），
   账本裁定不得覆盖原始退出码（UDP 不变量）。

**各站质检分歧**（裁判 vs 写手对定级/处置不服）→ 走「质检裁定协议」
对审+仲裁（见前节）。
