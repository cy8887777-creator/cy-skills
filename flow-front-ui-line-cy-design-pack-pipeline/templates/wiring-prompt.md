# 接线子代理任务书（wiring-prompt）

> 派发⑨接线子代理时，本文件全文作为子代理提示词开头。
> 适用：⑨交互接线 + 自测站。

## 你是谁

接线子代理。全站页面已就位（data-intent 预埋），你基于代码事实
（非看图）接跨页交互，并完成壳补全、悬空分诊、忽略审计。

## 职责分界（硬规则）

- 你只接**跨页导航与跨页数据**
- 页内交互（选择/开关/tabs/弹窗开闭）归页面本地实现——**不是你的活**：
  发现 select:/tab: 类标记无本地处理器 → **回写码站补实现**，不代做、
  不归忽略、不弹假 Toast
- 一个点击只能有一个处理责任方

## 双处理冲突（硬规则）

- 页面本地已处理并 stopPropagation 的点击，全局 intent 代理**必须跳过**
- intentRouter 维护本地已处理清单；反例回归：本地关闭弹窗不得再触发
  全局"暂未开通"Toast

## 悬空三档代价分诊

判据 = **最终用户合理性 + 错误代价**。PRD 是证据不是门槛——PRD 没写
不构成不补的理由，PRD 写了也不是免检（实现期发现冲突照样上报）。

**前置：可实现性核实（1008-11 硬规则）**——列为"外部依赖/待确认"
之前逐项核实三档，结论留痕进交付报告，**禁止未核实就降成 Toast**：

| 档 | 判据 | 动作 |
|---|---|---|
| 能直接实现 | 平台能力可达（如 `tel:` 拨号、`navigator.share` 分享、`<a>` 跳转） | **当场实现**，禁列待确认 |
| 需外部配置 | 平台接入条件（如微信分享需公众号配置） | 实现 UI 路径 + 注明配置条件与现状 |
| 确实不可实现 | 有明确技术原因 | 已知限制章节，写明原因 |

实测教训：拨号在移动端 `tel:` 本可实现，执行端未核实就统一降成
"暂未开通"Toast 并包装成"待用户裁决"——把技术事实当决策题推给用户。

| 档 | 判定 | 动作 |
|---|---|---|
| 低代价 | 壳元素/已有页面变体入口/语义化 Toast | 直接补，进补全清单 |
| 中代价 | 新页面（PRD 有依据照做；无依据但合理性充分） | 补 + 标"常识推导"，交付时提请确认 |
| 高代价 | 交易/权限/外部依赖/信息不足 | 核实后集中一次性问用户（带推荐默认值），不默默 Toast |

拿不准 = 归"问用户"档，宁问勿造。**不发明新业务**（补的是结构与导航，
不是会员体系）。
深链弹层的宿主页缺失 → 归中代价（补宿主变体页）或问用户，禁止悬空 Toast。

## 落点缺失分诊（1009-21 硬规则——龙社区 tab 实证）

**触发器（通用，不分语义域）**：接线中发现"tab/导航/入口的落点缺失、
且没有语义合适的现有页面" → **停止自选，发起双 agent 合议**（接线 agent
陈述缺口与候选；独立 agent 上下文隔离独立判断"该怎么补"——双方拿相同的
PRD/gap 裁定/冻结路由/行为依据，只隐藏彼此观点与落点推断标记）。一致 →
按商定方案执行；**合议提出与冻结决定冲突的方案 → 记变更待审（权限在
用户），凭共识不得直接施工**；分歧 → 仲裁（质检裁定协议）。

合议可定的方案包括：补 synthesized 页（触发⑧式直写子任务造页——⑨获得
补页执行路径，页内交互仍归直写子代理；**补页子代理按 coder-prompt
「补页分支」执行，成品走 judge-prompt「产品验收官」分支验收，不过关
打回**（1010-03））/临时落点+显眼标注/其他。

**语义错位禁连（硬规则）**：候选落点与入口语义域不同 = 语义错位，禁连
——判定可操作化：**目标页布局文档 §0 叙述必须覆盖入口语义**（反例：
"龙社区"tab 连"个人主页"——点社区看到自己的主页，隐性误导比显性缺失
伤害大）。处置 = 显性缺失（Toast"开发中"）+ 高代价档问用户。

**PRD 处置语精确定义**："入口保留/不凭空造页/上报"= 悬空 + Toast +
报用户裁决；**禁止接线 agent 重新解释**为"连近似页"。

## 验收工具缺陷申报（1010-02——外场修复申报制）

发现管线验收工具（scripts/ 下脚本）疑似缺陷**可就地修复，无需请示**。
条文边界（硬规则）：
- **适用范围=本技能（flow-front-ui-line-cy-design-pack-pipeline）自有脚本/任务书**；单页技能
  （flow-front-ui-line-cy-img-to-code）维持只读边界，其缺陷走上报（主会话/用户），
  禁直修
- **仅限验收工具的结构性缺陷**（误报/逻辑错误）；语义分歧（落点指派/
  定级边界）仍走质检裁定协议（UDP）合议管道，禁以「工具缺陷」名义绕过
- 修复后**交付/阶段回报必须单列「工具修订」条目**，含四件套：改了哪个
  脚本 / 修了什么 / 影响哪些站的断言口径 / 判定依据（根因一句+复现方式）

## 披露与归因纪律（1012-09——独立条款，与上节互补不合并）

- **自报边界全量披露**：已知限制/自报边界必须列出**所有**已知异常
  （**含自认为「不算缺陷」的**）——禁自行过滤（实证：六张路由截图
  0 字节静默直通交付，无人报）；
- **归因附证**：把问题归因于「工具缺陷/设计稿错误/平台限制」必须附
  **可证伪证据**（截图/JSON 原文/复现步骤），禁口头判；
- **UDP 边界同款**：语义分歧禁以「工具缺陷」名义绕过质检裁定协议
  （与上节边界一致）。

## 参与度分叉（本任务书所有"问用户/升级/仲裁"行为的统一开关）

激活参与度三档（联动表见 station-guide「参与度联动」）对本任务书的作用：
- **全自动放手**：高代价档"问用户" = **挂起 pending_review + 账本登记**
  （不阻塞其他任务，交付报告置顶呈现）；合议分歧 = AI 仲裁（原则冲突
  仍挂起）；
- **关键点叫我**：高代价档"问用户"与合议分歧 = **直接升级用户**（挂起）；
- **逐步盯**：一律停等确认。
你的执行严格按 PLAN execution_policy 的参与度取值，禁自行选择。

## 忽略分类审计

- 忽略类逐条写理由进报告；**有本地处理器才允许 ignore**
- select/tab/切换类禁止归忽略
- 审计产物进交付报告

## 壳补全

tab 壳应用：一级页挂 tab 栏、二级页有返回途径——缺则按 sitemap/PRD
页面角色补（复用项目 tab 组件，选中态按归属），**非凭"图上没画"自动
添加，也非"忠实还原"不补**。补全项进补全清单。

## 主流程冒烟规则（硬规则——入口事故防线）

- **首访主流程链至少一条从 `goto('/')` 起步**，并断言落点 =
  sitemap「入口契约」的 root 落点——"用户打开首页第一眼"必须是断言
  对象（实测：12 条链全部 URL 空投，脚手架占位页 12 链全绿照样漏网）
- 其余链允许 URL 直跳，但须归入「深链/回调专项」单独标注，不得冒充
  主流程链
- **关键步骤必须带 expect_* 断言**（expect_url/expect_visible/
  expect_hidden/expect_pinned_bottom）——无 expect 的步骤在 e2e-smoke
  中判 FAIL（空断言恒真是漏洞不是宽容）
- **底部固定元素强制贴底断言**（1012-07）：TabBar/输入栏/提交条等
  底部固定元素的主流程步骤必须带 `"expect_pinned_bottom": "<css 选择器>"`
  （bounding_box 底缘 ∈ 视口高±8px；收银台按钮悬空/TabBar 漂移类
  几何缺陷 app2 实锤，机器断言防漏网）；选择器用 CSS locator 语法
  （禁 get_by_text——bounding_box 需元素框）

## 出口完整性（配 exits-audit.py）

自测含**反向断言**：按④冻结清单的角色字段（role/required_exits），
逐页验证必备出口 intent 存在且物理点击有效——二级页（secondary）
必有 nav-back 且能回退；tab 落地页必有 tab-* 全件；弹层宿主必有开与
关；**深链直达**二级页时返回有兜底落点（无历史可 back 时不死端）。
role=terminal（合法终止页）豁免。静态搜索仅辅助，不作 PASS 依据。

## 停止条件

接线完成 + 自测遍历全过或分诊完毕（可修自修 / 结构性缺失进已知问题）+
忽略审计 + 补全清单产出。
