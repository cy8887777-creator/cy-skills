技能说明
PROJECT SYSTEM / 01

从效果图包
到可运行的多页工程

design-pack-pipeline 是一套由 AI 主会话编排的项目级工作流。它把一包页面效果图转为有路由、页面组件、模拟数据和交互的前端工程，并用逐站产物与门禁管理长任务。

输入 · 效果图包输出 · 前端工程现行 · 十站流程
效果图包 PNG / JPG
盘点与理解逐页制作集成验收
多页前端工程 路由 · 组件 · mock · 交互
01 / 定位

这套技能解决什么问题

单页高保真还原能够做好一张图，但一包图还包含重复页面、同页不同状态、页面之间的业务关系和工程交付。多图技能负责把这些工作排成有输入、产出和验收依据的顺序；需要精绘的页面调用单页技能，其他页面复用统一设计系统制作。

输入按编号、页面名和状态命名的图包；可附功能清单、设计规范
输出用户指定技术栈的多页 H5 工程与交付报告
边界当前入口针对位图图包；蓝湖切图链接是后续能力讨论，并非已支持输入

浏览器层验收适用于所选技术栈；文件形态检查目前适配 React 与 Vue。其他栈的自动检查范围须在启动时说明。第二次实跑促成了入口、旅程和质检规则的修订；这些规则的跨项目效果仍需新的完整运行验证。

02 / 使用

怎么启动，需要提供什么

在支持该技能的 AI 编程工具里提出“用 design-pack-pipeline 把这包效果图做成多页前端项目”。技能会先展示能力简介，再分两次收齐七项输入；图包路径必须由你提供，收齐后才开始盘点。

项目输入 · 4 项决定做什么、做在哪里
图包路径 必填上传图包或指定目录。图片按“编号-页面名-状态.png”等规则命名；技能不会自行搜索目录。
增强文档可给功能清单、已有 PRD 或设计规范的文件与路径；没有可填“无”。
技术栈默认 React + Vite + TypeScript + Tailwind；所选栈若缺自动检查适配，启动时应说明验收范围。
工程落盘地址指定项目输出目录；默认当前工作目录下的 app/。
执行策略 · 3 项决定参与方式、保真度和并发
参与度全自动放手（默认）：AI 合议与仲裁，原则冲突挂起并留痕；关键点叫我：各站 gate 停等、分歧直接问你；逐步盯：每站停等确认。
主力页精细制作开（默认）：走完整高保真流程；关：并入轻量铺量流程，交付时声明保真降级。
并行子代理数9（默认）、5 或 3；用于视觉盘点与铺量写手，裁判并发独立安排。
一次说清的输入示例

图包：…/design-pack/；增强文档：…/requirements.md；技术栈：React + Vite + TS；工程目录：…/app/。执行策略：全自动放手、主力页精细、并行子代理 9。

参与度同时控制审阅停等与语义分歧升级，原“暂停点密度”和“失败页处置”已合并。检测到单页技能时，⑤⑦使用完整高保真流程；未安装时走降级流程，并在交付报告中说明。

十站工作流

每一段先产生下游能用的事实，再进入制作和验收。典型页可与产品梳理并行；发现偏差时按对应产物定位返工，人工审阅的停等方式由执行策略决定。

逐站看输入、产出与检查

① 盘点图包文件名 → 图级清单与 PLAN 初稿全量解析，未知命名需处理
② 视觉盘点每张源图 → 布局文档与缺口清单逐图覆盖，缺失与矛盾有记录
③ PRD全量布局文档 → 业务规则、主流程、站点地图页面 ID 覆盖并审业务逻辑
④ 状态归并PRD 与同页状态图 → 默认态和冻结路由清单每组状态有据对账
⑤ 典型页精绘最难的 2–3 页 → 高保真样板与③④并行；逐页对照源图
⑥ 设计系统样板与冻结结果 → tokens、组件与工程模具模具过目后再规模复用
⑦ 主力页精绘高频页 + 模具 → 页面组件与 mock逐页视觉核对和转装检查
⑧ 其他页铺量剩余布局 + 模具 → 批量页面每页构建与结对裁判
⑨ 跨页接线全站页面 + PRD → 跳转与跨页数据主流程实际点击与自测
⑩ 集成验收工程与审计证据 → 交付报告构建、路由、视觉和失败项对账

十站背后的执行机制

编排层

主会话管进度与真值

SKILL.md 规定站序、输入确认和暂停策略；PLAN.md 记录页与站点状态。页面布局、PRD 和默认状态各有固定产物，避免下游凭记忆猜。

执行层

角色任务书随任务下发

盘点、PRD、写码、接线、裁判分别收到自己的短任务书。页内切换和弹窗由写码站完成，跨页导航由接线站处理。

验证层

脚本与独立裁判配合

脚本检查可确定的合同，裁判判断视觉与语义，浏览器走真实主流程。原始失败结果保留，不能在交付报告里重新解释成通过。

关键脚本落在哪些环节

setup-env.py开工前准备浏览器、Python 依赖与精绘环境
intake.py① 解析图包命名，建立图级清单和 PLAN 初稿
plan-io.py全程维护执行计划与页面状态
style-lint.py⑧ 检查页面样式是否偏离设计系统
contracts-lint.py逐页与⑩检查路由标记、目录和命名合同
route-audit.py⑩ 对账路由并验证目标组件真实渲染
e2e-smoke.py⑨⑩ 用浏览器物理点击检查主流程
跨站机制

十站怎样判断、裁定和留下证据

十站保持原有生产顺序。质量检查贯穿各站：机器核对确定的合同，独立裁判检查视觉与语义；有分歧时按依据对审并升级裁定。原始工具 FAIL 必须修正输入或工具后重跑，不能用讨论记录改写成 PASS。

质检裁定链对照物与产物 → 独立判断 → 分歧仲裁或用户终裁 → 裁量入账本机器结果进入证据索引 · 冻结的产品决定只能由用户变更
⑨ 交互接线接线表对照行为清单与入口契约；一级导航、主流程和补页落点逐条审语义。缺少合适页面时先分诊，不能硬连相似页面。
⑩ 集成验收从证据索引读取本工程版本下各工具的最新有效结果，按验收维度出结论；缺行、失败和待裁决范围不能报全绿。
用户参与全自动放手、关键点叫我、逐步盯控制合议后的升级与停等；选择会传到接线、裁判和交付说明。

新增的检查工具与记录

exits-audit.py按页面角色验证返回、tab 和弹层出口，物理点击后检查预期落点
explore-walk.py从首页探索可见交互，记录可复现路径，用于发现断链
evidence_index.py按工程版本汇总检查结果，终验拒绝缺失或失败的必要证据
plan-recon.py将冻结路由、工程页面、PLAN 状态与证据结果逐项对账

这些产物怎样被消费

页面清单与 PLAN①建立，④更新。前者告诉后续站点有哪些图与路由页；后者记录每站和每页做到哪、哪些事项待审。
布局盘点与 PRD②先记录图面事实，③再推导业务规则与主流程；④据此核对同页状态，写码站消费两者。
设计系统与页面代码⑥沉淀 tokens 和组件；⑤⑦⑧逐页生成页面与 mock，⑨接跨页关系，⑩检查工程。
审计与交付报告⑩汇总构建、路由、主流程和视觉裁判结果，保留失败项与补全清单；文件位置由工程配置决定。
