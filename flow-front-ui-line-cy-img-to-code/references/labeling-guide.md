# 标注指南（references）——第 1 步需求项 + 第 2 步标注细则

## §0 需求项与目录保护（第 1 步）

### 技术栈表（必选，模型无权代选；默认推荐项置首）

| 选项 | 口径（详见 system-rules.md §4） |
|---|---|
| HTML + CSS（默认推荐） | 纯 HTML/CSS 单文件，零框架依赖 |
| HTML + Tailwind | Tailwind Play CDN |
| React + Tailwind | React 18 UMD + Babel standalone@7.25.6 + Tailwind CDN |
| Bootstrap | Bootstrap 5.3.2（jsdelivr，带 integrity） |
| Vue + Tailwind (beta) | Vue 3.3.11 global build（npmmirror）+ Tailwind CDN |
| Ionic + Tailwind (beta) | Ionic CDN + Tailwind，图标用 ionicons |
| 其他 | 用户指定；先确认能否单文件运行再开工 |

含 CDN 的栈必须提示"产物打开需联网"（见 environment.md S1）。

### 档位逻辑

| 档位 | 流程 | 逻辑 |
|---|---|---|
| 保真 | 全流程含双模型抠图 + 结构断言 | 素材用真图、透明背景，最贴近原图；耗时最长 |
| 快速 | 同流程但 `--no-alpha`（跳过抠图） | 素材用原图裁剪（可能带底色），最快；适合草稿 |

### 覆盖保护（事故后新增）

**默认目录名必须用图名**（如 `image2code-work/首页白改/`）——禁止用
`1`/`2` 序号（多图并行时序号目录无法辨认是谁的产物，2026-09-30
实证）。同一张图重新处理/全流程重跑时，**默认新开递增目录**
（`<图名>-v2`、`-v3`…），旧产物一律不覆盖、不删除——上一次的产物
哪怕满是问题也是用户的版本历史；确需写进已存在目录，必须先列出将
被覆盖的文件并得到用户确认。受控修改轮（第 7 步）的定点重写不受
此限，但覆盖 layout.json 的管线重跑仍须先确认。

## §1 assets.json 格式（第 2 步）

```json
{
  "density_guess": 2.0,
  "assets": [
    {"description": "左上角公司logo", "box_2d": [30, 40, 80, 190], "want_alpha": true},
    {"description": "banner主图人物", "box_2d": [200, 500, 700, 980], "want_alpha": true}
  ],
  "skeleton": [
    {"type": "container", "text": "会员卡片", "box_2d": [400, 30, 620, 970]},
    {"type": "text_block", "text": "会员中心标题", "box_2d": [430, 60, 480, 300]},
    {"type": "button_bar", "text": "2 buttons", "box_2d": [900, 30, 1000, 970]},
    {"type": "nav_bar", "text": "bottom tab bar", "box_2d": [940, 0, 1000, 1000]},
    {"type": "decoration", "text": "渐变分隔带", "box_2d": [620, 0, 660, 1000]}
  ],
  "texts": ["立即登录", "¥299", "会员中心"]
}
```
- `density_guess`（2026-09-30 新增，必填）：看图判断源截图密度——
  1.0（1x 原生）、2.0（retina/2x 导出，常见：750 宽手机截图）、
  3.0（3x）；判据 = 状态栏文字与标准控件的像素尺寸（状态栏 cap
  ~11 逻辑 px，量它乘几倍）。管线用墨迹锚点交叉验证，两者打架会
  停下要求人工 --dpr——**非 2x 图不声明此字段 = 全局缩放错误**
  （事故：621 宽 dpr≈1.5 的长图按 ÷2 渲染，整页小 25%）；
- `box_2d` 为 0-1000 归一化 `[ymin, xmin, ymax, xmax]`；误差 ±3~5%
  可接受（说明书以脚本像素化+精化结果为准）；
- `want_alpha`：人物/图标/logo 等需要透明背景的为 true，大幅照片/
  背景图为 false。

## §2 素材三分类（标注前逐个强制决策，不许跳过）

1. **bitmap-content**——照片/人物/插画/复杂游戏图标等有辨识度位图 →
   标注素材；"宁多勿漏"只适用这一类；
2. **transparent-subject**——悬浮在页面渐变/纯色底上的主体（立体
   图标、发光单色图标、去背人物）→ 标注且 `want_alpha: true`。判据
   一句话：**素材边界处的背景是页面渐变还是素材自带底板？**页面
   渐变 → RAW 裁剪必然露底缝；
3. **css-native**——纯几何 UI（判据收紧：**≤2 笔画的规则形状**——
   加号、箭头、星星、勾选、纯色圆、细线框、简单胶囊）→ **禁止标注
   素材**，第 4 步用 CSS/SVG 重建（管线 brief 的 `[css-native]` 提示
   与 assets_report 的 `measure` 字段是机器参考，以人眼复核为准）。

### 压图文字判别（2026-10-08 重影根因修复）

"照片 + 半透明遮罩 + 交互文字"是高频设计模式（资料头图、卡片封面
压标题、banner 压字）。标注规则：

- **压在图上的 UI 交互文字**（昵称、标题、点赞数——活内容）→
  **照常标 text_block**。管线自动检测 text_block 与素材框相交
  （over_photo），裁剪后对相交区域 inpaint 擦除图内文字像素——
  HTML 文字层就是唯一文字，无重影；
- **图片内部的设计文字**（海报艺术字"国际博物馆日"、书法、铭文——
  它是图片内容本身）→ **不标 text_block**，整块归素材。这类字擦掉
  反而是错的；
- 一句话判据：**这个字如果内容变了，页面上的它要不要变？要变 =
  交互文字（标）；不变 = 图片内容（不标）**。

### 图标分类硬规则（堵"手画复杂图标"洞）

- **立体拟物质感图标**（多色阶渐变+高光+阴影的 3D 质感：游戏功能
  图标、宝箱、奖杯、手柄等）→ 只能抠图（want_alpha:true）。图标库
  不会有这类风格，手画更不可能还原质感；
- **扁平 2D 图标**（单色/渐变的线条或填充：购物车、齿轮、导航图标、
  按钮内图标）→ **照常标注素材** want_alpha:true，并加
  `"style": "flat"` 标签——写码前进入图标库识别（见 system-rules.md
  图标库节）：识别命中 → 引用库图标；未命中 → 用抠图。**禁止**凭
  "SVG 更清晰"把此类改判 css-native 手画（三路径可靠性恒定：源头
  引用 ≥ 像素提取 ≫ 凭空手画；齿轮两版手画均失真的实证）；
- 一句话判据：**图标一律入素材账本；css-native 只留给纯几何**。

### 状态样式与内容分离

选中框/发光边/焦点环是 UI 状态样式，不框进素材——素材框收缩到内容
本体，状态层由第 4 步按原图实测色用 CSS 重建。校准阶段发现框进了
状态层的素材，收缩 box 后重跑本步。

## §3 skeleton 与 texts 规则

- `skeleton`（推荐标注）：container（卡片/分区面板/列表行/胶囊底）、
  text_block（独立文字区）、button_bar（按钮组，text 注明按钮数）、
  nav_bar（顶/底导航条）、decoration（渐变带/分隔线/光效，**仅限
  影响视觉还原的残留项**；挖孔/信号电池/箭头圆等纯几何 css-native
  小物**不入**——无字体链路无形状保真诉求，标注只制造断言噪音）。
  **与素材严格分离**：不进素材账本、不参与抠图裁剪；text 字段填
  内容摘要；
- **text_block 必须全标**：它是字体探测（font_probe）的唯一候选池——
  每个文字块的 family/weight/size_css 合同都从它出，漏标 = 该文字
  失去字体合同与位置断言；
- `texts`：页面全部可读文案逐字收录（含数字、标点、大小写）——
  进入 layout_brief 的 TEXTS 段和 layout.json 的 expected_texts，
  **verify 阶段逐字断言**；纯装饰图形内的艺术字不收；
- **顶栏/底栏上的图标必须标注**——底栏判定（fixed 钉底）只认该行
  被标注的元素，一条不标 = 说明书判定无底栏 = 第 5 步不查底栏。

## §4 防漏复扫（必做，三向核对）

assets.json 写完后，用 Read 再看一遍原图，回答三个方向的问题：

1. **查漏（recall）**："还有漏标的素材吗？"（重点扫：角落装饰、
   小徽标、分隔图标、状态点）。漏的补进 assets.json；
2. **查误（precision）**："标注的每个框，在原图对应位置都真实存在
   且确为该元素吗？"逐条对照——常见误标是把图标**内**的艺术字看成
   图标**外**的独立 label、把背景渐变看成独立素材。标了但原图不存在
   的框必须删除；同时逐条复核三分类归属；
3. **查骨架边界完整性（structure）**："每个 container/卡片/导航条
   骨架的框，是否覆盖了该结构的完整视觉范围？"重点盯两类：
   a. **大卡片底部内嵌的条带区**（消息滚动条、公告行、页脚说明）——
      它们是卡片内部的一部分，不是独立行，漏了就会把卡片做矮、把
      内嵌区做成孤行；
   b. **渐变融入背景的底缘**——卡片背景向下渐隐时，肉眼容易把
      "对比消失处"当"边界处"，须沿边缘取色确认到色值真正并入背景
      为止。框小了的必须扩框重标。

三个方向都过才进第 3 步；**漏标 = 从产物里静默消失，误标 = 幻觉
元素进入产物，框小 = 结构残缺且校准/断言都发现不了**。
