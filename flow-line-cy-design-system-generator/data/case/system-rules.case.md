# 跑腿服务用户端 设计系统规则 / 跑腿服务用户端 Design System Rules

> **产物定位**：本文件是设计系统的 **AI 可读规则版**（由定案 HTML 派生：html_to_md.py）。
> 人看版（含实物演示）见 `system-spec/design-system.html`；机器版见 `system-rules.json`。
> 三者同源（定案 HTML），发现不一致以 HTML 为准并回改。

## 0. 使用方式（给 AI 的指令）

1. 生成 / 修改任何 UI 之前，**先读完本文件**，所有视觉决策从 token 表取值。
2. 表中不存在的值 = 禁止使用（不得自造颜色、字号、间距、圆角、阴影）。
3. 遇到规则未覆盖的场景：按价值观裁决，并把缺口记录回本文件。

## 1. 价值观（冲突裁决顺序）

一致 > 明确 > 高效 > 可生长

- **一致 Consistent** —— 4 页稿纸同类元素完全同参：卡片一律 r24 + 蓝调阴影，状态标签一律 12% tint 底 + 同色文字。

- **明确 Explicit** —— 状态用颜色+文字双通道（橙=进行中、绿=已完成），蓝只给可操作元素。

- **高效 Efficient** —— 主行动永远是蓝渐变胶囊，页面内唯一强按钮，不与用户抢决策。

- **可生长 Scalable** —— 131 个 token 四段分层；新场景先取档，取不到再按 4pt 网格补档并回填本文件。

- 两条规则冲突时，选更符合靠前价值观的方案；新规则必须能追溯到这里，否则不立。

## 2. 布局规则

> 移动端单列卡片流。所有页面按真实 375×812（源稿 750 的 1x）渲染：已提取的 4 页按实测复刻，其余 5 类用同一套组件拼装推断。

### PRINCIPLES · 原则

- 单列卡片流 —— 内容区只有一条纵向节奏：白卡 r12(1x) 浮于 #F0F7FD，卡间缝 12px（@2x 24px）。
- 骨架五层 —— 状态栏 44 → 导航 44 → 内容（边距 12）→ 底栏 58 + 安全区 19（均为 1x 实测值）。
- 模板先行 —— 新页面先归入九类布局模板；已提取 4 类按实测复刻，AI 补全 5 类也必须只用本系统组件与 token 拼装。

### WHAT · 作用

### APPLICATION · 九类布局模板（375×812 真实尺寸 · 组件实物拼装）

#### 使用规范

**DO ✓**
- 内容左右边距 12px（@2x 24px）；卡片纵列 gap 12px（@2x 24px）
- 横幅通栏出血 + gradient-overlay-page 渐隐
- 新页面先归入九类骨架，归不进的按 Hub/Feed 变体处理

**DON'T ✕**
- 禁内容区出现横向滚动
- 禁底栏页签超过 5 个
- 禁在卡片流里插入通栏元素打断 gap 节奏

## 3. 多端差异规则

> 源材料仅移动端（750px @2x）。本章以移动端实测为准；Web/Pad 行为为 AI 补全推导，待有对应稿纸后回填。

### PRINCIPLES · 原则

- 移动优先 —— 全部 token 以 750@2x 实测归档（换算 1x 即除以 2：卡片 r12、正文 12px）。
- 触控达标 —— 实测主按钮 56–32px（@2x 64px）、菜单行 60px（@2x 120px），远超 22px（@2x 44px） 硬线。

### WHAT · 作用

### APPLICATION · 三端矩阵（移动列 = 实测；其余 AI 补全）

| 维度 | 移动（实测基准） | Pad（AI 补全） | Web（AI 补全） |
|---|---|---|---|
| 导航 | 底部 tabbar ≤5 项，白底上缘分隔 | 底部 tabbar 或侧栏 | 顶部导航 + 内容限宽 750 居中 |
| 触控目标 | ≥22px（@2x 44px） 硬性（实测按钮 56/64、行高 120） | ≥22px（@2x 44px） | ≥12px（@2x 24px） |
| hover | 不存在，用按压态替代 | 部分失效，信息可点按获得 | 必须提供 |
| 弹层 | 底部抽屉 / 全屏 | 居中浮层 | 居中 Modal |
| 正文下限 | 22px@2x（=11pt）仅用于短提示；正文 12px（@2x 24px）@2x | 同移动 | 14px |

#### 使用规范

**DO ✓**
- 生成移动端 UI 直接按本文件 token（@2x 值）
- 适配 Web 时先做 1x 换算再取档

**DON'T ✕**
- 禁 JS 嗅探设备，只用断点与媒体查询
- 禁把 AI 补全列当已验证规则引用

## 4. 设计要求（跨场景组装规则）

### 概念性要求（理念层 · 跨页面类型普遍成立）
- 信息密度与呼吸感按页面任务平衡 —— 聚焦型页面敢留白、立重心；列表型页面保密度、立节奏（行卡等距、关键信息对齐、可扫读）。
- 视觉层级必须与信息层级一致 —— 重要的更大更醒目，次要的退后（本系统 16px 区块标题 → 14px 标题 → 12px 正文 → 11px 次级 的阶梯即此逻辑）。
- 一致性优先于个性 —— 同场景永远同样式；价值观「一致」在行为层的落点。

### 具体要求（本系统沉淀）
- 状态色彩语义 status-color-semantics —— 蓝 = 品牌/选中/可操作；橙 = 进行中/等待/强调；绿 = 已完成；红 = 删除/危险。状态标签一律『同色 12% tint 底 + 同色实色 12px（@2x 24px）/700 文字』
- 渐变策略 gradient-strategy —— 渐变只用于：主按钮底、功能图标圆底、装饰横幅/资料卡底、图片→页面底渐隐遮罩；卡片与控件常态一律纯色
- 阴影策略 shadow-strategy —— 阴影全部带蓝调（rgba(7,126,250,*) / rgba(20,90,180,*)），禁用纯黑阴影；悬浮元素 = 强阴影 + 白色描边环组合
- 地图层级 elevation-map —— 地图场景元素（价格卡/骑手标记）用高投影 + 白环悬浮于地图之上，z 轴高于一切卡片

**DO ✓**
- 新页面先归入九类布局模板（§02），组装时逐条对照本章要求
- 状态语义冲突时以 status-color-semantics 为准

**DON'T ✕**
- 禁绕过设计要求自创组装方式
- 禁用红/黄表达本系统未定义的状态语义

## 8. 设计禁令（产出前逐条自查）

### 概念性禁令（理念层）
- 禁把信息撑得太满 —— 布局要有呼吸感，间距留足，页面要有清晰主次；列表页的形态是行距挤压、卡片贴边。
- 禁为留白牺牲信息密度 —— 列表页每行信息必须完整可扫；禁硬造视觉重心、禁拉大留白充高级。（与上条成对：密度与呼吸感按页面任务平衡，两头都是极端）
- 禁让用户思考「这是什么」 —— 元素含义必须自明；图标必配文字标签（底部导航 = 图标+文字即此落地）。
- 禁一屏多主任务 —— 操作决策页一屏一个主行动（蓝渐变 CTA 全页唯一即此落地）；浏览列表页禁塞竞争性 CTA。

### 具体禁令
1. 禁裸 hex / 裸值 —— 一切取自 token 表（含状态标签 tint 底：用 rgba token，不手写 12%）。
2. 禁纯黑/中性灰阴影 —— 本系统阴影全部蓝调；黑阴影会立刻破坏环境光。
3. 禁魔法间距 —— 非 4pt 网格数值一律就近归档，不新造。
4. 禁一视图双主按钮 —— 蓝渐变胶囊全页唯一。
5. 禁阶梯外字号/字重 —— 非档值一律就近归档，禁止直接抄用。
6. 禁 #111/#000 作页面底 —— 那是导出兜底色；页面底只有 #F0F7FD。
7. 禁状态标签不成对 —— tint 底（tag-bg-*）与同色实色文字（tag-text-*）必须同时出现。
8. 禁颜色作唯一信息载体 —— 状态必须有文字（WCAG 1.4.1）。
9. 禁混用图标来源 —— 线性只用 Lucide 系；彩色面性仅限服务分类切图。
10. 禁 z-index 自造数值 —— 用 z-dropdown/modal/toast 三档。
11. 禁把 AI 补全值当实测引用 —— 标注为 AI 补全的 token 待实测后回填。

### 无障碍红线（自 A11Y 归位）
- 状态不只靠颜色 —— 订单状态 = 颜色 + 文字标签（照做）；禁只变色不加字；禁红绿作唯一区分。自查：设计稿转灰度自读一遍。
- 图标必须可懂 —— 底部导航 = 图标 + 文字（照做）；纯图形操作按钮必标语义文案（动词+宾语，如「复制订单号」）——这段文案就是开发的读屏标签。自查：遮住图形只读文字。

**DO ✓**
- 交付前对照本章逐项自查（概念 → 具体 → 无障碍）
- 发现新禁令线索：先登记本清单，再改代码

**DON'T ✕**
- 禁以「设计稿就这样」为由豁免禁令（导出兜底色除外，见具体禁令第 6 条）
