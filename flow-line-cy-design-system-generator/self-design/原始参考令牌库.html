体验准则

99 项 · ux-guidelines 中文版 · 每条 = 类别 + 准则 + 应该/不该 + 严重度
导航平滑滚动（Smooth Scrolling）高
Web

锚点链接应平滑滚动至目标区块

✓ 在 html 元素上设置 scroll-behavior: smooth
✕ 点击后直接跳转毫无过渡
导航吸顶导航不遮挡内容（Sticky Nav）中
Web

固定导航不应遮挡页面内容

✓ 给 body 设置与导航等高的 padding-top
✕ 让导航压住首屏内容
导航当前态标识（Active State）中

当前所在页面或区块应有清晰的视觉标识

✓ 用配色或下划线高亮当前导航项
✕ 当前位置没有任何视觉反馈
导航返回按钮（Back Button）高
移动

用户预期返回行为符合直觉

✓ 正确保留导航历史
✕ 破坏浏览器或应用内的返回行为
导航深链接（Deep Linking）中

URL 应反映当前状态以便分享

✓ 状态或视图变化时同步更新 URL
✕ 动态内容永远只有一个固定 URL
导航面包屑（Breadcrumbs）低
Web

展示用户在站点层级中的位置

✓ 层级超过三层的站点使用面包屑
✕ 扁平的单层站点也硬加面包屑
动效过度动效（Excessive Motion）高

动画太多会分散注意力甚至引发晕动症

✓ 每屏最多给 1~2 个关键元素加动画
✕ 所有会动的东西都加动画
动效时长（Timing）中

动画应干脆不应拖沓

✓ 微交互用 150~300ms
✕ 界面动画超过 500ms
动效减弱动效偏好（Reduced Motion）高

尊重用户的动效偏好设置

✓ 检查 prefers-reduced-motion 媒体查询
✕ 无视无障碍动效设置
动效加载状态（Loading States）高

异步操作期间要给反馈

✓ 使用骨架屏或加载指示器
✕ 界面毫无反馈地卡住
动效悬停与点按（Hover vs Tap）高

触屏设备上悬停效果无效

✓ 主要交互用点击/点按触发
✕ 重要操作只依赖悬停
动效持续动画（Continuous Animation）中

无限循环的动画会分散注意力

✓ 只用于加载指示器
✕ 用在纯装饰元素上
动效transform 性能（Transform Performance）中
Web

部分 CSS 属性会触发昂贵的重绘

✓ 动画只用 transform 和 opacity
✕ 对宽高/top/left 做动画
动效缓动函数（Easing Functions）低

线性运动显得机械

✓ 进场用 ease-out、退场用 ease-in
✕ 界面过渡全程线性
布局层级管理（Z-Index Management）高
Web

层叠上下文冲突会导致元素被遮挡

✓ 定义 z-index 阶梯体系（10/20/30/50）
✕ 随手写超大的任意 z-index
布局溢出裁切（Overflow Hidden）中
Web

隐藏溢出可能裁掉重要内容

✓ 确认所有内容都能完整放进容器
✕ 盲目套 overflow-hidden
布局固定定位（Fixed Positioning）中
Web

固定元素可能互相遮挡或挡住内容

✓ 考虑安全区和其他固定元素的位置
✕ 随手堆叠多个固定元素
布局层叠上下文（Stacking Context）中
Web

新建层叠上下文会让 z-index 失效

✓ 理解哪些写法会创建新的层叠上下文
✕ 以为 z-index 能跨上下文生效
布局内容跳动（Content Jumping）高
Web

内容加载时布局位移非常突兀

✓ 为异步内容预留占位空间
✕ 让图片和内容加载时把布局挤来挤去
布局视口单位（Viewport Units）中
Web

移动浏览器上 100vh 会出问题

✓ 使用 dvh 或为移动浏览器工具栏留出余量
✕ 移动端全屏布局直接用 100vh
布局容器宽度（Container Width）中
Web

行宽过长的文字难以阅读

✓ 限制正文最大行宽（65~75 字符）
✕ 让文字铺满整个视口宽度
触控触控目标尺寸（Touch Target Size）高
移动

过小的按钮难以准确点中

✓ 触控目标最小 44×44px
✕ 可点击区域极小
触控触控间距（Touch Spacing）中
移动

相邻触控目标需要足够间距

✓ 触控目标之间至少留 8px 间距
✕ 可点击元素挤在一起
触控手势冲突（Gesture Conflicts）中
移动

自定义手势可能与系统手势冲突

✓ 避免在主内容区做横向滑动
✕ 覆盖系统级手势
触控点按延迟（Tap Delay）中
移动

300ms 点按延迟显得卡顿

✓ 用 touch-action 或等价方案消除延迟
✕ 依赖移动端默认点按处理
触控下拉刷新（Pull to Refresh）低
移动

误触发刷新令人烦躁

✓ 不需要的页面明确禁用
✕ 所有页面默认开启
触控触感反馈（Haptic Feedback）低
移动

触觉反馈能提升操作实感

✓ 用于确认和重要操作
✕ 振动反馈滥用
交互焦点态（Focus States）高

键盘用户需要可见的焦点指示

✓ 交互元素保留可见的焦点环
✕ 直接移除焦点描边且无替代
交互悬停态（Hover States）中
Web

可交互元素要有悬停视觉反馈

✓ 变更光标并加轻微视觉变化
✕ 可点击元素悬停毫无反馈
交互按压态（Active States）中

按下时要有即时反馈

✓ 增加按压态的视觉变化
✕ 交互全程毫无反馈
交互禁用态（Disabled States）中

明确区分不可交互的元素

✓ 降低不透明度并更换光标
✕ 禁用态和可用态长得一样让人困惑
交互提交防重（Loading Button）高

防止异步操作期间重复提交

✓ 禁用按钮并显示加载状态
✕ 处理中允许连点多次
交互错误反馈（Error Feedback）高

出问题时用户必须知道

✓ 在问题附近给出清晰的错误信息
✕ 静默失败毫无反馈
交互成功反馈（Success Feedback）中

成功操作要向用户确认

✓ 显示成功信息或视觉变化
✕ 操作完成毫无确认
交互确认弹窗（Confirmation Dialogs）高

防止误触不可逆操作

✓ 删除等不可逆操作前必须确认
✕ 不确认直接删除
无障碍色彩对比（Color Contrast）高

文字必须在背景上清晰可读

✓ 普通文字对比度至少 4.5:1
✕ 低对比文字
无障碍不只靠颜色（Color Only）高

不能只用颜色传递信息

✓ 颜色之外加图标或文字说明
✕ 错误和成功只用红绿区分
无障碍替代文本（Alt Text）高

图片需要文字替代

✓ 有意义的图片写描述性 alt
✕ alt 属性为空或缺失
无障碍标题层级（Heading Hierarchy）中
Web

读屏器靠标题层级导航

✓ 按序使用 h1~h6
✕ 跳级使用或拿标题当样式
无障碍ARIA 标签（ARIA Labels）高

交互元素需要可访问名称

✓ 纯图标按钮补 aria-label
✕ 图标按钮没有任何标签
无障碍键盘导航（Keyboard Navigation）高
Web

所有功能都应可键盘操作

✓ Tab 顺序与视觉顺序一致
✕ 键盘陷阱或 Tab 顺序混乱
无障碍读屏友好（Screen Reader）中

内容被朗读时应当语义通顺

✓ 使用语义化 HTML 和正确的 ARIA
✕ 满屏 div 毫无语义
无障碍表单标签（Form Labels）高

每个输入框必须有对应标签

✓ 用 label 的 for 属性或包裹输入框
✕ 只靠 placeholder 当标签
无障碍错误播报（Error Messages）高

错误信息必须能被读屏播报

✓ 用 aria-live 或 role=alert
✕ 错误只做视觉提示
无障碍跳转链接（Skip Links）中
Web

让键盘用户跳过导航直达正文

✓ 提供跳到主内容的链接
✕ 导航繁重的页面没有跳转链接
性能图片优化（Image Optimization）高

大图会拖慢页面加载

✓ 选择合适的尺寸和格式（WebP）
✕ 直接塞未优化的原图
性能懒加载（Lazy Loading）中

内容按需加载

✓ 首屏以下的图片和内容懒加载
✕ 所有资源一次性全量加载
性能代码分包（Code Splitting）中
Web

过大的资源包拖慢首次加载

✓ 按路由或特性拆分代码
✕ 全部打成一个巨大 bundle
性能缓存策略（Caching）中
Web

回访应该更快

✓ 设置合理的缓存响应头
✕ 完全没有缓存策略
性能字体加载（Font Loading）中
Web

Web 字体可能阻塞渲染

✓ 用 font-display: swap 或 optional
✕ 字体加载期间文字隐形
性能第三方脚本（Third Party Scripts）中
Web

外部脚本可能阻塞渲染

✓ 非关键脚本异步或延迟加载
✕ 第三方脚本同步加载
性能包体大小（Bundle Size）中
Web

过大的 JavaScript 拖慢交互

✓ 监控并控制包体增长
✕ 无视包体无限膨胀
性能渲染阻塞（Render Blocking）中
Web

CSS/JS 可能阻塞首屏绘制

✓ 关键 CSS 内联、非关键延迟加载
✕ 大体积阻塞式 CSS 文件
表单输入标签（Input Labels）高

每个输入框都需要可见标签

✓ 标签始终显示在输入框上方或旁边
✕ 只拿 placeholder 当标签
表单错误位置（Error Placement）中

错误信息应出现在问题附近

✓ 错误显示在对应输入框下方
✕ 整个表单只在顶部给一条错误
表单即时校验（Inline Validation）中

边输入或失焦时即校验

✓ 大多数字段在失焦时校验
✕ 只在最终提交时校验
表单输入类型（Input Types）中

使用合适的输入类型

✓ 邮箱/电话/数字/URL 用对应 type
✕ 所有输入一律用文本框
表单自动填充（Autofill Support）中
Web

帮助浏览器正确自动填充

✓ 正确使用 autocomplete 属性
✕ 屏蔽或无视自动填充
表单必填标识（Required Indicators）中

必填字段要清晰标注

✓ 用星号或（必填）文字标明
✕ 必填字段没有任何标识
表单密码可见（Password Visibility）中

允许用户输入时查看密码

✓ 提供显示/隐藏密码的切换
✕ 没有可见性切换
表单提交反馈（Submit Feedback）高

提交状态要向用户确认

✓ 先显示加载再给出成功或失败状态
✕ 提交后毫无反馈
表单输入可供性（Input Affordance）中

输入框要看起来像输入框

✓ 输入框做差异化样式
✕ 输入框看起来像普通文字
表单移动键盘（Mobile Keyboards）中
移动

按输入类型调出合适的键盘

✓ 使用 inputmode 属性
✕ 所有输入都用默认键盘
响应式移动优先（Mobile First）中
Web

先为移动设计再增强到大屏

✓ 从移动样式起步再加断点
✕ 桌面优先导致移动端一堆问题
响应式断点测试（Breakpoint Testing）中
Web

常见屏幕尺寸都要测试

✓ 在 320/375/414/768/1024/1440 下测试
✕ 只在自己的设备上看一眼
响应式触控友好（Touch Friendly）高
Web

移动布局需要触控尺寸的目标

✓ 移动端加大触控目标
✕ 移动端沿用桌面的小按钮
响应式可读字号（Readable Font Size）高

文字在所有设备上都必须可读

✓ 移动端正文最小 16px
✕ 移动端用极小字号
响应式视口声明（Viewport Meta）高
Web

为移动设备设置视口

✓ 使用 width=device-width 和 initial-scale=1
✕ 视口声明缺失或错误
响应式横向滚动（Horizontal Scrolling）高
Web
