# prototype-and-design-system-to-hifi —— 原型+设计系统重构高保真设计

把「可编辑 HTML 原型目录 + 设计系统」重建为高保真 HTML 多页产物。
方法论三句话：**内容零编造**（逐字溯源自原型）；**视觉按设计系统语义重生成**（流式布局，非换肤）；**脚本断言归零制**（代码审核用现成断言脚本，修到问题数=0）。

## 输入与判定顺序（先原型分析，再设计系统）

```
① 原型路径（本地，必需）→ 可用性检测 + 原型分析
      不合法 → 终止，给转换出路
② 建议式问答（一个弹窗出完，只依赖原型分析）
      输出倍数（多选）· 自适应宽度（实验性）· 输出节奏
③ 设计系统路径（本地/线上，必需）→ 可用性 + 完整性分级
④ 按分级：完整 → 直接编译
        部分 → 必走「设计系统补充环节」：
               AI 从不全的设计系统特征推导缺项
               → 补充版规范 → 用户确认回填 → 再进重建
        缺失 → 不就绪，终止（恢复条件=提供最小 token 清单；
               缺失时的获得方式属独立原子能力，不在本技能范围）
```

**设计系统是必需输入**：部分质量不高 → 补充环节推导缺项；完全缺失 → 不进入管线。补充产物按完整性基准 10 节成文、逐节标注来源，随交付留档。

原型只收**本地、格式干净**的 HTML（逐页静态内容可解析）；JS 渲染页/接口页/整页大图/线上网址 → 拒绝并给自转换出路。设计系统路径本地/线上均收（线上抓一次存档）。

## 问询（两轮弹窗，候选禁止预置任何具体项目名/路径——只允许用户手输或运行时探测）

**第一轮（原型分析完成后，一个弹窗出完）**
- **输出倍数（多选）**：识别原型用什么系统——**读声明 → 读语义 → 理解内容**三层漏斗：第一层 读声明（viewport/显式画布宽/口径标注，零误差直接用；注意「声明宽=未声明」≠无声明，需下探第二层核 .stage 内联样式等显式声明）→ 第二层 读语义（DOM 现成标记）→ 第三层 理解内容清单（文本通道必做；多态模型可加截图，无图不影响）。查**宽度区间表**出初步判定，**连判定带建议一起亮给用户，识别错了用户一句话修正**——问询本身就是纠错机制，不做交界带硬判
- **自适应宽度**（实验性）：如实告知未实战验证；选「要」→ 强制案例先行，样板页先验证可行性，不行如实回报并退回固定宽
- **输出节奏**：案例先行（默认推荐，3~5 页样板定调后铺量）/ 全量直出（用户明确选才走）；选了自适应 → 强制案例先行

**第二轮（设计系统体检分级后）**
- 补充环节确认：AI 推导的缺项清单（哪些 token/组件/章节是推导的）→ 用户确认或修正 → 回填补充版规范

## 执行工作流（六个阶段）

```
阶段一 内容盘点    原型解析 → 每页内容清单（阅读序文字+图片，越界剔除）→ 对账（清单数=页数，不平终止）
阶段二 规范编译    设计系统 + 本项目决策（倍数口径/图标策略/缺失推导规则/惯例）→ guide.md（结构基准=references/guide-template.md，先读后编）
                    ※ 是「编译+决策固化」非重写：零丢弃机制见下
阶段三 样板定调    3~5 页覆盖主要模板 → 规格比对表+原型结构对照（前置产物 .gen/sample-check.md）→【用户验收门：定调】→ 不过改 guide 重做
阶段四 全量生成    子代理并行分批（见派发规则）
阶段五 代码审核    audit 断言 + 修复 → 重跑 → 问题数=0（归零制）
阶段六 交付        _index 总入口 + 报告 → 移交 UI 走查（用户技能）
```

**阶段二 规范编译 = 零丢弃转换**：把设计系统条目化（token 逐个/组件逐组/禁令逐条/章节逐个），每条强制落到五格之一：token CSS 块 / 组件配方 / 铁律 / 本项目不适用（标理由留档）/ 待样板门确认。审计断言 guide 覆盖率 = 已映射/总条目，静默丢弃=失败。产物侧再反向抽查：随机页样式值能对应回 token。条目化数据源优先用设计系统的机读版（json），markdown 表格有派生粘连风险。**零丢弃只覆盖「设计系统条目」；还必须有「区块→组件映射表」（guide-template §4.5：样板页逐区块、全量页按模板类归并）——无此表 = 编译未完成，禁止派发。** 设计系统只给到概览级（组件有规格、没给区块用法）时，映射在编译期显式推导并逐条留痕 `.gen/decisions-log.json`，禁止把映射缺口留给子代理即兴。

**阶段三 上定调门前置（不可跳过）**：样页完成 ≠ 可交用户。主代理必须先产出《规格比对表》：用到的每个组件，设计系统规格值 ↔ 页面 CSS 实际值逐项对照（落 `.gen/sample-check.md`），并截图对照原型原稿结构；存在未对齐项 → 先改再上门。**无比对表不得把样页交给用户。**

## 派发规则

- **派发模式（铁律）：子代理一律后台模式（run_in_background）——主会话保持可对话，用户插话不杀代理；回执靠完成通知回收，禁前台阻塞等待。**
- 每批 ≤10 页，**按模板类型分组**；批次任务落盘 JSON（rel/depth/内容清单 + **适用映射条目**——来自 guide 区块→组件映射表），子代理只认自己的清单
- 每批随附**派发简报**（模板=guide-template §4.6）：规范指针/本批构成/本类配方与坑/通用红线/完成定义，五块缺一不得派发；落盘后先跑 `validate-batches.mjs` 自校验再派
- 清单生成时做 **rel 唯一性预检**：同 basename 多页按内容清单语义配对路径，配不平标人工决策
- 内容清单预生成（content-dump 内置负坐标剔除，适用于带坐标的 data-idx 原型；无坐标的通用 HTML 由主代理在清单阶段语义把关），子代理禁读原始原型
- **子代理禁做结构决策**：区块用哪个组件由 guide 映射表说了算；遇到映射缺口 → 回执 `blocked: 页+缺口`，不得即兴组装；主代理补映射（推导留痕）后重派该页
- **决策采信必须留痕**：子代理决策清单 = 变更请求；主代理逐条按「原型结构 + 设计系统规格」双证据核验，采信/驳回写入 `<产物根>\.gen\decisions-log.json`；未留痕 = 未复核，终审按未复核处理
- 并发上限感知：占满排队、完成补位；子代理回执 done/failed/blocked/决策清单
- 代理挂掉：终审覆盖率核对发现缺口 → 自动重派补批（不惊慌不中止）

## 代码审核（归零制，不做渲染层检查/识图）

用 `scripts/audit.mjs`（现成），断言按倍数集参数化：
覆盖率（原型每页×每倍数=产物存在）｜.stage 容器与宽度=所选口径｜@font-face 前缀=页深｜素材全部本地引用｜title 存在｜内容反向溯源｜N 倍数值=基准×N。
**问题 → 修复 → 重跑 → 归零**；failed 页自动重派。全程**零截图**。

## 交付物

```
<产物名>\
├─ _index.html          总入口（按倍数分链接，按目录分组）
├─ <基准宽>\             基准版 <原型页数> 树（自包含 fonts+assets）
└─ <其他宽>\             派生版 ×N（各自自包含）
```
产物根只留 `_index + 版本目录`；工作档案移出产物根。交付报告：页数/倍数/推导补全项/模板决策备案/失败重派记录。

## 铁律（违反=返工）

1. 内容零编造：页面每段文字只能来自该页内容清单
2. `.stage` 画布容器：body 后第一个元素，宽度=该版本基准宽
3. 多倍数由 `scale.mjs` 派生，禁止手写非基准版本
4. 字体路径 = `'../'×页深 + 'fonts/'`
5. 素材全部本地引用（原型外链图生成期下载进产物 assets；原型 assets\ 目录由主代理整目录拷入各版本后再引用）
6. 声明优先：原型/设计系统自带声明（viewport/画布宽/口径标注）零误差直接采信，推断只兜残差
7. 弹窗三态识别：独立页/隐藏层（必获）/点击动态创建（按需交互探测，探不到如实标注，不编造）
8. 产物每页自包含（样式内联或页内；如用户选共享 CSS 架构则组件样式集中 components.css）

## UI 走查移交（边界）

渲染走查/DOM 断言/视觉规范 = 用户技能领域。本技能交付后明确声明移交，不做、不重复、不越界。

## 启动欢迎语（触发后第一句输出，照此输出；每条独立成行，勿合并段落）

```
把你的低保真原型，按设计规范，重做成高保真设计稿。

**你给**：低保真原型目录（HTML）+ 设计规范

**我做**：每一页按规范重做——布局不变、内容不变，视觉全部换成规范样式

**你得**：一套高保真页面（可直接打开看、可导入 Figma、可交给开发）

**要求**：原型为本地 HTML 目录（每页独立文件，单页也支持）；JS 渲染/需登录/整页大图的页面不支持。设计规范完整最好，只有颜色字号清单也能跑（缺的部分会标注）。你的原型不会被改动，成果存放在新目录。

**流程一句话**：读取原型内容 → 按设计规范重做 → 样板页你定调 → 全量生成 → 代码审核清零 → 交付（可直接打开、可导入 Figma）。

把「**原型目录路径**」发我就开始；输出倍数、输出方式到时选项里会标。
```

## 问询与文案守则（对用户说话的方式）

- **欢迎语只披露「能力 + 流程」**：能力写到维度级（不列缺陷名词）；强项一两句（批量、闭环）；流程一句话；能力边界分条 upfront；选项细节与耗时归选项菜单；结尾=「把什么发我 + 关键选择到时选项里会标」
- **问询一律用弹窗选择**（ask_user_question）：路径类给候选项+可手输；选择类按语义用单选/多选并带推荐项
- **问询候选禁止预置具体项目名/路径**：只允许用户手输或运行时从用户环境探测的候选（测试时尤其注意——不要把开发会话的项目上下文带进技能选项）
- **给用户看的文字用结果语言**：说清「查什么、多久、得到什么」；禁止把内部术语当文案（归因/机检/探针/仲裁/台账/画像/内容清单编号等，对用户说「已识别」「问题清单」）
- **自创体系命名用中文**：阶段一~六、第一层/第二层/第三层，禁自造字母编号（L1、P0 式命名不用）
- **行业标准词中英连用**：首次出现写全（行动点CTA、层叠z-index、样式css、布局跳动CLS），后文可用英文
- **代码级标识符保留英文原样**：文件名、字段名、函数名、标准条款号不翻译
- **机制解释不进对话**：内部编排、菜单过滤、实现细节——系统做了就做了，用户看到结果自然明白
- **欢迎语测试法**（作者不许自评）：找不懂项目的人看，只许问三句——这是干嘛的？你会怎么用？你会得到什么？任何一句答不上=重写

## scripts 速查

| 脚本 | 用法 |
|---|---|
| `content-dump.mjs` | `node content-dump.mjs <原型根> <dump输出目录>`（两参必填；**输出目录固定 = 产物根\.gen\dumps，audit 按此路径读取**；且必须在原型目录之外）→ dump txt + dump-report.json（均落在输出目录内） |
| `build-manifest.mjs` | `node build-manifest.mjs <原型根> <dump目录> <产物根> <基准宽>` → manifest 落 `<产物根>\.gen\manifest.json` + 同名冲突预检 |
| `scale.mjs` | `node scale.mjs <基准html> <产物根> <目标宽>` → 派生版本（校验 .stage 容器，拒绝手写） |
| `audit.mjs` | `node audit.mjs <原型根> <dump目录> <产物根> <基准宽> <倍数...>`（**倍数集含基准宽本身**，例：375 375 750）→ 问题清单（归零制） |
| `validate-batches.mjs` | `node validate-batches.mjs <原型根> <batches目录>` → 派发前自校验（dump 存在/rel 在原型树/样板排除/无重复未派发） |
| `build-index.mjs` | `node build-index.mjs <产物根> <基准宽> <倍数...>` → _index.html |

细节与配方：**生成规范模板**（token 块/组件配方/铁律全文）与**失败模式手册**见 [references/guide-template.md](references/guide-template.md) 与 [references/pitfalls.md](references/pitfalls.md)；宽度区间表见 [references/platform-matrix.md](references/platform-matrix.md)；输入契约全文见 [references/input-contract.md](references/input-contract.md)。
