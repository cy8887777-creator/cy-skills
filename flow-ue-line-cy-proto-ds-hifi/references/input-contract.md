# 输入契约与启动体检

> **流程顺序**：拿到路径 → 先体检 → 体检报告与问答一并向用户回放（不存在「先问还是先检」的悖论：问答的内容就是体检的结论）。

## 体检口径定义
- **N 页**：排除 `_` 前缀文件后的 .html 数（`_index.html` 等入口不计页）
- **树深 X 层**：rel 的路径段数（根级页=0 层）
- **图片 M 张**：页面引用次数（非素材文件数）；外链 K 张=其中 http(s) 引用数

## 一、原型（必需，不可替代）

### ✅ 接受
- 本地目录，含一个或多个 `.html` 页面（允许子目录树）；单页原型也收
- 每页内容为**静态 DOM 节点**：文字/图片直接写在 HTML 源码里（墨刀/设计工具/任何静态导出皆可；data-idx 平铺或普通语义 HTML 均可）
- 编码 UTF-8（其他编码自动转）
- 图片为本地相对引用，或可控外链（外链图生成期自动下载进产物 assets）

### ❌ 拒绝（逐条告知原因 + 出路）
| 形态 | 原因 | 出路 |
|---|---|---|
| 需 JS 运行才呈现内容（SPA/动态渲染） | 源码读不到内容 | 浏览器打开后另存为渲染后 HTML |
| 内容来自接口/登录态 | 同上 | 同上 |
| 整页一张大图（无文字节点） | 无结构可提取 | 需含真实文字图层 |
| 线上网址 | 入口只收本地 | 先保存为本地 HTML（渲染后另存） |
| 解析后零文字零图片 | 无内容可重建 | 检查导出完整性 |

### 体检输出格式
```
✅ 可用：N 页，树深 X 层，图片 M 张（外链 K 张将自动下载）
❌ 不可用：逐页原因（疑似 JS 渲染/编码异常已自动转/空壳页）
```

## 二、设计系统（必需——没有「缺了也能跑」，只有「补多少」）

### 完整性基准（10 节，源自实战案例 system-rules 的章节结构；补全时按此结构成文，一节不漏）

| # | 章节 | 必需度 | 缺失时的推导规则（补充环节内执行） |
|---|---|---|---|
| 1 | 颜色 token（基础+语义，带用途） | **必需** | 从设计系统已有特征推不出→终止（颜色是推导的锚点，不能无中生有） |
| 2 | 字体（家族/字阶/字重/行高） | **必需** | 同上 |
| 3 | 间距（网格+档位） | **必需** | 4pt 网格推导，标「AI 推导·待确认」 |
| 4 | 圆角（档位+载体） | **必需** | 按组件尺度推导，标待确认 |
| 5 | 阴影（档位+色相策略） | 重要 | 按品牌色推导，标待确认 |
| 6 | 组件规格（变体/状态/尺寸/说明） | 重要 | 样板验收门兜底 |
| 7 | 设计要求（状态语义/渐变/阴影策略） | 重要 | 行业惯例推导，标待确认 |
| 8 | 图标与素材 | 可选 | 保留原型切图（替代方案） |
| 9 | 设计禁令+无障碍红线 | 重要 | AI 保守处理，报告标注 |
| 10 | 布局/多端/动效/价值观 | 可选 | 最近似惯例补全，标待确认 |

### 完整性分级 → 处置
- ✅ 完整：直接编译进生成规范
- 🟡 部分：最小 token 清单（主色/文字色/圆角/字号，一页纸也算）→ 走补充环节，AI 从已有特征推导缺项
- ⬜ 缺失：**不就绪，终止**。恢复条件=提供最小 token 清单（颜色/文字色/圆角/字号，来源不限）。缺失时的设计系统获得方式属独立原子能力，不在本技能范围

> 设计系统不完整不终止（有补充环节兜底）；**完全缺失才终止**。补充环节产出的规范随交付留档，下次复用时即为现成完整设计系统。

### 补充产物格式
按完整性基准 10 节成文，每节标注来源：【用户提供】【AI 推导·待确认】【不适用·理由】；「AI 推导·待确认」条目汇总到样板验收门，用户定调后回填。补充产物随交付留档，下次复用时即为现成完整设计系统。

## 线上设计系统分支
设计系统路径为线上时：抓取一次 → 存档至工作区 `<产物根>\.gen\design-system\`（或工作档案区）→ 之后等同本地参与 10 节分级。**只抓一次**，后续管线不依赖网络。
