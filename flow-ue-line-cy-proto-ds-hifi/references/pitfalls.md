# 失败模式手册（实战踩坑 + 处置）

> 每条 = 症状 → 根因 → 预防/处置。全部来自真实全量跑批（120 页 × 多代理）与技能引导测试（新实例第一视角 13 条问题）。

## 1. 子代理中途挂掉 → 整批文件缺失
- 症状：覆盖率核对发现连续 N 页缺失，该批代理无 done 报告
- 处置：**覆盖率核对是兜底网**——缺口按清单自动重派补批，不惊慌不中止
- 预防：批次 ≤10 页缩小爆炸半径；任务落盘 JSON 可原样重派

## 2. 同 basename 页冲突（两 cid 指向同一路径）
- 症状：清单生成时两个页面映射到同一产物 rel，后者覆盖前者
- 根因：原型树存在同名页（跑腿/代驾各有 已取消.html 等），按 basename 找路径时相互覆盖
- 处置：build-manifest 直接以**原型树真实路径**为 rel（天然唯一）；若两个 cid 的 dump 内容一致→合并写一次；内容不同→各写各的真实路径
- 预防：清单阶段的 rel 唯一性预检（缺失清单自动进入补发批）

## 3. 字体路径深度错
- 症状：产物字体 404，回退系统字体
- 根因：子代理按错误深度写 `'../'×n + 'fonts/'`
- 处置：audit 断言「@font-face 前缀 = '../'×页深 + fonts/」逐文件必查；错则按页深重写
- 预防：guide 写明深度公式；**页面挪动目录后必须重算前缀**

## 4. 跨包/跨项目素材引用
- 症状：产物 HTML 引用 `../../../../其他包/assets/x.png`
- 根因：子代理发现本包缺素材，就近引用了源包
- 处置：audit 断言禁止；统一替换为本地 assets 前缀；assets 目录缺失→先从源拷贝
- 预防：铺量前确保产物根 assets 就位（写在流程阶段一）

## 5. 越界内容混入（相邻画板串入）
- 症状：dump 出现与页面无关的发单页/其他画板文字（负 x 或远超画宽）
- 根因：原型导出时相邻画板内容渗入
- 处置：content-dump 剔除负坐标/越界画板条目；子代理按「内容只来自 dump」铁律天然免疫

## 6. 手写非基准版本 → 数值漂移
- 症状：750 版与 375 版内容/数值不一致
- 预防：**非基准版本只能由 scale 脚本派生**（脚本校验 .stage 容器存在才肯跑）；audit 断言各树 stage 宽=目录口径 + 倍率数值=基准×N

## 7. 工作文件混进产物根
- 症状：产物根出现 .gen/dumps 等目录，交付不干净
- 预防：工作档案写产物根**之外**；交付前核对产物根只含 `_index + 版本目录 + 资源`

## 8. stage 宽度断言误报
- 症状：audit 报「stage 宽错」但实际正确
- 根因：断言正则假定 width 是 .stage{} 首个属性，部分写法 position:relative 在前
- 处置：断言正则放宽为 `.stage{[^}]*?width:\s*(\d+)px`

## 9. 弹窗漏检/动态弹窗
- 症状：点击才出现的弹窗没被重建
- 分态：独立画布页（天然识别）/同页隐藏层（解析完整 DOM 含隐藏节点，按遮罩+白窗特征抓）/点击 JS 动态创建（仅带运行时 JS 的页面存在——静态原型无此问题）
- 处置：按需启用交互探测（点击前后 DOM 差异）；探不到的如实标注「无法静态还原」，不编造

## 10. 审计脚本自身 bug 导致误报/漏报
- 症状：计数与盘面不符（如 750 树遍历得 0）
- 根因：遍历排除规则把整树文件排掉（-750 后缀被当作排除项）；比对键归一化方向不一致
- 处置：审计结果与盘面独立核对（find vs 审计计数）交叉验证；断言正则放宽后复跑
- 教训：**审计脚本也要被审计**——数字异常先查脚本再查产物

## 11. 文档与脚本实现漂移（引导测试发现；**audit 链路已复发一次**）
- 症状：新实例照 SKILL.md 用法表执行脚本必报错（参数个数/顺序与实现不符）；输出路径三处说法矛盾；文档承诺的行为（如越界剔除）脚本未实现
- 根因：脚本与文档分别演化，无一致性校验
- 处置：脚本参数化定稿后**回写 SKILL.md 速查表**；副作用（默认输出位置）在文档明示；承诺的行为要么实现要么改口径
- 预防：改脚本必查 SKILL.md 速查表同步
- **复发实录**：audit 脚本初版——素材断言用 `.match()` 只查第一个引用（近乎失效）、倍率断言只有注释没实现、dump 目录硬编码未接线且无存在性保护、排除目录写死本项目目录名。全部由「注入缺陷→断言必须各报一条」的有效性测试暴露

## 12. 设计系统不完整时的 guide 编制（补充环节）
- 症状：设计系统不完整时，「覆盖率=已映射/总条目」无从计算（缺项根本没有条目）
- 处置：**先走设计系统补充环节**——按完整性基准 10 节成文补充版 system-rules（缺节按推导规则生成、逐节标【AI 推导·待确认】）→ 再对补全后的条目集做映射覆盖率 → 「AI 推导·待确认」条目全部汇总样板验收门，用户定调后回填消除待确认态

## 13. 双目录副本漂移
- 症状：同一技能在 `.claude\skills\` 与 `.dsh\skills\` 各有一份，改一处另一处过期
- 处置：`.dsh\skills\<名>` 建为指向 `.claude\skills\<名>` 的 **Junction**（目录联接，无需管理员）；**`.claude` 为唯一源**，永不当场编辑 .dsh 侧
- 核验：`Get-Item .dsh\skills\<名> | Select LinkType,Target` 应显示指向 .claude

## 14. 区块→组件映射缺失 → 子代理组装漂移（实战复发：首页四入口被做成 2×2 大卡+越权黄底、白卡加规范外描边）
- 症状：内容溯源全过、结构机检全过，但组件选型/装饰细节偏离设计系统；用户一眼看出「不对」
- 根因：guide 只有配方集没有「区块→组件」映射，子代理禁读原型、结构真相无人传递；样式保真无断言（audit 按设计不管渲染层）；主代理对子代理决策清单橡皮章放行
- 处置：guide 补 §4.5 映射表后重做该页；已生成页逐组件做《规格比对表》纠偏
- 预防：编译期产出映射表（样板页逐区块、全量页按模板类）；批次清单携带映射条目；子代理遇缺口回执 blocked 不即兴；决策采信双证据留痕 decisions-log.json；定调门前置《规格比对表》（sample-check.md），无比对表不得交用户
