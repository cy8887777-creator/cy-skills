## 前言（使用契约段，位置在九段之前）

九段是**风格契约**（这个风格长什么样）；前言是**使用契约**（怎么读它、怎么用它做事）。两者性质不同，不可互相替代。

- **位置**：排在九段之前。AI 先读到它，心态才是"读一位设计师的品味"，而不是"读一份规格表"——顺序颠倒，这段就失效。**它不是第 10 段。**
- **文案**：全库通用，**逐字照抄**（下方全文），一字不改、不删、不换算例。它是声明与授权，不是描述这个风格。
- **禁止**：不得改写成"使用说明/契约"等元标题（标题固定 `前言`）；不得按项目定制；不得放在九段之后；不得在正文里解释这段本身。

固定文案：

```
前言

这张卡不是约束清单，而是一位设计师的品味。你读完它，就是这套风格的设计师本人，此后每个决定从这份品味出发：写实的数值与明确禁令是硬习惯，照办；倾向与氛围由你自行权衡——业务可用优先，再用这套风格的语言完成表达；卡里没写的，由这份品味自行推导，不必另请示。验收只有一条：它像不像这位设计师亲手画的。
```

## 九段结构（按此顺序，槽义照搬正本原文）

1. **整体风格**：建立整体观感，突出最有辨识度的核心特征。不用历史介绍、家族知识或模糊比喻替代实际描述。
2. **色彩**：写这个风格在颜色上真正讲究的东西——讲究什么写什么（明度结构、饱和策略、色数纪律、对比承担、色相氛围……），**维度不设清单**，不讲究的维度不凑；写到别人能复现这个风格的用色感觉为止。**起草场景例外：写实值色号**（项目自用，铁律 2"实值照办"与文字层实值校验的依据；正本禁色号是库卡可迁移性要求——色值存数据层、提示词只交付可迁移的用色语法，起草不受此限）。色相是不是这个风格的身分，按风格真实情况判断：是身分的写色相氛围方向，不是身分的不提色相。
3. **字体**：字形气质、字重、标题与正文的关系。不把推荐字体包装成风格唯一字体。
4. **图形与图像**：图标、插画、照片、装饰图形的表现方式。区分核心特征与可选手法，避免要求所有元素同时出现。
5. **材质与光影**：纹理、透明、描边、阴影、表面效果及其关系。避免与图形段重复，避免无依据的精确参数。
6. **布局与排版**：构图、留白、密度、对齐和信息层级。不根据风格擅自规定具体项目的页面功能、导航和业务结构。**具体功能模块名、导航项清单、入口卡命名属于产品 IA，不是风格——九段只写它们的形态语法（数量档/容器样式/层级关系），命名与题材归业务材料。**
7. **控件与容器**：风格在按钮、输入框、卡片、面板等界面元素上的体现。不写 API/DOM/组件适配；没有专属控件要求的风格不强造控件规范。
8. **动效与反馈**：与风格有关的运动、过渡和可见操作反馈。不涉及业务逻辑，不默认每种风格都有特定动效。
9. **限定与排除**：澄清易误解的边界，提供必要的负面约束。不重复正文，不把个人偏好写成风格禁令。

必要时可增加简短备注，但必须是理解风格所需的内容。结构是工作底稿，不以段数和字数形式达标替代内容质量。

## 写作要求（照搬正本原文）

- **前言是写作姿态的自我声明，不是内容**：九段写这个风格长什么样，前言写"你该怎么用它"。写九段时心里要有这个前提——你是在向一位读者转述一位设计师的品味，不是在交付规格书。**九段因此不能写成特征清单**：逐条罗列"斜切标题 + 硬阴影 + 噪点 + 撞色"这种写法，会让前言失效（读者读到的仍是清单）。九段写这位设计师会怎么做、为什么这么做、在哪里会克制。
- **风格 vs 工程分界（全局原则）**：九段描述风格的样子与规则（是什么样），不写制作流程与工程实现（怎么做到）——素材获取与处理、文件格式与体积、内联/外链方式、换色脚本、字体加载栈、性能数值属于工程纪律，归本技能铁律 5/8 与生成任务书，不进九段。逐句自检：任何一句在回答「怎么做出来」即删。
- 总体几百字简洁表达，不写成长篇设计系统文档。
- 自然、明确的语言，不堆砌抽象形容词。
- 有可靠规范的写准确数值；只有倾向的用准确概念与视觉关系；该风格没有限定的维度明确"不作风格要求"。
- "不作要求"不等于"禁止"，也不等于让 AI 任意重做其他内容。
- 描述明确作用范围，避免"粗描边""强对比"无法判断用于何处。
- 各段不必等长，避免某段塞多个大问题、其他段只剩空话。九段偏重按风格类型自定（产品工具卡重官网实证与产品结构；运动/经典卡重文献与历史语境；美学卡重视觉技法与手法边界），**不照搬任何单卡的偏重比例**。
- 来源记录、调研过程、方法论解释不进提示词正文。
- **"尚未查清"是调研缺口，不能写成"该风格不作要求"**——起草场景对应：没有依据的数值不伪装成风格规范，如实标注"暂定，待用户改"。
