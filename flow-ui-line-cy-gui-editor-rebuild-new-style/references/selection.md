# 第 0 步 · 风格选型（可选前置）

触发条件：第 0 问用户选了 **B 没想好，帮我挑**。已有风格提示词的用户跳过本文件直达第 1 步。

凝练自源选型比稿技能（gui-style-picker）与 wiki 检索协议（wiki-access），自包含。裁定纪律继承：**AI 给推荐排序是意见，选权全在用户**；候选相关的全列出，禁设淘汰坟场；只报证据确凿的适配判断，品类氛围想象不算理由。

## 六步

### ① 读产物 docs（=业务约束表的原料）
产物 `docs/` 供料四件（铁律 3 口径，对应主管线 V0.1 业务节的等价物）：用户输入文档（用户裁决原文）、开工文档 1.0（项目定义/业务链路）、盘问文档、页面地图扩展（页面清单与行为叙述）——旧风格的设计资产规范不进供料、不读（新风格自产，铁律 1/3）。缺件按铁律 1 上报停线。

**docs 缺受众/品牌层信息时的最小三问**（正本原文，语境适配：V0.1=docs 供料）——只问风格决策相关的三件事：**给谁用（受众）/要什么感觉（气质）/什么设备（平台）**，每问带 2-4 个口语选项让用户点选，一次一问；**禁开放式作文题，禁问产品功能与商业模式**（产品是什么从用户的话里能知道即可——需求调研不是你的活）。其中**气质/感觉是主观题**：用户答"说不准/都想看看"是常见且合法的回答，如实记录——文字描述不可决的维度，不逼用户做文字决策（交给比稿卡看图选，见 ③）。

### ② 业务约束表（先翻译业务，再碰风格库）
- 产品性质一句话（效率工具/内容消费/交易工具…）；
- 使用场景与成败标准（从受众推：师傅端=户外/快速读单/工人用户 → **可读性硬要求：高对比、大字号、一眼可读**——效率工具的红线，低对比美学风格直接出局，静奢风事故定案）；
- 品牌层缺什么（文化定位/品类）——缺了先按 ① 三问问用户补齐再检索，禁自行硬猜（品类气质联想不是适配理由：风格服务于任务与认知习惯，不服务于品类想象）。

### ③ wiki 检索与候选报告（操作协议正本=wiki-access.md，整件已进包照读）
- 检索/深读/内容校验/勿读清单/兜底链全按 **references/wiki-access.md** 原文执行——紧凑视图（禁整读 manifest）、语义扩散不限关键词、**过滤永不隐藏**（用户点名的卡不在候选=检索失误先回全量核对）、深读 prompt.md 的时机=**比稿池呈报前**（拍板前不是拍板后）、平台按锁定单端型筛（mobile/tablet/desktop）、排除约束表硬冲突卡；
- **候选报告呈现规格**（正本原文）：**相关的卡全部列出**——每张写：为什么相关（落到约束表某一条）+ 短板或硬冲突 + 适配点；深读过的写九段实据，未深读的如实标注"仅一句话初筛、点名即补读"。**AI 给推荐排序（首推/对照/存疑分档，写明取舍意见）+ 比稿规模建议**——推荐是意见不是门槛，选权全在用户；
- **气质答"说不准/都想看看"时**（正本原文）：不按气质筛候选——各气质方向各 1-2 张全部进池，比稿卡承担最终收敛（用户看图选）；比稿规模建议分档给出（精简版/全方向版）由用户拍板；
- **AI 自创兜底**（用户裁决 2026-11-23：允许，仅兜底位）：wiki 拉不到且包内 style-presets.json 九槽也无合适候选时，AI 按起草协议（prompt-protocol.md）**原创起草**候选提示词，**显著标"AI 新创"**（呈报时与库卡分组/带角标，禁混排让来源不可见）——用户需要知道哪些是库里的现成资产、哪些是 AI 新造的。

### ③b 比稿池硬卡点（正本原文，先拍板再画）
池清单呈用户 → **拿到用户的确认文字（如"就要 1234"/"678 也要"）才算拍板**。呈报、检索、点名、加批讨论都属讨论阶段——**讨论阶段禁做任何派工准备动作**（复制参照/读比稿规格/派子代理全禁）；未拍板先动手=越权，立即停并交代现状。

### ④ 比稿卡（2-3 张；规格正本=specimen-card-spec.md，整件已进包）
- **比稿卡规格正本=references/specimen-card-spec.md**（252px 统一基准/载体条标注齐全/去颜色化命名/任务书五样/只复制 prompt.md 禁 card.md——照原文执行）；定调样章卡的 specimen-rules 是另一种卡（第 1 步用），不互替代；
- 每张候选按 card-spec 产比稿卡，落 `rebuilt/preview/specimens/<卡id>/sample.html`；合集页用现成壳模板 **assets/collection-shell.html** 拼（落 `rebuilt/preview/specimens/collection.html`，file:// 直开）；
- **用户点名某张库卡**（第 0 问 A 场景；含检索漏掉库里有时）→ **该卡九段原文直接冻结使用**（换风线用户裁决 2026-11-23：用原文，试点三轮验证过的路子），呈报时问一句"要不要按你产品适配起草一版"，要 → 按 prompt-protocol.md 起草并呈用户确认后冻结。

### ⑤ 用户三选一
- 话语一等公民：用户说什么都听——风格情绪类（"调暖一点"）当场微调或换候选；内容结构类登记待定；
- **微调定稿落提示词副本**：微调内容改写进 `rebuilt/intake/风格提示词.md` 对应段落（**wiki 母本永不改**），改稿呈用户确认——确认后的副本=下游唯一风格定义，禁"样张微调版/提示词库卡原版"双轨漂移。用户给白话描述要并入时，按 prompt-protocol.md 九段格式改写后再落，禁白话直接混进九段；
- 混搭请求（"结构要 B 颜色要 A"）→ 重生长为新候选再选，禁手工拼装。

### ⑥ 冻结
用户选定 → 该卡提示词副本冻结为 `rebuilt/intake/风格提示词.md`，并下载该卡封面存档 `https://design-style-wiki.pages.dev/cards/<slug>/cover.svg` → `rebuilt/intake/风格封面-<风格id>.svg`（回装时注入器转 data URI 填 pack.screenshot，面板卡缩略禁色板条降级；自创风格由画师手绘程序化 SVG 封面，参考 wiki cover.svg 画风，禁位图）→ 进第 1 步样章（选中风格的单卡定调）。落选候选目录保留不删（用户反悔可回看），交付说明登记选型记录。

## 纪律

- **失败宁停勿错**：两轮比稿仍不收敛 → 停线报告，禁猜默认风格硬推进；
- **只读产物 docs、只冻结提示词**——不改产物、不越权进第 1 步之后的环节；
- 本步产出的比稿卡与最终定调样章卡是**两种东西**：比稿卡=多候选并排供选；定调样章=选中风格的单卡精修——比稿选定后，选中那张升格为基础做定调样章（补全九段对账的深度）。
