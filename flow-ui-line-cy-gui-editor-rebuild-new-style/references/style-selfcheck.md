# 交稿自查体系（四层各查各的，互不冒充）

> **【本包适配注记】** 本文自源绘制技能全文复制，正文一字未改。本包对应关系：①原文调 solo-ui-line-cy-ui-walkthrough 走查 → 本包等价物=`scripts/ui_audit.mjs` 机检 + `audit-rules.md` 七轴规则审；②原文"样张"=本包第 1 步样章卡（禁看的原始骨架样张=完整样章卡，参照副本=sample-ref.html）；③原文"跑批收尾"=本包第 3 步全量完成后的走查闭环；④交互档位出处"开工文档 §5"=供料开工文档 1.0 的动效档字段；⑤悬空分诊/系统渲染规矩与端型细则见 `端型约束/`；⑥评审/盲测截图对象 `<风格id>/<风格id>.html`=本包 `rebuilt/preview/` 静态稿。与本包 SKILL.md 流程冲突处（如卡点时机）以 SKILL.md 为准。

质量检查分四层，每层只查自己维度的事，通道互不替代。本文件是所有自查/校验条款的唯一家：新检查项先看落在哪一层、进哪条通道，不另开条款散落。

## 分层总表（谁管什么，互不冒充）

| 层 | 查什么 | 通道 |
|---|---|---|
| 视觉硬伤 | 溢出/遮挡/对齐/断图/**密度失调** | 渲染实看（≤3 次）→ solo-ui-line-cy-ui-walkthrough 走查 |
| 风格 | 像不像亲戚、哪块出戏 | 逐页感性比照 → 审美评审 → 三方盲测 |
| 文字 | 错别字/病句/术语一致/**实值转录** | 画师通读 → 文字盲校 |
| 交互 | 结构标注合法/跳转死链/悬空=0（机器全量断言）+ hover/active/过渡活着 | 按交互档执行（a 档豁免本层）：结构标注自检 → 悬空分诊 → 死链断言 → 真实点击验证 → 画师点检 → 复核点检 |

## 视觉硬伤层

- **渲染实看**（每页画完，≤3 次）：抓溢出/遮挡/对齐/断图；**实看视口按端型**——mobile 375/390/430，桌面 1440（口径不写死，硬伤看不全）。顺带一问**密度**："这页的信息密度像真产品，还是像演示稿？"（对照端型惯例：手机列表行高、间距档位——比稿卡 7% 内边距的教训：密度失调不是硬失败，看图查不出，只有这一问能拦）。
- **最长真实文案压力测试（每页必过，删字迁就=违规）**：拿本页最长的真实标题/状态/金额/说明塞进每个列表行、时间线项、面板验排布——塞不下**改行结构**（单行改两行式、收窄辅助列、换面板组织），**禁删字、禁砍内容、禁缩字号凑合**。机器检查（溢出/遮挡）全绿不代表过关：删字迁就布局后每一项都是绿的，信息却丢了——内容完整性与可读性 > 制式符合（铁律 2 的可操作口径）。
- **solo-ui-line-cy-ui-walkthrough 走查**（实看修完）：布局/溢出/遮挡/字号/断图，退出码裁定。

## 文字层

- **界面文案分类自检（每页写完，对应铁律 3 三分类）**：①界面文案（按钮/提示/空态/错误/标签）逐个过——看的人三秒内明白这是什么、该干什么？错误给原因和出口没？空态给下一步没？②动态输入内容逐类过——像真实用户在该场景会填的样子吗（质感随填写者/场景自然变化）？长度贴场景吗？换行断句自然吗（界面边界硬折/孤字=改）？③数据——格式规范、值像真、对得上账吗？通用一刀：删掉后信息无损失的句子=装饰性废话，砍。
- **画布净度自检（每页写完）**：①页面上的每个业务字段有出处（开工文档/盘问记录/真实业务常识），自拟的字段删（如凭空造"所属平台/合作起始/审核时限"）；②每个字过一遍读者检验——"产品上线后，终端用户会看到这行字吗？"给评审/开发看的机制说明（白名单规则/平台建档/对账口径/"这套系统怎么运作"式讲解）删——这类料不归画布。
- **读者决定反向验（每页写完，对应 SKILL.md 铁律"信息先行"）**：回答两问——这页的读者是谁、他打开这页要做什么决定；然后只看这一页（允许滚动），检验读者能否做出那个决定。做不了决定 = 决定所需信息缺位或缺形态（如被缩成一行标签、只存在于别的页面），回补信息或调整结构；机器检查全绿不豁免这一条。
- **画师通读**（每页写完）：读文本不看图——错别字、病句、术语与开工文档一致；文案用行业真实用语、具体不空洞（师傅端说"竣工/工单闭环"不说"完成任务"，禁 AI 味套话）——文案水平=产品可信度的一半。
- **文字盲校**（跑批收尾，与盲测对偶：盲测不看代码只看图裁风格，盲校不看图只读字裁文字）：提取全部页面文字，派只读字的校对挑错别字/病句/前后术语不一致/数字矛盾；顺带机械对照——风格提示词写明的实值（色值/圆角/字重）逐个对照 CSS 里的值（#DA291C 抄成 #D921A0，四道看图的关全查不出）。
- 主代理复核双通道：看图（视觉/风格）+ 读文本（文字）。

## 交互层

> **档位适用**：本层各条按交互档执行——a 档（纯静态，交互只画样子）豁免结构标注/死链断言/真实点击验证/悬空分诊（"点了没反应"在静态稿不成立）；b/c 档全量执行。档位出处=开工文档 §5。

- **结构标注自检**（每页写完）：三类标注齐且值合法——跨页跳转 `data-go="目标页id"`、弹层触发 `data-sheet="open"`/遮罩关闭 `data-sheet="close"`、分段切换容器 `data-seg`+选项 `data-tab`+面板 `data-panel`。**行为由壳标准 JS 统一接管，画师禁自造交互 JS**（定制行为如输入计数可写，登记交付说明）。
- **悬空分诊决策树**（每个可点元素必有落点）：产物内页面→data-go 连线；系统/外部承载（客服会话/拨号/第三方）→**写固定标注 `<!-- 系统渲染: 拨号 -->`**（HTML 注释必含"系统渲染"四字，审计按此 grep；注释贴在该可点元素旁）+真实入口（拨号 `href="tel:"`、邮件 `mailto:`、客服链接——零网络产物里以"入口+系统标注"呈现，行为交宿主，模拟器点不动的在交付说明登记），禁自绘假界面，禁未核实就降级成"暂未开通"Toast；业务需要的新页→补页+页面地图登记+提请确认；视觉暗示可点但业务无落点（假 hover 变色/假箭头/按钮样式）→ 撤掉可点暗示（样式改回普通文本/卡片）+ 登记交付说明。**自己拿不准的才上升主代理**；禁"点了没反应"的悬空元素；不发明新业务。
- **死链断言**（自查脚本必含）：每个 data-go 的目标页 id 必须存在于产物内——零死链才过。
- **真实点击验证**（机器全量断言 + 真点抽验）：未观察到真实跳转，不得声称点击已验证——收尾自写审计脚本**逐屏激活**后盘点全部可点元素（多页同文件产物隐藏屏几何为 0，必须逐屏加 `on` 再测、测完恢复首页），悬空=0 才过；主代理在此之上真点抽验复核，观察到页面切换才算数。
- **画师点检**（每页写完）：可点元素必须真的活着——hover/active 反馈、输入框聚焦态、基础过渡（100-200ms CSS 过渡即可；motion 编排本阶段不做）。静态帧交出去，客户一摸就穿帮。
- **复核点检**：主代理复核时随机点几个可点元素。

## 一、逐页风格比照（画页循环的最后一环）

时机：**solo-ui-line-cy-ui-walkthrough 走查通过之后**。布局没走查就比照没有意义——对着一张会大改的图认亲戚是白认。

方法：把风格提示词和风格参照副本（如有；原始骨架样张禁用）放在眼前，看渲染页面（整页缩到 480px 宽看三秒，再看原尺寸），凭直觉回答一个问题：

**"这像不像这个风格的亲戚？有没有哪块出戏？"**

- 出戏的块点名回改 → 修完重跑走查（改了画面就要复走查）→ 再比照，看顺了就过。
- 变种合法：设计师故意做的风格变种，只要缩远了整体还认得出是这个风格的亲戚，就是合格的设计。判据是**识别性**，不是逐项对得上号——机械对照单会把合法变种判成不合格，已废。
- 辅助两眼（非清单，顺带看）：每屏构图概括成一个词，同一个词连续出现就是模板复读；扫一眼有没有填缝文字和"示例/示意"字样——有就删（删后同样复走查）。

## 二、审美评审（盲测前先行，独立于盲测的另一道关）

时机：全部页面完成、逐页走查与四层自检通过之后——审美评审只裁观感差距，功能错误（溢出/截断/数据矛盾）归四层自查，评审意见与之重叠属冗余保险，正常。

做法：派没参与制作的独立评审，**只看无壳渲染截图**（产物裸渲染，不含手机框/状态栏/灵动岛等壳装饰，截图前隐藏壳刘海 `.device.mobile::before`——壳元素只会引来假意见，灵动岛两次被当页面控件误报的教训；画师自查截图仍带壳，用于验证避让——两个用途两种截图），不读代码（防作者锚定），逐页回答一个问题：

> **这页属于什么品类？同类品类里公认做得最成熟的产品的设计水准就是标尺——这一页，哪一眼会被那个水准的设计师打回？**

评审产出差距清单：**位置 + 差在哪 + 成熟产品同样位置会怎么做**；哪里最弱挑哪里，不必面面俱到。职责边界：层次/密度/呼吸感/视觉权重/细节质感/交互预感的差距归它；**修法不归它**——评审只诊断，怎么改是画师的发挥（零透题纪律对评审同样成立）。没把握的点不凑数——说不出差距的意见等于没提。

评审者不给任何维度清单（层次/对比/密度枚举）——枚举永远慢问题一步，唯一指定的锚是"成熟产品水准"，差距让评审自己撞出来。

流程：差距清单 → 回原画师逐条修 → 复渲染 → **评审复审确认清单清零或有意识保留项** → 再进盲测。

## 三、收尾风格三方盲测（审美评审回改后收口，与文字盲校并行）

时机：全部页面完成、审美评审回改复走查之后。

做法：
1. 抽样页（含全部代表页）截图，混入样张截图和其他风格的图，打乱编号——截图口径（与审美评审一致，一律无壳）：对 `<风格id>/<风格id>.html` 用 playwright 做**元素级截图**（取当前页 `.screen.on .viewport`，并先注入 CSS 隐藏壳刘海 `.device.mobile::before{display:none}`——元素截图会把它截进去；不含侧栏与机身边框等壳装饰，纯静态、无弹窗遮挡）；带壳整页截图只归画师避让自查用，不进盲测/评审；样张截图取 wiki 卡封面
2. 派**没参与制作、不知道哪张是谁画的**的独立评审（子代理），只给图，不给代码/历史/风格提示词之外的任何信息
3. 评审只回答一题：**"哪张和样张是同一个风格、哪张出戏、出戏在哪"**
4. 出戏页回改 → 复测该页

边界：不打分、不评布局、不评业务、不查文字（文字归盲校）。盲测防的是"自己画的自己看着都像"——制作者的惯性会让每页自查都手下留情，只有不知情的第三方能裁风格归属。审美评审与盲测是两道独立的关：评审者不得是画师本人或参与验货的主对话，两关评审者也不得相互兼任。
