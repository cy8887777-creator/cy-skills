# 端型约束 · 微信小程序（差异层，配合 _共用.md 读）

> 本文件只装微信小程序**独有**的平台行为；通用规则（系统弹窗禁自绘/安全区/操作真实性三问）见 `_共用.md`。
> 教训出处：两稿实测（订阅授权自绘、胶囊画错/未画、"微信已绑定"语义越界——均已登记为违例样本）。

## 一、宿主接管清单（禁自绘，页面标注"系统渲染"留空间即可）

| 交互/界面 | 微信真实形态 | 断言（可机械检查） |
|---|---|---|
| 订阅消息授权 | **系统底部弹窗**（微信官方样式+「总是保持以上选择」勾选） | 禁页面自绘授权 UI；页面只画引导入口，弹窗标注"系统渲染"（违例样本：两稿都画了自定义授权弹层） |
| 定位授权（wx.getLocation） | 系统授权弹窗 | 同上——打卡页禁自绘授权形态 |
| 客服会话 | button open-type="contact" 唤起微信客服系统会话页 | 页面只画入口行，禁画会话 UI |
| 下拉刷新/启动页 | 宿主接管（onPullDownRefresh 系统样式） | 禁自绘刷新指示器/启动画面 |
| 支付（wx.requestPayment） | 系统支付弹窗 | 本业务不涉及（师傅收钱走打款），约束登记备用 |

## 二、原生组件规范（带实值）

- **右上角胶囊**：`… + ◉` 两件套（**禁画 ✕**），微信渲染、不可自定义/遮挡/移位——页面导航区必须预留胶囊位（违例样本：一稿未画、一稿画成 `… + ✕`）
- **导航栏**：原生 44-48px + 状态栏；自绘导航需 `navigationStyle: custom` 语义——返回箭头自画，布局=左返回、右胶囊共存
- **tabBar**：高度含 safe-area（≈81px，其中 home indicator 避让≈34px）；tab 页无返回箭头；**tab 页不能是普通 navigateTo 目标**
- **home indicator**：底部横条，页面底部操作/按钮必须避让
- **状态栏文字颜色**跟随头部底色（沉浸式头部深底=白字）

## 三、生态行为边界

- **页面栈 ≤10 层**：交互流程跳转超 10 层被系统拦截
- **登录**：wx.login 静默 + 手机号快速验证（button open-type="getPhoneNumber" 触发系统弹窗）——白名单模式画登录页合理（手机号授权绑定场景存在）
- **提现/打款语义**：师傅收钱 = 平台服务端打款（商家转账到零钱走 openid，师傅零操作；线下打款则银行卡仅为登记）——**师傅侧不存在"绑定微信支付"操作**（违例样本："微信已绑定"收款渠道）；未来做零钱转账需的是实名姓名字段（转账校验用），不是绑定 UI
- **订阅消息通知**送达"服务通知"，不在小程序内——消息 tab 里的订阅引导合理，通知本身不复现
- **外链字体禁**：小程序不支持外链字体加载（产物零网络口径天然合规）
- **页面标题**：自绘导航后页面标题画在页面里（navigationBarTitleText 语义）

## 四、跳转标注与真机导航对照（给下游开发，画师零感知）

产物里的 `data-go` 是效果图演示跳转；真机实现按目标页性质选 API，照普通页写 `navigateTo` 会直接报错：

| 目标页 | 真机 API | 说明 |
|---|---|---|
| tab 页（tabbar 常驻页：首页/消息/我的） | `wx.switchTab` | navigateTo 打不开 tab 页（违例隐患：照稿直译） |
| 普通页 | `wx.navigateTo`（可返回）/ `wx.redirectTo`（替换当前页） | 页面栈 ≤10 层，见生态边界 |
| 宿主能力（客服/支付/授权） | 无导航 API 对应 | 见宿主接管清单，系统渲染标注类 |

画师无需处理本节——防的是下游开发照标注语义误写导航 API。
