# 换肤模块 · 思路记录

> 性质：思路便签 + 定案记录（细节到开发时再定）。来源：2026-11-04 实例生成会话 → ZCode 会话多轮定案 → 2026-11-05 solo-tool-line-matt-grilling 23 问终审定稿。
> 位置：`.claude\skills\` 真身（`.zcode\skills\` junction 透链，单一改动点）。
> 总纲：**设计的第一性是风格和业务需求，而不是拿模板套住他们。** 零机械资产：判定 AI 判、骨架 AI 长、参考只事后照镜，唯一硬的是令牌禁硬值门禁。

## 起因

- 风格切换器现在只切几个 CSS 参数变量，间距/背景/字重/组件形态/图标都硬编码在页面样式里——切不动。
- 编辑器「添加组件」插的是中性组件，不带当前风格——切风格后新旧内容两套皮拼接。

## 思路要点

1. **三层皮肤**：L1 令牌集（CSS 变量，值可为任意 CSS 片段）+ L2 覆盖样式（按组件类重写外观）+ L3 图标按形态族备多套内联 sprite。
2. **组件包**：生成时顺手产出 10–15 个带当前风格的高频组件，存 COMPONENT-PACK 受控块；编辑器组件面板读包。
3. **受控块**：STYLE-REGISTRY（族登记+皮清单）/ STYLE-PACK ×N（含 palettes 色板变体）/ COMPONENT-PACK / STYLE-CONTRACT。照 K2 迁移范式校验。
4. **引擎正交**：切换器注册表驱动，加皮=插包+注册一行，引擎不改。
5. **深度换肤外置**：产物内轻量令牌切换；深度换肤走 style-reskin。生成管线技能不外发。
6. **产物内不做结构级切换**：跨族=换原型（面板 Tab2 出口或脚手架管线）。

## 主流程（定版）

```
U1 问答收口（interrogation 九协议 + 新增两问，见下）
   → start-doc V0.1：业务+受众组+信息架构清单（页面/模块/层级），
     完整度档+动效档，风格槽空占位
   → 调起 solo-ui-line-cy-gui-style-picker（见下节）→ 选中结果回传
   → 策划环节（0.1→1.0 的收口回流延续）：必要问题补问，
     用户可委托"你定"→AI 直接决策输出 → 简单汇总确认（复用现有收口确认步骤）
   → start-doc 1.0（风格槽填充+策划产物）→ manifest 冻结（校验风格槽非空）
   → U2 令牌展开（只扩不改选型已锁值）+ 组件包 → U3 页面生产（令牌禁硬值）
   > ⚠ 站点映射历史行：本文件早期写法为「U3 页面生产」，**现行以 SKILL.md 为准（U2=页面生产、U3=构建合成）**——本节其余内容仍为有效定案。
   → 交付 → 编辑器内族内换皮秒切 / 跨族切 DOM 集 / Tab2 生成级出口
```

**U1 新增两问**（策划输入，非门禁；交付前提醒式核对——缺什么列清单问用户，不拦截）：

- **完整度三档**：a 只做核心功能 MVP（页面少，但 UXUI 完善）/ b 核心功能+闭环（页面适中，边缘/逆向功能逻辑齐）/ c 完整打磨（页面多，前瞻性/创造性/交互合理性/同业页面不同状态机）；
- **动效三档**：a 纯静态 / b 按风格出基础动效 / c 按风格完全发挥。

## solo-ui-line-cy-gui-style-picker（原子技能，solo-tool-line-matt-grilling 定稿）

**六步画像**：读 V0.1 → 出适配报告 → 用户拍板配置 → 子代理并行比稿 → 用户选 → 回传确定值。

1. **选型单位=受众组**（给谁用决定哪套风格）：C 端用户端与内部管理端各自选型、组间可完全不同（用户端古怪气质 / 管理端 ant）；同受众产物（App+PC 官网）才复用一套。**组间并行**（多批子代理同时跑，比稿互相无数据依赖）。
2. **适配报告**：每组一行——候选风格清单（名字+一句为什么适合+是否建议多稿）+比稿规模建议。候选来源：wiki 探查检索优先（取值逻辑先跑通、后续固化），AI 自创=彻底没有了才兜底。
3. **用户拍板**比稿配置：选哪些风格、几稿、谁多稿——数量不写死，AI 按产品风格空间建议（有些产品可用风格很多），用户抉择。
4. **子代理比稿**：每个候选一个子代理（诠释差异=比稿价值的一部分）；同风格多稿启用与否=AI 分析 0.1 后建议告知（"该项目适合 XX，XX 可出多稿供挑选"）。产物=**带颜色带情绪的骨架图集**：3-5 个代表页（AI 挑最能拉开风格差异的页），一张比稿卡 HTML，多卡放一起比较。
5. **比稿卡规格**：内容=**示意级且故意不含项目信息**（防用户扣字眼+防 AI 后续真生成时偷懒复用占位、不思考文案组织）；风格载体=真实级（真色板/真字体渲染/真组件形态/真图标族）；图片=色块/渐变占位不找真图（批评面来自内容仿真，情绪传达来自风格载体——两者分离）；整卡带"方案示意"标定（长比稿卡的脸，不长效果图的脸）。
6. **选型交互**：三选一/多选；混搭请求（"结构要 B 颜色要 A"）=重生长为新候选（骨架与配色一体生长，禁手工拼装）；不满意可指定保留重出；微调=正常对话（"调暖一点"AI 直接处理）。失败宁停勿错：重出仍不收敛→停下报告，不猜默认风格硬推进。

**生长公式**（骨架这条链的因果，全 AI 现场干）：

```
start0.1 → 选适合风格 → 风格 × start0.1 = 适合的布局 → 骨架样张
```

布局=派生品（f(风格,需求)），没有独立存在权；**不做骨架图库/枚举/标注**；extract 九类=参考提示词素材（放附录降权、标注"禁止套用"，**先生长后对照**：长完才照镜查常识错误，参考是事后校对镜不是事前图纸）。

## 双管线架构（管理后台大类，2026-11-05 定）

- **主线不动摇**：单 HTML+编辑器（可编辑交付，file:// 直开）。
- **脚手架管线**：选型选到大厂 UI 脚手架风格（antd 等）时，**必须问用户**："静态原型（可编辑单 HTML）还是直接工程（可开发）？"——选工程则不走静态 HTML 一套，**直接下载整套 UI 技术栈在上面开发**+静态实例数据（不搞 vite mock）。实战实例：`D:\ai program\JAM3A\plus-ui-6.X-Vue`（工作量已验证可行）。
- **管线职责=只做初版工程**；后续修改=智能会话式一点点改需求=常规功能设计开发范式（非本技能职责）。
- **复用边界**：收口/策划/两问/选型全复用；编辑器/受控块/族体系不适用（框架自带 token 主题，如 antd ConfigProvider）。
- **交付物文件树要微调**（支持工程目录形态）——待办。
- 排期：P3 之后独立。
- **已废案**：copy 纯净 UI HTML 路线（大厂框架剥离不出纯 HTML/纯 HTML 模板又要改造成编辑器体系，两头夹死省事初衷）；"归纳提取归化"方案（copy 的价值在不用改，归化=白 copy）。

## 族的定义与判定（定案）

- **族=骨架一样，唯一判据**。骨架=DOM 结构四观测面（类型学语言，有滞回——参数微调不翻类型，皮=类型内连续移动，骨=类型间离散跳跃）：密度类型（每屏信息单元数）/大小类型（粒度角色：hero 型/卡片型/列表项型/微件型）/布局范式（轴线单列/网格/分栏/流式）/类型分布（图主导/文主导/控件主导）。参数性间距（gap 值）不算骨架。
- **皮层全族内自由**：色板/字体/组件表层/材质/间距尺寸档位（同范式档位变体合法）。材质（像素/手绘/拟物/毛玻璃）不是骨架、不参与判族，可叠加任何骨架。
- **令牌调不出骨相**：跨范式令牌切换=调参≠那个风格（伪极简=稀疏的 ant≠极简）→兼容提示两态：族内=真切完整/跨族=生成级。
- **判定权归 AI，现场判**：生成骨架时判归现有族 or 起新族+盘点可用皮→落 STYLE-REGISTRY，下游机制照读。不建机械判定体系（维度比对脚本/172 卡机械标注全废，AI 读卡描述与封面现判；wiki 流派/标签是气质语言，与骨架轴两套不通用）。
- **族内变体 2-3 个上限**（封面实证：同骨架换颜色/圆角/锐利度照样读得出风格，但摆一堆即雷同）；生成时 AI 顺手产 1-2 个同族令牌包。
  > 2026-11-07 修订：上限只管 AI 顺手送的变体（每族 1-2 个）；用户选中的同骨架风格全部进族，成员数不设上限。判族按四个方面逐个风格列给用户确认（见 references/editor-runtime.md「AI 判族」）。
- **族暴露给用户**：面板按族分组，可问缺啥族（答=族库现状+Tab2 出口）；藏的只是"一套 DOM 复用"的实现。
- **跨族多选=同一 HTML 内多套 DOM 显隐切换**（单文件自包含铁律不变）。
- 动效参数进令牌（motion tokens：duration/easing 阶梯）——风格切换连动效一起换。

## 风格槽面板（UI 定稿方向）

- **右侧抽屉（非模态）**：打开推画布让位、预览完整可见，关闭恢复批注栏；左缘拖宽（280–620px）并记住宽度；窄=风格卡一行一张，拖宽一行两张；Esc/关闭收起，再点入口=开关。
- **双页签**：Tab1「已生成的可选风格」（族分组）/ Tab2「AI 生成其他风格」（风格库候选卡带"需重新生成"角标，点卡展开提示词可复制；页脚=下载修改技能入口）。
- 卡片=截图缩略+风格名+介绍+「风格令牌」人话特征词行+**配色版胶囊平铺**（勾打在当前应用的那粒胶囊上，只有当前卡有勾）。材质/阴影=风格内置，**不做面板开关**（面板不出现材质 UI）。
- **换配色=全角色换色**：配色只写四槽（主/底/文/表），横幅、边框、次要文字、浅衬底、按钮文字深浅由配色推算（palette 可带显式 hero/line/muted 字段强制指定）；风格特征色（如瑞士硬黑边）不在推算线上则保留。
- 定位=style-chooser 现行版，不做两入口并存。

- 边际成本：+40-60%，几乎全在组件包多套变体；172 卡免机械标注=减负。
- 一次性：schema+校验器+seed 面板（+500-800 行最大头）+picker 技能+文档+测试 ≈ V06 量级。
- 减法杠杆：变体数不设下限；组件包懒派生；落选同族候选白送登记。
