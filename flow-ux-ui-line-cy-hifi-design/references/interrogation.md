# 盘问协议（interrogation）· V06

技能内通用问询能力。消费方：阶段1 收口盘问（主战场）、阶段5 完善文档的策划补问、用户对产出提异议时的澄清。不依赖外部技能。V06 下靶子=**开工文档 0.1 五节合格线**（项目定义/业务链路/页面地图/功能刻度/动效档，见 start-doc.md）与**1.0 完善节**。

## 靶子原则（第一原则）

每个问题必须对着**开工文档的合格线**生成：先读文档模板要什么（start-doc.md 0.1 五节），再问缺什么。禁止空问、禁止问内部工程参数（并行度/子代理数/工具选型——这些 AI 自评决定并写进收口确认单供知晓）。

问题从两处长出来：**资料的缺口**（消化后仍缺的输入项）和**下游的契约**（0.1 五节合格线）。

**缺口前置（强制物化）**：盘问开始前，先输出**缺口对照表**（0.1 五节逐节：够 / 半够 / 不够 + 缺口一句话）呈用户——缺口即问题的来源清单，之后每个问题都从表里长出来。禁止"感觉清晰"跳过对照表；禁止把缺口烂在肚子里等用户主动问。
**对照表只对五节**：页面地图（§3）只盘到主线（链路每步有没有页承载、这页办哪几件事说得清说不清）——凡冒出"每页里有什么、怎么呈现、有什么控件"这类靶子=越界，砍掉（页面呈现是阶段4 画师长出来的，明面设计问题归阶段4 精修）；布局、样张、令牌不在 0.1。

## 九协议

1. **目的上追（触发式）**：数量大/范围模糊时，先向上追三层再问——真正想要的结果 → 背后目标 → 现做法是否最好；结论可能改写需求本身（数量/形态/路径），避免"方向对执行错"。
2. **节奏分阶段**：材料研读阶段一次一问（贴着材料流式走，读一点问一点）；**缺口对照表呈报后进入正式盘问=轮次制**（见下节）——两种节奏不混用，切换点=对照表呈报。
3. **每问带推荐**：AI 基于材料与行业惯例给出建议答案，用户确认或改——"支付演示到下单成功页（推荐），还是要走到退款？"
4. **人话原则**：问题永远是业务语言。禁止向用户暴露中间产物术语（台账/契约/围栏/断言）。档位编号（a/b/c）只做回复键——选项正文第一次出现就必须是人话，禁止让用户回看定义才懂。
5. **能点选不打字（按宿主能力自适应）**：宿主支持交互组件（如 ZCode AskUserQuestion）时，≤4 题且选项可精简的裁决优先弹点选卡；超 4 题、复合裁决（长发现+多候选+推荐）、预期用户要自由发挥的场景 → 文本表格+编号回复（表格承载完整语境，卡装不下选项外的表达）。唯一例外是开放性内容（如业务描述）。
6. **靶子先行**：问之前自查——这题的答案会填进 0.1 哪一节？填不进的不问。功能刻度（§4）与动效档位（§5）属必备靶子，收敛前必须已拍板（对照表逐节核对时覆盖）。
7. **换轴自查（收敛前强制）**：收敛判定之前强制换视角把问题重问一遍——时间轴（需求有没有时效/先后依赖）/用户轴（每类角色都覆盖了吗）/反方向轴（反过来想要什么）/对表轴（与已确认内容对表有无冲突）——逐条过，查出遗漏回盘问；两轴结论一致才准收敛，冲突点记录并呈用户裁决。
8. **收敛判定**：0.1 五节全部达到合格线 + 无未裁决矛盾 = 共识达成，停止盘问。（轮次制的"无可答问题"只是过程走完，收敛仍以本条为准——不替换出口。）
9. **确认落盘（checkpoint 制）**：每轮盘问结论（含用户原话要点）即时写回 0.1 草稿与 ledger.md，带确认方式与时间——答案确认一批就落盘一批，禁止攒到收敛才写（防长盘问上下文压缩丢答案）。

## 轮次制（正式盘问阶段的节奏，源自 solo-tool-line-matt-grilling 的 frontier 机制）

缺口对照表呈报后，盘问切换为轮次批量节奏：

- **可答问题**：前置条件已解、现在就能问的问题（不猜没听到的答案）。依赖未解的问题归入后续轮次，禁止提前问、禁止猜依赖。
- **每轮格式**：把当前全部可答问题一次性编号列出，每题=人话问题+推荐答案（协议 3/5 照用）；一轮只围绕当前模块或紧密相关的决策组，禁止凑数问、禁止重复已确认项。
- **答完重算（硬动作）**：用户整轮作答后，先**吸收回复里的新信息**——用户补充的业务点/纠正 = 新的盘问靶子（如用户随口提到"超时会自动提醒"，就要问清触发条件与后续走向）；已确认决议落盘（协议 9），缺口清单收缩，**重算下一轮可答问题并呈报**（哪怕只剩一两条也要列出）。**禁止不重算直接转入写草案**——问一轮就收口 = 轮次制形同虚设。
- **终止**：可答问题清零（没有再被默默假设的问题）→ 走协议 7 换轴自查 → 协议 8 收敛判定。

## 触发时机

- **写之前**：业务逻辑清晰度判定为"模糊/矛盾/链路断裂"（见 onboarding.md §业务清晰度三查）
- **补问（阶段5）**：完善 1.0 时必要问题补问——只补业务与规则缺口，用户可委托"你定"则 AI 直接决策输出
- **异议时**：用户对产出提出分歧/质疑，需要澄清意图再动

**V06 禁问清单**：明面设计问题（归阶段4 精修修）、明显后期才加的功能（发散是阶段4/6 的事）、布局与页面规划（页面长出来不规划出来）、设计级问题（机械问题——错别字/样式值——直接修，不问）。

## 动手纪律（技能执行对话）

技能在为用户执行任务时，涉及**解读用户材料/拍板信息**的动作（读文档得出结论、上传的规范怎么用、风格怎么理解），先向用户**陈述完整理解并获得确认**，才允许落地到文件或后续动作——"我以为理解了"不等于用户确认了。例外：纯机械问题（错别字/样式值）直接修不问。

## 禁止

- 固定问题清单（问题从资料缺口与文档合格线动态生成）
- 把中间产物甩给用户"你看怎么改"
- 正式盘问阶段零散多问（该按轮批量）；研读阶段轮次轰炸（该一次一问）——两种节奏用错位置
- 无推荐答案的开放式提问（用户没义务替 AI 思考）
- 凑数问、重复问已确认项（可答问题不足一轮就少问，禁止编造问题填轮次）
- 盘每页的内容与实现细节、规划主线之外的页面（页面地图的主线照常盘——V06 禁问清单，违者=把旧流程的病带回来）
