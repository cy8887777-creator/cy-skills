# 引导决策树（onboarding）· V06

阶段1 收口盘问的对话剧本。执行者沿树行走；问答行为遵守 interrogation.md。

## 欢迎语（触发后的第一句输出，逐字使用勿改——含 emoji）

```
🧭 效果图流水线 · 就绪

这是一个把需求做成"高保真效果图图包"的技能：先聊清楚业务，选定风格，
画出精修代表页定调，再铺全量页面——好看像效果图，页页过精修与动效。
可选追加（转化工序，需另安排工期）：可编辑版本（能点能改能保存）、功能旁批。

两种开局：
· 有现成材料（功能清单/效果图/文档）：丢给我，我消化出方案给你确认
· 只有想法：我按行业惯例逐项问你，聊清楚再动工

流程一句话：盘问收口 → 选风格 → 画代表页（你定调）→ 完善文档 → 全量出图。
全程产物落盘工程目录，随时回来续做。

把需求材料发我就开始；功能做多细、动效做多满，收口前会让你选，选项里会标。
```

> **硬规矩**：
> 1. 欢迎语 = **触发后的第一句输出**（体检在其后跑，结果以"流水线状态"一行追加在欢迎语下方）——禁止先播报体检/激活再出欢迎语
> 2. **逐字使用**，含 🧭 emoji——禁止换符号、禁止改写措辞
> 3. **合并简问**：触发句已含答案的问题跳过该屏（用户首句已发材料 → 不再问"你要做什么"；已说"用识图" → 不再问识图）
> 4. **表述分工勿互改**：欢迎语面向用户讲能力与开局；SKILL.md 的 description 面向模型讲触发匹配

## 引导决策树

```
【第一问】做什么？手头有什么？
   │
   ├─ 有材料 → 读（probe.py 随手跑：档位/端型线索预填）
   │    │
   │    ├─◆ 既成文档类输入（PRD/需求文档/功能清单）【三方审查 · 强制卡点】
   │    │    AI 以三个独立立场各审一遍原文：业务方（链路通不通/合理吗）/
   │    │    用户方（用得顺吗/缺什么）/ 终端实现方（能落地吗/有何坑）
   │    │    → 审查发现呈用户逐条裁决（钱包独占 tabbar 教训：文档
   │    │      信息架构硬伤必须在这里抓，不能等画完才发现）
   │    │    ⛔ 跳过审查直接消化 = 违反流程
   │    │
   │    ├─ 缺口对照表【强制输出】（审查裁决清零后，产草案之前）
   │    │    对照 0.1 五节合格线逐节盘点：够 / 半够 / 不够 + 缺口一句话
   │    │    → 表呈用户；半够/不够的节 = 待定标记 = 盘问靶子清单
   │    │    §3 页面地图若为半够：梳理出的主线页清单**必须呈用户确认**（地图是
   │    │    用户确认的主线，AI 不得自行梳理定稿）
   │    │    ⛔ 表里有非"够"项却出了无待定标记的草案 = 违反流程
   │    │
   │    ├─ 业务清晰三查 + 草案（对照表摆出后）
   │    │    ├─ 全绿 → 直接产出 0.1 草案 → 呈确认
   │    │    ├─ 有缺口 → 先按 interrogation.md 轮次制问完（可答问题清零）→ 再出草案
   │    │    │    "草案+待定标记"只允许**依赖外部信息**的缺口（如"提现规则待查源码"）；
   │    │    │    凡能问而未问的缺口不算待定——没问完就出草案 = 流程违规
   │    │    └─ 矛盾/大段存疑 → 按 interrogation.md 盘问 → 澄清 → 回到分析
   │    │    盘问纪律：只纠理解偏差与遗漏，不追设计、不盘明显后期才加的功能
   │    │    （矫枉过正禁令——明面设计问题归阶段4 精修，发散功能归阶段4/6 长出来）
   │
   └─ 无材料/只有一句话 → 访谈支线：按功能域清单化提问
        （每问带行业默认建议；角色→链路→范围边界→数据方向）
        → 产出需求材料 → 回到分析
   │
   ├─◇ 呈确认（0.1 草案）
   │    ├─ 全确认 → 收口
   │    ├─ 修改 → 修订 → 再呈（循环至收敛）
   │    └─ 追加新需求/新材料 → 增量分析 → 更新草案 → 再呈
   ▼
【收敛自查 · 强制卡点】（不展示此表 = 没走收敛判定，禁止继续）
   向用户显式输出四条自查（逐条 ✓/✗，✗ 附缺什么）：
   ① 角色：谁用这个产品，说得清吗
   ② 主链路：从起点到核心转化每步说得清吗，每步有页承载吗（页面地图 §3）
   ③ 范围边界：哪些功能做、哪些明确不做，说得清吗
   ④ 数据来源：真实感等级 + 演示内容的行业依据有了吗
   ⛔ 任一 ✗ → 回盘问补齐
   ✓ 全过 → 才进入【做到什么程度 · 三问】
    ▼
【做到什么程度 · 三问】（收敛自查全过才问；答案写进 0.1 §4/§5）
   第一问 · 功能刻度（功能做到多完整）：
     a 只做核心功能 MVP
     b 核心功能+闭环（边缘/逆向功能逻辑齐）
     c 完整打磨（前瞻性/创造性/状态机齐）
   第二问 · 动效档位（动效做到什么程度）：
     a 纯静态（零动效）
     b 按风格出基础动效
     c 按风格完全发挥
   第三问 · 交互档（壳内演示深度）：
     a 静态形态（交互只画样子，零交互）
     b 导航级（默认：页面跳转可点 + hover/active 反馈）
     c 演示级（弹层/分段真开真关，壳标准 JS 承载，零后端）
   （三问拍板结果照录进 0.1 §4/§5；交互行为由壳标准 JS 统一接管，画师只写结构标注
     data-go/data-sheet/data-seg/data-tab/data-panel——档位口径唯一权威 = start-doc §5）
    ▼
【收口】（三问答完即收）
   ① 答案逐条写进 0.1 对应节（§4 功能刻度 / §5 动效与交互档），行文照 start-doc.md 全文规范
   ② 0.1 全文给用户过目 → 确认"就是这个业务" → 阶段 1 过，落盘 intake/开工文档.md
   ③ 原始业务材料按铁律 1 引路径归档（已在工程内的不用动），路径随收口确认单一并给用户过目
   ⛔ 用户不确认 → 回盘问继续，禁带病进阶段 2
