# 验收细则（qa-assertions）

> **V06 归属：随 U5 五档验收手续退役**——主流程（阶段1-6）守门收敛为代表页用户卡点+收尾硬检（solo-ui-line-cy-ui-walkthrough）+构建内建校验，不再消费本文件。附加A 转化线验收=前后对比无回归+用户验收；verify-interactions/audit 仍可作转化后产物的检查工具（工具在 scripts/ 不删）。

U5 的执行规格。原则：**完成由退出码裁定，禁止口头宣称**；真实浏览器操作、真实磁盘回读；"未验证"必须逐条明说，不得以静态检查、控件数量或接口模拟冒充。

## 〇、质检方式分支（开工文档第 5 节，用户锁定时拍板）

| 档 | 内容 | 视觉结论地位 |
|---|---|---|
| ① 无头浏览器后台自查 | verify 全量断言 + audit 数据项 + 裁判读数据报告 | — |
| ② 主要页视觉 + 其余数据 | ① + ⭐主要页截图走查（裁判加读主要页截图） | 视觉结论**仅供参考需人工复核，不进门禁** |
| ③ 全量截图视觉 | ① + 全页截图走查 | 同上 |
| ④ 只做代码审查 | build --check + audit 静态项；交付说明声明覆盖范围 | — |
| ⑤ 不检查直接交付 | 跳过 U5；交付说明声明"按用户要求未执行质检" | — |

各档通用：audit 自动项 + 编辑器可达性探针 + **保存链路人工验收四步**（不随档变化）。
**红线：视觉（多模态识图）结论不稳定不可信，永远只作"观感提示"交用户人工判断，绝不作为自动打回的门禁依据。**

## 一、交互断言（verify-interactions.mjs）

从开工文档第 6 节交互声明集**逐条机械生成**断言用例（声明读自 ```interaction-claims 围栏；旧文档无该围栏时按旧口径扫 ```json，普通 ```json 示例不执行——见 start-doc §6）：

- 每条声明 = 一个用例：`page + action + expect + assert`
- Playwright 按 data-screen 定位页面 → 执行 action → 断言 expect（DOM 变化/路由/提示出现）
- 台账落 `qa/interactions.json`：每条 passed/failed + 截图；装饰性元素（开工文档第 6 节已申报）不计入失败数，单独计数进报告
- **退出码 0/1/2**：0=零失败；1=有失败；2=用法错误/未捕获异常。**失败条数只进报告 `qa/interactions.json`，不进退出码**（旧"exit=未通过数/cap-250"约定已废除）

生成规则：声明里 action 模糊（"提交表单"无字段细节）→ 断言生成失败 → 回 U1 补声明，**禁止猜**。

## 二、总检（audit.mjs，自动跑在临时副本上，不碰交付原件）

| 查 | 通过条件 |
|---|---|
| 构建 | HTML 完整、含编辑器标记 |
| 控制台 | 零 error |
| 死链 | 每个跳转目标页存在（DOM 实查） |
| 断图 | 零 404/零空图 |
| 几何 | 移动 375 + 桌面 1280 双视口无整页横向溢出 |
| **编辑器可达性探针** | 副本解锁口令后编辑态可达（自动，跑在临时副本上） |
| **保存链路人工验收** | 用户按四步执行：改字→保存→关掉重开→确认还在（人工，结果记入交付说明，不进 audit exit） |

audit 退出码三态（与 verify 同一口径）：0=passed 过；1=质检失败 → 按台账根因聚类修复 → 重建（旧产物移 build/history/）→ 重跑（上限 3 轮，超限转人工决策清单，格式见 §五后注）；2=error/用法错（html 不存在、未知 --mode、基础设施问题）→ **先修调用与环境，不可当质检失败聚类**。
修复后重标 U5 passed 须用**新回执**；该站带历史失败时用 `state_check --mark U5 passed --resolve-note "<说明>"` 写入解除标记，否则 `--require` 因 unresolved failure history 关门（history 保留可见）。

## 三、视觉走查

每页截图落 `qa/shots/`，按维度出问题清单：风格一致性（同令牌？）/ 视觉层级 / 真实感达标（对照真实感等级）/ 换行尴尬 / 间距失衡。

**独立裁判**：子代理只喂【全部截图 + 开工文档】，无生产上下文；按裁判任务书（下）出"通过/退回"结论。退回 → 问题入台账走修复循环。

## 四、裁判任务书模板

```
你是视觉终审裁判。输入：某站点的全部页面截图 + 它的开工文档。
任务：假设你是收货的客户——
 1. 每页对照开工文档职责声明，判断"页面是否兑现了承诺"
 2. 全站判断风格是否统一（同一套令牌观感）
 3. 找出任何"看起来像半成品/假数据占位/默认样式"的痕迹
输出：逐页 通过|退回(理由+位置) + 全站结论。只依据截图与文档，不猜测实现。
```

## 反假装红线（违反 = 交付无效）

- 禁止以"功能点/页面数量"宣称完成
- 禁止接口模拟冒充真实交互通过
- 禁止同一浏览器新开标签替代"完全关闭重开"
- 禁止只在内存验证不回读磁盘
- 未实测的原生对话框/真机/特定浏览器，必须标记未验证
