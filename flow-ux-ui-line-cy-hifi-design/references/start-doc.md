# 开工文档（start-doc）· V06

阶段1/2 的收敛产物（**0.1**）与阶段5 的完善产物（**1.0**）的模板。落盘 `intake/开工文档.md`。
**1.0 定稿即冻结**：未裁决不许改；经用户裁决的修订可直接修订对应行，并在 ledger.md 记一行——冻结挡的是"未经裁决的修改"。

> V06 变化：机器契约围栏（prototype-contract）、交互声明集（interaction-claims）、质检五档全部随编辑器直出线退役——附加A 转化线的规格由转化技能自己登记，不进开工文档。守门=代表页用户卡点+收尾硬检+构建内建校验。

## 0.1 写作三条铁则（先于模板）

1. **每行带出处**：只有三种内容能进文档——用户原话说的 / 用户在盘问里选的 / 用户明确委托的（委托件标「AI 决定」）。**未裁决内容不进文档**：AI 的发散建议在盘问里当场呈用户裁决，裁完才落行；文档里没有"待确认"可让下游误消费。
2. **只写业务逻辑，禁写设计**：全文不写页面内容、功能点、布局、导航形态、样张、令牌。**反面案例（2026-11-10 事故实录）**：把页面写成"待办/全部、状态筛选、工单卡片跳转、空态"——这些是设计师的产出物；写进需求文档=写死+必错+污染下游。
3. **页面地图写白话行为叙述**（详见 §3）：页名+用户在页面里做什么（30~150 字自然语言，把页说透）；禁控件词、禁字段罗列、禁动机注水、禁三段式模板腔。

## 0.1 模板（五节，收口盘问产出、文档质检定稿）

### 1. 项目是什么
一段话说清：什么行业、什么主题、给谁用、核心转化是什么；功能范围按用户口径逐条列（做 X、不做 Y——业务级条目，不是页面内容）；**端型**（移动 / PC / 双端，默认单端）与**真实感等级**（A 像真营业数据 / B 示意）随本节拍板记录。
**受众组**："给谁用"按组列——每组一行=组名+谁+在那干什么（多端/多角色项目如：师傅端｜外勤师傅｜接单干活结钱；平台端｜运营人员｜建单派单审核）；单组项目写一组即可。**阶段3 按组独立选型比稿**（各组气质可以完全不同）。
**合格线**：用户看到会说"对，就是这个业务"；端型、真实感、受众组分组已拍板。

### 2. 业务链路
主链路逐步骤（起点→…→核心转化），每步写**业务环节**（接单确认、提交完工、退回重提、提现审核），不写页面（哪个环节由哪张页承载归 §3，每页有什么内容归设计师）。异常与分支在业务层的走向列出（被退回可重提、取消后留记录）。
**合格线**：一口气走得通，无断点；异常分支有走向。
**质检视角（阶段2 硬检查点）**：信息架构硬伤在这一节抓——某环节是否该独立存在、链路是否有去无回（钱包独占 tab 教训的 V06 版：硬伤=业务逻辑错，不是页面规划缺）。

### 3. 页面地图
一张两列表：**页面名称｜用户在页面里做什么**。第二列写**自然语言的白话叙述段**——把这个页面说透：谁来、进来办哪几件事（含事与事的业务先后和关联、办完通向哪），30~150 字（页面承载的业务多就写满，不许为省字压缩；写不满 30 字=这页没讲透）。

**四条禁令（违反即污染设计，画师没活干了）**：
1. 禁控件词、界面词（按钮/弹窗/标签页/筛选器/列表卡片/空态……）；
2. 禁字段罗列（"展示姓名、地址、时间、状态"=变相页面内容清单）；
3. 禁编造动机注水（"以便不被冤枉""免得跑空趟"——真实业务闭环自带理由，不用表演）；
4. 禁三段式模板腔（"作为X我想Y以便Z"八股填空中毒，行业已弃——取用户目标视角的魂，弃它的形）。

**消歧规则**：叙述里出现与界面组件同名的业务概念词（时间线、列表、卡片、状态……），**按业务含义判断**——写用户做什么（行为与事实）合法；写页面怎么呈现（形态/布局/控件组织）才违规。禁令禁的是"写成界面设计"，不是禁词。

> **方法论注脚**：本列写法=用户故事的目标视角（不规定实现、留设计对话空间），但拒绝其模板形态；页面怎么呈现、用什么组件、状态如何组织，全部归画师从业务+风格推演。

**合格示例基准（师傅端工单系统）**——只演示每页的写法与密度，**页数以实际盘问确认为准，不是标准页数**：

| 页面名称 | 用户在页面里做什么 |
|---|---|
| 登录 | 师傅进入系统的门面。点授权手机号，平台拿号码比对后台建好的师傅档案：对得上放行进入，不在档案或账号已停用会被拦住并告知原因；不小心取消授权或网络不好，可以重来 |
| 工单 | 师傅每天进来的第一页。哪些新单等着自己确认、哪些活办到一半、哪些被退回要重新交，一共压了几件事都在这看；干过的旧单也能翻出来。挑中一张点进去，就开始办事 |
| 工单详情 | 一张单从头办到尾都在这页。先看清要干什么活、完工要交什么凭证、截止什么时候、钱给多少、去哪找谁；看好了点确认接下，这单的内容就定死不再改。办的过程中有情况在这记一笔进展；活干完从这发起交工；被退回了，平台给的原因和上次交的内容都在这，对着整改再交一次；有事先在这打电话找平台 |
| 添加日志 | 办到一半写的备忘：写清楚现场什么情况、配几张照片每张图说一句话，发出去给平台留底。发出去不能改，写错了追加新的更正，双方都有据可查 |
| 提交完工 | 活干完的交账单。按这张单提前定好的要求交照片、给定位、填说明，缺项会被拦住不让交；交了之后进入平台审核。被退回能针对原因重新交一次，每一版交的记录都留着 |
| 消息 | 平台对师傅做的每一步动作都在这登门：派了新单、改了任务、退回、审核通过、报酬进账、打款进展，看得到哪些还没读；随手点开一条，直达它说的那张单或那笔提现，办完回来接着看 |
| 我的 | 师傅的个人中心：自己档案什么样、账上有没有钱一眼看到；往下钻资料、资金、渠道各功能都从这进，找平台客服也在这 |
| 师傅资料 | 平台眼里你的档案长什么样，在这照镜子：姓名、归哪几个行业、账号正不正常、还能不能接新活；发现不对，找平台改 |
| 余额 | 现在账上有多少能提的钱在这看数；审核通过的报酬进来、提走的钱出去，大账对不对在这核，有疑点转去明细查 |
| 收支明细 | 钱拆开一笔一笔记的账：每笔进钱是哪张单的报酬、每笔扣钱是哪次提现，按收入支出分类筛着看；跟平台对不上账，依据就是这 |
| 申请提现 | 想把钱取出来在这办：填多少、到账选哪个收款账户、提交；钱数不合规或账户有问题当场告知原因，改好可再交 |
| 提现记录 | 提过的每一笔各走到哪一步——还在审、已打款、还是被驳回——一张列表全看到，挑一笔进去细看 |
| 提现详情 | 一笔提现的完整经过：提了多少、打到哪个账户、现在卡在哪个环节；被驳回或打款失败，原因写在这，下一步是重新填还是找平台，一目了然 |
| 收款渠道 | 管自己收钱的账户：看看现有的、新增一个、改一个；保证每次提钱都有能到账的地方 |

**连接**：表后一行链路走向即可（工单→详情→提交完工；我的→余额→申请提现→提现详情…），不单独成表。多受众组项目页名前冠组名（用户端-首页｜平台端-工单管理），单组不冠。
**出处**：沿用全局规则①——地图整段来源（对话确认/增项文档）标注在节头，不必逐页挂。
**地图是主线种子**：画师阶段4 从地图出发长出**页面地图扩展**（分支/状态/配套页由他长，定调卡点你把关）；主线页无用户裁决不得删减。
**合格线**：§2 每个业务环节有页承载；每页说明 30~150 字且四禁令零违反。

### 4. 功能刻度（三必问之一，用户拍板）
`a 只做核心功能 MVP | b 核心功能+闭环（边缘/逆向功能逻辑齐）| c 完整打磨（前瞻性/创造性/状态机齐）`
档位为策划输入与阶段4/6 铺量对账依据，不做机器拦截。刻度 b/c 意味着画师要给异常/状态长页，不意味着这里预先列页。

### 5. 动效与交互档位（三必问之二、之三，用户拍板）
动效档：`a 纯静态 | b 按风格出基础动效 | c 按风格完全发挥`

交互档：`a 静态形态（交互只画样子，零交互）| b 导航级（默认：页面跳转可点+hover/active 反馈）| c 演示级（弹层/分段真开真关，壳标准 JS 承载，零后端）`

交互行为由壳标准 JS 统一接管（画师只写结构标注 data-go/data-sheet/data-seg/data-tab/data-panel，见 gui style-selfcheck 交互层）；交互档管效果图壳内演示深度，可编辑归阶段 7 转化线，正交。

签字行：`确认人：用户 · 方式：对话确认 · 时间：<时间>`

## 阶段2 · 质检任务书（派独立质检子代理）

写 0.1 的脑子查不出自己的理解偏差——质检派**独立子代理**，默认 **2 个、互相隔离**（禁交换意见），各自独立复述+查检；主对话合并结论：两家共报=必修，单家报=核实（真就修，误报说明 0.1 写得有歧义，也要修）；两个复述互相不一致=文档歧义实锤，同样要修。质检报告不落盘（用完即弃），ledger.md 记一行结果。

```
【角色】你是独立质检员，从未参与这份需求文档的编写。
你的任务：像接手项目的新 PM 一样，只凭文档本身把业务读明白，然后挑出这份文档的毛病。

【输入】（只读这三样，全程禁向主对话提问——你的价值就是"没被主对话的认知污染"）
1. 待检文档：<0.1 草稿路径>
2. 原始业务材料：<路径（可多条）>
3. 质检依据与禁令口径：<start-doc.md 路径>（五节合格线+页面地图四禁令+消歧规则）

【第一件事：盲态复述】
只凭待检文档，用你自己的话把业务完整复述一遍：
行业、给谁用、链路怎么走、有哪些页、每页用户干什么、功能做多细。
先复述，后对照——不许先看原始材料对答案。

【然后逐节查五样】（对照 start-doc 五节合格线 + 原始材料）
1. 漏：原始材料里用户明确说了的，文档里有没有漏掉
2. 偏：文档的表述与原始材料有没有出入（AI 誊写走样——重点查这里）
3. 断：业务链路有没有断点；页面地图与 §2 链路是否逐条对上（每步有页承载）
4. 违：页面地图四禁令（按消歧规则——业务概念词按业务含义判断，如"时间线/日志"
   属业务事实则合法；写成页面呈现方式才违规）
5. 蔑：笔误、病句、术语前后不一致

【回执】（只认证据，禁写"我检查了XX"式流水账）
1. 盲态复述全文
2. 问题清单：每条 =【漏/偏/断/违/蔑】分类 + 位置引用 + 原始材料依据 + 一句话修改建议
3. 没发现问题的节，也要明说"查过，无发现"——禁沉默糊弄
```

## 流程纪律

- **版本机制**：阶段1 出 0.1（用户确认"就是这个业务"）→ 阶段2 质检定稿 → 阶段3 选型（失败=宁停勿错，不猜默认风格硬推进）→ 阶段4 代表页定调 → 阶段5 多文档定稿（1.0+页面地图扩展模板+设计资产，用户确认后**冻结**）→ 阶段6 跑批（新页边画边补进页面地图扩展）。
- **修订与变化**：经用户裁决的修订直接改文档+ledger.md 记一行；不设附属文档（双重记账必漏）。
- **报错逃生**：执行者发现 0.1/1.0 与用户业务逻辑冲突（疑似写错）→ 停该项上报用户裁决；禁将错就错，禁未经裁决改冻结文档（裁决后的修订直接改对应行+ledger 记一行）。
- 文档修订（1.0 冻结前）= 增量更新 + ledger.md 记一行，不重写历史。
