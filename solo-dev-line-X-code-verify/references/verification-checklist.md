# AI编程验证检查清单

## 概览
本清单用于引导AI在每次代码修改后进行系统性反思，确保功能真实落地，避免"假完成"。

---

## 第一层：基础验证（必须全部通过）

### 1.1 页面可访问性
- [ ] 页面可以正常访问（HTTP状态码为200）
- [ ] 页面加载时间合理（< 5秒）
- [ ] 页面有完整的HTML结构（包含html、head、body标签）

### 1.2 控制台检查
- [ ] 浏览器控制台无致命错误（红色报错）
- [ ] 无资源加载失败（404错误）
- [ ] 无JavaScript语法错误

### 1.3 代码基础检查
- [ ] 修改的文件已保存
- [ ] import/require路径正确（文件存在且路径匹配）
- [ ] 组件/函数名称拼写正确

---

## 第二层：功能验证（根据具体需求）

### 2.1 引用关系检查
- [ ] 新创建的组件是否已在父组件中引入？
- [ ] 新创建的函数是否在正确的位置被调用？
- [ ] CSS/样式文件是否被正确导入？

### 2.2 事件绑定检查
- [ ] 事件处理函数是否已绑定到对应元素？
- [ ] 事件名称是否正确？（onClick vs onclick）
- [ ] 事件处理函数的参数是否正确传递？

### 2.3 数据流检查
- [ ] 父子组件间的props是否正确传递？
- [ ] state/hooks是否正确初始化？
- [ ] API返回的数据是否正确处理和渲染？

### 2.4 条件渲染检查
- [ ] 条件判断逻辑是否正确？
- [ ] 是否处理了所有可能的分支情况？
- [ ] 默认值/兜底逻辑是否存在？

---

## 第三层：逻辑验证（深度自查）

### 3.1 需求对照
- [ ] 代码修改是否完全覆盖了用户需求？
- [ ] 是否存在需求理解偏差？
- [ ] 是否遗漏了隐含需求？（如错误处理、边界情况）

### 3.2 逻辑完整性
- [ ] 数据流向是否清晰完整？（输入→处理→输出）
- [ ] 异步操作是否正确处理？（loading状态、错误捕获）
- [ ] 是否存在未处理的异常情况？

### 3.3 副作用检查
- [ ] 修改是否影响了其他功能？
- [ ] 样式修改是否影响了其他组件？
- [ ] 全局状态修改是否合理？

---

## 常见假完成模式警示

### 模式1：创建但未使用
**症状**：创建了组件/函数，但在代码中找不到引用位置

**自查问题**：
- 这个组件在哪里被使用？
- 是否忘记在父组件中import？
- 路由是否正确配置？

### 模式2：定义但未触发
**症状**：定义了事件处理函数，但点击/交互无反应

**自查问题**：
- 事件是否正确绑定到元素？
- 元素是否被正确渲染？
- 是否有CSS阻止了事件传播（pointer-events: none）？

### 模式3：修改但未生效
**症状**：代码改了，但页面效果没变化

**自查问题**：
- 是否修改了正确的文件？
- 样式选择器是否正确？
- 是否被其他样式覆盖？（检查浏览器开发者工具）
- 是否需要重启开发服务器？

### 模式4：逻辑错误
**症状**：功能执行了，但结果不符合预期

**自查问题**：
- 条件判断是否正确？（== vs ===）
- 数组遍历是否正确？（是否遗漏return）
- 异步操作是否正确等待？（async/await使用）

## 反思引导问题

在声称"已完成"之前，问自己：

1. **验证证据**：我有哪些客观证据证明功能已实现？
   - [ ] 验证脚本通过了
   - [ ] 浏览器控制台无报错
   - [ ] 实际测试了功能（或请求用户测试）

2. **代码追踪**：从用户操作到最终效果，代码执行路径是什么？
   - 用户点击 → 事件触发 → 函数执行 → 数据更新 → 界面渲染
   - 这条链路上的每个环节都确认了吗？

3. **边界情况**：如果出现异常情况会怎样？
   - 数据为空？
   - 网络请求失败？
   - 用户重复点击？

4. **影响范围**：这次修改可能影响哪些其他功能？
   - 是否需要回归测试其他功能？
   - 全局状态/样式是否被影响？

---

## 验证通过标准

只有满足以下**所有条件**，才能确认"验证通过"：

✅ **第一层验证**：基础验证项全部通过
✅ **第二层验证**：功能相关的检查项全部通过
✅ **第三层验证**：至少进行了一轮逻辑自查
✅ **客观证据**：有脚本输出或测试截图作为证据

---

## 快速自查流程

```
修改代码
    ↓
运行验证脚本（verify_page.py）
    ↓
打开浏览器控制台检查报错
    ↓
对照本清单逐项确认
    ↓
发现疑点？
    ├─ 是 → 定位问题 → 修复 → 重新验证
    └─ 否 → 确认完成
```

## 示例：按钮点击事件验证

**需求**：点击按钮后弹出提示框

**验证流程**：
1. [x] 第一层：运行verify_page.py → 页面可访问
2. [x] 第二层：
   - [x] onClick事件已绑定到button元素
   - [x] alert函数在事件处理函数中被调用
   - [x] 事件处理函数已定义且无语法错误
3. [x] 第三层：
   - [x] 点击按钮时，事件处理函数会被调用
   - [x] 提示框内容符合需求
4. [x] 客观证据：请求用户在浏览器中测试点击

**结论**：✅ 验证通过，功能已实现
