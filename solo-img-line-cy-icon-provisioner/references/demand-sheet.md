# 需求单与交付单模板（demand-sheet）

I1 冻结的唯一事实源 + I5 交付的输出契约。**输出必须是可直接消费的产物，不是链接和建议。**

## 图标需求单（I1 冻结稿）

```markdown
【图标需求单】
用途：<登录页 / 底部导航 / 仪表盘侧栏…>
语义清单：
  1. search  搜索
  2. user    个人中心
  ...（逐个列，数量 N）
风格族：<线性 / 圆角线性 / 面性 / 多色 / 双色调 / 动态质感(kubai 分层) / 双色面性(kubai duotone) / 软3D / 黏土 / 拟物 / 贴纸 / 粉彩 / 像素 / 游戏剪影 / iOS原生>
参考：<可选——某 App / 某风格卡 / 截图；无则删行>
规格：
  尺寸：<24px 网格 / 16px / …>
  颜色：<currentColor（跟随主题）/ 品牌色 #RRGGBB / 多色原生>
  描边：<1.5 / 1.8 / 2 / 实心剪影>
  目标环境：<纯 HTML / React / Vue（影响属性写法：stroke-width vs strokeWidth）>
交付形态：<内联 SVG / base64 data URI / SVG sprite / JSON 子集包 / 交互 SVG 组件（kubai 动效：内联引擎自包含片段或官方 react/vue 包，需 JS 宿主——网页/H5/React/Vue 可用，切图/原生 App/文档不可用）>
  **呈现协议（通用机制）**：该字段对上游呈现 = 供给菜单 + 推荐——列出可选形态，
  每项附一句"什么需求用哪个"（例：网页/H5 → 交互组件，hover 会动；切图/文档 → 内联 SVG），
  上游拍板。**自动化无用户交互流程**：按需求单目标环境自决策（宿主可跑 JS → 交互组件；
  否则静态），决策依据如实写进交付单，上游主对话有异议随时改单重交付
产物约束：<单文件 HTML 内嵌 / 独立文件 / …>
许可约束：<商用 / 内部演示；接受署名与否>
数量与优先级：<全套 N 个 / 先核心 M 个>
禁忌：<可选——负向排除项，如"不要 emoji 风/不要过密/不要描边超过 2px">
档位：<简单档 / 复杂档——判定标准见 onboarding.md §复杂度分级>
上游：<人类对话 / 代理调用（调用方 ID）>
冻结时间：<时间>（冻结后只读；变更见下方变更规则）
```

**档位判定标准**：语义常见（导航/操作/状态类）+ 常见风格族 + 数量 ≤10 = 简单档；任一超出（罕见语义/质感族/成套/数量 >10）= 复杂档。

**模式 B（代理调用）最小字段集**：语义清单 + 风格族 + 交付形态，三字段齐即可执行；规格为**可选第四字段**——未指定时**默认 24px / currentColor / 2px** 并在交付单注明"未指定规格已按默认适配"，禁因规格缺失打回索取。缺前三字段任一 → 返回缺字段清单索取（缺的必是调用方才能补的信息）。

## 冻结后变更规则

- **语义清单变更**（增/删/换个别图标位）：增量补单——已交付位不受影响，新位走漏斗补交付
- **风格族/规格变更**：全套重开——旧交付单标注失效，重走漏斗
- 任何变更 = 受影响面重开 → 再呈确认 → 重冻结（版本 +1），禁止边执行边改契约

## 图标交付单（I5 输出契约）

```markdown
【图标交付单】
产物：
  <直接可粘的代码块——内联 <svg> 源码 / sprite 块 / base64 data URI>
  （多图标时：先 sprite 定义块，后逐图标 <use> 引用片段）
来源：<库名（许可）× 数量；如 Lucide (ISC) ×4、tabler (MIT) ×2>
规格快照：<最终适配值——如 24px / 1.8 描边 / currentColor；默认适配需注明>
合规动作：<无需署名 / 需附署名文本——给出即用署名文本>
形态自检：<风格族 vs 图标形态逐项判定，PASS/FAIL+一句理由>
台账：
  search → lucide:search（ISC）（24px/2/currentColor）
  user   → tabler:user（MIT）（24px/2/currentColor）
  ...
验收：<需求单逐面回查 ✓；emoji 扫描 0 命中>
```

**验收闭环**：验收 FAIL（形态不符/emoji 命中/规格错）→ 回适配加工步骤修正重验；**二次 FAIL → 转未命中交付单**（该语义视为不可交付，走五处置）。禁止带 FAIL 交付。

## 未命中交付单（失败处置，最高优先纪律）

```markdown
【图标交付单 · 未命中】
需求：<复述>
已尝试：<本地JSON ✗ → Iconify(库名) ✗ → 3dicons ✗>
最近似候选：<prefix:name>（形态✓ 语义近似，差异：<哪里像哪里不像>）——供定夺
处置选项：
  a) 用最近似候选
  b) 转手绘定制——**前置条件：上游具备手绘渠道或确认追加工期**；确认后另开定制需求单
     （含工期/交付形态字段，本技能按需求单交付定制 SVG）
  c) 改语义（拆词/换隐喻重新路由）
  d) 生图提示词包（见 wf-genicon.md）
  e) 程序化生成——kubai 引擎按同款风格现画（环境探测与流程见 wf-icons.md §程序化生成；
     交付单许可行标「生成引擎 Kubai Icons License (source-available)，产物图标归需求方，无需署名」）
```

**三条铁律**：
1. 未命中必须显式声明——禁止静默降级塞违和图标充数
2. 最近似候选必须带差异说明——决定权归上游
3. 处置选项 d 的提示词包必须即拿即用（中英双版+质感词+底色约束+负面词+后处理指引）
