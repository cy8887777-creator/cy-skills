# 引导决策树（onboarding）

I0 需求澄清的对话剧本。执行者沿树行走；问答行为遵守 interrogation-icon.md。

## 欢迎语（触发后的第一句输出，逐字使用勿改——含 emoji）

```
🎯 图标交付服务 · 就绪

这是一个图标供给技能：你说要什么图标，我负责找齐、挑准、交付——
交付的就是能直接粘进页面的代码，拿来即用，不用二次加工。

两种开局：
· 直接报需求（如"登录页 5 个线性图标，蓝色"）：快速通道，分钟级交付
· 需求模糊或要成套：我问清楚再动工，问的都是影响交付的问题

本地 17 万枚图标离线检索（43 库：线性/圆角/iOS风/多色/动态质感/双色面性/软3D/黏土/拟物/贴纸/粉彩/像素/游戏剪影），
Iconify 276 库在线兜底。找不到不糊弄——给你最近似候选，或按同款风格现画/生图兜底，决定权在你。

报需求或丢材料就开始；风格拿不准的话，我会出对比图给你挑。
```

> **硬规矩**：
> 1. 欢迎语 = **触发后的第一句输出**——禁止先播报体检/环境检查再出欢迎语
> 2. **逐字使用**，含 🎯 emoji——禁止换符号、禁止改写措辞
> 3. **合并简问**：触发句已含答案的问题跳过该屏（用户首句已说"5 个线性图标"→ 不再问风格族）
> 4. **表述分工勿互改**：欢迎语面向用户讲能力与开局；SKILL.md 的 description 面向模型讲触发匹配

## 引导决策树

```
【第一问】什么产物要用图标？想要什么感觉？
   │
   ├─ 需求明确（语义+风格可复述）→ 复杂度分级
   │    ├─ 简单档（语义常见 + 常见风格族 + 数量 ≤10）
   │    │    → 快速路径直接执行（跳过全套盘问；三最小字段齐即可）
   │    └─ 复杂档（罕见语义 / 质感档 / 成套一致性 / 数量 >10）
   │         → 补齐需求单缺面 → 冻结 → 全流程
   │
   ├─ 需求模糊（"好看点的图标"/"跟这个页面搭的"）
   │    ├─ 有参考物（截图/风格卡/竞品链接）→ 读参考 → 提取风格族 → 复述确认
   │    └─ 无参考 → 出网格对比图：同语义 3-4 种风格候选一次给看 → 上游挑
   │         → 流程降级为"候选确认"：上游拍板后 → 回需求单呈确认
   │
   └─ 要成套（"整页图标"/"游戏场景一套"）
        → 先按 I1 冻结场景需求单（语义清单=逐位枚举）→ 再转 wf-iconset
   │
   ▼（三条分支汇聚）
【需求单草案呈确认】人话复述：要什么/什么风格/交付什么形态
   ├─ 确认 → 进收敛卡点（下方）
   ├─ 修改 → 修订 → 再呈（循环至收敛）
   └─ 追加新需求/新材料 → 增量澄清 → 更新草案 → 再呈
   ▼
【收敛自查 · 强制卡点】（冻结前显式自查，逐条 ✓/✗——自查表按档位对齐七面）
   · 复杂档七面：用途/语义清单/风格族/规格/交付形态/许可/数量
   · 简单档三面：语义清单/风格族/交付形态（规格默认 24px+currentColor+2px，许可默认可商用宽松库）
   ⛔ 任一 ✗ → 禁止冻结，回盘问补齐（风格族 ✗ 优先走网格对比图）
   ✓ 全过 → 【换轴自查 · 九协议7】（时间轴/用户轴/反方向轴/对表轴，逐条输出，
             发现遗漏回盘问）→ 两轴一致 → 需求单冻结 → I2
```

> **冻结唯一**：需求单只在一个点冻结——收敛自查+换轴自查全过之后。呈确认环节的"确认"只是进入卡点的门票，不是冻结。

## 复杂度分级（I0 同时完成，默认简单档）

| 档 | 判定标准（三条件同时满足=简单档，任一超出=复杂档） |
|---|---|
| **简单档**（默认） | 语义常见（导航/操作/状态类）+ 线性/面性/圆角等常见风格族 + 数量 ≤10 |
| **复杂档** | 罕见语义 / 3D·黏土·拟物·贴纸·粉彩·像素质感族 / 动态质感·双色面性(kubai 系) / 成套一致性要求 / 数量 >10 |

升级规则：简单档执行中未命中或上游不满意 → 升级复杂档 = **补齐三最小字段需求单并冻结（已确认面不重问），从漏斗重走（路由不重做）**——不推倒重来；复杂档交付后上游仍不满意 → 转未命中交付单走五处置。
