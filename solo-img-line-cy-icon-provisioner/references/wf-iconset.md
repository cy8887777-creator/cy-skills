# 成套场景图标工作流（wf-iconset）

场景：整页图标一致性 / 场景套装（如"游戏 HUD 一套"/"电商首页一套"）/ 底部导航组。

**入口前置**：进入本工作流前，需求单必须已冻结（语义清单 = 逐图标位枚举）——未冻结先回 I1。

## 核心原则：一致性优先于单枚最优

成套场景里，**同库同风格的一套 80 分图标 > 东拼西凑的单枚 95 分**。库锁定后中途不换库；备库补缺口的图标**按图标位分组使用并在交付单台账声明**（"位 7-9 出自备库"）——这是唯一的混库豁免，其余混装禁止。

## 流程

```
1. 场景语义清单化
   需求单的场景 → 逐位枚举图标位（导航5位/HUD4位/操作8位…），每位一句语义

2. 库锁定（一次决策，判据可执行）
   风格族 + 场景类型 → 查 sources.md 选主库 + 备库
   命中率算法：AI 用 iconify_fetch.py --search <语义关键词> --prefix <主库>
   逐图标位统计"主库键名命中位数 / 总图标位数"——≥70% 锁主库，<70% 换库重算
   统计结果写入交付单台账

3. 语义筛选（毫秒级，无逐个比对）
   AI 一次调用：场景 → 10-20 个英文关键词展开
   本地 JSON 键名检索 / Iconify search API → 候选名单
   AI 第二次调用：候选归并剔误 → 每个图标位 1-3 个候选

4. 批审（触发条件：某图标位候选 ≥2 且上游要求确认时出网格图；
   单候选 + 上游未要求确认 → AI 代码读形直接定，理由写台账）

5. 一致性校验（强制卡点，判据量化）
   同库 ✓（备库位已在台账声明豁免）
   描边粗细 ✓（线性族 stroke-width 差 ≤0.5；实心族统一 fill 模式）
   视觉密度 ✓（path 数同档：≤3 简洁 / 4-8 中等 / >9 高密度，套装内同档）
   圆角风格 ✓（圆角族 linecap/linejoin=round；直角族=butt/miter，不混用）
   校验结果逐项写入交付单台账
   ⛔ 任一 ✗ → 换库重筛或该位转手绘/生图，禁止混装交付

6. 未命中位处置（不阻塞其他位）
   某图标位在主库+备库均 0 候选 → 该位走未命中交付单五处置（含程序化生成，见 wf-icons §程序化生成），其余位照常交付

7. 交付
   sprite 统一打包 + 场景套装台账（沉淀格式见下）
```

## 场景套装沉淀（越攒越多的资产）

每个做过的套装按此格式沉淀到 `assets/scene-packs.json`（**文件不存在时按此 schema 首建**）：

```json
{"scene": "游戏HUD", "lib": "lucide", "license": "ISC",
 "icons": ["heart", "shield", "sword", "backpack", "settings", "pause"],
 "note": "主菜单/生命与能量/武器/背包/暂停设置"}
```

下次同场景需求直接复用（秒级），不同上游可微调图标名子集。

## 高频场景预生成建议

电商首页 / SaaS 后台侧栏 / 移动底部导航 / 登录注册页 / 游戏HUD / 社交动态页——这六个场景最常见，首次遇到时做完必沉淀。
