# 游戏素材微动 APNG

目标是让原画的大部分保持稳定，只让少数有动作依据的局部发生连贯变化。APNG 是输出格式，不能用“会动”代替动作品质。只交付素材；用户未要求时不要接入项目。

## 工作流程

1. **分析输入**：确认原图尺寸、透明度、主体、遮挡关系、必须静止的区域和可动局部。若输入是截图而目标要透明素材，先抠出主体并检查边缘、孔洞和被遮挡处；不要把背景色烙进透明区域。
2. **策划动作**：根据材质、支点、风向、姿态和场景语义，选择一个主要微动，必要时加一个相容的次要变化。写出起点、变化、回到起点的运动意图和静止区域。参考 [motion-scenarios.md](references/motion-scenarios.md)，不要按物体名称套固定动作。先定制作路径：动作若只是画面已有部件的整体位移（悬浮、下沉等刚性微动），跳过图生图，走确定性合成——抠出部件精灵、底图打洞、逐帧偏移贴回，身份与静止区可做到像素级不漂移；只有形变、表情或需补绘遮挡区的动作才进第 3 步。
3. **写图生图提示词**（仅模型路径）：以原图为身份和画风基准。一次取多张时描述允许出现的细微姿态范围；补生时描述缺失的具体姿态。两种情况都写清可动局部、固定部分及透明度要求。按 [production-workflow.md](references/production-workflow.md) 准备关键姿态。
4. **生成与质检**：优先使用已有 [solo-img-line-cy-bailian-image-gen](../solo-img-line-cy-bailian-image-gen/SKILL.md) 的图生图入口；一次请求可以用 `-n` 返回多张候选图。遵守其密钥检查及交互式调用限制，不写循环脚本反复调用模型。逐张检查候选图的主体身份、轮廓、纹理、透视、静止区和透明边缘；缺少某个动作阶段或某张不合格时，再针对性补生。
5. **排帧与合成**：依据动作过程手动确定顺序和每帧时长，不按文件名或像素相似度盲目自动排序。相邻帧间部件位移不应超过 1 像素，幅度大则加密时间格（总时长不变），停顿用加长时长表达、不用复制帧。首尾衔接要和相邻帧一样自然。用 [apng_pipeline.py](scripts/apng_pipeline.py) 生成接触表、检查报告和 APNG；完整回放，并解码核验每帧。

## 交付门槛

- 静止区不抖；可动局部无形状突变、重影、闪烁或跳帧；透明背景无色边和残留。
- 动作有因果依据，幅度与画面尺度匹配。轻微悬浮、眨眼、笑意、丝带飘动等都只是候选，不是默认动作。不能用整图呼吸或挤压变形作为失败兜底。
- 模型无法稳定生成合格姿态时，缩小编辑范围、减少动作复杂度，或如实说明目前无法交付；不要把失败帧强行拼装。
- 交付最终 `.apng` 的绝对路径，说明实际动了哪里。只有用户要求时再交付帧图、提示词或接入代码。

## 本地工具

依赖 Python 3 与 Pillow。清单和命令见 [production-workflow.md](references/production-workflow.md)。脚本不调用生图服务；它只处理已经生成并人工选定的帧。若不使用这个脚本，也必须完成同等的静止区、帧序、循环和解码检查。
