# 微动制作工作单

本文件给出执行细节。动作候选见 [motion-scenarios.md](motion-scenarios.md)；候选不是自动模板。

## 1. 输入与动作计划

先记录：输入路径和尺寸、最终是否要透明、主体边界、被遮挡后需要补绘的区域、需要静止的区域、允许变化的局部。再用一句话写动作因果，例如“丝带根部固定，末端随弱风轻摆”或“骰子已悬于棋盘上方，位置轻微升降，阴影随之变化”。若无法从画面推断动因，先保持静态，不强行让每个元素都动。

为每个动作列出少量有意义的姿态：原始、变化中、极值、返回中。帧数、时长和停顿由动作决定；眨眼可以有短促的闭合段，轻飘可以更缓慢。不要规定所有素材必须 8 帧、正弦循环或统一像素差比例。

截图要做透明素材时，先得到干净的主体及必要的补绘底层。移动主体会暴露原来被遮住的区域；没有可靠补绘时应缩小动作或放弃该区域。保留原始文件和每次通过质检的候选图。

判断部件能否独立位移，用 alpha 阈值连通域分析（如 >128）：独立悬浮部件（四周仅半透明阴影、不与主体实心区粘连）可直接抠件位移；与主体粘连的部件一动就暴露主体，需补绘或放弃。刚性位移类动作（悬浮、下沉、平移已有部件）不走图生图，直接确定性合成：把部件 alpha>0 的全部像素（含抗锯齿边）抠为精灵图，底图把同一足迹清零，逐帧把精灵按偏移贴回底图。位移方向注意曝光带，见 motion-scenarios.md。

## 2. 图生图生成

本节仅适用于需要模型的动作：形变、表情、织物摆动、补绘被遮挡区域。刚性位移不要交给模型——用图生图制造几个像素的位移，只会引入身份漂移、静止区抖动和透明边缘色边风险，确定性合成路径（§1）在像素级严格占优。

使用 `../solo-img-line-cy-bailian-image-gen/SKILL.md` 的图编辑方式与密钥检查。已有脚本 `C:/Users/admin/.claude/skills/solo-img-line-cy-bailian-image-gen/gen_image.py` 接受 `--image <原图>`、`--size <宽>*<高>`、`-n <张数>` 和 `-o <输出目录>`。例如 `python C:/Users/admin/.claude/skills/solo-img-line-cy-bailian-image-gen/gen_image.py "<这张图的微动候选提示词>" --image "<原图路径>" -n 4 -o "<候选输出目录>"`。可以在一次交互式调用中获取多张候选，不要写循环脚本反复调用模型。`-n` 返回的是同一提示词下的多张结果，并不保证分别对应预定姿态或天然有时间顺序；先筛选实际得到的姿态，再针对缺口补生。模型未必能输出原尺寸或透明背景，必须以实际文件检查结果为准。

提示词围绕一张具体输入图写，不机械套用文字。一次取多张时，说明共同的可动范围和允许出现的细微状态差异；若必须得到某个特定姿态，再用针对该姿态的提示词补生。可按以下结构组织：

```text
以参考图为构图、角色身份、材质、颜色和光源基准。
目标姿态或候选范围：[当前动作阶段，或允许出现的几种细微变化]。
只编辑：[具体区域和支点/方向/形态]。
保持：[脸型、服饰主体、图案、透视、静态底图等与本图相关的项目]。
输出：[目标尺寸、透明背景或原背景要求]。
避免：[本次最可能出现的错误，例如边缘重影、额外手指、骰子点数变化]。
```

例如人物飘带的中间姿态要说“根部仍固定在肩部，末端沿已有风向稍向右展开，布料褶皱随末端连续变化”；不要仅说“让丝带动起来”。骰子轻微悬浮要保住可见面和点数，不默认加自旋。笑意只改变嘴角附近，不重绘整个脸。

参考始终包含原图；可在模型允许的参考图数量内补充已通过质检的相邻姿态，但不能只依赖上一张而逐帧累积漂移。若模型改动了静态区域，优先缩小输入裁切或编辑掩膜，重新生成该局部，再贴回固定底图。提示词本身不能保证静态像素完全相同。

## 3. 逐帧质检与退回

先查硬错误：尺寸、可解码性、透明通道和主体是否完整。再对照原图与前后姿态看轮廓、身份、图案、透视、光影、背景和边缘。接触表只能辅助比较；需放大观察动区边界并播放连续帧。发现错误时记录“哪张、哪个局部、什么错误”，只重做有问题的姿态。多次失败则降低动作复杂度或改变分层方式，不把整图缩放当兜底。

静态底图和可动局部能分离时，制作与画布同尺寸的灰度 `editable_mask`：白色允许采用生成帧，黑色保持原底图，灰色仅用于边缘过渡。合成后仍需检查边界、遮挡和 alpha。像素差数据可用于定位异常，但不同画幅和动作没有通用合格百分比。

确定性合成路径有一条可执行的硬门槛——**静息恒等**：把精灵贴回原位（偏移为 0）的合成帧，必须与源图在所有可见像素（任一像素 alpha>0）上逐像素相等。打洞必须覆盖精灵全部 alpha>0 像素，漏打会在部件运动时露出月牙形鬼影；本门槛能抓到"底图被后续操作重建、漏挖部件"这类隐蔽错误。注意 Pillow 的 `alpha_composite` 整数 floor 取整会让半透明抗锯齿像素 ±1 漂移、破坏恒等；需手写 straight-alpha over 混合（浮点计算 + 四舍五入），dst 全透明时结果与源像素精确相等。全透明像素的 RGB 差异无视觉意义，不计入比对。

## 4. 排序与 APNG

按动作阶段明确列出帧顺序和时长。比较每对相邻姿态，也比较末帧到首帧；顺序不能仅用“差值最小”求出，因为眨眼、回摆和停顿可能在相似画面间有不同时间含义。跳变时重新排序、补中间姿态或改变时长，不能靠复制帧掩盖几何错误。

时间采样判据（确定性合成与图生图两条路径通用）：相邻帧间部件在画面上的位移不应超过 1 像素。不达标时——确定性路径加密时间格（缩短单帧时长、总时长不变），而不是砍幅度硬凑；图生图路径以该判据反推所需中间姿态数量，作为提示词补生与候选筛选的验收标准，缺姿态就针对缺失阶段补生。停顿合法，但只放在速度自然趋近于零的两端，并用加长 duration_ms 表达。

清单中不得放相邻重复帧文件：Pillow ≥11 写 APNG 会自动合并相邻相同帧，导致解码帧数小于清单帧数，`build` 的核验会直接失败。观感上的停留应当以合并后的帧配更长 duration 写进清单。

在工作目录新建 JSON 清单，路径相对清单文件解析：

```json
{
  "base": "source.png",
  "editable_mask": "editable-mask.png",
  "frames": [
    {"file": "pose-00.png", "duration_ms": 120},
    {"file": "pose-01.png", "duration_ms": 120},
    {"file": "pose-02.png", "duration_ms": 180},
    {"file": "pose-03.png", "duration_ms": 120}
  ]
}
```

`base` 和 `editable_mask` 可同时省略，此时每张姿态图必须是完整画布。提供掩膜时必须提供 `base`；脚本将生成帧按掩膜合成到底图上，使黑色区域保持原样。清单中的顺序就是输出顺序，脚本不会自动重排。已在源图中出现的可动物体若要位移，底图必须先补好它原来的位置，否则会留下重影。

```text
python scripts/apng_pipeline.py inspect path/to/manifest.json --report path/to/report.json --sheet path/to/contact-sheet.png
python scripts/apng_pipeline.py build path/to/manifest.json --output path/to/final.apng
```

先检查报告与接触表，再执行 `build`。最终在支持 APNG 的播放器中循环回放，并用解码器核对帧数、尺寸、时长及首尾；脚本会在保存后再次解码核验。模型生成文件、清单和检查产物保留在工作目录；默认只交付最终 APNG。
