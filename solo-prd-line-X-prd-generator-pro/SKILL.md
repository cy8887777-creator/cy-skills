# PRD生成器 2.0

基于 Harness 工程思想：Agent = Loop(Model + Harness)，Context 和 Tools 都属于 Harness 的一部分。

## 核心原则

1. **约束**：有明确的输入输出边界和终止条件
2. **反馈**：检查结果格式化，机器可解析
3. **稳定**：通过工具脚本保证检查可验证、可复用

---

## 输入

用户提供方案书文档（来自 solo-sale-line-cy-sale-case-gen skill 的产物）。

---

## PRD文档结构

```
PRD文档
├── 修改日志（无编号章节）
├── 1. 产品概述
├── 2. 角色与权限
├── 3. 功能页面清单（索引：页面-功能-角色对应关系）
├── 4. 页面细化 ← 核心章节
│   ├── 4.1 Web端页面
│   └── 4.2 移动端页面
├── 5. 交互流程（用户用例）
├── 6. 接口设计
├── 7. 数据字典
├── 8. 验收标准
├── 9. 非功能需求
└── 10. 开放平台与三方对接
```

### 修改日志格式

每次编辑 PRD 时，在文档最前方追加修改记录：

```markdown
# 修改日志

| 时间 | 修改人 | 修改内容 |
|-----|-------|---------|
| 2026-04-21 10:30 | AI | 新增「用户管理」页面 |
| 2026-04-21 11:00 | AI | 修改登录接口参数 |
```

## 终止条件

当以下所有条件同时满足时，PRD 生成结束：

| 条件 | 标准 |
|-----|------|
| 结构完整 | 10 章节全部存在，无缺失 |
| 覆盖率 | 方案书功能点覆盖率 ≥ 95% |
| 检查通过 | 当前轮次检查发现的问题已全部修复 |
| 连续通过 | 连续 2 轮检查无新问题 |
| 达到轮次 | 第 7 轮强制结束 |

## 生成流程

### 步骤0：初始化修改日志

生成新 PRD 时，在文档最前方插入空的修改日志章节：

```markdown
# 修改日志

| 时间 | 修改人 | 修改内容 |
|-----|-------|---------|
| （初稿生成） | - | - |
```

### 步骤1：解析方案书

从方案书中提取内容，建立 PRD 基础结构。

### 步骤2：扩展交互流程

每个角色至少覆盖：登录、主操作、数据管理 3 类用例。

### 步骤3：校验完整性

交叉对比方案书，确保覆盖率。

### 步骤4：生成页面细化

详见 `references/page-template.md`。

### 步骤5：生成接口设计与数据字典

### 步骤6：生成验收标准

### 步骤7：生成非功能需求

### 步骤8：生成开放平台与三方对接

## 编辑已有 PRD

当用户要求修改已存在的 PRD 时：

1. **读取现有修改日志**：找到文档最前方的 `# 修改日志` 章节
2. **追加本次修改记录**：在表格最上方插入新行
   ```markdown
   | 时间 | 修改人 | 修改内容 |
   |-----|-------|---------|
   | 2026-04-21 14:00 | AI | 修改登录接口参数 |
   ```
3. **执行修改内容**
4. **验证**：运行 `scripts/validate.sh` 和 `scripts/check-format.sh`

## 自检流程

### 执行原则

```
检查 → 发现问题 → 修复 → 验证通过 → 终止条件满足则结束
                ↓
            验证失败 → 继续修复
```

### 各轮检查内容

| 轮次 | 检查内容 | 执行方式 |
|-----|---------|---------|
| 第1轮 | 章节完整性、角色完整性、页面完整性、功能完整性 | AI 检查 |
| 第2轮 | 页面跳转一致性、数据流转一致性、权限一致性、状态流转一致性 | AI 检查 |
| 第3轮 | 鉴权说明、错误码定义、字段校验规则、时序图 | AI 检查 |
| 第4轮 | 敏感数据加密、接口权限校验、越权防护、操作日志 | AI 检查 |
| 第5轮 | 章节交叉验证、用例与流程匹配、接口与数据匹配、术语统一 | AI 检查 |
| 格式检查 | Markdown 格式、表格对齐、代码块闭合 | **脚本检查** |

### 终止判断

每轮结束后判断：
1. 覆盖率 ≥ 95%？
2. 当前轮次问题已全部修复？
3. 连续 2 轮无新问题？
4. 已达到第 7 轮？

任一条件满足则结束。

## 工具脚本

### check-format.sh

```bash
scripts/check-format.sh <prd_file>
```

检查 Markdown 格式问题，返回 JSON 格式结果：

```json
{
  "passed": true,
  "format_issues": []
}
```

或：

```json
{
  "passed": false,
  "format_issues": [
    {"type": "unclosed_code_block", "line": 42},
    {"type": "table_not_aligned", "line": 15}
  ]
}
```

### validate.sh

```bash
scripts/validate.sh <prd_file>
```

验证 PRD 基础结构完整性：

```json
{
  "passed": true,
  "chapters": ["1. 产品概述", "2. 角色与权限", ...],
  "missing_chapters": []
}
```

## 熵管理规则

1. **规则优先级**：硬性规则（缺失章节）> 一致性规则 > 格式规则
2. **过期处理**：检查规则每季度更新一次
3. **文档分离**：完整模板和简化模板分开维护
