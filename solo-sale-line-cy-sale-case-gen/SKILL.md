# 项目方案生成器

## 任务目标
- 本 Skill 用于：快速生成符合售前要求的标准IT项目方案书
- 能力包含：需求分析澄清、十大章节内容生成、流程描述、技术方案设计
- 触发条件：用户描述项目情况，需要输出结构化方案书文档

## 前置准备
无需依赖安装

## 操作步骤

### 步骤1：需求收集与澄清
当用户提供项目描述后，首先检查是否包含以下关键信息：

**必需信息清单**：
- 项目类型（如：电商系统、CRM、OA、移动应用等）
- 核心业务场景
- 目标用户群体
- 关键业务痛点

**如果信息不足，主动提问**（按优先级）：
1. 项目的具体业务场景是什么？
2. 主要服务哪些用户角色？
3. 解决的核心问题是什么？
4. 是否涉及第三方系统对接？
5. 有哪些特殊的技术要求或约束？

**提问原则**：
- 一次提问不超过3个问题
- 基于已知信息推断，避免问显而易见的内容
- 收集到足够信息后立即进入生成，避免过度澄清

### 步骤2：按章节生成方案书

按照以下10个章节顺序生成内容：

#### 1. 项目背景
- 描述行业现状和痛点
- 阐述项目建设的必要性
- 说明项目预期达成的目标
- 长度：150-300字

#### 2. 系统角色
- 列出所有涉及的系统角色
- 每个角色包含：角色名称、职责描述、权限范围
- 至少包含：终端用户、管理员、运营人员等角色

#### 3. 客户诉求（用户故事）
- 以用户故事格式描述核心需求
- 格式：作为<用户角色>，我希望<功能/能力>，以便于<价值/目标>
- 至少列出5-8个关键用户故事
- 覆盖主要业务场景

#### 4. 终端设计
- 说明系统涉及的终端类型（如：Web端、移动端、小程序等）
- 描述各终端的适用场景
- 说明终端间的关系（如：移动端为主，Web端为管理后台）
- **不包含页面结构，只说明终端类型和适用场景**

#### 5. 信息结构设计
- 按终端分别列出页面结构
- 每个终端包含：页面结构（一级、二级、三级页面）、导航结构
- 页面结构说明各层级页面的完整列表
- 导航结构说明顶部导航、侧边导航、底部导航、面包屑等导航方式
- **页面内的布局不需要在文档中体现**

#### 6. 终端功能清单
- 使用表格形式呈现，确保颗粒度足够细且功能全面
- 表格列：终端、模块、功能点、功能说明
- 功能点名称使用动词+名词结构（如"对话处理"、"快捷回复"）
- 功能点应该是一个相对独立的功能单元，不要拆分过于细致
- 功能说明长度：30-100字，简洁明了地说明功能的主要内容和价值
- 必须全面覆盖所有业务功能，包括主流程、分支流程、异常处理、配置管理等

**表格格式**：
| 终端 | 模块 | 功能点 | 功能说明 |
|------|------|--------|---------|
| Web端 | 对话管理 | 对话处理 | 处理客户的对话请求，包括接收消息、发送回复、转接人工等全流程对话功能，支持多种消息格式 |
| Web端 | 对话管理 | 快捷回复 | 设置和使用快捷回复语，支持分类管理、搜索查找，提高客服响应效率和服务质量 |

#### 7. 核心业务流程
- 识别3-5个核心业务流程
- 使用文字描述流程逻辑，包括开始、判断、操作、结束等步骤
- 每个流程包含：流程名称、流程目的、详细步骤说明、异常处理
- 使用编号列表或箭头符号清晰描述流程走向
- 对判断节点说明条件分支
- 对异常情况说明处理方式

**流程描述格式**：
```
流程1：智能应答流程

流程目的：自动识别客户咨询意图并返回相应答案

详细步骤：
1. 客户发起咨询，系统接收消息
2. 系统对消息进行预处理，去除无关信息
3. 使用NLP模型识别用户意图
4. 在知识库中匹配答案：
   a. 如果匹配成功，返回自动应答
   b. 如果匹配失败，执行步骤5
5. 判断是否达到转接阈值：
   a. 如果达到阈值，转接人工客服
   b. 如果未达到阈值，返回引导性问题，引导客户补充信息
6. 客户确认答案，流程结束

异常处理：
- 如果NLP识别失败，返回默认欢迎语
- 如果知识库服务异常，转接人工客服
- 如果客户长时间无响应，发送提醒消息
```

**注意事项**：
- 流程描述必须清晰易懂，避免歧义
- 使用编号或字母标记分支路径
- 明确说明每个步骤的输入和输出
- 对关键判断点详细说明条件

#### 8. 三方开发内容（如果有）
- 识别需要对接的第三方系统
- 说明对接方式（API、SDK、数据同步等）
- 描述对接的核心内容和数据流向
- 如果无三方对接，明确标注"本阶段不涉及第三方系统开发"

#### 9. 技术难点与解决方案
- 识别3-5个关键技术难点
- 每个难点包含：问题描述、技术挑战、解决方案
- 方案应具体可行，包含技术选型和实施思路
- 考虑性能、安全、可扩展性等维度

#### 10. 总结
- 总结项目的核心价值
- 概括主要技术方案
- 说明项目预期效果
- 长度：100-200字

### 步骤3：校验与优化
生成完整方案后，进行自我检查：
- ✓ 所有10个章节是否完整
- ✓ 内容是否逻辑连贯
- ✓ 流程描述是否清晰准确
- ✓ 技术方案是否可行
- ✓ 是否符合售前文档要求

如发现不足，主动优化内容

## 注意事项
- 始终以"快速输出"为优先，避免过度设计
- 方案内容应具体可落地，避免空泛描述
- 主动识别信息缺口，但避免频繁打断用户
- 技术方案应体现专业性和可行性
- 信息结构设计是指页面结构和导航结构
- 功能点颗粒度要适中，功能描述控制在30-100字

## 使用示例

### 示例1：电商系统方案
**用户输入**：
```
我需要做一个B2C电商平台，主要服务于中小商家，帮助他们在网上开店卖货。
核心功能包括：商品管理、订单管理、支付、物流跟踪。
```

**处理流程**：
1. 信息评估：有基本场景，但缺少用户角色、技术要求等信息
2. 适度提问：询问商家类型、是否涉及第三方物流对接等
3. 生成完整方案书

### 示例2：企业管理系统方案
**用户输入**：
```
为一家制造业企业开发生产管理系统，需要对接ERP和MES系统，包含生产计划、质量管理、设备管理等功能。
```

**处理流程**：
1. 信息评估：信息较完整，已知类型、角色、三方对接
2. 直接生成，无需额外提问
3. 重点关注三方对接内容和技术难点章节
