## ① 用户红线与拍板口径

- **严禁自编文案/内容**——「你为什么有给主活动和战队赛加了副标题 你别他妈的加内容啊」；固化口径：美化只许动样式（颜色/渐变/描边/投影/尺寸/字重/位置），原型里没有的文案一个字不许加（来源:96848）
- **格子/容器类图标一律顶满不留呼吸感**——「顶部的游戏logo你居然没定顶满 你是sb么？」32×32 居中留 8px 呼吸感被打回，改 48×48 顶满贴边框（来源:96848）
- **禁止"编瞎话"宣称修了但没生效**——跑马灯动画挂错层无效仍称已补，用户：「你越没加啊，编瞎话」；没实测验证效果的改动不许宣称完成（来源:96848）
- **不得擅改基底基调**——「你做什么深色底啊 英文的不是浅色背景么」；基底替换法原则=布局和基底基调不动只换皮肤，浅色基底配客户 Light 系规范（来源:54827/small4）
- **缺素材只报中文缺口清单，提示词不由 AI 出**——「你就说 你缺什么素材，有这个列表就行，中文的」「瞎编的提示词…不用你出了」；生成交用户，落 `生成素材/` 后直引替换（来源:54827/small4/96848）
- **3D 图标唯一来源=美术素材库（客户素材快照+用户生成），外站一律不用**——icons8/3dicons/thridy 全部禁用；thridy 实测全站 CDN 图带平铺半透明水印（PIL 测不出、analyze_image 可见）整体作废，AI 外找的风格与客户不搭配（来源:54827/small4/311b）
- **tag/称号族素材禁挪功能位**——2472 闪电/2475 火箭/2477 火是称号标签组件配套素材（2454/2457/2460 是底条），挪作功能入口图标连环被否；manifest 里标"禁挪功能位"警示（来源:311b/96848）
- **布局可微调但幅度保守、注释标注原值**——「间距、背景、卡片大小尺寸 你都可以微调啊」按 8pt 节奏执行，改动处注释标"调整自原型 xx 值"留痕（来源:54827/small4/311b）
- **实验产物用户定性前不 git 提交**——「这都是实验产品 没定性之前不要 git 提交」，此后不再反复请示 commit；但正式工作相反：完成一块自测通过立即请示 commit（未 commit 改动会被并行会话 reset 说没就没）（来源:311b/54827/7cec-p2）
- **拍板口径必须当场落决策记录/memory，不依赖会话记录存活**——v2 会话没吃透 v1 拍板就开工（底栏五 tab 口径只存旧会话记录），"第三个会话再丢"；补「APP 高保真原型」章节（来源:54827/small4）
- **素材库结构以用户为准，用户重组助手跟改**——「我已经把文件夹名称和结构改了 原先的目录导航已经不对了 你改一下」；重组后页面引用路径与 manifest 必须同步重写（来源:54827/small4）
- **原型漏画≠照搬空缺（反半成品）**——底栏位 4 墨刀原稿无图标，AI 严格还原为空被怒斥「第四个是消息…就做半成品？」；缺口应主动发现补全（同血缘素材或请示拍板），忠实空缺≠忠实原型（来源:311b）
- **真值源三分工铁律**——内容（入口集/结构/文案）查墨刀 → 样式查 Figma 规范 → 缺口素材走单一 3D 库/生成流程（来源:311b）
- **规范替换不能无脑覆盖墨刀内容真值**——Battle 主按钮墨刀橙渐变被"按规范"抹成粉紫，与 Quick 撞色主次不分；两源冲突项单列 A/B 请示拍板，不自作主张（来源:311b/54827）
- **图标尺寸档位化**——混档（21/28/36 或 34/36/42/45）被点名「尺寸怎么和别的不一样」；定档：按钮图标 32 高档/tab 24/星 12（来源:311b/96848）
- **按钮图标按墨刀素材原大显示**——缩放显示比例失调；按钮宽度回墨刀真值（Quick 164/Create 123），放不下时放宽按钮而非缩图标（来源:311b/96848）
- **规范陈列态外框≠真机效果，用户视觉验收>规范字面值**——底栏按 Figma 组件 359×80 做被用户两轮说"大"，拍板改回墨刀内容条 343×56 r22，「样式基因保留 Figma」（来源:311b）
- **头像框=装饰环，垫底、比头像大、完整显示不裁切**——「这麦穗环形的是头像框，你要放到原型头像的底下，而且还要比头像大」；环 52×52 z 更低垫底+真头像 30×30 圆形居中从环心露出；alpha 实心盘则反向：头像压上层、框盘露 3px 边当装饰（来源:96848/311b）
- **显示不全零容忍（最后遗言级）**——「怎么做的页面老是有这种元素显示不全的问题？？全部自检不要有这个问题」（来源:96848）
- **微件口径按成组恢复别只修被点名的一个**——「左右悬浮按钮的徽标 都改为小红点吧 不用再要数字了」六处 10×10 粉点整组下线大数字角标；角标/红点类微件按 v1 口径成组处理（来源:96848/54827）
- **方案未确认绝不动手**〔通用〕——「你给我的方案我同意了么？？？」AskUserQuestion 局部选项被选≠整体方案批准；用户回复带反问=还在讨论，答完停下等确认（来源:e08-p2）
- **列计划≠动手授权**〔通用〕——用户说"列一个计划（不要做文件）"，AI 列完就 Write 被两次打断；计划被认可前任何 Write/Edit 都算越权，用户给的执行顺序要严格排程（来源:e08-p4）
- **验证≠删除授权**〔通用〕——「删东西的时候你让我确认啊 我都没有明确让你删」验证结论只汇报不行动，"没区别"≠"可以删"；删未跟踪文件=永久丢失（无 git 历史可恢复），删前必须向用户点明（来源:e08-p2/e08-p3）
- **让分析绝不动手、问可行性≠授权修改、排查阶段禁改文件**〔通用〕——「我让你找问题 找遗漏，不是让你硬删除的啊」「我没让你动 我只问你能不能改」「先找，不要动文件」；"看看有什么问题"=输出问题清单+方案，直接改代码是最大违约（来源:7cec-p2/e08-p2）
- **复制优先，禁止重写**〔通用〕——「你直接把老的删掉，把对的复制进去不就完了，你还再写一遍干嘛？？」（v2 方法论第 1 条的直接来源：有现成正确基底时只做复制+定点替换，不重写）（来源:e08-p2）
- **被否定过的概念必须全链彻底删**〔通用〕——「说了没有 还是不删？？」半删（留字段/派生函数/数据点）=激怒用户（来源:7cec-p1）
- **指令已明确禁止再抛选择题**〔通用〕——「我都告诉过你了 你还问我？？」；已给过的信息再反问=没认真读上下文（来源:7cec-p2/7cec-p1）
- **虚构缺失=信用破产**〔通用〕——「明明就有匹配耗时分布，你再睁眼说瞎话啊」；列遗漏/报缺口前先核对现状（来源:7cec-p2）
- **修 bug 优先级：结构>参数；验收标准比 AI 自估高一档**〔通用〕——两轮参数（间距/字号）调不平=布局模型错，立即换结构思路而不是第三次调参；分区标题 14px/500→18px/600 用户连续加码三次才满意，返工两轮没打中时问题不在参数在结构（来源:e08-p1）
- **同一问题两轮修无效必须换打法或主动让贤**〔通用〕——「算了你别改了 我让别人改」；别人接手后禁再碰：「其他对话已经改过了 我需要你做别的事情」（来源:7cec-p2）
- **待拍板项显式挂起、需求留白标"待拍板"不臆造**——Battle 橙 vs 粉紫列 A/B 交用户；09 送礼权限维度判"需求级留白"标待拍板，用户后来直接给答案（做法正确获配合）（来源:54827/e08-p4）
- **用户措辞逐字用**〔通用〕——「你换了几个短语是有病么」命名/文件名/文档标题用用户原话，连"编辑"这类字都要落进（来源:e08-p2）
- **用户记忆错误用证据纠正，不盲从**〔通用〕——查决策记录原文（113 行）+后台已实现，回复"您记错了"附证据；面对用户质疑已拍板口径：先查档、承认原口径来源、再评估是否被新逻辑取代，不急着护盘（来源:e08-p4/7cec-p1）
- **用户发的截图必须先看图再答**〔通用〕——「截图我发过了 你没看到么 顶部有一行提示」（来源:e08-p3）
- **文案级修改先发草稿过目**〔通用〕——「先发我 我同意你再加」；汇报"参考过什么"必须给逐条出处表，空口"有参考"会被追问（来源:e08-p4/e08-p1）
- **发布三级铁律**〔通用〕——只有用户明确说"发布/部署/上线"才执行；顺序=①本地 commit →②push 远程 →③部署；修复≠发布授权，改代码和发布分开（一次事故：拍板后一口气 build+部署线上被怒斥「你咋就更新呢？？」）（来源:e08-p3/e08-p4）
- **改版前必须读参照实现的源码本体，只凭截图目测=应付工作**〔通用〕——「你他妈的好好看看若依的…就应付工作啊」；AI 从截图目测诊断"间距松散"方向全错（间距大是 i18n 故意设计）（来源:e08-p1）

## ② 素材语义与判定

- **nodeId 反查法是语义判定主力**——素材文件名 `3236-2267` ↔ Figma 节点 `3236:2267`，查 `Design System/*/figma-node.raw.json` 的 name+完整父链定语义，实测「大部分语义直接落定」（来源:54827/small4）
- **nid 不能猜、反查要多轮递进、差一位也要验证**——round3「没找到 Frame——nid 猜错了」，改为打目标节点的完整父链（带真实 nid）才落定；语义名 1622/1626 对应导出文件却是 1623/1627（可能父子节点），验证后再定映射（来源:54827/311b）
- **PIL ASCII 判形只做辅助手段**——完整解码+alpha 阈值分级字符 `' .:@'`+主色聚类+亮度判深浅；禁截图防 context 爆（来源:54827/small4/96848）
- **ASCII 判形会错，节点名定语义才硬**——80×80 六枚曾全族误判"星爆/礼花"，从 raw.json 挖到 Rank: Diamond III/Gold I/Silver II（Frame 829-831）才翻案；素材语义必须 nodeId 反查+判形双确认再记档（来源:311b）
- **错判一次进档案会连环放大**——096 凭观感定性"段位徽章"并记档，后续沿错档案越换越乱（v0.5 判错→memory 记档→v0.8 被批「对决图标怎么放成段位图标了」），PIL 重判形实为 X 形双剑交叉（来源:311b）
- **判 alpha 镂空定素材结构**——中心 alpha 占比 0%=环形头像框不是头像（仅看外形拿去当头像裁切填充=三层框事故「头像框里套头像框？？？」）；alpha=255 实心圆盘则头像压上层露边当装饰（来源:96848/311b）
- **sprite 图必须先算单枚格位再缩放引用**——2376 实为成就框 sprite（360×360 三枚竖排，单枚 180×180），132 缩放后 44 宽容器只露第一枚左缘 4px（来源:311b）
- **同语义多形态要看 bbox 选形**——fire 有 174×64 横幅版与竖火苗版，横幅塞 24×24 压成扁条；Storefront 有线性版/渐变版（渐变版契合主题色）（来源:311b）
- **徽章族=「段位样式徽章 × 2 配色组」非六个不同段位**——Game Cards 两组 Container（2249/2278）各三卡（Ludo Hero Classic=Diamond III/Jackaroo Hero=Gold I/Evil Magic Defence=Silver II）；实用口径 2258/2287=Diamond、2267/2296=Gold、2276/2305=Silver（来源:54827/small4/311b）
- **manifest.md 是语义权威+使用约束索引**——用户原话「manifest 是这个md文件 用于定位美术素材的」；承担"称号族禁挪功能位"类约束；但 manifest 会滞后（用户重组目录后没同步），引用前以实际目录为准；25 个"待判形"4 轮脚本反查补齐后才开工（来源:96848/54827/small4）
- **客户 svg 直引前先查着色机制**——`head -c 600`+`grep stroke` 确认固定色 #2C2C3A（浅底设计）→方案=读原 svg 文本把固定色换 currentColor 后内联：形状保持客户原套、颜色由容器色板驱动（来源:54827/small4）
- **整帧导出 svg 陷阱**——3182-2527.svg 是 Nav item 整帧（56×56 含留白，图标只占中心 30×30），CSS 缩到 30 显示后真实图标仅 16px；引组件导出素材前先看 viewBox 内容实际占比，按原尺寸显示（来源:311b）
- **无扩展名素材 file:// 拒解码且编号本身是目录**——墨刀 uploads7 真实结构 `18400/184007095/v2_tku4bm.png`，引目录必 broken（7 个素材全是同名 v2_tku4bm.png）；批量修正用 sed -E 精确捕获组（来源:311b）
- **底栏入口集真值要多页交叉验证**——墨刀真值=Games 手柄/Explore 罗盘/Group 双人/位4 漏画（实为消息）/Me 人形；AI 曾错搬 Figma Nav 组件的 Chat/Shop；交叉验证法=对比 Ludo 首页与群组大厅页同位图标选中色（来源:311b）
- **墨刀 uploads7 白剪影素材族语义表**——095 闪电 32/096 双剑（对决）24/097 绶带（老版段位）/098 空心星 12/099+101 实心星 12/102 加号 24/112+113 奖杯 24（**Rankings 墨刀真值是奖杯非皇冠**）/118 商城袋 28×22（来源:311b）
- **"3D Shaded Icons Filled"组名名不副实**——挂名 3D 组实际导出=投影滤镜+单色填充渲染扁平；素材风格要渲染验证，不能信命名（来源:311b）
- **客户规范无第 4 游戏（UNO）素材，用 CSS 自绘+注释**——Game Cards 4 个 svg 是棋盘环/小图标非游戏卡；UNO 用 CSS 自绘（红渐变卡+白斜椭圆）并注释"自绘替位"，不硬凑（来源:311b/96848）
- **字体语义按页判定**——Tajawal 只出现在 Typography-2（阿语排版页，14 节点全是阿语示例），英文页规范就是 Inter/Poppins，Tajawal 是阿语 RTL 阶段字体；外部审查"没换 Tajawal"核实 raw.json 计数后驳回（来源:small4/54827）
- **背景素材用亮度判深浅再决定能否上**——3221-2074 顶亮 210/底亮 243/主色 #E0E0E0→判浅色可上，不违背浅色口径；「错在深色方案，不是错在用背景素材」（来源:54827/small4）
- **图标缺口分两类记录**——①客户库没导出（Compass/ChatCircle→DiceFive/Users 近义替代+交付时明说）②3D 生成缺（Check-in/Create/Battle/Quick→中文清单交用户，现状 2D 着色占位不影响整页）（来源:54827）
- **库重组后真丢失的入口退回 2D 占位+缺口清单，不硬找替代**——3221-1581 Battle Pass 旗随 alt-v3 被裁、2472 被归称号族→两入口退墨刀原 2D 占位，等用户生成素材入库后直引替换（来源:54827/small4）
- **同血缘优先不外找，保真手段=原样内嵌原版 svg**——位 4 消息图标从聊天页产物抽同库信封（24×24 实心）补全；v1 定稿的信封/罗盘 svg 直接抠（已验证视觉）染紫即用；从转换产物抽 path 组装内嵌，不是找相似素材替代（来源:311b/54827）
- **3D 库建库法**——按来源分子目录（客户素材/生成素材）；manifest.md 列 nodeId/尺寸/语义（文件名即 Figma 节点 id 可反查）；tag 族标"禁挪功能位"警示；大图（banner/组图）排除出库；单一来源库必须快照拷贝集中管理（与"素材直引不拷贝"的页面级引用相对）；盘点时 svg/webp 也要翻不能只扫 png（coin.svg/diamond.svg 漏扫被骂）（来源:311b/96848）

## ③ 基底 DOM/svg 机制

- **基底本质：375×812 绝对定位 DOM**——每节点 div+行内 style，注释标 [idx] 与图层名，z-index=idx；643 行/105KB「结构可控」；先通读全文盘点替换点（状态栏/顶栏/六入口/三按钮/锦标赛/底栏），心里有数才写脚本（来源:54827）
- **所有 data-idx 节点平级 absolute、互不嵌套（挂 .stage 或 body）**——推论一：overflow:hidden 加在某一层裁不到平级兄弟层（给 273 加 hidden 裁不到 275/277/278=白改）；推论二：需要父子关系必须构造真父子（来源:96848）
- **跑马灯/裁切类动效必须构造真父子**——277 当 296px 宽裁切窗口（+overflow:hidden），真实文字层 278 挪进 277 内部成真子元素挂动画，无效空层下线；`@keyframes jam3a-marquee{from{transform:translateX(296px)}to{translateX(-430px)}}`+14s linear infinite+white-space:pre（来源:96848/small4）
- **svg fill="currentColor" 只认 svg 直接所在的层**——染外层容器（330/333/336）无效，必须染 svg 层（332/335/338）；染错层→星星没变色→被骂"编瞎话"（来源:96848）
- **残尾 `</div>` 会把 .stage 提前闭合**——整行替换锚点只吃到旧行中段，残尾里的 `</div>` 让 270~908 共 89 节点被踢出 stage 直挂 body，下半页整体偏 (24,24)（表现：底栏下方空一条、卡片不齐）（来源:96848）
- **多行 svg 是行级替换的天然陷阱**——idx70 原行跨 3 行（内嵌 svg 换行），replace_line 只换首行留残尾 `</svg></div>` 又差点闭合 stage（来源:96848）
- **基底自带引号截断 bug（上游转换产物）**——style 属性内 font-family 带未转义双引号（`"Microsoft YaHei"`）在 HTML 双引号属性里截断，font-family 之后的 white-space 等全失效；换字体栈时顺手修掉（先 grep 原始字节确认）（来源:54827/small4）
- **svg display:inline 基线下坠被裁顶**——svg 默认基线对齐导致下坠，被 overflow:hidden 父框裁顶（状态栏信号/WiFi/电池"元素显示不全"的根因）；修复=全局 `[data-idx] svg{display:block}`（来源:small4）
- **getBoundingClientRect 不反映 overflow 裁切**——只给布局框不给可视框；跑马灯裁切报警是误报（中间层是空 div 无视觉内容），健康判定用结构断言非 bbox（来源:small4）
- **body{padding:24px} 是墨刀展示壳**——stage 原点不在 (0,0)；任何截图像素采样必须加 stage 偏移，否则「所有异常采样全部错位」（(273,460) 实落按钮外空白）（来源:54827/small4）
- **验证视口太窄会压缩 stage**——视口 375 时滚动条吃 15px+body padding 48px→stage 被 flex-shrink 压到 312 宽、右侧 63px 被 overflow:hidden 裁掉，「截图判形全部作废是验证环境问题，非页面问题」；排查用 getBoundingClientRect 读 stage 绝对位置，别跟 flex 理论打架（来源:54827/small4）
- **data-idx 是绝对定位 DOM 唯一可靠锚点，不是内容**——Quick/Create 两节点同串，sub_once 无法区分；字符串定位失效时改 data-idx 定位（来源:54827/small4）
- **多行 div 用切片定位法**——内嵌 svg 带换行把一行 div 撑成跨多行，单行 grep/正则失败；按锚点字符串切前后段再字节区间拼装替换（来源:54827/small4）
- **绝对定位 DOM 的 height 写死在 style 里，框高≠内容折行**——idx78 "Ludo" 高 26px 是显式框高，scrollWidth 断言通过即无真溢出勿误判（来源:54827/small4）
- **空容器层与视觉层要分清**——底栏 309 是空容器无视觉、310 才是 svg 层；替换前先 grep -B1 看清层级，别替换错层（来源:54827）

- **换 3D 必隐藏旧 2D 容器族（成对层同步改）**——漏隐藏 BP 旧层 130-132 造成 2D/3D 叠影；同类 114-117（Check-in）/283+263（两卡）/341/342（Create）；断言清单也随设计反转同步更新（bp2dVisible 正反翻转两次）（来源:96848）

## ⑤ transform 脚本安全

- **规则表驱动+原语化**——sub_once/hide_line/inline_icon/swap_to_3d 四个原语，所有替换写成规则表；swap_to_3d 把 2D 节点整行换成 3D img 直引，坐标显式传入并保留 z-index=idx 层序（来源:54827/96848）
- **先特定节点后全局**——特定节点（data-idx 定位）替换先于全局字体/颜色替换，避免全局规则误伤已特调节点；每处标注原值（来源:54827/small4）
- **每个替换带命中次数断言**——`sub_once(old, new, expect=1)`；Quick/Create 同串歧义就是被断言抓住的（expect 与命中不符即报错）（来源:54827/small4）
- **断言失败不写盘（两段式）**——先全部 assert count==1 校验（失败中止=已做的 replace 全不落盘防半改状态），最后才统一 write；失败现场可查、脚本可修可重跑（实测定位失败后改脚本直接重跑无需回滚文件）（来源:54827/small4/7cec-p1）
- **整行替换必须锚到旧行末尾**——只吃一半就留残尾，残尾 `</div>` 提前闭合 stage（89 节点错位事故）；修法=残尾截断到新节点自身 `</div>` 为止（来源:96848）
- **replace_line 前先确认原行不跨行**——多行 svg 跨 3 行只换首行必留残尾（来源:96848）
- **每次 transform 后必跑 div 开/闭平衡计数**——327/328 不平衡当场抓住残尾；327/327 确认嵌套改造安全（来源:96848）
- **一轮改版=一段独立脚本**——v2（换肤）/v2b（底栏重建）/v2c（审查修复）/v2d（库重组适配）各自独立可重跑，出错不连坐（来源:54827）
- **构造串自查（replace 自污染）**——多轮脚本叠加时查找串会被历史变更污染（2472 实际还是旧库名路径导致 Quick 定位失败）；脚本要可重跑并核对中间产物（来源:54827/small4）
- **相对路径深度按页面实际目录层数算**——页面在 `JAM3A/app高保真原型v2/01-xx/`，`../../../` 多写一级直接跑出仓库；verify 静态 404 断言兜住（来源:54827/small4）
- **sed 转义不匹配会静默失败**——verify 插打印段 sed 没生效→改用 Edit 工具；sed 批量改引用路径必须用精确捕获组（`18400/184007[0-9]{3}`+后引号锚点）并重跑 404 断言（来源:96848/311b）
- **手抄坐标/svg 必错，能 cp 文件直引就不要手抄进 HTML**——36.1913 抄成 16.1913（来源:96848）
- **脚本可断言可重跑+mtime 断点判定**——「脚本 mtime vs 产物 mtime」（11:50>11:23=写好未跑）可无损判定断点，补跑即接续；transform 脚本落盘 .claude-tmp 不依赖会话内状态（来源:96848）
- **python 一律 Write 成 .py 再跑，禁 heredoc 内联**——heredoc/python -c 遇中文路径 GBK 必坏；中文字面量目录用 `os.listdir`/`startswith` 规避；PIL 路径用 `D:/` 盘符写法（`/d/` POSIX 写法 Python 原生不认）；io.open(p,'w',encoding='utf-8',newline='')（来源:small4/54827/311b）
- **净变更字符数回显**——每轮跑完报（v2 +5228/v2b +11545）作为变更规模的量化记录（来源:54827）
- **grep 收尾自检清单**——3D 直引计数/currentColor 计数/旧色零残留（老色值逐个 grep 必须为 0）/display:none 节点数；「脚本跑完必须 grep 目标词残留+逐落点核对，不能信退出码 0」（来源:54827/small4/e08-p4）
- **替换清单逐类过，每类跑一次视觉校验**——字体→色板→按钮→卡片→图标；一把全换=出错无法定位（来源:311b）
- **批量脚本默认不可重入**〔通用〕——第一次跑完全部文件结构已变，二次跑同一脚本正则锚点失效只抓到 2 个；要么一次跑对，要么另写针对"已改形态"的第二脚本（来源:e08-p1）
- **属性内特殊字符是正则批改雷区**〔通用〕——`v-show="total > 0"` 的 `>` 把正则匹配截断产出残缺模板；改完必须全量 grep 特征回验（来源:e08-p1）
- **跨段容器（tabs/collapse 等）纯正则拆分会撕破结构**〔通用〕——7 个文件编译 500；这类页面放弃脚本走 git 恢复+手改（来源:e08-p1）
- **分两步走策略**〔通用〕——先做 100% 安全的简单替换（外层容器/全局样式类），再处理结构拆分；大批量改造保留 git 全量回滚退路（脚本事故波及面比手改大一个数量级：7 文件坏 vs 1 文件坏）（来源:e08-p1）
- **批量 sed 删代码先逐页 Read 确认边界**〔通用〕——按原行号 `sed -i '178,217d'` 的前提是"函数体+按钮行边界全部确认"（来源:7cec-p2）
- **批量改版砍功能"三重呼应"检测法**〔通用〕——script 死代码（函数全文件零引用）+词条孤儿（有 key 无消费）+API 孤儿（导出无调用）三者同时出现=template 被砍的痕迹；四波批量改版实锤砍 8 处功能块；audit 脚本固化为提交前自检（30 秒跑完）防再发（来源:7cec-p2）

## ⑥ 验证与自检

- **三层验证链**——grep 静态自检 → CDP DOM 断言（Runtime.evaluate 渲染后）→ 截图 PIL ASCII 判形走查；DOM 断言+像素采样双验兜住皮肤替换漏网；**禁用视觉模型做测试**（截图只落盘供人工验收），判形走查由 PIL 脚本 ASCII 回读（来源:54827/small4/96848）
- **"挂上了"≠"生效了"**——跑马灯动画挂空层 275 上 verify 却全绿（verify 只测改过的层）；终极验证=双采样 transform 实测（1.5s 内 translateX 169→90.3 ≈52.5px/s，与 726px/14s 理论值吻合才算真滚）（来源:96848）
- **verify 只断言自己改过的层，结构性/兄弟层问题测不出**——结构改动要加针对性探针（问真实父级、div 平衡、clip 扫描）（来源:96848）
- **静态扫 HTML 不可靠**——多行 svg 干扰闭合判断；用 CDP 探针问浏览器各节点真实父级（getBoxModel/parentElement）（来源:96848）
- **视觉模型有误报史，报告要逐条 DOM 反查甄别后再动手**——6 条报障甄别后仅 2 真；误报 4 条都有据（箭头偏低=墨刀原版本来居中/按钮宽窄=原版布局/跑马灯截断=静态截图必然截断/千位分隔符=mock 数据）（来源:96848）
- **验证视口必须锁手机版式**——headless 默认 800×600 截不到 stage；1600 宽视口下 stage flex 居中到 (296,24)、body 直挂节点从 (0,0) 起，rect 参照漂移 -296.4,-24（假偏移）；锁定 423×900 且落位 rect 一律相对 .stage 原点算（来源:96848）
- **正确截屏姿势**——视口放大到 430×880（大于 stage+padding+滚动条）+用 stage rect 做 clip 截图恢复真 375×812；局部放大用 deviceScaleFactor 2-3 倍；截图像素采样以 stage.x/y 为基准加偏移（来源:54827/small4）
- **CDP evaluate 返回是双层结构**——`{result:{result:{value}}}`，少取一层得到 undefined；eval 失败必须打印 exceptionDetails，否则静默失败像"断言全挂"；断言 key 用英文（①②不能做裸 JS 标识符）（来源:54827/small4/311b）
- **查色要双属性**——纯色按钮只断言 backgroundImage 会漏（Create 底色 #E0D8FB 在 backgroundColor）；两个都要查（来源:small4/54827）
- **三通道 DOM 扫描（probe-clip）**——A) svg/img bbox 超 overflow:hidden 父容器（容差 0.5px）A2) img 无保护超盒 B) 可见层越出 stage 375×812 C) nowrap 文字 scrollWidth 溢出；崩溃会话写好没跑成、接续会话直接复跑即得 11 处问题（来源:small4）
- **CDP 直连用 /json/list**——fetch webSocketDebuggerUrl 直连最可靠；`/json/new` 会卡死（截图脚本 120s 超时）；端口分工（9224=V2 实验、9225=墨刀线）不互碰（来源:small4）
- **断言清单/verify 是活文档，随改版同步长大**——v2b 重建后旧断言失效先 Edit verify 适配再复验；130-132 移进移出隐藏清单两次；断言随拍板口径同步更新（来源:54827/96848）
- **跑 verify 前先核对选择器真实性**——逐个 grep verify 引用的 14 个 data-idx 在页面中唯一存在再跑；选择器失效比断言失败更隐蔽（来源:54827/small4）
- **断言红了先验断言自身**——两次"红"都是断言算式错、页面实现其实正确（flex 取整 317/2=152 vs 理论 151.5→放宽 ±1；"中心点+16"错当左上角期望）；先复核断言算式再动页面（来源:311b）
- **文本换行自动检测**——换字体后文字变宽必然；verify 加 scrollWidth vs clientWidth 对比+块高度异常（换行撑高）自动判红，不靠肉眼（来源:311b/54827）
- **层叠断言验证 z-index 真实生效**——elementFromPoint 中心命中 avatar、边缘命中 avatar-frame（来源:311b）
- **资源 404 断言是第一道关卡**——静态资源全 200（30/30 无 404、broken imgs=0、img naturalWidth 全加载）；它同时兜住相对路径深度坑（来源:54827/311b）
- **审查五步法（可复用的交叉审查套路）**——find/du 盘产物→wc/grep 确认基底节点数（311 个 data-idx 原样）→python diff 基底统计改动处（几何仅改 7 处全在图标放大）→grep 关键 token 出现次数定替换完成度（Tajawal 0 次=字体没换）→渲染 ASCII 看观感+配色值溯源对两源（来源:311b）
- **交叉审查报告的处理姿势**——不全盘接受：先并行核查硬事实（Tajawal 计数/背景亮度/底栏口径），再逐条列表「已修/误判驳回/待拍板」（来源:54827/small4）
- **产物验证≠源码验证**〔通用〕——dev serve 正常≠构建包正常（压缩/env 内联/分包是另一条代码路径）；交付前必须在目标环境实测（来源:e08-p3）
- **三重证据法识破假差异**〔通用〕——diff 报 536/470 行"巨大差异"实为 LF/CRLF 换行符差异：`file` 换行符检测+`diff --strip-trailing-cr` 归零+去 CR 后 MD5 逐一相等；任何"全文件都变了"的 diff 先查换行符/编码再谈内容（来源:e08-p3）
- **端口残留进程假绿（验证的是错误对象）**〔通用〕——TaskStop 杀不干净 node 子进程，strictPort 新进程退出，curl 200 来自残留旧进程 serve 的旧目录「绿灯属于别人」；netstat 定位 PID→taskkill /F→重启确认启动输出里的目录与端口（来源:e08-p3/small4）
- **声称的改动必须 grep 到文件与行号**〔通用〕——协作会话声称的"三补丁"逐个 grep 落点（L62/154/222）才算数；关键词全仓零命中=可疑，深挖（来源:e08-p3）
- **验收=问题清单，不是合格印章**〔通用〕——终版报告仍挖出 1 个严重问题（数值大 10 倍且自相矛盾）+5 项建议级（来源:e08-p3）
- **切图先验内容**〔通用〕——局部截图可能切偏（问 Battle 区切到的是中段）；模型答"图中不存在"本身可用（排除法），但下结论前要意识到可能切偏（来源:small4）
- **用户贴截图不说明页面时先反查**〔通用〕——问"页面标题/tab 名/红框区域内容/表格列名"反查是哪个页面再 grep 渲染代码；截图坐标乘换算系数（显示 924x2450→实际 1.23 倍，或提示行 "Multiply by 1.28"）还原原图（来源:e08-p1/7cec-p2/e08-p4）
- **probe 独立成脚本+输出重定向**——probe/probe2/3/4 各自落盘 .mjs，输出 `> xxx.txt` 后 sed -n 挑段读，排查链不占 context（来源:54827）

## ⑦ 会话防爆纪律

- **崩溃死因档案**——`Prompt is too long + automatic compaction failed: API Error 400 [1301]`（内容安全拦截）：19.7MB/6789 行会话崩且 /compact 也被拒=不可自救；41MB jsonl 同死因；长会话+大文件+激烈用词会触发自动压缩失败，会话直接死亡（来源:7cec-p1/54827/311b）
- **吃 context 的操作实锤清单**——①analyze_image 返回大段 JSON（几千 token/次）且同一截图连调两次纯属浪费；②大段 HTML 原文输出（grep -o 'style="[^"]*' 全行打印、sed -n 大范围打印）；③每轮 transform 后重复全量 verify 长输出；④continuation summary 本身也占额度（来源:96848）
- **防崩三动作（本会话做对的）**——①关键节点随时 Edit 记忆文件（断点状态/拍板口径/终态，「再崩也能无损接续」）；②脚本/产物 mtime 对比无损判定断点（写好未跑=补跑即接续）；③transform 脚本落盘 .claude-tmp 可重跑，不依赖会话内状态（来源:96848）
- **崩溃恢复链路四步**——①读 memory 相关文件→②看 .claude-tmp 遗产（ls -lat 找最新脚本：transform-v2a~v2p/verify-v2.mjs/probe-clip.mjs）→③从崩溃会话 jsonl 提取全部用户消息+尾部动作（落 session-users.txt/session-tail.txt）→④确定中断点：「写好脚本还没跑」的直接先跑（来源:small4）
- **崩会话的最后一条用户指令往往是最有价值的待办**——v0.5 四点纠偏（头像框/3D 图标/底栏尺寸/商城图标）就是崩溃会话 13508cd6 的临终指令；恢复时必须先挖出来（来源:311b）
- **断点信息三源对齐再动手**——①memory 文件（已被前会话维护）②崩会话最后一条用户消息 ③.claude-tmp 中间产物（nodes dump/verify 脚本/svg 提取物）（来源:311b）
- **接手别人的半成品先"只看不动"**——盘点产物落点、汇报清楚再选线执行；别重复别人已做过的调研（用户红线「别再做一些别的对话都干过的事情了」）（来源:311b）
- **超大 jsonl 禁整读**——41MB 崩溃 jsonl 用 python 小脚本只提取首尾消息/用户消息定位身份与死因；考古 jsonl 流式过滤大对象勿整读 17MB（jsonl 里 Write 调用带完整源码，已删脚本可挖回）（来源:311b/e08-p2）
- **换实验=换会话**——旧会话历史堆满 v1 实现细节（素材排查过程/旧代码结构）对 v2 是包袱不是资产，继续用很快再触发压缩丢细节；冷启动成本靠 memory 落档归零（用户采纳 AI 建议）（来源:311b）
- **同一实验线连环崩是常态，宁可多开会话分段做**——54827 崩了被 be513be8 接续、接续会话又两次 /compact；单会话内及时落盘（脚本/manifest/决策记录）使任何时刻崩溃可恢复（来源:small4）
- **口径外置**——拍板口径写进 memory/需求决策记录/manifest，不依赖会话记录存活；"v2 会话没吃透 v1 已拍板口径"的真因即口径只存在旧会话记录里（来源:small4/54827）
- **重活交 subagent；后台 agent 不保活**——大范围读文件/词条提取/四路并行走查在子代理消化（各 5-10 万 token），主会话只收结构化结论摘要；宿主进程退出后后台 agent 无完成记录，transcripts 保留可 SendMessage 按 id 续跑，重启后别假设后台任务已落地（来源:7cec-p2/e08-p3/e08-p1）
- **大文件不整读**〔通用〕——3.6MB html 先 grep 关键词定位行号再 Read offset 局部读；`grep -o '.\{80\}关键词.\{120\}' 文件 | sed 's/<[^>]*>//g'` 抽上下文去标签；按 section 锚点抽节；643 行基底也分 3 次 Read（来源:e08-p1/7cec-p2/54827）
- **截图不进 context+输出截断**——判形全走 PIL ASCII 降采样回读结论；需要语义时才 Read 小图（80×80 token 可控）；判形/verify/probe 结果全部输出到文件再挑读；截图诊断一次调用收敛 prompt（同图两次纯属浪费）；grep HTML 用 cut -c 截断长行；verify 输出 sed -n 只取相关段（来源:54827/311b/96848）
- **用户连问"卡了么"的应答法**——长任务收尾后 UI 没渲染用户会反复问；应答保持简短并给"随便回一个字"的验证通道；读大文件被切断恢复后直接给结论别重新流程化叙述（来源:7cec-p1/e08-p1）
- **长任务及时收口落盘勿拖到压缩后**——压缩摘要丢早期细节导致用户连纠三轮（勋章文档）（来源:e08-p2）
- **红线类文字逐字保留**——context 续接靠 summary，安全/纪律类约束换摘要复述会失真；压缩摘要写法本身就是断点恢复资料：任务意图、真值数据（坐标/色值/路径）、错误修复史三段最值钱（来源:e08-p3/311b）
- **接任务先跨会话查重**〔通用〕——自荐前检索其他会话记录（python 扫 ~/.claude/projects/ 下 jsonl）避免两个会话做同一件事（重复劳动+口径打架）（来源:e08-p1）
- **用户反馈截图是 CDN URL**——`curl -sL -o 本地.png "URL"` 落盘再 Read/PIL 判读，配合墨刀节点 dump 对照定位被批区域（来源:311b）
- **analyze_image 本地图路径坑**——Read 大图返回 CDN URL，路径含反斜杠/空格 400；复制到纯 ASCII 短路径+反斜杠编码 %5C（该工具只用于帮用户看图，不做测试判据）（来源:small4）
