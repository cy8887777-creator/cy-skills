# 英转阿 UI 文案翻译（已归档）

> ⚠️ **本技能已停用并归档（2026-09-02）**：其翻译方法论已全部并入 `solo-ue-line-cy-mockingbot-ar-flat` 技能（`references/spec.md` §5，作为唯一翻译权威）。阿语本地化请统一使用 `solo-ue-line-cy-mockingbot-ar-flat`，勿再调用本技能。

只做**语言翻译与文案适配**，不动页面结构、布局、交互。与「原型翻译」技能的分工：

| | 原型翻译 | 本技能 |
|---|---|---|
| 输入 | 原型 HTML 文件 | 已提炼的**英文文案清单**（文本 + 元素类型 + 页面名） |
| 输出 | 整套多语言原型 | 「英文 ↔ 阿语」映射表 + 风险标注 |
| 范围 | 翻译 + 排版 + 结构复制 | 只翻译与文案级适配 |
| 语言 | 仅 LTR（明排除 RTL） | **专门处理 EN→AR / RTL** |

---

## 适用范围与边界

**方法通用**：任何英文界面转阿语的项目都能用本技能的流程与规则。
**术语表项目专属**：术语表按项目替换，见下方「术语表加载」。

**不做**：不改页面结构/跳转/交互；不拉伸布局；不复刻交互热区（墨刀里 `rgba(255,140,25,.15)` + 橙色描边的块是热区，不是视觉元素）。

---

## 执行流程

### 1. 语境推断（先于翻译，必做）
对每个文案，先确定三层上下文再动笔：

1. **页面名** → 场景（如 `手机号登录Phone Login` → 登录流程 / `年龄验证提醒` → 合规拦截）
2. **所属模块** → 领域（如 `群组group` / `GVG` / `Main Events` 各有术语）
3. **元素类型** → 语气（见下表）

| 元素类型 | 语气要求 | 例 |
|---|---|---|
| 主按钮 | 祈使式，尽量短 | Log In → تسجيل الدخول |
| 次级按钮 | 动名词/名词短语 | Send Code → إرسال الرمز |
| 输入框标签 / 占位符 | 名词短语，占位符可稍长 | Phone Number → رقم الهاتف |
| 标题 | 名词短语，可带定冠词 | Welcome Back → مرحباً بعودتك |
| 错误 / 警告提示 | 完整句，直陈，不加感叹堆砌 | You must be 13 years or older... |
| 条款正文 | 正式书面语，完整句 | Terms of Service → شروط الخدمة |
| Toast / 结果反馈 | 短句，口语但不方言 | Profile Shared → تم مشاركة الملف |

### 2. 术语表加载（优先级从高到低）
1. 项目内的 `术语表.md`（若存在，直接用，不得自创）
2. 本技能 `references/` 下与项目同名的术语表（如 `jam3a-术语表.md`）
3. 都没有 → 翻译前先向用户要，或标注「待确认术语」并给出候选，不自行定名

**命中术语表必须照抄**，包含术语的短语也必须按术语表译该项。

### 3. 翻译
遵循 `references/阿语规则.md`，要点：
- 用**现代标准阿拉伯语（MSA）**，不用埃及/海湾方言
- UI 短文案优先**简洁**，阿语常见比英文长 30–50%，能短则短
- 禁逐字直译；动宾搭配按阿语习惯重组

### 4. 标注风险（每条都判）
| 风险 | 判定 |
|---|---|
| **超长** | 阿语明显长于英文且元素宽度受限（按钮/标签）→ 标注并给**短版候选** |
| **歧义** | 一词多义（如 Rank = 段位 / 排名）→ 标注，按语境给推荐并说明依据 |
| **不可译** | 品牌名、游戏名、国家区号、时间 → 保留原文，仅音译时标注 |
| **待确认** | 术语表未覆盖且影响一致性 → 列出，不自行定名 |

### 5. 输出格式
产出 Markdown 表格，可直接回填生成脚本：

```
| # | 页面名 | 元素类型 | 英文原文 | 阿语译文 | 风险 |
|---|---|---|---|---|---|
| 1 | Phone Login | 按钮 | Log In | تسجيل الدخول | — |
| 2 | Phone Login | 次级按钮 | Send Code | إرسال الرمز | 超长，短版：أرسل |
```

末尾附：**待确认术语清单** / **超长需改版式清单** / **未翻译（有意保留）清单**。

## 硬性规则

- **禁直译**：先定场景与语气，再译；不通顺就重造句子，不做字对字搬运。
- **术语一致**：同一英文词在所有页面译法统一，不前后混译。
- **不可译项保留**：品牌名、游戏名、国家区号（`+966`）、时间（`12:00`）、纯数字符号（`×1`）。
- **数字体系按项目定**（西阿拉伯 `1234` 或 阿语-印度 `٠١٢٣`），全项目统一；未定则**默认西阿拉伯数字**并标注待确认。
- **纯数字符号串在 RTL 中需 LTR 隔离**：渲染时加 `direction:ltr; unicode-bidi:isolate`。
- **长度是硬约束**：翻译完必须评估是否会撑破容器，超长必须主动标注，不静默交付。

## 提问边界

- **必问**：目标项目是否有术语表；数字体系用哪种；超长文案是改短译法还是调版式。
- **不问**：单个词的译法（按规则自行判断并标注）；视觉细节。
