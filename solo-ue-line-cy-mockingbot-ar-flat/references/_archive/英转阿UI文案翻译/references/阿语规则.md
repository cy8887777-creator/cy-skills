# 阿语（AR）专项规则

面向 UI 文案，只写落地要用的部分。

## 1. 变体选择

- **用现代标准阿拉伯语（MSA / فصحى）**，覆盖所有阿拉伯地区，不会出错。
- **不用方言**（埃及 ammiya、海湾 khaliji）——方言只适合特定市场营销，UI 文案会得罪其他地区用户。
- 海湾产品可适度用海湾习惯词，但**必须记入术语表**，全项目统一。

## 2. 长度（最容易翻车）

- 阿语通常比英文**长 30–50%**（有时更甚），按钮、标签、Tab 首当其冲。
- **UI 短文案优先要短**：能用名词短语就不用完整句；能省冠词就省。
  - `Send Verification Code` → `إرسال الرمز`（省 Verification）
  - `You must be 13 years or older to create an account` → 完整句，长文本可保留
- 翻译后**必须评估是否撑破容器**；超长给短版候选，不静默交付。

## 3. 数字与符号

| 体系 | 形态 | 说明 |
|---|---|---|
| 西阿拉伯数字 | `1234` | 海湾/黎凡特多数 App 与系统默认，本技能默认 |
| 阿语-印度数字 | `٠١٢٣` | 埃及、苏丹常见；iOS `ar-EG` 默认 |

- **全项目二选一，不得混用**。
- **必须保留原样**：国家区号 `+966`、时间 `12:00`、版本号、金额、验证码、数量 `×1`。
- **RTL 中纯数字符号串要 LTR 隔离**，否则顺序错乱：
  ```css
  direction: ltr; unicode-bidi: isolate;
  ```

## 4. 排版/渲染

- 用 `dir="rtl"`，配 CSS 逻辑属性（`margin-inline-start` / `text-align: start`），不用 `left/right`。
- **双向文本**：阿语段落中夹英文品牌名（如 `Jam3a`、`UNO`）时，用 `<bdi>` 或 `unicode-bidi: isolate`，否则标点会跳位。
- **标点**：阿语用 `،`（逗号）、`؟`（问号）、`؛`（分号），不要用英文标点。
- **字体**：需支持阿语连写与字形变换（`Noto Sans Arabic` / `Segoe UI` / `Tahoma`）。缺字形会显示成断裂方块。

## 5. 排版换算（坐标镜像）

画布宽 `W` 时，元素 `x` 镜像为：

```
x' = W − x − width
```

- 对齐逻辑化：`left → start`（RTL 下即视觉右）、`right → end`。
- **行高**：阿语字形上下延伸大，源设计用中文字体给的行高常偏小，需放宽或按盒高收敛。
- **`display:flex` 行方向下**：`align-items` 管垂直、`justify-content` 管水平；RTL 下 `flex-start` = 视觉右。单行文本用 flex 定位，多行/两端对齐用 `display:block` + `text-align`（否则 `justify` 失效）。

## 6. 文化适配

- **禁用**：酒精、赌博暗示、宗教敏感表达、暴露描述。
- **称谓**：UI 一般用第二人称，性别中立优先；需区分性别时按项目定，记入术语表。
- **日期**：用 `١٤/٠٣/٢٠٢٦` 或 `14/03/2026`，随数字体系统一；伊斯兰历（هجري）默认不用，除非项目要求。

## 7. 常见坑

| 坑 | 后果 | 做法 |
|---|---|---|
| 把品牌名音译 | 用户认不出 | 保留拉丁原文，加 `<bdi>` 隔离 |
| 数字体系混用 | 显得不专业 | 全项目统一，写进术语表 |
| 忽略长度 | 按钮文字换行/截断 | 译完必测，超长给短版 |
| 用方言 | 其他地区用户看不懂 | 一律 MSA |
| 直接机翻长句 | 语法生硬、语序英语化 | 按阿语句法重组，动宾顺序常需调整 |
