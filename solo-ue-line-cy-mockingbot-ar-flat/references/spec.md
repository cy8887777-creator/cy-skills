# 墨刀 → 阿拉伯语平铺版 · 技术规范与陷阱

本文件供 skill 执行时参照。覆盖：数据来源、Chrome 连接、画板选取、嵌套提取、前置过滤、翻译、RTL 镜像、字体、长文、母版、高度、已知坑。

## 0. 数据来源（重要：先搞清楚格式）

- 用户给的通常是**墨刀导出 HTML 的 `.zip`**（解压出 `index.html` + `extra/data.1.js`）。
- 偶尔会见到 `.mdrp`：墨刀私有 4 字节长度前缀帧格式，**不能**当 zip 解；里面 `data.1.js` 是 flpk 私有序列化（坐标用引用 token），**离线无法解析**，必须靠 Chrome 真渲染 + CDP 提取。
- 同事用 WorkBuddy「截图 OCR」也能读到文字，但**拿不到坐标/层级/样式**，无法还原布局。本 skill 走 DOM 提取路线，所以能重排为 RTL。

## 1. Chrome + CDP 连接（连接已运行的实例，不负责启动）

- 启动（路径按本机 Chrome 实际位置，**独立 `--user-data-dir` 隔离，禁止 `taskkill`**）：
  ```bash
  "/c/Program Files/Google/Chrome/Application/chrome.exe" \
    --headless=new --disable-gpu --no-sandbox --allow-file-access-from-files \
    --remote-debugging-port=9223 \
    --user-data-dir="C:/Users/1/AppData/Local/Temp/jam3a-chrome2" \
    "file:///解压目录/index.html"
  ```
  > ⚠️ **不要用 `taskkill /F /IM chrome.exe`**——会杀掉用户所有 Chrome 窗口。独立 `--user-data-dir` 隔离后不与用户浏览器冲突；后台常驻用 `sleep` 保活即可。后台启动带 `file://` 时父进程可能立即退出，**必须 `sleep` 保活**（收到 completed 通知属正常，直接轮询端口）。
  > ⚠️ **端口被占用 → 改新端口，勿 taskkill**：若 9223 已被残留的旧任务 Chrome 占用（现象：`/json/list` 返回的页面标题/URL 指向**别的**墨刀文件，而非本次源），说明有上一轮无头 Chrome  lingering。此时**不要 `taskkill` 误杀**（可能误伤用户浏览器），改用 `--remote-debugging-port=9224`（配独立 `--user-data-dir`）启动干净实例，并让 `extract_en.mjs`/`list_tree.mjs` 连该端口（`--port 9224`）。从源头避免「读错源文件」污染翻译。
- 端口默认 9223；脚本用 `http://127.0.0.1:9223/json/list` 取 `webSocketDebuggerUrl`，`Runtime.evaluate` 执行页面内 JS。
- 提取期间**不要关闭**后台任务；用完可 `taskkill`（仅限本技能自己的 `--user-data-dir` 实例，或按窗口标题精确清理）。

## 2. 画板选取（挑英文版）

> **硬规则（PM 2026-09-01 拍板）：读取、翻译一律找英文页面。**

- 候选：`document.querySelectorAll('.group-list .tree-node.rResCanvas')`，过滤 `w===375 && h>=600 && 有文本节点 && cid 不含 '/'`。
- **英文板 = CJK 字符数最少者**（CJK 最小者）。同一页常并存中文/英文多块画板，必须按 CJK 计数挑，否则会抽到中文板。
- ⚠️ **不能假定英文板 CJK=0**——实测 Ludo 对战页英文板 CJK=12（漏翻中文残留）。只要它是候选里 CJK **最少**的那块，就是英文板。
- 锁定手段（任选）：`--screen <cid>` 用 URL 参数 `?view_mode=device&screen=<cid>` 直达（最稳）；或 `--keywords` 正则（如 `Quests|Check-in|...`）；或 `--pages` 按页面树名/序号。
- 只取 `.group-list` 内整块画板 ⇒ **自动排除页面外参考元素**。

## 3. 嵌套提取（extract_en.mjs）

- **嵌套 walk**：`walk(el, parentIdx, depth)`，每个节点记 `{idx,parent,depth,tag,x,y,w,h,cls,text?,img?,svg?,st?}`。
  - 坐标：`dx=(r.x-brr.x)*sx`（相对画板顶左，设计坐标）；`sx=offsetWidth/getBoundingClientRect().width`，高度同理 `sy`。
  - `parent`：父节点 `idx`；根（画板自身）为 `null`。生成时据此递归渲染。
- **捕获属性**（存入 `st`）：`bg`/`bgi`/`br`/`bw`+`bc`+`bs`/`op`/`clr`(所有节点，供 SVG `fill=currentColor` 继承)/`zi`(z-index)/`ovf`(overflow≠visible，父裁剪子)/`bsh`(box-shadow)/`ow`+`os`+`oc`(outline，须 `os!=='none'` 才输出)/`bst`/`flt`(filter)/`cp`(clip-path)/`mk`(mask，含 `url()` 则跳过)/`tf`(transform，视觉坐标已含，镜像用相对坐标无需重算)。
- **SVG**：`tag==='svg'` 整抓 `outerHTML`（含 viewBox）直出真图标；容器上输出 `color:${st.clr}` 让 `fill="currentColor"` 按原色渲染；`svg` 内部不再深入。
- **img**：记 `src`；生成时若相对路径则用 `meta.pkgBase` 补全为 `file://` 可加载 URL。
- **可见性**：`display:none`/`visibility:hidden`/`opacity<=0.01` 的节点**整棵子树跳过**。
- **缩放健康门**：`画板 rect.width < 80` → 拒绝提取（子像素退化会空白）。首次启动退化时循环重设视口 + 等待重试。
- **母版告警**：内容页节点数 < 20 → 提示「疑似母版」，回报 PM。

## 4. 前置过滤（交互指示层整删 · PM 2026-09-01 18:33 定）

> 提取 → **过滤（整删）** → 翻译 → RTL 布局 → 输出。旧「opacity:0 隐藏」模式已废弃（隐藏只为给后置步骤留参照，PM 判定后置会增加工作量）。

- 识别三类纯指示层：
  1. **黄块**：`!n.text && bg` 匹配 `/rgba\(255,\s*140,\s*25,\s*0\.1/i`（墨刀热区半透明橙，自身无文本）。
  2. **蓝闪类**：`cls` 匹配 `/InteractionMark|InteractionMarker|StyledInteraction/i`。
  3. **蓝闪 SVG**：`svg` 含 `fill="#298DF8"`（亮蓝 rgb(41,141,248) 内联 SVG 交互覆盖层）。
- **整棵删除**（非隐藏）：命中节点（含整棵子树）直接从节点数组移除，产物更小、后续无噪音。
- **误伤降级保护**：命中节点若子树内含真实内容（文本/图片/非蓝闪 SVG）→ 降级为「仅中和指示特征」（剥橙底 / 不发射蓝闪 SVG），**保留容器与子节点**，不整删。Ludo 实测整删 58、降级 0 = **零误伤**。
- 生成脚本 `gen_ar_flat.mjs` 在渲染前统一执行此步。

## 5. 翻译（术语表优先 + Agent 语境翻译）— 本技能唯一翻译权威

> 本技能只做语言翻译与文案级适配，不改原型结构/布局/交互。翻译方法论为**单一事实源**：① 术语表是一致性权威；② 术语表未覆盖的由 Agent 按「语境推断 + 元素类型定语气」做语境翻译填入 `--extra`。任何自动翻译（如未来 `--autotr`）也必须遵守本规范。（原「英转阿UI文案翻译」技能的方法论已并入本节，2026-09-02 收编，避免多技能分流误导。）

- 语言源优先级（PM 2026-09-01）：① 一律英文页为源；② 漏翻中文直翻阿语，不回译英文；③ 术语对照表优先级最高，跨页跨模块复用。
- **翻译模型（PM 2026-09-02 纠正——核心概念）**：
  - **术语表 ≠ 翻译词典**。术语表的唯一作用是**规范行业用语、统一翻译用词**（consistency authority）。它不会给你全量翻译覆盖。
  - **正确流程**：术语表有的 → 严格按术语表来；术语表没有的 → **由 Agent 从英文语义 + 页面场景推断语境，做语境翻译**，填入 `--extra` JSON。
  - 脚本 `translate()` 是"翻译映射的机械应用器"，它本身不会英→阿。真正的翻译能力在 Agent 这层。
  - **"未命中"的含义**：= Agent 尚未为该串提供翻译（TODO 提示），≠ "不可译"。Agent 必须补译，不应把未命中数当最终质量指标汇报。

### 5.1 语境推断（先于翻译，必做）
对每个文案先定三层上下文再动笔：
1. **页面名 → 场景**（如 `手机号登录Phone Login` → 登录流程 / `年龄验证提醒` → 合规拦截）
2. **所属模块 → 领域**（如 `群组group` / `GVG` / `Main Events` 各有术语）
3. **元素类型 → 语气**（见下表）

| 元素类型 | 语气要求 | 例 |
|---|---|---|
| 主按钮 | 祈使式，尽量短 | Log In → تسجيل الدخول |
| 次级按钮 | 动名词/名词短语 | Send Code → إرسال الرمز |
| 输入框标签/占位符 | 名词短语，占位符可稍长 | Phone Number → رقم الهاتف |
| 标题 | 名词短语，可带定冠词 | Welcome Back → مرحباً بعودتك |
| 错误/警告提示 | 完整句，直陈，不加感叹堆砌 | You must be 13 or older... |
| 条款正文 | 正式书面语，完整句 | Terms of Service → شروط الخدمة |
| Toast/结果反馈 | 短句，口语但不方言 | Profile Shared → تم مشاركة الملف |

### 5.2 术语表加载（优先级从高到低）
1. 项目内 `术语表.md`（若存在，直接用，不得自创）
2. 技能 `references/术语表.md`（**默认内置：团队定稿合并版 335 条**，权威源为 `术语表_Jam3a团队定稿.md`——项目组+PM 2026-08-29 拍板；合并技能原内置 140 条作缺口补充，同词冲突以团队表胜；由 `build_terms.py` 从团队原表重生成）
3. 都没有 → 翻译前先向用户要，或标注「待确认术语」并给候选，**不自行定名**
- **术语权威单一来源（2026-09-02 PM 定）**：所有术语以技能内 `references/` 资产为准，**不再从项目其他文件夹读取术语表/规范**。
- **不可译与合规禁用**：`references/keep_latin.json` 含 `keep_latin`（Jam3a/GvG/XP/ELO/VIP/Ludo/Jackaroo/Carrom/Uno/WOLF/PDPL/GDPR/COPPA/PCI DSS/AR/X 等保留拉丁、RTL 中 `<bdi>` 隔离）与 `banned_ar`（`قمار/مراهنة/رهان/مقامرة`，面向用户文案禁用）、`banned_en`（Stake/Staking/Age Restriction/Daily-Weekly Staking Cap）。翻译时这些词**不得翻译/不得出现**，命中即照 `keep_latin` 处理或拦截。
- 命中术语表必须照抄，含术语的短语也按术语表译该项。

### 5.3 阿语专项规则
- 用**现代标准阿拉伯语（MSA）**，不用埃及/海湾方言。
- UI 短文案优先**简洁**，阿语常比英文长 30–50%，能短则短。
- **禁逐字直译**；动宾搭配按阿语习惯重组。
- **数字体系按项目定**（西阿拉伯 `1234` 或 阿语-印度 `٠١٢٣`），全项目统一；未定则**默认西阿拉伯数字**并标注待确认。
- 纯数字/符号串在 RTL 中需 `direction:ltr; unicode-bidi:isolate`（生成脚本已自动 `<bdi>` 包）。
- **长度是硬约束**：翻译完必须评估是否撑破容器，超长必须主动标注，不静默交付。

### 5.4 风险标注（每条都判）
| 风险 | 判定 |
|---|---|
| **超长** | 阿语明显长于英文且宽度受限（按钮/标签）→ 标注并给**短版候选** |
| **歧义** | 一词多义（如 Rank=段位/排名）→ 标注，按语境给推荐并说明依据 |
| **不可译** | 品牌名、游戏名、国家区号、时间 → 保留原文，仅音译时标注 |
| **待确认** | 术语表未覆盖且影响一致性 → 列出，不自行定名 |

### 5.5 翻译优先级（gen 内 `translate()`）
1. **保留类**：数字/符号/时间（`^\d{1,2}:\d{2}$`）/拉丁专名/专有名词缩写（XP/EXP/GVG/PVP/LV/VIP/Ludo 等，`PROPER_RE`）→ 原样保留。
2. **术语表**（`--terms`，PM 提供，最高优先）：Markdown 三栏 `| 中文 | 英文 | 阿拉伯语 |` 解析（EN 键小写化、`/` 切多值；CN 键直用）；或 JSON `{ "English": "Arabic" }`/`{ "中文": "阿语" }`。默认内置 `references/术语表.md`（335 条）。
3. **Agent 语境翻译**（`--extra` JSON）：Agent 从页面场景 + 英文语义翻译的完整映射，遵循 5.1–5.4。这是非术语表文案的主要来源。
4. 未命中 → 原样保留（英文），列入「未命中清单」作为 Agent TODO 提示。

### 5.6 键归一化（normKey，2026-09-02 实装）
查找前自动去除零宽字符（U+200B-U+200F/FEFF/2060-2064）、各类连字符（U+2010-U+2015 → `-`）、不换行空格（U+00A0 → space）、合并多余空白。避免原型工具注入的隐形格式符导致精确匹配失败（实测：`Matches\u200bdo\u200bnot` 匹配不到 `Matches do not`）。

## 6. RTL 镜像（嵌套递归）

- **嵌套镜像**：渲染时父节点 `position:absolute` 成为子级 containing block；子节点相对父级定位 `rx = n.x - p.x`，再在父容器内水平翻转 `mx = containerW - rx - n.w`（递归传递至根）。等价于全局镜像，且能正确处理父背景/裁剪。
- **对齐逻辑化**：`left → right`、`right → left`、`start → end`；其余原样。容器 `direction:rtl` 下 `start` 即视觉右侧。
- **方向符号翻面**：`‹↔›`/`<↔>`/`←↔→`/`❮↔❯`（仅 ≤2 字且命中时）。
- **组合级镜像（G1，已固化）**：纯几何组合（子树下无文本、无位图、**无 SVG**、且有 z-index 已建层叠上下文）整体 `transform:scaleX(-1)` 一次镜像；三重护栏（① 无文本/位图/SVG ⇒ 不镜像阿语文字/照片/方向性图标；② 有 z-index ⇒ 不改变层叠语义；③ 仅取顶层候选避免嵌套双重翻转）。含 SVG 的组合退回逐节点镜像（结果等价且安全）。实测教训：SVG 图标大量有方向性（箭头/闪电/骰子点阵/Tab 图标），scaleX(-1) 整体翻后方向反转或裁切区偏移导致空白框——必须排除。。

## 7. 字体 / bidi / 防裁切

- 阿语文本：`'Noto Sans Arabic','Segoe UI',Tahoma,sans-serif`（禁用 PingFang，无阿语字形）。
- LTR 内容（区号/时间/邮箱/拉丁专名）：`'Noto Sans SC','Noto Sans',sans-serif` + `direction:ltr;unicode-bidi:isolate`。
- 阿语行盒高于英文源盒 ⇒ 文本节点加 `min-height:max(h, fs*1.4); height:auto` 防裁切；行高收敛 `min(lh, h)`（单行时）。
- 拉丁专名在译文中用 `<bdi>` 隔离；生成脚本只还原译文里手写 `<bdi>`，其余标签转义。

## 8. 长文处理（G2 检测 + G3 适配，已固化）

阿语单词通常比英文短，但短语/长描述可能更长。处理优先级（逐级降级）：
1. **精简译法**（首选，零布局成本）：更短阿语表达。
2. **换行展示**：容器宽度允许时自然折行（`white-space:pre-wrap`）。
3. **高度适配**（G3 已固化）：文本元素 `height:auto` + `min-height` 防裁切；**完整「父级逐层撑高」已实现**——预翻译全部文本 → 估算译文宽超原宽则按行高估算换行行数 → 该文本节点 `min-height` 增至 `行数×行高`、并对全部祖先强制 `overflow:visible`（避免被父级 `overflow:hidden` 裁掉）；舞台 `maxY` 改用增长后高度，长文换行后舞台跟随增长。

- **G2 超宽检测（已实现）**：用 **G5 校准后的按字符类字宽估算** `estTextWidth(译文, fs)`（阿语 0.52em / 拉丁数字 0.50em / 空格 0.28em，替代旧单一 0.55）；超出原宽 105% → 输出**告警清单**，供 PM/人工精简译文或换行。G3 的换行增长触发仍沿用已验证的保守常量（防裁切，不随 G5 变动）。

## 9. 母版检测（G4，已实现）

- 设计侧统一用「**组合**」而非「**母版/Master**」：母版导入墨刀后只能整体替换、难拆到元素级；组合可元素级编辑。
- **提取侧应对**：遇「元素抱团 / 无法拆到元素级 / 坐标异常集中 / 节点数异常少（<20）」→ 疑似母版，**回报 PM 而非硬解**。

## 10. 高度与平铺布局（最终交付）

- **高度不设限**：每页取 `max(812, 所有元素 top+height)`。超过 812 的页面整页完整显示，不裁切。
- 平铺版：CSS Grid `grid-template-columns:repeat(auto-fill,375px); gap:28px; justify-content:center`（**列数随屏宽自适应，无上限**）。
- 每卡：中文标题（墨刀原名）+ 375 宽白底圆角舞台；**无 `<script>`、无交互**。

## 11. 已知坑（踩过）

1. **V1 引导页元素重叠**：旧提取混用缩略图+主画布节点且误抽中文板。根因=数据源，非生成逻辑。修复=精确抽英文画板。
2. **误抽中文板**：候选画板按 CJK 计数挑英文（CJK 最少），务必校验相对最少。
3. **SVG path 取不到矢量**：icon 渲染为半透明占位块。现整抓 `svg.outerHTML` 真渲染。
4. **字体残留 PingFang**：源 `st.ff` 可能带 PingFang，生成时**强制覆盖**为 Noto。
5. **3 列上限**：平铺版切勿加 `max-width` 限制列数。
6. **页面外参考元素**：只取 `.group-list` 内整块画板，天然排除。
7. **翻译键隐藏 Unicode**：见 §5，匹配前归一化。
8. **英文板也含漏翻中文**：即便挑到英文画板，里面仍可能残留未翻译中文（设计师漏翻，非提取错）。判据是 CJK 相对最少，不是 CJK=0；漏翻中文经 `--extra`/术语表直翻阿语。
9. **蓝色交互指示** `#298DF8` + `InteractionMarker`：墨刀交互覆盖层，由 §4 前置整删处理（整删 + 误伤降级）。
10. **缩放退化**：headless 视口过小 → 墨刀 fit-to-window 把画板压到 scale≈9 → 坐标子像素退化 → 页面全白。§3 健康门拦截。
11. **outline 噪声**：墨刀 outline 默认 `3px none` 恒为 no-op，生成时**必须** `os && os!=='none'` 才输出，否则注入数百条无效 `outline:3px none`。
12. **术语表元备注泄漏（2026-09-02 群组模块实测）**：术语表 16 个词条（Ludo/Jackaroo/Carrom/Uno/XP/ELO/GvG/合规缩写等）的"阿语"栏填的是**给人看的中文备注**（"✅PM已定：不做音译…"、"品牌名，不音译"），不是阿语译文。直接消费会把中文备注渲染进 UI（群组模块 46 处）。修复：术语命中后判 **译文含 CJK 即元备注**（阿语译文绝不含 CJK）→ 跳过该词条、按"保留原文不译"处理（备注语义本就是不译），已合入 gen_ar_flat.mjs translate()。
13. **G1 组合顶层位置不镜像导致压字（2026-09-02 群组模块实测）**：G1 组合旧逻辑只对内部 `scaleX(-1)`、顶层位置保持原 x——而兄弟文字坐标已镜像到对面，两者相向错位 → 开关压字等 208 处重叠。修复：G1 顶层也做位置镜像 `mx = containerW - rx - w`，仅 G1 后代保持原相对位，已合入 gen_ar_flat.mjs render()。等价性可用「原版 en_nodes 坐标 vs 渲染层 bbox 对比」全量验证（同层兄弟镜像间距守恒，不应产生新重叠）。
14. **PROPER 前缀误保留真句子（2026-09-02 群组模块实测）**：`PROPER_RE` 以 `^(Ludo|GVG|…)\b` 开头即判保留，"GVG Match Started" 等真句子被整句留英文。修复：保留类分支先查 `--extra`，命中译文优先输出，已合入 gen_ar_flat.mjs translate()。
15. **组件定宽导致阿语折行（2026-09-02 群组模块实测，G8 拉宽后处理）**：阿语比英文长 20-40%，墨刀组件按英文短文案定宽 → 译文折行。实测 219 页 450 处真实 2 行换行中 **85% 周围有空间，拉宽组件即可**（PM 确认不必精简译文）。解法 = `scripts/stretch_ar_flat.mjs` 后处理，三个关键判据（均踩过坑）：
    - **组件级扩宽**而非文字节点级——文字外常包紧贴的透明 wrapper（与文字同宽），以其为边界会大面积误判"没空间"；要看文字+紧贴胶囊（最近带背景祖先且宽 ≤ needW+30）在**屏幕坐标系**里的可用空间，更外层大面板（列表底板/弹窗背景）不跟随扩。
    - **碰撞只认「新压到」**——扩后与新 bbox 相交且与原 bbox **不相交**的叶子才是障碍；文字原本就叠着的背景层不算。此判据修正前误判率 98%+（6/450），修正后贴合实际（428/450 可扩）。
    - **行数判定用 Range 行矩形数**——盒高/行高比会被 `min-height` 防裁切属性撑高的盒子欺骗（假性 2 行）；真实行数以 `range.getClientRects()` 为准。另：垂直收回行盒时 top 补 `(原高-行高)/2` 保持视觉居中。
    缩字号兜底（-1/-2px，fs≥12）+ 描述句放不下一行自动保持多行（PM 认可设置项描述换行），无需人工分类。

## 12. 暗色模式配色重映射（G7，2026-09-02 实装）

> 布局来自原型镜像，**暗色模式只改色值、不改布局**（PM 2026-09-02 定）。规则来源优先级：
> 1. **PM 2026-09-02 暗色规范截图**（按钮/输入框/选项/图标组件色，最高优先）；
> 2. `D:/zdh/项目/26.7/JAM3a/墨刀测试/Jam3a_页面风格规范.md` §3 暗色模式 Dark + §13.1 `:root` Token（通用映射兜底）。

### 12.1 入口与配色源

- 开关 `--theme light|dark`（**默认 `dark`**，阿语版暗色优先，PM 2026-09-02 定）；自定义配色 `--palette <json>`（默认技能内置 `references/dark-palette.json`）。
- 配色表结构：`page.screen`（屏内底层背景）、`bg`/`clr`/`bc` 三套「亮色→暗色」映射表、`keep.colors`（保持原色的品牌/语义色）。
- 代码内把 hex 与 `rgb()` 双向归一化为 `r,g,b` 再做匹配，故原型提取到的 `rgb(...)` 色值可直接命中，无需先转 hex。
- 配色载入失败 → 自动退回原主题并告警（`检查 --palette 路径`），不影响其余页面输出。

### 12.2 分属性上下文映射（核心）

同一亮色在不同 CSS 属性下映射**不同**暗色，必须分表：

| 亮色 | 作背景 bg | 作文字 clr | 作边框 bc |
|---|---|---|---|
| `#FFFFFF` | `#333333`（卡片面） | `#F2F2F2`（反白字） | — |
| `#333333` | `#0A0A0A`（沉浸深面） | `#D0D0D0` | — |
| `#444444` | — | `#D0D0D0` | — |
| `#666666` | `#444444`(bg) | `#8A8A8A`(clr) | `#AAAAAA`(bc) |
| `#BBBBBB` | — | — | `#505050` |

渲染时按属性各自查表：`background`→`bg` 表、`color`(含 SVG `fill:currentColor`)→`clr` 表、`border-color`→`bc` 表。这避免了「白底变深 → 白字也变深 → 看不见」的歧义。

> **组件级优先**：若节点被识别为按钮/输入框等语义角色，优先查 `components` 组件表（见 §12.7），未命中再回落到本分属性表。

### 12.3 不映射 / 保持原色的情形

- **半透明色**（`rgba` 带 alpha）：保持原样。多为叠加/蒙层，改色会破坏叠加效果。
- **渐变 / 图片 / 无法解析色**：`colorKey` 返回 null → 不映射。
- **品牌 / 语义色**（`keep.colors`：如 `#E64040`/`#FF5252`/`#FFB300`/`#4CAF50`/`#2196F3`/`#03DAC6`/`#F46160`/`#1684FC`/`#6190E8` 等）：色相明确、暗色下同样成立，保持原色且不进未匹配告警。
- **G7-补：未知字面量亮度启发式兜底（2026-09-02 实装）**：原行为"未命中→保持原色"导致亮色矩形框在暗底上刺眼、暗色图标不可见。现改为按 Rec.601 相对亮度自动映射：
  - `lum > 180`（近白/浅色）：背景→`#1e1e1e` 暗面、文字→`#e8eaed` 浅字、边框→`#3a3a3a` 暗边。
  - `lum < 50`（近黑）：文字→`#c8c8c8` 可见、边框→`#4a4a4a`、背景→`#252525`。
  - `lum ∈ [50,180]`（中间灰）：保持原色（已接近暗色系可接受范围）。
  - 仍记录进「暗色未匹配色值」清单供 PM 复核，但不再出现亮色孤岛。
- **G7-补：图标可见性滤镜（2026-09-02 实装）**：暗色模式下 SVG 图标（`.ic` 内 `<svg>`）和 img 图片自动施加 `filter:brightness(0) invert(0.85)` 强制亮化为近白轮廓。解决墨刀 SVG 图标 `fill="#222"` 等暗色原值在 `#121212` 暗底上不可见的问题。品牌彩色图标如需保留原色可后续扩展 keep 列表排除。

### 12.4 弹窗页豁免（PM 2026-09-02 规则）

- 页面命名含「**弹窗**」或「**Popup**」的页面**不做暗色**，保留原（亮色）主题。
- 判定：`/弹窗|popup/i` 匹配页面名（`isPopupPage`）；命中时该页 `pal=null` → 所有色值保持原样。
- 平铺产物中此类页标题后追加 `<span class="tag-dark">原主题</span>` 黄色标签，便于评审一眼识别「此页按规则保留亮色」。
- 运行日志单列「弹窗页保留原主题 N 屏」清单。

### 12.5 画布中性规则

- 预览画布（`body` / `.stage` 外壳）**恒定中性灰**，不随主题变。否则暗色下与手机框黑边近乎同色、边界糊掉。
- 仅屏内 `.stage`/`.screen` 承载主题色（`screenBg`：暗色非弹窗页取 `#121212`，弹窗页取 `#fff`）。

### 12.6 维护指引

- 新增模块出现的未命中色值 → 跑一次 `--theme dark`，从日志「暗色未匹配色值」复制 `r,g,b` → 在 `dark-palette.json` 按属性补到 `bg`/`clr`/`bc`；品牌/语义色补到 `keep`。
- 新增模块出现的未命中色值 → 跑一次 `--theme dark`，从日志「暗色未匹配色值」复制 `r,g,b` → 在 `dark-palette.json` 按属性补到 `bg`/`clr`/`bc`；若属于按钮/输入框等组件，优先补到 `components.<role>.{bg|clr|bc}`。
- 配色规范若随 `Jam3a_页面风格规范.md` 或 PM 截图更新，需同步回刷 `dark-palette.json`（截图定义优先于 §3 + §13.1）。
- 回填实例（2026-09-02，Ludo 首跑）：未匹配 `#1A1A1A`/`#9F9F9F`/`#555555`/`#7A7A7A`/`#444444`/`#EEEEEE`/`#FFFFFF` 按 `bg`/`clr`/`bc` 分角色补暗色值；品牌黄 `#E8CA2C` 补入 `keep` 保留原色。回填后该原型暗色未匹配 = 0。

### 12.7 组件级语义色覆盖（2026-09-02）

PM 提供的暗色规范截图对按钮、输入框等组件给出了明确的独立色值，部分值与通用 `bg`/`clr`/`bc` 表冲突（例如主按钮亮色原型常用深色底白字，若走通用 `bg` 表 `#1A1A1A` → `#0A0A0A`，按钮会变成黑色；而截图要求主按钮暗色下填充 `#F0F0F0`、文字 `#0A0A0A`）。因此引入组件级语义表 `components`：

| 组件角色 | 背景 bg | 文字 clr | 边框 bc | 截图定义 |
|---|---|---|---|---|
| `button-primary` | 深色/浅色底 → `#F0F0F0` | 白/深色字 → `#0A0A0A` | 无 | 主要常规按钮 |
| `button-primary-disabled` | 浅灰底 → `#333333` | 灰色字 → `#F2F2F2` | `#505050` | 主要禁用按钮 |
| `button-danger` | 红色系保持红 | 白字 → `#FFFFFF` | 无 | 危险按钮 |
| `button-disabled` | 浅灰底 → `#444444` | 灰色字 → `#5C5C5C` | 无 | 禁用按钮 |
| `input` | 白/浅底 → `#444444` | 深色字 → `#D0D0D0` | 浅边框 → `#505050` | 输入框 |
| `option-text` | — | 深色字 → `#D0D0D0` | — | 单选/复选项文字 |
| `icon` | — | — | — | 图标统一走 `filter:brightness(0) invert(0.85)`，目标近 `#EEEEEE` |

- **识别规则**（`gen_ar_flat.mjs detectRole`）：按节点几何（宽/高/圆角）、`wRect`/`wLr` 类名、后代是否仅含文本、背景/边框颜色等综合启发式判定。
- **优先级**：`components` 组件表 > 通用 `bg`/`clr`/`bc` 表 > `keep` 品牌/语义色 > 亮度启发式兜底。
- 若识别误伤（如卡片被误判为按钮），从运行日志中确认组件角色后，可通过调色板组件表调整或反馈优化识别规则。
