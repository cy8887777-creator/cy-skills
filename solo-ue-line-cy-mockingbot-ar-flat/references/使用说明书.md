# 技能使用说明书 · solo-ue-line-cy-mockingbot-ar-flat（墨刀 → 阿拉伯语平铺版）

> **给谁看**：① 人类同事——按本文分步操作即可产出阿语平铺版；② AI 执行者——本文是本技能的可执行操作手册，加载技能后按本文命令、参数与规则执行。
> 配套文档：`SKILL.md`（技能定义/七阶段）、`references/spec.md`（技术规范与坑）、`references/术语表.md`（术语表）。

---

## 0. 一句话说明

把**墨刀导出的原型 HTML** 翻成**阿拉伯语 RTL** 版本，最终交付一份**矩阵式平铺静态 HTML**（无交互、评审可读、列数随屏宽自适应、单文件自包含）。

- 不是截图 OCR（拿不到坐标/层级，无法重排 RTL），而是 **Chrome CDP 提取 DOM 节点 → 真实重排为 RTL**。
- 适合：中东/GCC 游戏、社交、棋牌等项目的阿语本地化、阿语评审版、阿语静态展示版。

## 1. 前置准备（一次性）

1. **拿到导出文件**：墨刀里「导出 HTML」得到 `.zip` → 解压出 `index.html`（+ `extra/data.1.js`）。
   - ⚠️ 若是 `.mdrp` 私有格式：**无法离线解析**，必须让用户在墨刀里先「导出 HTML」再走本流程。
2. **启动 Chrome（独立隔离，禁止 `taskkill`）**：
   ```bash
   "/c/Program Files/Google/Chrome/Application/chrome.exe" \
     --headless=new --disable-gpu --no-sandbox --allow-file-access-from-files \
     --remote-debugging-port=9223 \
     --user-data-dir="C:/Users/1/AppData/Local/Temp/jam3a-chrome2" \
     "file:///解压目录/index.html"
   ```
   - ⚠️ **绝不用 `taskkill /F /IM chrome.exe`**——会杀掉用户所有 Chrome 窗口。用独立 `--user-data-dir` 隔离；后台常驻用 `sleep` 保活。
3. **确认端口可达**：浏览器打开 `http://127.0.0.1:9223/json/list` 能返回页面列表。
4. **准备术语对照表**（PM 提供，中英阿三栏 Markdown 或 JSON）：表内词条优先级最高、跨页跨模块复用。

## 2. 标准操作流程（两段式）

> 提取与生成是两步独立脚本：提取可一次跑多页缓存 JSON；生成可反复跑（换术语表/补译不重提）。

### 阶段 A · 提取英文画板（嵌套节点）

```bash
node scripts/extract_en.mjs \
  --file "file:///解压目录/index.html" \
  --screen <cid> \
  [--keywords "Quests|Check-in|..."] \
  [--out en_nodes.json]
# 或按页面树分批：
node scripts/extract_en.mjs [--pages all|1,2,3|引导页Onboarding,手机号登录Phone Login] [--out en_nodes.json]
```

- **精确定位（推荐）**：`--screen <cid>` 配合 `--file` 用 URL 参数 `?view_mode=device&screen=<cid>` 直达，避开不可靠的侧边栏点击；可选 `--keywords` 用正则锁定画板。
- **画板选取**：候选里 **CJK 字符数最少者**即英文板（未必为 0，漏翻中文残留按漏翻中文直翻阿语处理）。
- **缩放健康门**：画板屏幕宽 < 80 拒绝提取（会子像素退化导致空白）。
- 产出：`en_nodes.json`（嵌套结构，含 `meta.pkgBase` 用于图片路径补全）。

### 阶段 B · 生成阿语平铺版

```bash
node scripts/gen_ar_flat.mjs \
  --src en_nodes.json \
  [--terms 术语表.md] \
  [--extra 补充.json] \
  [--out ar_flat.html] \
  [--title "标题"] \
  [--theme dark|light] \
  [--palette 配色.json]
```

- 默认已内置 Jam3a 通用术语表（`references/术语表.md`，335 条）与暗色配色（`references/dark-palette.json`），多数情况直接跑即可。
- 产出：`ar_flat.html`（矩阵式平铺版，无 `<script>`、无交互）。

## 3. 翻译怎么准备（关键）

翻译分两层，**术语表是权威、extra 是兜底**：

1. **术语表（最高优先）**：行业术语、已定统一用词。格式支持：
   - Markdown 三栏：`| 中文 | 英文 | 阿拉伯语 |`
   - JSON：`{ "English": "Arabic" }` 或 `{ "中文": "阿语" }`
2. **`--extra` JSON（术语表没覆盖的文案）**：由翻译者（人或 AI）从页面场景 + 英文语义**语境翻译**成阿语后填入：
   ```json
   {
     "Log In": "تسجيل الدخول",
     "Send Code": "إرسال الرمز",
     "Play for fun": "العب للمرح"
   }
   ```
   - 键可用英文原文，也可用页面里出现的原文（含漏翻中文）。
   - **语气按元素类型定**：主按钮=祈使短句、标签=名词短语、报错=完整句、Toast=口语短句（详见 `spec.md` §5.1）。
3. **保留不译（自动）**：数字、时间、区号、拉丁专名、专有名词缩写（XP/GVG/PVP/LV/VIP/Ludo 等）原样保留。
4. **「未命中」= 还没翻，不是不可译**：运行报告里的未命中清单是待办提示，翻译者必须补译直到 **未命中 = 0**，不该把未命中数当最终质量指标。

## 4. 暗色模式与平铺方向

- **暗色模式默认开启**（`--theme dark`）；`--theme light` 可切回亮色。自定义配色用 `--palette <json>`。
- **平铺方向 = LTR（中文习惯）**：整个平铺版面从左往右排（网格/标题/目录 LTR），**仅每屏 `.screen` 内部内容做 RTL 镜像**。即「平铺不套阿语阅读习惯，屏内才镜像」。
- 弹窗类页面（命名含「弹窗」/「Popup」）自动豁免暗色、保留原主题。

## 5. 产出后你要复核什么（人工清单）

运行日志（控制台）会输出这些，逐项确认：

1. **翻译未命中是否 = 0**：>0 说明还有文案没翻 → 补进 `--extra` 后重跑阶段 B（无需重提）。
2. **超宽「频率高页面」清单**：按超宽条目数降序列出各页（如「对战 game battle（Ludo）10 条」排首）。阿语比英文长属正常，**只告警不自动处理**——优先精简这些页面的译文或换行。HTML 页眉也显示超宽总条数。
3. **暗色未匹配色值**：若有，说明出现新色值；可补进 `references/dark-palette.json`。属于按钮/输入框等组件的，优先补进 `components.<role>.{bg|clr|bc}`；通用色按 `bg`/`clr`/`bc` 分角色补；品牌色入 `keep`。Ludo 原型已回填，未匹配 = 0。
4. **视觉抽检**：图标在暗底是否可见（已自动 `brightness(0) invert(0.85)` 亮化）、有无亮色孤岛、阿拉伯文 RTL 方向是否正确、箭头/方向符号是否翻面。

## 6. 常见问题 / 坑

- **抽到的画板是中文板**：按 CJK 计数最少挑英文板，不要假定 CJK=0。
- **页面全白**：headless 视口过小导致缩放退化，健康门会拦截；新 Chrome 首次启动退化时自动重试。
- **别用 `taskkill` 关 Chrome**：独立 `--user-data-dir` 隔离后不与用户浏览器冲突。
- **交互热区/蓝闪已自动整删**：橙热区、蓝闪交互指示层在生成阶段第一步自动处理（整删或降级），无需人工。
- **禁用 PingFang**：阿语用 Noto Sans Arabic，PingFang 无阿语字形。
