> 模型在每个设计决策上都选“最可能讨好所有人”的选项——这就是均值，也就是平庸。
> 本技能的全部手段，都是为了把随机性、品味与判断从模型**外部**带进来。

## 铁律（先读，全程有效）

> **本技能由两个 AI agent 协作完成**：
> - **实现者**（中型模型）= 写代码的设计师 agent —— 调 Write/Edit/Bash 工具产出**代码资产**
> - **评审者**（大模型子代理）= 看截图的设计师 agent —— **只看截图**，不知道代码、阈值、历史
> 主会话是协调者（用户 → 协调者 → 实现者 + 评审者）。

### 角色总览（本节先读，决定"谁做什么"）

| 角色 | 谁 | 用什么工具 | 产出 |
|---|---|---|---|
| **协调者** | **主会话 Claude Code**（你自己） | 自然语言对话 / AskUserQuestion / Task 调度 | 5 项 brief、阶段切换、AskUserQuestion 选项、用户参与节点的判定 |
| **实现者**（写代码的设计师） | **主会话 Claude Code**（你自己） | **Write / Edit / Bash** | **代码资产**（HTML / JSX / Vue / 任何前端栈）—— 调当前环境可用的生图能力生成图片/视频（探查式：探查到生图技能/API 则用；无则外链图库/占位并告知） |
| **评审者**（看截图的设计师） | **`Agent` 工具派 `general-purpose` 子代理** | Agent 调用（独立上下文） | 评分 + gaps（JSON） |

**关键**：
- **主会话 = 协调者 + 实现者**（你自己，**不用派子代理当实现者**——直接 Write/Edit 写代码）
- **评审者 = 必须用 Agent 派子代理**（独立上下文，**禁止**主会话自评）；**派发一律后台模式（run_in_background）**——主会话保持可对话，用户插话不杀代理，评分靠完成通知回收
- 用户参与节点清单见 `references/start-guide.md`

### 6 条铁律

1. **激活协议优先**：用户激活后**先**走激活协议（见下文 §1.5），3 项设计 brief（1 必填输出目录 + 2 选填）未集齐前不进入发现阶段。**禁止**抢跑——用户说"随便/你定"也必须问清。
2. **种子必须外部生成**：随机性**禁止**由模型"想出"——用 `node scripts/seed.mjs` 或 `references/discover.md` §2.3 列出的 shell 命令。"请随机一点"不是随机来源。
3. **评审独立上下文**：评审者 = `general-purpose` Agent 子代理（任务书 [`templates/judge-prompt.md`](templates/judge-prompt.md)，调用规范 [`references/judge-prompt.md`](references/judge-prompt.md)）。**只传**截图 + 评审提示 + 美学简报，**不传**代码、停止阈值、评分历史、之前轮次。
4. **每步先读 references**：本文件只保骨架；细则在 references/，按阶段加载——阶段一 → discover.md，阶段二 → define.md + media.md，阶段三 → deliver.md + ai-tells-checklist.md。**禁止**跳读（防上下文衰减）。
5. **用户"停" = 冻结**：用户在任何节点说"停" → 立即按当前状态交付，不续期、不"再修一处"。冻结后**禁止**继续修复。
6. **PASS 含金量原则**：评审无把握时必须明确指出"未达"；不允许"差不多就行"。坏→OK 的成本（终局穿透）永远高于误报→未达（多看一眼）。

## 1. 适用范围

### 1.1 何时使用

- 从零设计或重设计任何视觉界面：落地页、应用页面、仪表盘、作品集、内部工具、报告页；
- 用户反馈“太普通 / 像模板 / 像 AI 做的 / 没有记忆点”；
- 需要在短时间内探索多个**差异显著**的视觉方向。

### 1.2 何时不用（或只用一部分）

| 情形 | 处理方式 |
| --- | --- |
| 严格遵循既有设计系统（用户已在 brief 提供）的增量改动 | 不做发现阶段；只执行交付阶段的减法与验收 |
| 用户明确要求“标准 / 保守 / 平台原生” | 跳过种子发散；保留评审回路与减法 |
| 纯后端、无界面任务 | 不适用 |

## 1.5 激活协议（一次性收集 3 项：1 必填 + 2 选填）

用户说"用 solo-ui-line-cy-amazing-vibe-design 设计 X" → 走激活协议。**1 必填 + 2 选填，全部到手才进阶段一**：

**AskUser #1（必填 1 项）**：

| # | 必填 | 缺则后果 |
|---|---|---|
| 1 | **设计产物输出目录**（路径） | 产物落哪不知道 |

**AskUser #2（选填 2 项）**：

| # | 选填 | 缺则后果 |
|---|---|---|
| 2 | 目标受众（谁会看 / 在什么场景） | 方向可能偏 |
| 3 | 设计系统（已有组件库 / 风格范本） | 字体/组件库重做（可答"无"） |

3 项到手后立即：
1. **建产物目录**：`mkdir -p <output_dir>/screens <output_dir>/media <output_dir>/code`（`<output_dir>` = 第 1 项）

3. **直接进入阶段一**（生成种子 + 方向探索）

**完整指南**（开场白措辞、AskUserQuestion header 标签、问题措辞）：见 [`references/start-guide.md`](references/start-guide.md)。
**环境自检**（跑前可选）：`python scripts/doctor.py`。

## 2. 核心理念：五条公理

1. **随机性来自外部。** 模型只能预测最可能的下一个词元，无法真正随机；“请随机一点”只会产生*听起来*随机的输出。真实的多样性必须由外部注入（脚本生成的种子字符串）。◆
2. **品味来自人。** 把 AI 生成的点子原样喂回 AI，得到的是人人都能得到的结果；只有主动注入个人品味（想象、避免、取而代之），才能做出只有你做得出的设计。◆
3. **制作与评判分离。** 实现代理审视的是自己的代码、决策与理由，无法客观；评审必须交给只看截图、处于全新上下文的独立代理。◆
4. **视觉要有真实素材。** 代理偏爱写代码，惯用渐变、形状与基础图案充当视觉——这是最明显的 AI 痕迹之一。图像、视频与着色器能体现“不止于表面”的投入。◆
5. **成品靠减法。** AI 爱加不爱减；删除对模型来说是“风险”。克制的设计立刻显得高级，而这一步需要人来推动。◆

> 任何一条公理失守，结果都会滑回均值。详见 [`references/principles.md`](references/principles.md)。

## 4. 操作步骤（代理执行版）

### 阶段一 · 发现

1. **激活协议（3 项 brief，已在 §1.5 完成）**：输出目录（必填）、目标受众（选填）、设计系统（选填）。**禁止**假设补齐——必须 3 项到手才能进下一步（与铁律 1 一致）。◇
2. **生成种子**：用脚本生成 ≥ 32 位随机字母数字串（`node scripts/seed.mjs` 或 shell 命令）。**禁止**由模型自行“想出”随机串。◆
3. **解读种子**：从字符串中寻找子模式、特殊数字与节奏，据此确定配色、版式、字体、母题与语气；把解读过程记入设计记录。◆
4. **并行发散**：重复 2–3 步得到 3–4 个方向；或使用野心简报（跨领域灵感源 + 影响方式）。◆
5. **注入品味**：请用户用“我想象… / 避免… / 取而代之… / 还缺…”四类批注锐化一个方向，再压缩为一段简洁的构建提示。◆
6. **产出简报**：按 [`templates/design-brief.md`](templates/design-brief.md) 填写，**落 `<output_dir>/brief.md`（人读）+ `<output_dir>/brief.json`（机器读入口）**。直接进入下一阶段——无"用户确认简报"步骤。◇

### 阶段二 · 定义

7. **实现首版 POC**：按简报实现，先保证结构与功能完整。
8. **启动评审回路**：截图 → 全新上下文的评审子代理（只给截图）→ 美学意图、顶级工作室如何执行、最大差距、10 分制评分 → 实现者修改。◆
9. **素材补强**：用图像生成替换渐变、色块与几何图形；在合适位置使用循环视频或关键帧过渡；在浏览器中逐帧验证。◆
10. **停止**：评审独立给出 ≥ 9/10 即停止；先跑 1–2 轮确认收敛；连续两轮提升 < 0.3 或达到轮次上限时停止并向用户报告。◆ / ◇

### 阶段三 · 交付

11. **减法**：逐元素追问“它的作用是什么”，删除、合并或降级；对照 [`references/ai-tells-checklist.md`](references/ai-tells-checklist.md) 清理。◆
12. **聚焦**：每屏只保留一个主角元素，让视觉自己说话。◆
13. **打磨与验收**：字体、间距、对齐、动效；加载 / 空 / 错误 / 成功四态；可访问性；三宽响应式。◇
14. **记录与交付**：更新 [`templates/design-record.md`](templates/design-record.md)，附三宽截图交付。◇

## 5. 规范摘要

### 5.1 必须

| 编号 | 规范 | 来源 |
| --- | --- | --- |
| M1 | 随机性必须来自模型之外（脚本 / 系统熵）；“要求随机”不构成随机来源 | ◆ |
| M2 | 确定方向前必须先广后深，至少探索 3 个差异显著的方向 | ◆ |
| M3 | 评审必须由全新上下文的独立代理执行，且只看截图，不看代码、实现细节与以往评审 | ◆ |
| M4 | 各轮必须使用同一份评审提示；停止阈值只告诉实现者，不写入评审提示 | ◆ |
| M5 | 必须设定停止准则（阈值 + 轮次上限），并先跑 1–2 轮观察是否收敛 | ◆ |
| M6 | 主视觉不得仅由渐变、色块、几何图形或基础图案充当 | ◆ |
| M7 | 交付前必须做减法：每个保留元素都能说明其作用 | ◆ |
| M8 | 种子仅用于灵感，不得出现在设计中 | ◆ |
| M9 | 素材生成密钥必须独立、限额、仅本地使用，不得进入代码或产物 | ◆ |
| M10 | 动效与生成素材必须在浏览器中逐帧验证 | ◆ |
| M11 | 风格不得以牺牲可用性为代价：对比度 ≥ 4.5:1、全键盘可达、焦点可见、四态齐全、尊重减少动效偏好 | ◇ |

### 5.2 应当

| 编号 | 规范 | 来源 |
| --- | --- | --- |
| S1 | 用具体、大胆、跨领域的灵感源（游戏、室内设计、艺术装置、印刷品、工业设计）描述方向，而非堆砌形容词 | ◆ |
| S2 | 向 AI 要点子时“广而浅”，再由人用品味筛选、锐化 | ◆ |
| S3 | 评审标准尽量客观：优先“排名式”（4 张专业作品 + 1 张我们的截图）；其次“先想象顶级工作室如何执行，再对标” | ◆ |
| S4 | 为评审提供基准图，并声明它是情绪板 / 基准而非临摹对象 | ◆ |
| S5 | 模型分工：大模型做评审（品味与决策），能胜任的中型模型做实现 | ◆ |
| S6 | 评审反馈要具体、尖锐、有主张，并惩罚过度使用或明显 AI 生成的模式 | ◆ |
| S7 | 图像可与着色器 / 3D 效果结合；视频用于循环素材或关键帧过渡 | ◆ |
| S8 | 优先使用平台原生组件；自造控件只有在明显优于原生时才保留 | ◆ |
| S9 | 保存失败的提示，新模型发布后重测 | ◆ |
| S10 | 记录种子、简报、评分历史与被否决方向，保证可追溯、可复现 | ◇ |
| S11 | 评审取 3 次独立评分的中位数，以降低单次评分方差 | ◇ |
| S12 | 截图固定视口（至少 390 与 1440），并在字体加载完成、动画停在约定帧后截取 | ◇ |

### 5.3 可以

| 编号 | 规范 | 来源 |
| --- | --- | --- |
| A1 | 可以尝试“听起来很糟”的点子——觉得“这绝对行不通”时，往往方向正确 | ◆ |
| A2 | 可以通过聚合平台（如 fal.ai）让代理自行评估并选择视频模型 | ◆ |
| A3 | 可以把循环视频抠像后叠加在界面任意位置；可以用关键帧插值制作随滚动擦洗的过渡 | ◆ |
| A4 | 可以串联多个模型（如一个负责结构，一个负责素材） | ◆ |
| A5 | 可以固化种子解读规则（见 [`direction-catalog.md`](references/direction-catalog.md)），也可以自由联想 | ◇ |
| A6 | 可以在交付阶段请评审做一次“减法专审” | ◇ |

### 5.4 避免与禁止

| 编号 | 规范 | 级别 | 来源 |
| --- | --- | --- | --- |
| N1 | 把“要求随机”当作随机来源 | 禁止 | ◆ |
| N2 | 让实现代理自评“是否够好” | 禁止 | ◆ |
| N3 | 把停止阈值写进评审提示 | 禁止 | ◆ |
| N4 | 在代码、仓库或产物中硬编码 API 密钥 | 禁止 | ◆ |
| N5 | 使用主观评审标准（如“判断是否好看、不像 AI”） | 避免 | ◆ |
| N6 | 把 AI 生成的点子不经筛选原样喂回 AI | 避免 | ◆ |
| N7 | 紫色渐变、左文右图英雄区、无目的光晕、随机彩色高亮、冗余标签 | 避免 | ◆ |
| N8 | 卡片套卡片、标题 emoji、满屏毛玻璃、纯装饰渐变 | 避免 | ◇ |
| N9 | 不做收敛检查就无限迭代消耗 token | 避免 | ◆ |
| N10 | 照抄参考作品 | 禁止 | ◆ |

| 门 | 判据 | 证据 |
