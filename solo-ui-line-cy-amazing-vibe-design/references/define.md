> 目标：把初始设计从“仍然依赖陈旧模式”推进到“拥有独立个性”，同时保持其原有的高层美学。

即便种子带来了不同的配色，初始设计往往仍依赖同样的陈旧模式：左侧文字、下方 CTA、顶部导航、右侧图形。下一步是通过鲜明的设计选择，为每个设计赋予独立的个性。◆

---

## 1. 为什么需要独立评审 ◆

迭代是必要的，但简单地让代理“看看设计并改进”行不通：代理并不客观——它审视的是自己的代码、过往决策与理由，很难退一步看全局、“think different”。

解决办法：不让实现代理决定设计何时“够好”，而是让它去问**另一个代理——设计评审**。评审只看当前设计的截图并给出反馈；它不关心实现方式和投入了多少努力，只关心是否达到质量标准。

---

## 2. 回路结构

```
┌──────────────┐   1. 截图（仅截图）   ┌───────────────────────┐
│   实现者      │ ───────────────────▶ │ 评审者（全新上下文）     │
│ 知道：代码、   │                      │ 只看到：截图 + 基准图    │
│ 历史、阈值 9   │ ◀─────────────────── │ + 固定评审提示           │
└──────────────┘   2. 差距清单 + 评分   └───────────────────────┘
        │
        └── 3. 修改 → 回到 1；评审独立给出 ≥ 9/10 时停止
```

### 2.1 信息隔离表

| 信息 | 实现者 | 评审者 |
| --- | --- | --- |
| 代码与实现细节 | ✓ | ✗ |
| 以往迭代与评审 | ✓ | ✗ |
| 停止阈值（9/10） | ✓ | ✗ |
| 当前截图 | ✓ | ✓ |
| 基准图 / 情绪板 | 可选 | ✓（推荐） |
| 评审提示 | — | ✓（每轮相同） |

## 3. 实现者指令要素 ◆

每轮迭代：

1. 截取当前设计；
2. 在**全新上下文**中调用评审，只提供截图——不提供代码、实现细节、早先的迭代或评审；
3. 请评审评估设计所追求的美学，想象顶级设计工作室会如何执行这种美学，然后列出最大的差距；
4. 最后给出 10 分制评分，表示当前设计距离工作室水准有多近。

完成条件：**评审独立给出 9/10 或以上**。不要把这个标准写进评审提示，保持其评分客观；每次使用同一份评审提示。

> 完整模板见 [`prompt-library.md`](prompt-library.md) P5（实现者）与 P6（评审者）。

---

## 4. 评审者提示要素 ◆

| 要素 | 写法 |
| --- | --- |
| 双层视角 | 既要从高层思考整体结构与构图，也要审视细节 |
| AI 痕迹 | 警惕显得过度、过量或明显 AI 生成的模式，并扣分 |
| 反馈形式 | 紧凑、具体的反馈，而非含糊的散文 |
| 态度 | 大胆、有主张，不依赖安全或省事的做法 |

原文效果：不再是千篇一律的模板布局，每个设计都有了自己的身份，同时仍保持原有的高层美学。

---

## 5. 评审标准的三个等级 ◆

| 等级 | 示例 | 为什么 |
| --- | --- | --- |
| 差 | “判断我们的设计是否美观、不像 AI 生成。” | 过于主观，每次运行结果差异巨大 |
| 可 | “回顾我们追求的美学，想象顶级设计工作室会如何执行，再以此为标准评判。” | 仍然模糊，但提供了一致的框架与质量标准 |
| 优 | “这里有 5 张设计：4 张专业作品，1 张我们产品的截图。按精致度与品味排名。” | 具体、客观，并提供了视觉基准 |

---

## 6. 基准图 ◆

- **应当**提供示例图来展示目标质量：可比的截图、你喜欢的设计，甚至 AI 生成的概念图；
- **必须**指示评审把它们当作**基准或情绪板，而非目标**——你不希望它照抄其他设计。

---

## 7. 停止准则

| 规则 | 说明 | 来源 |
| --- | --- | --- |
| 阈值 | 评审独立给出 ≥ 9/10 即完成；阈值只告诉实现者 | ◆ |
| 先试跑 | 先做一到两轮，观察是否收敛，再决定是否追加 | ◆ |
| 轮次上限 | 设置上限（建议 5 轮），防止为讨好评审而无助地烧 token | ◆ |
| 停滞检测 | 连续两轮提升 < 0.3 → 停止并上报，检查评审标准是否主观、是否缺基准图 | ◇ |
| 回退 | 分数下降时回退到历史最高分版本，而不是在下降版本上继续 | ◇ |

---

## 8. 模型分工与成本 ◆

- **评审**：考虑用更大的模型——参数越多，通常意味着更好的设计感与更宽的创意分布；
- **实现**：小模型可以胜任，但不能太小，仍需有能力把设计方向执行到位；
- **成本**：原文案例中评审输出 token 占比不到 10%；直接让大模型重做设计，成本约两倍且耗时更长。

---

## 9. 降低评审方差 ◇

| 做法 | 理由 |
| --- | --- |
| 每轮调用 3 个独立评审，取中位数 | 单次评分波动大；中位数抗离群值 |
| 固定截图视口（390 与 1440） | 不同视口会改变构图，导致分数不可比 |
| 等字体加载、动画停在约定帧后再截图 | 避免截到半成品状态 |
| 截图使用中性文件名（如 `shot-a.png`） | `v5-final-improved.png` 之类的文件名会向评审泄露上下文 |
| 记录每轮分数、离散度与最大差距 | 便于发现停滞与回归 |

## 10. 评审报告格式 ◇

建议评审以结构化格式返回，便于实现者逐条处理：

```
{
  "aesthetic": "暗调工业控制面板：触感、克制、单一信号橙",
  "studio_vision": "顶级工作室会让控制面板的物理质感成为唯一主角……",
  "gaps": [
    { "area": "结构", "issue": "仍是左文右图模板", "fix": "改为非对称网格，让面板图像跨两栏", "severity": "高" },
    { "area": "细节", "issue": "间距节奏混用 24/28/32", "fix": "统一到 8 的倍数", "severity": "中" }
  ],
  "score": 7.4
}
```

## 11. 阶段规范汇总

| 级别 | 条目 |
| --- | --- |
| 必须 | 评审在全新上下文中只看截图；评审提示每轮相同；阈值不写进评审提示；设定停止准则 |
| 应当 | 使用排名式或“想象顶级工作室”式标准；提供基准图；大模型评审 + 能胜任的实现模型；反馈具体有主张 |
| 可以 | 三评审取中位数；停滞检测；结构化评审报告；交付前追加一次“减法专审” |
| 避免 | 让实现者自评；主观标准；无上限迭代；评审偏离原有美学（应对标“该设计追求的美学”，而非评审自己的偏好） |

---

## 12. 常见失败与排查

| 症状 | 可能原因 | 对策 |
| --- | --- | --- |
| 评审永不满意 | 标准主观；缺基准图；阈值过高 | 改为排名式标准；提供基准图；先试跑两轮观察 |
| 分数忽高忽低 | 评审提示被改动；上下文泄露 | 固定提示；全新上下文；中性文件名；取中位数 |
| 设计越改越“像别人” | 基准图被当作目标 | 声明“基准而非目标”；更换多样的基准图 |
| 设计丢失原有气质 | 评审按自身偏好打分 | 要求评审先陈述“该设计追求的美学”，再对标 |
| token 消耗失控 | 无上限、无停滞检测 | 设置轮次上限与停滞规则 |
