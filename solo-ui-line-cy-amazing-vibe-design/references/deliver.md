> 目标：清理细节，删繁就简，聚焦关键元素，让独特的设计同时成为可上线的产品。

AI 能构建惊艳、醒目的视觉，但设计是否合理、是否流畅、是否服务于用户的实际目的，取决于你的判断。◆

---

## 1. 原则：克制即高级 ◆

AI 爱加，却很少减。AI 生成设计最明显的迹象之一，是它**过度解释一切**，或包含**不服务于任何实际目的**的元素。相反，一个懂得克制的设计会立刻显得高级、有品味。

> 打磨 AI 设计时，大部分精力应花在**删除**上。

---

## 2. 减法流程

| 步骤 | 做法 | 来源 |
| --- | --- | --- |
| 1. 元素清单 | 列出屏幕上的每个元素（含装饰、标签、容器、图标） | ◇ |
| 2. 作用追问 | 对每个元素问：“它完成什么任务？没有它，用户会失去什么？” | ◆ |
| 3. 处置 | 删除 / 合并 / 降级（更小、更淡、移入次级界面）/ 保留 | ◇ |
| 4. 复核 | 重新截图，交给评审做一次“减法专审” | ◇ |

处置判据 ◇：

| 判断 | 处置 |
| --- | --- |
| 与另一元素传达相同信息 | 删除其一（通常删文字，留图像） |
| 只有装饰作用且与主张无关 | 删除 |
| 有用但不是当前任务所需 | 降级或移入次级界面 |
| 多个小元素表达一件事 | 合并 |
| 自造控件不如原生 | 换回原生组件 |

## 3. 案例：卡路里追踪器 ◆

作者描述了应用功能，并明确要求“干净、极简”的设计。初版不算差，作为完全由 AI 生成的结果也令人印象深刻——但尽管要求了极简，很多东西并未增加价值：

| 问题 | 说明 |
| --- | --- |
| 粉色光晕 | 背景与进度条上的粉色发光效果 |
| 随机着色 | 文字上随机的颜色与高亮 |
| 冗余标签与空白 | 展示当天所有食物时多余的标签与空白——图片本身已经说明了一切 |
| 自造控件 | 自定义按钮与输入框，看起来不如 iOS 内置组件 |

作者要求 Claude 收敛：

1. 简化为**以图片为中心的网格**；
2. 去掉渐变、光晕与不必要的容器；
3. 追求真正极简、有 Apple 原生感的美学。

结果：设计有主张，让视觉自己说话；使用原生 iOS 组件；多余的颜色与渐变消失；文字**更小、更简单、更紧凑**。

> 今天的 AI 模型永远不会自己做出这些选择。记住：AI 不喜欢冒险，而精简设计、删除代码是有风险的。模型需要你推一把。审视你的设计，问自己：**什么真的需要在那里？** 很多时候，屏幕上放得更少，传达得反而更多——因为你能抓住用户的注意力，而不是用杂乱淹没他们。

## 4. 聚焦关键元素

| 规则 | 说明 | 来源 |
| --- | --- | --- |
| 一屏一主角 | 每屏只有一个视觉焦点（一张图、一个数字、一句标题） | ◇ |
| 让视觉说话 | 图像能表达的，不再用文字重复 | ◆ |
| 用尺寸与位置建立层级 | 而不是用颜色噪音 | ◇ |
| 主操作 ≤ 3 个 | 首屏只做一件事 | ◇ |

---

## 5. 细节打磨标准 ◇

| 领域 | 标准 |
| --- | --- |
| 字体 | 字号 ≤ 7 档；正文 ≥ 16px；中英文行高 ≥ 1.6；行宽中文 30–40 字、英文 60–75 字符 |
| 间距 | 只用 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 形状 | 圆角 ≤ 4 档；阴影 ≤ 3 级；不套娃（卡片套卡片） |
| 色彩 | 1 个主色 + 中性色 + 语义色；正文对比度 ≥ 4.5:1；颜色必须编码含义 |
| 图标 | 一套图标库，统一描边与尺寸；不在标题中使用 emoji |
| 动效 | 过渡 ≤ 320ms；只动 `transform` / `opacity`；跟随减少动效偏好 |
| 文案 | 短、具体；无营销空话（“释放潜能”）；不过度解释；不夸奖用户 |
| 令牌 | 先写设计令牌，再写样式；样式只引用令牌 |

## 6. 实用性验收 ◇

### 6.1 状态完整性

| 状态 | 要求 |
| --- | --- |
| 加载 | ≤ 100ms 直接切换；> 2 秒显示进度、已用时间与取消 |
| 空 | 说明原因 + 给出下一步操作 |
| 错误 | 说明发生了什么 + 如何恢复；保留已完成的工作 |
| 成功 | 明确确认；可撤销的操作提供撤销 |

### 6.2 表单

可见标签；两级校验（字段失焦 + 提交时汇总）；首个错误自动聚焦；保留已填内容；允许粘贴；不以禁用提交按钮代替校验；超过 7 项时分组或分步。

### 6.3 可访问性底线

全键盘可达；焦点可见（不得无替代地移除 outline）；目标尺寸 ≥ 24px（触屏 44px）；对比度 ≥ 4.5:1；320px 宽可回流；不用 `div` 冒充按钮；不做仅 hover 可用的功能；不用 `alert`；不禁止粘贴与缩放。

### 6.4 响应式

在 390 / 768 / 1440 三个宽度截图验证；页面级不得出现横向滚动；组件内横向滚动需可被键盘操作。

### 6.5 危险操作

远离首屏；二次确认；默认焦点落在“取消”；能撤销的优先提供撤销而非确认。

## 8. 阶段规范汇总

| 级别 | 条目 |
| --- | --- |
| 必须 | 做减法并能说明每个元素的作用；四态齐全；可访问性底线；三宽验证 |
| 应当 | 以图像为中心；优先原生组件；文字更小更简更紧；一屏一主角；减法专审 |
| 可以 | 把被删除的元素记入设计记录，以备回溯；对关键页面做 A/B 验证 |
| 避免 | 光晕、渐变、随机着色、冗余标签、卡片套卡片、标题 emoji、过度解释、夸奖用户的文案 |

## 9. 常见失败与排查

| 症状 | 可能原因 | 对策 |
| --- | --- | --- |
| 要求“极简”却仍然拥挤 | 模型不敢删 | 明确列出要删除的元素类别，并要求说明每个保留元素的作用 |
| 删完显得空 | 删掉了承载主张的元素 | 回到“一屏一主角”，放大主角而不是补装饰 |
| 原生组件显得平淡 | 缺少主张 | 主张应体现在构图、图像与字体上，而不是控件皮肤上 |
| 上线后出现空白页 / 白屏 | 只设计了快乐路径 | 补齐加载、空、错误状态，并演练恢复 |
