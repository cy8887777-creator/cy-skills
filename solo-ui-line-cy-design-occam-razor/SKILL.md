# 设计奥卡姆剃刀

如无必要，勿增实体；完美不是无可增添，而是无可删减。

本技能只做一件事：把已经做完的界面剃到只剩最有力的部分，并用无上下文的独立评审证明它站得住。

## 定位边界（不越界）

- 方向探索与风格比稿 → solo-ui-line-cy-gui-style-picker
- 去 AI 味专项精修 → solo-ui-line-X-unslop
- 界面问题体检（溢出/对比度/断图/字号）→ solo-ui-line-cy-ui-walkthrough
- 本技能 = 减法纪律 + 独立盲评。输入是"已做完的界面"，输出是"剃刀清单 + 盲评分 + 收敛判定"
- **宿主规则优先**：目标文件自带的项目铁律、注释约定、令牌规范（如"注入块绝不可删""颜色一律用令牌"）效力高于本技能剃刀纪律；剃刀永不推翻宿主禁删规则
- **体检归属**：纪律 4 的"顺带检查"只记录问题并在交付说明中列出，**修复移交 solo-ui-line-cy-ui-walkthrough**，本技能不顺手修
- **外部协议优先**：任务书附**协议页**时（如主线 flow-ux-ui-line-cy-hifi-design 阶段6 调起），位次与登记口径以协议页为准——管线内「终审」=主线收尾全量硬检，剃改记录与盲评结论登记进七段对账表；无协议页按本文件原生流程

## 输入裁定（动手前先划边界）

- 混合文件（产品 UI 与工具 chrome、编辑器面板、调试面板、插件注入块混在同一文件）先划清剃刀对象边界：**只剃产品用户可见的界面层**；工具 chrome 与注入块不在剃刀范围内，即使它们体量巨大
- **目录树输入**（多文件工程）先确认剃刀范围：用户指定了子树/页面清单就以指定为准，未指定且规模超过 20 个文件时必须先问清范围再动手
- **一致性源豁免**：设计令牌全集、主题变量表这类"当前 0 引用但属体系资产"的一致性源，与宿主铁律同等级——不因零引用而剃（它们是未来的 vocabulary，不是死代码）
- **导出格式惯例优先**：自包含单文件、内联资源、导出工具的固有结构等惯例，效力高于"减少冗余"的剃刀直觉
- 素材的真实规模、屏数、结构与任务描述不符时，以实测为准并如实修正工作口径
- 目标文件的宿主铁律逐条读出并记录为禁删清单，剃刀全程避让

## 剃刀纪律（改什么）

1. **先定主次策略，再判竞争失控**：主角数量由设计意图和品类决定——产品页可以一屏一主角；杂志/编辑风天然多主角并置；大促、满铺、巴洛克式繁杂风格元素密集但有密度节奏。剃刀判的不是"主角有几个"，而是**视线动线是否受控**：一眼扫过去有清晰的观看顺序、满铺版式里也存在留白呼吸，没有两个元素在无意图地抢同一层关注。"多而无序"剃，"多而有序"是风格，不动。**落地扫描动作（可脚本化）**：对操作栏做同宿主/同目标双按钮扫描——grep 全文件 `data-host`/`data-go` 属性，两个按钮挂同一宿主（如双入口进同一客服会话）或跳同一目标（data-go 相同），即为"无意图抢同一层"的确定性证据，剃泛化留具体、剃幽灵留主按钮。这类撞车多源于逐轮迭代各加各的按钮，单轮评审看不见，必须全局扫描才能抓到。
2. **逐项意图判断**：渐变、发光、卡片、不对称布局逐项审问——"它帮助用户理解、操作或感受核心意图吗？"意图不限于功能：**情绪、氛围、品牌调性的贡献也算意图**（大促页的热闹、游戏 UI 的华丽框体是有意图的）。不能因为常见就一刀切禁用（模板感来自缺乏意图和层级，不来自某个单独样式），也不能因为流行就保留。
3. **删减顺序**：无用的说明文字 → 重复标签与装饰容器 → 竞争注意力的效果 → 可合并的状态。对象名称、判断依据、当前状态、主动作必须保留。死代码三步验证后再剃：HTML 使用数 → JS 运行路径 → 模板/插入面板引用，三重零引用才判死。**列表页克隆卡规则**：列表页的重复卡片/状态变体，若其状态模式已由独立页面文档化承载（如"待补款/待完成"已有专属页面），列表只保留结构不同的代表卡，同结构重复卡剃掉——"待补款/待完成状态已有独立页面文档化，列表页重复摆就是机械重复"。
4. **原生优先（有语境豁免）**：工程产品里原生控件更合适时用原生控件。**原型/演示语境豁免**：模拟控件（span 复选框、自绘步进器）属原型组件语言，是视觉一致性的意图表达，不适用本条——除非用户明确要求工程化。顺带检查文字密度、对齐、图片一致性、焦点态、对比度与窄屏表现——**只记录，修复移交 solo-ui-line-cy-ui-walkthrough**。
5. **降级验证（按素材类型分派）**：可交互原型→在运行环境验证主操作与相关状态，有动效时验证过渡与代表性帧，并提供 prefers-reduced-motion 降级体验；素材未加载完时主任务仍应能走通。**纯静态稿**（无交互的导出件）→验证对象是结构与样式：DOM 结构断言 + 样式令牌核查 + 资源路径有效性，交互验证条款不适用。两者都无浏览器/截图环境时统一降级为代码级验证，并在交付说明中标注"未做运行时验证"。

## 盲评协议（怎么证明站得住）

1. **派发**：独立子代理后台模式，只给三样东西——截图、用户/任务一句话、审美方向一句话。不给代码、不给历史、不给之前的批评和分数。
2. **截图净化**：截图前关闭一切标注角标、调试面板、编辑器 chrome、默认开启的说明浮层——不让工具痕迹污染评审画面。
3. **评审提示词（原样发送）**：

   > 根据截图判断视觉质量。先概括它试图表达的审美，再设想优秀设计团队如何把这个方向落实。评估整体构图、信息层级、字体、色彩、间距、图像整合和细节一致性，以及主任务是否清楚。指出缺乏用途的装饰、机械重复的布局和削弱个性的选择。给出最多三个最有影响的问题，每项包含截图中的位置、具体表现、用户或视觉影响，以及可执行的调整建议。最后给出 0–10 分的整体完成度及简短理由。建议可以大胆，但需保持产品用途与给定方向。截图无法证明的交互、性能和无障碍行为标注为未验证。

4. **质量基线（可选但推荐）**：可附一张专业设计图或概念图给评审者当质量基线——**比较完成度，不复制风格**；有多张可比参考图时匿名排序，防顺序偏见。
5. **收敛判据（量化）**：每轮只修最伤的 1–3 个问题，改完重新截图再评；**top 问题全部消除、或分数较上轮上升 ≥2，即判收敛**；最多两轮。两轮后仍不收敛就报告剩余缺口，并标记「方向可能需要重选」交还用户或上游管线决策——**剃刀只报告，不自行推翻方向**。评分用于观察改进趋势，不当作客观质量测量，更不当作上线验收证据。
6. **打分锚点（防分数漂移）**：10 = 可直接上线且有惊艳感；7 = 完成度高、有明确可改进项；5 = 明显粗糙、层级混乱；3 = 存在结构性问题。中间分值为相邻锚点插值。派发时把锚点随提示词一并发给评审者。
7. **同一任务的两轮评审必须用同一评审模型**——换模型分数不可比。
8. **多屏项目抽样规则**：「屏」视同「页」。核心转化路径的屏（首页/下单/支付等主链路）全部独立打分；长尾屏抽样（每组同类屏抽 1-2 个代表）。每评屏独立打分，另附一份整站动线评价（页面间风格一致性与导航连贯性）；剃改按屏收敛，整站结论汇总报告。
9. **诚实边界**：没有独立评审条件时自检并注明"未独立评审"；无截图环境时代码级走查的评分注明"未渲染验证"；审美评分与功能验证分开报告。

## 流程

1. **接手与输入裁定**：确认素材真实规模与结构；混合文件先划剃刀边界（只剃产品层）；读出宿主铁律记为禁删清单。
2. **列候选**：按剃刀纪律 5 条审读，列出候选剃点，每条按格式记录：**位置 / 依据纪律条目 / 剃法 / 风险**。
3. **逐项裁决**：对每个候选用纪律 2 的意图判断做剃/留裁决，写明理由；否决的也留档（为什么留）。**早退档**：裁决后剃率为 0（全部候选被否决）时，直接交付「无可剃减项」结论与候选否决记录，跳过剃改与盲评——不为走流程而空转。**早退判定必须覆盖视觉重复维度**（克隆卡、重复数据行、重复状态戳、同形图标组），不能只查代码维度（死 CSS/未引用令牌/渐变）——代码纪律干净 ≠ 无视觉赘肉（实测教训：120 文件静态稿代码层面干净，视觉层仍有 9 组克隆订单卡与 6 组重复状态戳）。
4. **剃（改文件）**：只动裁定为"剃"的条目；每剃一批做结构守恒断言（关键节点计数、删除块零残留）。
5. **取证与盲评**：目标视口截图（先净化画面）→ 派盲评 → 收报告 → 只修 top 问题 → 复评（不超过两轮）；无截图环境则降级为代码级走查并在评分中注明"未渲染验证"。
6. **交付**：剃掉清单（删了什么、为什么）、否决清单（留了什么、为什么）、盲评各轮分数与剩余缺口、未验证项。
