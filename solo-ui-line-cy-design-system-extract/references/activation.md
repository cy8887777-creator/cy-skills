# 激活前置参数与表单组装（Activation）

> 核心原则：**只问"未决项"**。能自动判定的参数、契约已定的常量，一律不许变成问题抛给用户。
>
> 铁律 7：激活先锁前置参数——6 项未全部锁定 → 不动手。
> 铁律 10（对外话术纪律·全程）：表单标签与参数一一对应；选项只用材料语言；未决项 = 0 → 不出表单；**进度播报/异常上报/交付同样只说人话**，内部代号（A/B-1/站号/gate）禁上屏幕（对照表见本文 §7）。
> 铁律 6（异常必上报）：证据全 0 / 数量骤降等未预期结果 → 定性上报等拍板，禁把工具故障合法化成降级路线。

---

## 一、参数清单（6 项）

| # | 参数 | 获取方式 | 何时才问用户 |
|---|---|---|---|
| 1 | 输入类型 | **自动判定**（材料特征 + 优先级） | **永不问** |
| 2 | 输入位置 | 从用户消息中提取路径/URL/文本 | 提取不到才问 |
| 3 | 提取范围 | 默认"全部给定材料" | 多页/多材料且子集有歧义才问 |
| 4 | 输出目录 | 默认 `<cwd>/design system/out/`（产物根上统一加一层 `design system` 文件夹，便于多套设计系统并存） | 仅当目标目录非空（覆盖风险）才问 |
| 5 | 参与度 | 默认"全自动放手" | **不问**；确认语里播报一次停等点 |
| 6 | 产物形态 | **契约常量**（design-system.html + system-rules.md + system-rules.json 三构造） | **禁问**（不是参数） |

### 输入类型自动判定规则

按材料特征识别；多种输入并存时取**最高优先级**：

```
①图包 > ④蓝湖 > ②HTML > ③URL > ⑤Figma JSON > ⑥文本
```

| 特征 | 判定 |
|---|---|
| 目录内 ≥1 张 `.png/.jpg/.webp`（命名约定 `编号-页面名-状态.png`） | ①图包 |
| 蓝湖域名 URL | ④蓝湖 |
| `.html/.htm` 文件 | ②HTML |
| `http(s)://` 非蓝湖 | ③URL |
| JSON 且含 `variables`/`styles` 数组（Figma 工具导出格式） | ⑤Figma |
| 其余纯文字描述 | ⑥文本 |

判定结果只写进确认语和 `middle.json` 的 meta（例如"输入类型：HTML ×5 页"），**不作为问题选项出现在用户面前**。

### 提取范围的合法触发

多页材料且存在"有源码的页"与"只有截图/引用的材料"混杂时（如 5 页 HTML + 1 张退化页 PNG），范围是**真未决**，允许问——但必须按第二节组装规则：标签就叫"提取范围"，选项是用户看得见的事物 + 代价。

---

## 二、表单组装规则（AskUserQuestion 硬约束）

1. **一个 tab = 一个参数，tab 标题 = 参数名，tab 内只准问这个参数。** 严禁挂着"输入位置"的标签问"提取范围"——标签错挂即违规。
2. **tab 数 = 未决参数数（0-3 个）。** 已自动判定的项**不占 tab**；未决项 = 0 → **不出表单**，直接文字确认自动判定结果后开工。
3. **选项用材料语言**：每个选项 = 用户看得见的事物 + 选了会怎样（代价/收益）。内部代号（A 类、B-1、C-1、D、站号、gate、Schema、token、引擎路由）**一律禁止出现在用户界面**——它们是写给脚本和我的，不是写给你的产品的。
4. **每题必标推荐项 + 一句理由**（含代价），让用户一秒能做主。
5. **契约常量不得作选项**：产物形态（design-system.html + md + json 三构造）、15 章结构（定案版）等是已决事项，拿出来投票 = 提问违规。

### 反面实例（真实事故，引以为戒）

> tab"输入位置" → 问题"提取范围取哪些页面？" + 选项"②HTML 源码 → B-1（推荐）"
>
> 病灶一：标签与内容错挂（输入位置早已从用户消息拿到，空标签被挪作他用）。
> 病灶二：内部代号 B-1/A 类直接抛给用户——用户无法评估，问了等于没问。

### 正面实例（混合材料场景，只问真未决）

> **tab：提取范围**
> - **全部 5 页（推荐）**：5 个页面的 html+css 完整，一次提全；那张单独的截图先只做参考标注
> - **只做那 4 页有源码的**：跳过"××模式"页——它没有源码，硬提会多一层看图估读误差
> - **其他**

### 未决 = 0 时的正确动作（不出表单）

> 收到。以 `D:\...\Page 1` 下 5 页 HTML 为源，产物出到 `<当前目录>\design system\out\`：给人看的演示 HTML + 给 AI 读的规则 md + 机器版 json（三构造同源）。终稿落盘前会停一次给你过目。开工。

## 三、流程

```
用户消息
    ↓
① 自动判定：输入类型（特征 + 优先级）/ 输入位置（提取路径）/ 输出目录（默认）/ 参与度（默认）/ 形态（常量）
    ↓
② 生成未决清单：通常是 0-2 项（提取范围子集歧义 / 路径缺失 / 目录非空）
    ↓
③ 未决 = 0 → 文字确认后直接开工
   未决 > 0 → 按第二节组装规则出表单（一项一 tab）
    ↓
④ 6 项全部锁定 → 播报确认语 → 进入站①
```

---

## 四、校验（静默自动，失败才转为未决项补问）

- 路径不存在 / 提取不到路径 → 转为参数 2 的补问（这是唯一允许因校验失败发起的提问）
- HTML：后缀 `.html/.htm` + 可读
- URL：`http(s)://` 开头 + 域名非 localhost
- 蓝湖：仅当用户自己点名蓝湖且需登录态时确认一次
- Figma JSON：含 `variables`/`styles` 数组；格式不符 → 直接告知"这份 JSON 不是 Figma 工具导出格式，请先用工具导出"（终止，不强行路由）
- **禁止自行扫描/猜测目录**（镜像 flow-front-ui-line-cy-design-pack-pipeline 铁律 4）——路径只能来自用户消息或问答

## 五、参数归宿（**不立台账文件**）

> 本技能是一次跑完的短任务——**产物文件就是台账**（middle.json / normalized.json（过程区）+ 三构造交付物），不学长任务管线立 PLAN.md。抄机制先问一句：这个机制是为多长的任务设计的？

6 项参数两个去处，零新增文件：

**1. 给人看：确认语**（未决清零后播报一次，格式固定；**播报前先按 `onboarding.md` 输出导览**——回访用户可压缩为一句）：

> 收到。输入类型：[自动判定结果]，源在 `[路径]`，提取范围 [N 页全部/子集]，产物出到 `[输出目录]`：给人看的演示 HTML + 给 AI 读的规则 md + 机器版 json（三构造同源）。终稿落盘前会停一次给你过目。开工。

**2. 给机器看：`middle.json` 的 meta**（站② 产出时填，Schema 现成字段，不加新键）：

| 参数 | meta 字段 |
|---|---|
| 输入类型 | `meta.source_type`（如 `B_html`） |
| 输入位置 | `meta.source_id` |
| 提取范围 / 取舍原因 | `meta.supplementary_notes` |
| 输出目录 / 参与度 | 运行时信息，只活在确认语与会话里 |

## 六、拒绝激活的边界

**以下情况一律拒绝激活，走知识问答**：

- 用户消息里没出现任何 6 类材料（仅"什么是设计系统"）
- 用户在调试组件视觉细节（不是提取，是修改）
- 用户要直接生成 UI（solo-ui-line-cy-amazing-vibe-design 范围）
- 用户要单图转 HTML（flow-front-ui-line-cy-img-to-code 范围）

**以下情况走混合策略（自动，不问用户）**：

- 消息给 2 种以上材料 → 主流程按最高优先级判定走，其余进 `supplementary_notes`
- 含 Figma 链接但未跑工具 → 提示用户先跑 Figma 工具出 JSON（职责边界 = 收 + 出：消费 JSON，不调工具）

| 内部说法（只留在文件里） | 对用户说的话 |
|---|---|
| 站① 输入识别+路由 | 先看您给的是什么材料 |
| 站② B-1 提取 | 从源码里读这套设计的规矩 |
| B-2 / fetch_url | 先把网页抓下来存个快照，再从源码提 |
| ②+ / 扫 figma-node.raw.json | 这页源码太薄，我问您一声，改用导出数据补一份 |
| A 类图包管线 | 图片先盘点，挑几张代表页做成高保真，再从页面提规矩 |
| C-1 / C-2 | 直接用您从 Figma 工具导的数据 / 直接把这段文字规矩整理成体系 |
| 站③ 体系化 | 把零散的值归成有名字的规范值 |
| 站④ 定案+双标+派生+自检 | 演示页定稿后，出给 AI 读的规则和机器版数据，然后机器检查一遍 |
| gate 不过 / 熔断 / 降级 | 这一步结果不对，停下来等您拍板 / 需要改道，先问您 |
| middle.json / normalized.json | 中间证据表、整理好的规范表（一般不提，提了说"证据"） |

违规示例（真实事故）："站② 提取中……走 B-1+ 路由，DOM 证据薄降级扫 rawjson"——用户看得见的应该是：*正在从您那 5 页的源码里读设计规矩*。
