# 组件坑位契约（component-anatomy）

> **定位（2026-10-16 升级：提取驱动 → 契约驱动）**：本字典是**强制坑位**，不是"提到什么放什么"。
> 提取到的组件对号入座（标 **已提取**，带实测证据）；**没提取到的坑位由 AI 按已有设计语言补全**
> （标 **AI 补全**，写推断依据）。目的：前端 / AI 接手设计规范时不会发现缺组件——设计系统覆盖未来，不只是记录过去。
>
> **来源标注是铁律**：补全值冒充实测 = 造假（禁）；显式标注的补全 = 工程完备（必须）。计数分列报：实测 N + 补全 M = 全量 N+M。

## 坑位填充规则（站④ 执行）

每个坑位交付**四件套**：

```
规格 + 分级变体 + 使用说明 + 来源标注
```

1. **来源标注**：`已提取`（带实测证据：页名/频次）或 `AI 补全`（带推断依据："源材料无 Input；按本系统深底白字 + 白 24% 描边 + radius-12 推断"）。**推断依据优先引用 `design-quality-rules.md` 条目编号**（如"按 S1 双层阴影 + 本系统主色相推断"），不再拍脑袋
2. **分级变体**：主要 / 次要 / 危险 / 禁用——按钮的 primary/secondary/danger 范式推广到全部坑位（Tag 的强调/普通、Input 的默认/错误）
3. **使用说明（WHEN TO USE）写法红线**：
   - ✅ 通用设计语义："页面唯一主行动时使用""内容过多需收纳时""高风险操作需二次确认"
   - ❌ 业务强耦合："对战大厅的开始匹配按钮""结算页的支付按钮"——别的项目/前端 AI 看到对不上场景就会弃用规范，又开始瞎编
   - 提取时看得到业务场景，归纳时**必须上提一层去业务化**；业务名只允许出现在证据栏（"实测自 rank 选择页"）
4. **坑位覆盖规则**：缺项必须显式二选一——`AI 补全`（默认动作）或 `声明不适用`（如纯游戏 UI 无 Table，写明原因）。**不允许空白坑位**。

## 组件库 vs 素材库边界（防混装）

- **组件库** = 交互控件（能点、能输、有状态）
- **素材库** = 美术资源（插画/照片/图标/道具图——图就是图）
- 复合元素拆开标注：货币徽章 = Badge 组件（引用 Gems/Gold 素材图）；图标按钮 = Button 组件（引用图标素材）。素材归素材库逐枚清单，控件归组件库——互相链接，不混装。

## 倒金字塔叙述模板

每个组件文档按此结构写：

```
1. 概览（OVERVIEW）—— 一段话讲是什么、归哪族
2. 解剖（ANATOMY）—— 图标注 + 关键尺寸（高 / 内边距 / 圆角 / 字号）
3. 状态（STATES）—— 列每态实物；可点击可聚焦的必给实物
4. 使用说明（WHEN TO USE）—— 什么场景用哪个变体；通用设计语义，禁业务强耦合
5. 用法（USAGE）—— Do 列表 + Don't 列表
6. 无障碍（A11Y，可选）—— 键盘行为 + aria 属性
7. 代码（CODE，可选）—— HTML/JSX/Vue 等实现参考
```

## 自检锚点

- **坑位覆盖**：字典坑位逐个核对——已提取 / AI 补全 / 声明不适用，三态必居其一，禁空白坑位
- **来源标注**：每个组件必须带 `已提取`（含证据）或 `AI 补全`（含依据）标注；计数分列报（实测 N + 补全 M）
- **计数以项目实测为准**：33 类字典是坑位契约与归类字典，不是及格线——项目只有 9 类不是缺陷，严禁凑数
- 项目实测组件**已声明的变体/状态**在产物中未覆盖 → 警告
- 每个组件至少 1 个变体声明（缺失 → 警告）
- 每个组件至少 2 个状态声明（缺失 → 警告）
- Button / Modal / Tabs / Card / Table（移动项目加 NavBar）高优组件必须有**实物演示**（HTML 模板实例已含）
- 字典有、**源无证据**的组件必须在产物中显式声明「源无证据」清单 + 工程引入指引（静默省略 → 警告）
- 已声明状态须有**实物演示**或标注「源无证据 / 工程兜底」（只写表格不演示 → 警告）
- 尺寸标注统一**双口径：1x 主口径括注 @2x（如 `12px（@2x 24px）`）**，由 dual_scale.py 在站④统一折算（单口径或口径混写 → 警告）
- 来源页面中的区块类型（表 / 数据格 / 入口组 / 横幅 / 装饰矢量）未入组件清单且未标「AI 补全」→ 警告
