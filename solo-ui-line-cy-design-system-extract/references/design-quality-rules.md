# 设计质量规则库（design-quality-rules）

> **定位**：本库是"设计要求 / 设计禁令"两章**概念层**的规则来源——概念层不是从源稿提取出来的，是给下游消费的约束提示词。提取层（值→档→组件）不消费本库：输入是什么输出就是什么，质量不好只提示不改。
>
> **来源诚实声明**：条目消化转述自《Refactoring UI》（Adam Wathan & Steve Schoger）的设计质量规则，按本技能一句话条目形态重写——**转述非照抄**。与既有契约重合的条目不收录（焦点环 / 禁无 label / 错误就近 / 浅底配对 / 一视图一 primary 已在坑位契约与 A11Y 归位条目中，以原契约为准），本库只收增量。
>
> **六域**：层级 / 排版 / 色彩 / 深度 / 间距 / 表单与焦点。每条一句话、动词开头。

---

## 层级 Hierarchy

- **H1 用字重和颜色建立层级，别只靠放大字号**——字号一放大布局就失守；加粗 + 加深足够抬升标题。
- **H2 全系统字重收敛到 2 种**（正文常规 + 强调半粗/粗）——字重一多，层级立刻糊。
- **H3 次级文字只降一档**——降字号就别再降色阶；又小又浅等于删信息。
- **H4 标题不必巨大**——字重与色深建立层级即可，巨型标题挤压内容空间。

## 排版 Typography

- **T1 正文行长控制在 45–75 字符**——过长丢行，过短跳眼。
- **T2 行高比例随字号反向走**：字越小行高比例越大，标题收紧——视觉密度才均匀。
- **T3 数字列右对齐并启用等宽数字（tabular-nums）**——数位对齐才可比。
- **T4 居中只用于短文本**（标题/按钮），长正文一律左对齐——居中长文行首参差难扫读。
- **T5 强调手段单条正文最多用一种**（字重/颜色/斜体）——全都上等于没有强调。

## 色彩 Color

- **C1 灰阶带色相**——用系统主色调制的灰，禁突兀的纯灰死黑。
- **C2 强调色克制**：大面积中性 + 小面积饱和，一屏一个饱和峰——处处强调 = 没有重点。
- **C3 饱和度即视觉权重**：越重要的元素越饱和——反例：大面积高饱和底会把小面积重点淹没。
- **C4 同色相跨底色微调**：深底提亮、浅底压暗，保持感知亮度一致——同一色值在不同底上观感并不一致。

## 深度 Shadow

- **S1 阴影用双层**：环境影（大而淡）+ 直射影（小而实）——单层影要么脏要么假。
- **S2 层级靠阴影表达**（浮层 > 卡片 > 页面），别全靠边框——边框一多界面变栅栏。
- **S3 分隔用极浅边框或边框+阴影组合**，禁生硬深色边框——生硬边框比阴影更抢眼。
- **S4 阴影带色相**：基于页面底色相（或主色相）调影，禁纯黑投影——纯黑影显脏。
- **S5 悬停反馈抬阴影不缩放**——缩放引发布局抖动。

## 间距 Spacing

- **P1 相邻近、分组远**：相关元素贴紧、组间跳档——间距是分组的第一语言。
- **P2 文字与相关元素的间距必须小于与无关元素的间距**——间距倒挂 = 分组错误。
- **P3 拥挤时加留白，禁加装饰**——装饰只能更挤。
- **P4 段落越长，段落间距越大**——间距与内容块的相关度成反比。

## 表单与焦点 Forms & Focus

- **F1 占位符不是 label**：label 常驻、输入后仍可见——占位符一输入就消失。
- **F2 禁用态降对比但保持可辨认**——禁用不等于消失。
- **F3 校验错误就近显示且逐条对应字段**——笼统报错让用户自己猜。
- **F4 单列表单优先**，两列只用于强相关字段对——表单沿一条动线扫读。

## 用法（三处，按场景取用）

### ① 填充"设计要求 / 设计禁令"概念层（站④ 定案补全时）

逐域核对（六域禁空白域）：适用条目**消化**为产物条目形态——一句话 Do/Don't、动词开头、**能用本系统值举例的带例证**；不适用条目**声明不适用**（写明原因，如纯游戏 UI 无表单）。禁把本库条目原文照抄进产物——产物条目必须过一道"本系统值例证"消化。

消化示例：

```
本库条目 T1：正文行长控制在 45–75 字符——过长丢行，过短跳眼。
产物条目：限制正文行长——正文栏实测约 640px，约合 48 个汉字，处于 45–75 舒适区。
```

### ② 提取后质检（提示层，禁改值）

定案前用本库逐域对照实测值与实测档：违反条目的，在产物对应位置标 REVIEW 提示——**只提示，禁改值**（输入是什么输出是什么）。话术：

```
⚠ REVIEW（质量规则 T1）：正文栏实测约 960px，折合 72+ 字符，超出 45–75 舒适区——
通则提示，是否调整由人裁定。
```

字号下限、对比度等可机器化的质检已在自检件套（counts/doc_contrast），不在本库重复；本库只承载机器做不了的语义判断。

### ③ AI 坑位补全的推断依据（component-anatomy 补全规则）

补全坑位的推断依据**优先引用本库条目编号**（如"按 S1 双层阴影 + 本系统主色相推断"），不再拍脑袋。
