# 用户导览（Onboarding）——站① 激活时播报

> **时机（顺序铁律）**：导览 = 技能被调起后的**第一段输出**——先播报，后做任何事。
> 读技能文件、盘点工作目录、分析材料，全部放在播报**之后**。四句模板是通用的，
> **不需要任何盘点就能播**（材料详情属于第二段的确认语，不属于导览）。
> "先盘点清楚再说话"的工作习惯在这里是违规——用户要的第一眼是欢迎语，不是进度条。
> 有材料 → 播完接 activation.md 确认语直接开工；没材料 → 以挂起句收尾待命。
> **形态纪律**：按当前调用**用 3-5 句话生成，每句独立一行（换行排版，禁挤成一个段落）**，禁止照搬本文件全文；
> 全程材料语言与结果语言，内部代号（A/B-1/站号/gate/Schema/middle.json）禁用（SKILL.md 铁律 10 同款纪律）。
> **成本纪律**：导览只进对话（用户屏幕），不写进任何产物文件。

## 模板（四句骨架，按当前调用填空）

1. **启动宣告**：`solo-ui-line-cy-design-system-extract 已启动。`
2. **它做什么（产物导向）**：把你给的设计材料提炼成一套设计系统，产出三构造——给 AI 读的规则文档（md）+ 给人看的演示页（HTML）+ 机器可消费的结构化数据（json）。
3. **怎么跑（四步）**：识别你给的材料并确认细节 → 从材料里提取设计规矩（颜色/字体/间距/组件…） → 归纳成有名字的规范体系 → 生成三构造产物（HTML/md/json）并机器自检。
4. **你在哪里参与**：过程自动跑；开始时如有必要会问 1-2 个小问题（材料范围/输出位置），终稿落盘前会停下来给你过目。

## 变体规则

- 材料类型已可判定 → 第 1 步顺带点明（"看起来是 5 页 HTML 源码"）；不可判定 → 说"先看您给的材料再确认"。
- 用户是回访（本会话已跑过一次）→ 导览压缩成一句"同样流程，这次源是 X、产物到 Y"，不重复四步。
- **回访导览内容纯净**：只讲流程与本次参数，**禁带历史待办**（如"黑框修复等您发令"）——挂起事项是否仍有效以技能文件与产物的**现状**为准，不从旧对话推断；不确定就先核实现状再提，提不出现状依据就不提。
- **挂起变体（调起但没给材料）**：四句照播，第 4 句换成收尾句——"把设计材料发我即可开始：图包 / HTML 源码 / 网页地址 / Figma 导出数据 / 文字描述都行。"
- 用户在提问/讨论（不是要求提取）→ 不播报导览（该场景不走提取流程）。

## 反例（真实教训）

- ❌ 把本文件全文贴出来（用户要导览，不是要说明书）。
- ❌ "走 B-1 路由、过 Schema gate、产出 middle.json"——内部代号上屏（SKILL.md 铁律 10 违规）。
- ❌ 导览写进产物 md/HTML——导览是对话内容，不是交付物。
