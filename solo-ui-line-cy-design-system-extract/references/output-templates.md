# 三构造生成规则（output-templates）

> 产物根（`<项目>/design system/out/`）下**三构造** = `system-spec/design-system.html`（人看，**定案事实源**）+ `system-rules.md`（AI 读）+ `system-rules.json`（机器读）。后两者由定案 HTML 派生（html_to_md.py / html_to_json.py），**同源同版本同计数**，一致性靠单源派生在构造上保证，不靠纪律。以 `templates/` 案例实例为骨架生成；`normalized.json` 只是 gen_html 渲染初稿的数据源（work/ 过程件，不改不交付，禁以任何交付口径提及）。
>
> **诚实声明（2026-10-15 修正）**：本节旧版描述过一套 `{{path.to.value}}` 占位符机制——**模板里从未存在过占位符，该机制从未生效**，是"空转机"事故（gen 脚本原样复制演示案例还报满分）的根因。现行机制为**区域重渲染**，见 §3。

## 0. 输出规则（撰写时生效的 8 句正本——先于一切检查，源头不产垃圾；SKILL.md 的"7 句"为概括口径，以本节为准）

> 生成正文时逐句对照。这些是输出规范，不是事后扫描目标——自检件只兜规则管不住的（溯源真伪/环境/演进同步）。

1. **正文不带思考过程**——只写结果（值、载体、怎么用），不写怎么提取的、怎么归档的（"63px 实测就近"式表述禁止）。
2. **频次要带主语**——写"源稿 5 处"；禁止裸 ×N、禁止无主语的"实测 N 处"。
3. **所有实物按 1x 真实大小渲染**——token 是 @2x 稿的，写入 style 前先折算（1x = 设计稿像素 ÷ 2；源值保留在双标括注里，如 `12px（@2x 24px）`）。来源自带倍率约定（如设计稿注明 pt = px ÷ 2）时以其为准，并写进产物口径声明。
4. **档位只收整数网格值或惯例值**（999px/50% 这类）——源码精确实测值（190.38）放证据层，不进档。
5. **组件库只收交互控件**（能点/能输/有状态）——图标、插画等内容资产归各自章节。
6. **来源标注到条目级**——AI 补全的条目逐条标注，提取的不标；组头徽章如实汇总两边的数。
7. **溯源声明不确定就不写**——写了就必须真实（自检第 8 件会回源核对）。
8. **字体档位不低于 11px（1x）**——设计稿更小的微字值（@2x 12/14px 类）不立档，并入最近可读档；低于可读下限的字号不是规范是噪音。

## 2. system-spec/design-system.html 生成规则

**模板实例**：`templates/system-spec/design-system.html`（**真实案例** · 15 章 · 实物演示 + 交互脚本 + 字体自托管）

**结构固定**：侧边栏 15 章锚点 / hero / 15 个 `<section class="chapter" id="s1..s15">` / footer 统计行（章数随规范演进，锚点检查为动态互验不写死）。

**15 章固定（先面 → 再细 → 后补充）**：

| # | 章节 | 内容要点 |
|---|---|---|
| 01 | 设计价值观 / Values | 4 词 + 应用链路（面层 §02-04 → 细层 §05-13 → 红线 §14） |
| 02 | 布局 / Layout | 骨架五层 + 九类模板（线框+token 示例页）+ PC 横版组 |
| 03 | 多端适配 / Platforms | 三端差异矩阵（实测基准 vs AI 补全列） |
| 04 | 设计要求 / Requirements | **两层**：概念性要求（跨页面类型普遍成立；规则来源 = design-quality-rules.md 六域）+ 具体要求 |
| 05 | 颜色 / Color | 色卡墙 + 语义/组件层表 + **对比度实测小节**（A11Y 归位） |
| 06 | 字体 / Typography | 字号阶梯实物（**1x 渲染**）+ 字重档 + 字体混排 |
| 07 | 间距 / Spacing | 档位标尺（蓝条=1x 实宽） |
| 08 | 圆角 / Radius | 档位实物，**载体全列举**（惯例值 999px/50%，实现值不进档） |
| 09 | 阴影 / Shadow | 实物档（1x 投影） |
| 10 | 动效 / Motion | 时长档；装饰动效禁循环（加载指示除外） |
| 11 | 组件库 / Components | 分组 + 坑位契约 + **条目级来源标注**（只收交互控件） |
| 12 | 图标 / Icons | 库陈列 + 生成母版 + **使用形态**（裸图标/带容器/带文字） |
| 13 | 素材资产 / Assets | 缩略网格 + 语义分组 + 登记表 |
| 14 | 设计禁令 / Don't | **两层**：概念性禁令（规则来源 = design-quality-rules.md 六域）+ 具体禁令 + 无障碍红线（A11Y 归位） |
| 15 | 变更日志 / Changelog | 版本 + 日期 + 变更 |

**每章固定 4 段式**：原则 → 作用 → 应用 → 使用规范

**内容准入三分区**（2026-10-16 根因规则：三构造不是同一文档的三种格式，是三种受众的三种文档）：

| 产物 | 准入 | 禁入 |
|---|---|---|
| HTML（人看） | 实物演示、规格值、变体/状态、使用说明、Do/Don't | 过程叙事、证据登记指引、源工具名（Figma/节点号/Rectangle 430） |
| md（AI 读） | 可执行规则 + 值 + 简短依据 | 过程叙事、现状描述（AI 只需要"命名必须 kebab-case"，不需要"现状是节点号以后要改"） |
| 证据表（meta/清单） | 过程、溯源、原始编号、迁移策略 | — |

**复写内容要求**（2026-10-16 契约驱动升级，细则见 station-guide 生成器纪律与 component-anatomy.md）：
- **组件条目四件套**：规格 + 分级变体 + 使用说明（通用语义，禁业务强耦合）+ 来源标注（已提取/AI 补全）；每组件 ≥1 变体、≥2 状态声明，已声明状态须有实物演示或标注「源无证据/工程兜底」
- **坑位契约**：component-anatomy.md 字典（33 类）逐坑核对，缺项 AI 补全或声明不适用，禁空白坑位；**源内无证据的坑位在产物中显式列「源无证据」清单并给工程引入指引，禁静默省略**；实物演示须覆盖实测组件**全量条目**（默认态 + 已声明状态）；高优组件（Button/Modal/Tabs/Card/Table，移动项目加 NavBar）给解剖式尺寸构成（"高 = 行高 + 内边距×2 + 描边"）
- **素材章强制交付**：逐枚清单（img_asset_refs 证据）+ 实物预览（切图贴出，美术语义分类）；样页内插画/图标必须引用落盘资产，禁灰盒占位（管线见 §3.2）
- **布局章升级**：页面类型模板库——骨架家族九类（枢纽/聚焦/流览/详情/表单配置/档案/对话/过渡/系统）+ 用途开放标签，每模板六件套
- **元素形态自适应**：样式渲染→按值渲染实物；切图→直接贴图；混合→贴图+容器规格
- **质量规则域覆盖**：设计要求/设计禁令**概念层**按 `design-quality-rules.md` 六域（层级/排版/色彩/深度/间距/表单焦点）逐域核对——适用条目消化为带本系统值例证的条目形态，不适用声明不适用，**禁空白域、禁照抄原文**；提取层实测值违反通则只标 REVIEW 提示，**禁改值**

**生成脚本**：scripts/core/gen_html.py（区域重渲染：`:root` token 块、页脚统计、版本/日期/系统名、组件计数）

### 2.1 文档皮肤（Skin）规则

> **强制（铁律 9）**：产物用自己的设计规范排版——演示页的皮肤色/字体/圆角/间距必须取自本次提取的 token 表，让演示页"看起来就是被提取的那套系统"。这不是加分项，是交付标准；皮肤色不在项目 token 白名单会被 raw_values 抓为品牌污染。

> 动机（2026-10-16）：深色游戏 UI 提取出纸感白底演示页，气质割裂不直观——演示页应当"看起来就是被提取的那套系统"。

- **分层**：演示页的**排版骨架**（章节结构、交互 JS、字号阶梯、checker 验证底）固定不动；**色彩皮肤**随提取对象气质走。
- **参数化**：模板皮肤集中在 `--skin-*` 变量组（页面底/正文字/次级字/分隔线/侧栏/点缀/格纹/代码底），骨架代码只挂别名（`--paper`/`--ink` 等），不写死色值。
- **换肤机制**：gen_html 第 5 步 `apply_skin` 自动判定——`color-bg-page` 实值明度 <0.4 判**深色项目** → 皮肤挂项目 token 实值（正文字自动切白系、侧栏程序派生加深一档）；**浅色项目** → 皮肤同样跟随项目：页面底=color-bg-page 实值、分隔线=color-border 系、正文字=color-text-primary、次级字取对比度达标的项目灰、点缀色=品牌主色——**不保持模板纸感默认**（2026-10-19 修正：浅色项目曾是模板暖调直出，与被提取系统的气质割裂）。
- **取值纪律**：皮肤色**只允许**来自项目 token（color-bg-page / color-text-* / color-border-subtle / primary 角色）或程序派生（加深/白色透明度），禁自造第三色——皮肤色因此天然落在 self_check 的 raw_values 白名单内。
- **可读性底线**：换肤后正文对比度仍须 ≥4.5:1；checker 色卡验证底、Do/Don't 功能色等**内容功能色不随皮肤变**。
- agent 复写正文时**不得**把 `--skin-*` 收编为字面值（那是 gen 的职责）；正文区自带的演示卡底色（内联样式）不受影响。

## 3. 执行序（v4.1 · HTML 事实源 + 先双标后派生）

> **架构定案（2026-10-20）**：HTML 是定案事实源；md 与 json 均为其派生视图——同一内容三种构造（HTML 给人看 / md 给 AI 读 / json 给机器消费），一致性靠单源派生在构造上保证，不靠纪律。

```
提取层（过程数据，进 work/，不交付不改）
  parse → middle.json → tokenize → normalized.json
    ↓
① gen_html.py：从 normalized 渲染 HTML 初稿（:root 全量 4 段 + 换肤 + 计数）
    ↓
② agent 补全 HTML（所有 AI 补全组件/图标/规则只做在 HTML 上），补全到定案
    ↓
③ dual_scale.py <out>：双标折算——@2x 源稿值折算为 1x 主口径、括注 @2x（如 `12px（@2x 24px）`）；
   CSS 渲染区整体摘除不动；口径基准值（375/750/812）跳过；幂等可重放，--dry 预览
    ↓
④ html_to_json.py <out>：定案 HTML → system-rules.json（机器消费版）
   html_to_md.py   <out>：定案 HTML → system-rules.md（AI 读版；度量小节复用 json 全量表）
    ↓
⑤ fetch_fonts.py：字体自托管（@font-face / base64 woff2 随产物打包，不依赖系统安装）
    ↓
⑥ self_check 十三件套 → 交付
```

- **站④ 工序顺序禁反：先 dual_scale 双标折算（③），后 html_to_json / html_to_md 派生（④）**——顺序反了 json/md 口径错、三构造不自洽。
- **一键管线**：`run_pipeline.py` 可一条命令跑完渲染→形态（组件 33 类枚举/素材网格/线框）→双标→派生（json/md）→字体→自检；agent 只做中间的定案补全（语义活），完成后 `--derive-only` 重派生。
- **补全不回填**：AI 补全只做在定案 HTML 上，md/json 派生自动携带——禁止"正文写了账本没记"类双写。
- **中间 json（middle/normalized）不改不交付**：归 work/，是提取原始记录。
- **派生后校对**：转换器保结构，agent 对照定案 HTML 过一遍 md 规则散文语义完整性。

## 3.1 区域重渲染规范（现行，替代占位符幻想）

| 区域 | 机制 | 谁负责 |
|---|---|---|
| `:root` 变量块（全量 4 段）/ 页脚统计 / 版本日期名称 | gen_html **自动再生** | 脚本 |
| `--skin-*` 文档皮肤变量组（见 §2.1） | gen_html `apply_skin` 自动换肤 | 脚本 |
| HTML 正文实物演示（色卡、组件实物、演示文案）与 md §3/§4/§5/§8/§9 | **主会话 agent 复写**：以模板对应章节为骨架复制，逐值替换为项目实测值，**交互代码（JS）原样保留** | agent |
| 兜底 | self_check 十三件套（§4 清单；源头规则管不住的才进检查：溯源真伪/环境交互/演进同步） | 脚本守门 |

**生成器纪律**：允许 agent 自写渲染脚本（官方 gen 覆盖不了全部正文），但**必须从 templates 骨架复制起步、以提取数据为唯一数据源**——手搓空白生成器丢功能会被 features 件套当场抓获（Ludo 事故：7 项交互资产全丢 + 粉色叫 blue，现行自检 2 项 REVIEW 拦截）。**复写每一章之前，必须先打开案例模板同名章对照形态**（spec-label 序列 + 可视化要素：实物/网格/缩略图/lightbox/对照卡），形态对不上 = 这一章没写完——禁只读文本不渲染、禁凭想象补形态（事故链：布局样页、素材登记表两次同病；兜底 = self_check 第 13 件 template_form）。**禁照抄案例**：照抄 = 把示例设计系统的价值观塞进别的项目——案例只给形态，数据与规则散文必须换成本项目实测。

## 3.2 产物工程目录、work/ 回流与美术资产管线

**产物工程目录（work/）与回流**：产物根 = `<项目>/design system/out/`（统一多一层 `design system` 文件夹，多套设计系统并存互不干扰）。根下白名单：design-system.html / system-rules.md / system-rules.json / system-spec/ / assets/ / hifi/ / work/ / source/——网页快照 fetched.html 归 source/；中间 json（middle/normalized）归 work/；美术资产归 assets/；图标归 system-spec/assets/icons/<库>/（**技能包 templates/ 内不得预置图标库资产**，产物图标由 fetch_iconset.py 按项目风格判定现拉）。执行时在产物目录下建 `work/` 放临时脚本与过程件，交付前清理临时件；**通用机制脚本用后回流** `scripts/core/`（判据：换项目仍可复用）。**内联 absolute 元素必须有 containment**：小样里的蒙层/浮层（`position:absolute;inset:0`）必须配容器 `position:relative`，否则相对定位祖先铺开罩全页（事故：布局章弹窗小样蒙层逃逸，整页被 32% 黑罩住）。

**学习回流（LEARNINGS.md）**：执行中发现来源约定 / 最新案例与技能模板、规则不一致（章节命名、倍率口径、图标上游库、路径约定等），**当场记入产物 `work/LEARNINGS.md`**；任务结束前按「换项目仍成立」判据回流技能对应文件（templates / references / scripts），回流即更新对应细则并跑最小单元测试。

**源回读义务（防「编造已提取」）**：凡在产物中标「已提取 / 实测」的内容——样页复刻、布局小样、页面结构、组件规格——**必须回到提取来源逐段核对**，并在产物 `work/source-refs.json` 登记「断言 → 源文件 → 证据字符串」对照清单；self_check 第 8 件（source_audit）回源抽查，证据未命中即 REVIEW。无依据不得标「已提取」。

**素材登记义务**：来源中的插画 / 图片 / 装饰矢量（logo、卡面插画、网点纹理等）必须登记进素材清单并给落盘指引；来源图包 assets/ 切图可直接采集落盘，禁只写"占位"。

**美术资产管线**：①②站 parse_html.py 第 6 桶采美术资产（内联 SVG 按 **语义名 > 结构特征（渐变/色彩数/path 数）> 相对画布比例** 分级为 icon_lucide / icon / illustration，**禁绝对像素阈值**——1x/2x/3x 倍率下必错）；**归属判定第 0 步**：插画级默认「待确认（组件件 / 素材位 / 装饰）」，列清单问设计师，**禁默认当组件**（事故：星空主视觉结构像组件，实为后台整张 PNG 素材位）；**凡归属为素材的内容一律不产生 token 证据**——素材内部的文字/颜色/尺寸只随素材走（登记 manifest），不进 token 表、不进字号阶梯与颜色口径；token 证据只来自功能组件与页面级 UI 文字。落盘器 asset_exporter.py 按容器归组写盘产物 assets/（插画合成 SVG + 位图复制 + manifest.md 登记，插画状态默认「待确认」）；素材章必须由 manifest 转写为**真实登记表**，禁分类学作文；样页内插画/图标必须引用落盘资产，禁灰盒占位；self_check 第 12 件（assets_registry）对账：normalized.assets 语义核心词必须出现在素材章。

生成完毕后**必须**跑十三件套（路径参数必填，指向**本项目 out/ 目录**）。**多数坑已在 §0 输出规则与生成器里源头防住，检查件只兜规则管不住的**（溯源真伪/环境交互/演进同步）：

 2. anchors         ← 导航↔id 动态互验 + 编号连续（不写死章数，规范演进自动跟随）

 4. raw_values      ← 裸 hex/阶梯外字号；白名单 = 本项目 token 值 + 文档排版白名单
 5. features        ← 交互资产存活 + 名实一致（颜色词命名与色相相符）
 6. gradient_truth  ← 还原度（--source-dir 启用）：源渐变种类 vs 产物渐变 token 对照
 7. doc_contrast    ← 文档可读性：结构元素实际底×字对比度（含 var 链穿透）
 8. source_audit    ← 溯源审计（--source-dir 启用）：「值…N 处」声明回源核对，0 命中=瞎编
 9. css_syntax      ← 文件头完整（DOCTYPE 截断/游离块）+ CSS 缺分号粘连/无单位值

## 5. 计数与命名纪律（Ludo 事故换来的铁律）

- **计数以项目实测为准**：134 token（35+29+22+48）/ 33 类坑位字典是**案例参考值与坑位契约**，不是及格线。**严禁为凑数硬塞槽位**。
- **名实一致**：token 命名跟着真实值走——粉色值不许叫 `blue-*`，`#16A34A` 不许叫 `danger`。"改值不改名"是反模式。
- **组件覆盖**：项目实测有 9 个就写 9 个（Ludo 对）；坑位字典 33 类只用于坑位核对与归类去重，不要求全覆盖。
- **未覆盖声明**：字典有、源无证据的组件（如 Toast/Loading 等）不是"不写"，而是**显式声明**——产物中列「源无证据」清单 + 工程引入指引，禁静默省略。
- **状态与解剖**：每组件 ≥1 变体、≥2 状态声明；已声明状态须有实物演示或标注「源无证据/工程兜底」；概览表含状态列。
- **双标折算**：尺寸统一「1x 主口径括注 @2x（如 `12px（@2x 24px）`）」，由 dual_scale.py 在站④对定案 HTML 统一折算（先双标后派生，顺序禁反）；口径与来源倍率约定冲突时以来源约定为准并全量声明。
