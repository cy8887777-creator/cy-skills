设计价值观DESIGN VALUES

一切规则的上游依据。后续每章的具体规定，都能追溯到这里的四个词。

PRINCIPLES · 原则
  • 一致 Consistent —— 同类元素永远长一样、动一样。用户学一次，处处可用。
  • 明确 Explicit —— 每个视觉选择都传达确定信息，不留歧义。
  • 高效 Efficient —— 减少决策与操作步骤，默认值即最优解。
  • 可生长 Scalable —— 新场景优先复用既有 token、组件与资产，而非新增。
WHAT · 作用

价值观不是口号，是裁决依据：当两条具体规则冲突、或遇到规则未覆盖的新场景时，回到这里做判断。

APPLICATION · 应用链路

价值观 → 设计原则（§02–§09）→ 资产与组件（§10–§12）→ 模式（§13）→ 具体方案。越靠右越具体，越靠左越稳定；下层规则不得违背上层。

USAGE · 使用规范
DO ✓
  • 新增规则前，先对照四价值观检查是否自洽
  • 评审争议时引用价值观条目作为依据
DON'T ✕
  • 不要写无法落到具体规则的空话价值观
  • 不要为单个需求临时突破价值观

04

设计要求REQUIREMENTS

跨场景的组装规则，分两层：概念性要求定方向（跨页面类型普遍成立），具体要求给做法（本系统沉淀）。页面骨架归 §02 布局。

CONCEPTUAL · 概念性要求（理念层 · 跨页面类型成立）
  • 信息密度与呼吸感按页面任务平衡 —— 聚焦型页面敢留白、立重心；列表型页面保密度、立节奏。
  • 视觉层级必须与信息层级一致 —— 重要的更大更醒目，次要的退后。
  • 一致性优先于个性 —— 同场景永远同样式。
SPECIFIC · 具体要求（本系统沉淀）
FORM · 表单流程
  • Label 在上，左对齐；必填用 * 标记，选填可不标。
  • 校验时机：失焦时校验单个字段；提交时全量校验；禁止输入中逐字报错。
  • 错误就近显示在字段下方（红色 12px），同时顶部不重复弹窗。
  • 提交按钮：请求期间转为加载态并禁用，防重复提交。
LIST · 列表页组合
  • 筛选区（Select / DatePicker）→ 工具条（批量操作）→ 表格 / 卡片 → 分页，四段自上而下。
  • 批量操作依赖行内 Checkbox；选中数量实时显示在工具条。
  • 无数据时表格区域内嵌 Empty 组件（带行动按钮）。
LOADING · 加载策略（spinner vs skeleton 的唯一判据）
  • 结构可预期（列表 / 详情 / 卡片墙）→ Skeleton 骨架屏，占位与真实结构同形。
  • 结构未知或短暂等待（< 1s 的按钮提交、局部刷新）→ Spinner。
  • 页面级跳转允许顶部细进度条；禁全屏转圈遮罩。
CONFIRM · 危险操作确认
  • 删除 / 转让 / 停用等不可逆操作，必须过 Modal 二次确认（§12 实物样式）。
  • 确认按钮用 danger 变体；正文写清后果与恢复方式（"30 天内可恢复"）。
  • 执行期间按钮转加载态；成功后 Toast 反馈并刷新列表。
USAGE · 使用规范
DO ✓
  • 新页面先对照四模式，能拼则拼
  • 模式与组件冲突时，以模式为准上报修订
DON'T ✕
  • 不要自创第四种加载形态
  • 不要跳过危险操作确认

颜色COLOR

主色只有一个；三层 token 架构（基础层 → 语义层 → 组件层）。写样式只允许引用后两层。

PRINCIPLES · 原则
  • 可访问 Accessible —— 正文对比度 ≥ 4.5:1（WCAG AA）。
  • 可扩展 Scalable —— 色阶成档，不散点用色。
  • 有目的 Purposeful —— 每个颜色 token 必须回答"用在哪、禁用在哪"。
  • 分角色 Role-based —— 色板按 主色 / 中性色 / 功能色 三组管理，不可互相越界。
WHAT · 作用

颜色同时承担三件事：传达状态（成功/警告/危险）、建立层级（页面→卡片→元素）、识别品牌（主行动色）。一处颜色只能优先服务一件事。

APPLICATION · 应用（基础层 · 三组角色）
PRIMARY · 主色品牌主色 1 枚 + 深色悬停档
TINTS · 主色辅助阶浅底、边框、聚焦
NEUTRAL · 中性色文本、背景、边框专用
FUNCTIONAL · 功能色每色 = 主色 + 浅底配对

语义层 Semantic · 每格 4 列（名称 / 值 / 用途 / 禁用于）

CONTRAST · 对比度验收（A11Y 归位）
  • 正文 ≥ 4.5:1；大字（≥18px 粗体）≥ 3:1；UI 部件描边 ≥ 3:1。
  • 自查：取色器测前景/背景比对 WCAG 表；页面转灰度看信息是否仍完整。
USAGE · 使用规范
DO ✓
  • 样式一律引用语义层 / 组件层 token
  • 主色只用在 CTA、链接、选中态三处
  • 状态信息用 颜色 + 图标 / 文字 双通道传达
DON'T ✕
  • 不要写裸 hex（如 #3056D3）——含 Tag 底色在内一律走 token
  • 不要自造新颜色，先复用现有色阶
  • 不要用颜色作唯一信息载体（WCAG 1.4.1）
  • 不要让主色出现在大面积背景上
06

字体TYPOGRAPHY

6 档字号阶梯覆盖全部场景。任何文字先归档，再使用。

PRINCIPLES · 原则
  • 层级清晰 Hierarchical —— 字号差 ≥ 4px 才能形成可感知层级。
  • 阅读优先 Readable —— 正文行高 1.6（--line-height-body），行长 ≤ 42em。
  • 少档位 Restrained —— 同一内容区块内可见字号 ≤ 3 档；组件内部文字（标签 / 帮助文字 / 按钮字）不计入。
WHAT · 作用

字体是信息架构本身：用户靠字号与字重判断"什么更重要"，不读也能扫出结构。

APPLICATION · 应用（字号阶梯实物 · 字重三档 400/600/700）
--font-size-display
28px / 行高 36 / 字重 700 · 页面主标题大标题 Display
--font-size-title
22px / 行高 30 / 字重 700 · 区块标题区块标题 Title
--font-size-subtitle
18px / 行高 26 / 字重 600 · 次级标题次级标题 Subtitle
--font-size-body
16px / 行高 26 / 字重 400 · 正文正文 Body——承载主要阅读内容
--font-size-caption
14px / 行高 22 / 字重 400 · 辅助说明辅助说明 Caption
--font-size-footnote
12px / 行高 20 / 字重 400 · 注脚标签注脚 FOOTNOTE

字重三档各司其职：400 正文 / 600 次级标题与组件强调 / 700 仅限 display 与 title 两档标题。字族统一 --font-family-base（系统栈），不做品牌字体混排。

USAGE · 使用规范
DO ✓
  • 新文字先归入 6 档之一，再取 token
  • 标题 = 字重 + 字号同时升级一档
DON'T ✕
  • 不要使用阶梯外字号（如 15px、19px）
  • 不要在正文中用加粗替代标题层级
  • 不要一个视图排布超过 3 档内容字号
07

间距SPACING

8pt 体系：页面布局间距一律取 4 的倍数。间距表达"关系"——近者相关，远者无关。

PRINCIPLES · 原则
  • 基准统一 Base-8 —— 页面布局间距取自 4/8/12/16/24/32/48 七档。
  • 豁免边界 Exemption —— 组件内部尺寸（padding / 高度）按 §12 组件规格表执行，不受档位约束；布局层间距（组件之间、区块之间）必须取档。
  • 节奏 Breathing —— 相关内容近，无关内容远；组内 < 组间。
WHAT · 作用

间距是不画线的分隔线。密度过高让人紧张，过疏让人失联；七档标尺让"多远算远"有唯一答案。

APPLICATION · 应用（两块夹一隙 · 蓝色区域即真实间距）
--space-1 · 图标与文字间隙
--space-2 · 组件内部元素间隙
--space-3 · 紧凑列表行距
--space-4 · 组件之间
--space-6 · 卡片内边距 / 分组之间
--space-8 · 区块之间
--space-12 · 章节之间
USAGE · 使用规范
DO ✓
  • 布局间距就近归档（±2px 内取档）
  • 用间距分组替代画线分割
DON'T ✕
  • 布局层不要出现魔法数字（13px、17px）
  • 不要嵌套累加导致对不齐（4+8 ≠ 16）
08

圆角RADIUS

圆角是亲和度旋钮，也是组件身份的一部分：同尺寸元素必须同圆角。

PRINCIPLES · 原则
  • 身份一致 Identity —— 圆角档位与组件类型绑定，不随页面变化。
  • 克制 Restraint —— 常规界面不使用超过 lg(12px) 的圆角。
APPLICATION · 应用（实物）
sm · 4px
开关 / 小元素
md · 8px
按钮 / 输入框 / 下拉
lg · 12px
卡片 / 弹窗 / 弹层
full
标签 / 头像 / 圆点
USAGE · 使用规范
DO ✓
  • 按组件类型取档：按钮与输入框 md、卡片与弹窗 lg
  • 嵌套时外圆角 = 内圆角 + 内边距
DON'T ✕
  • 不要混用相邻档位（按钮 8px、旁边卡片 9px）
  • 不要单角异形圆角（无明确构图目的）
09

阴影SHADOW

阴影即高度：元素离"桌面"越远，影子越大越淡。三级封顶。

PRINCIPLES · 原则
  • 高度隐喻 Elevation —— 阴影大小严格对应悬浮层级。
  • 顶部光源 Top light —— 纯垂直投影（x 偏移恒为 0），全局一致。
APPLICATION · 应用（三级实物）
shadow-sm
卡片 · 默认浮起
shadow-md
下拉菜单 · 浮起
shadow-lg
模态弹窗 · 最高层
USAGE · 使用规范
DO ✓
  • 悬浮越高，阴影越深——按层级取档
  • 阴影与描边二选一，不做双重强化
DON'T ✕
  • 不要彩色阴影、发光效果（品牌场景除外）
  • 不要 x 偏移阴影（破坏全局光源）
10

动效MOTION

动效只为三件事服务：反馈、引导、连续性。悬停下方各行体验三档时长。

PRINCIPLES · 原则
  • 快而不跳 Swift —— 反馈 ≤ 150ms，超过即被感知为迟钝。
  • 有因必有动 Purposeful —— 每个动画对应一个状态变化，无动画则不变。
APPLICATION · 应用（三档时长 · 悬停体验）
fast · 150ms — 微交互（hover / 按压 / Toast）
base · 250ms — 展开 / 收起 / 下拉
slow · 400ms — 页面 / Modal 转场

缓动统一 ease-out；进出场成对出现；实现必须尊重系统减弱动效设置：@media (prefers-reduced-motion: reduce) { * { animation: none; transition-duration: 0s; } }

USAGE · 使用规范
DO ✓

设计禁令DON'T LIST

跨章高频错误的集中对照。AI / 新成员产出前，逐条自查。

CONCEPTUAL · 概念性禁令（理念层）
  • 禁把信息撑得太满 —— 布局要有呼吸感，间距留足，页面要有清晰主次。
  • 禁为留白牺牲信息密度 —— 列表页每行信息必须完整可扫。（与上条成对：两头都是极端）
  • 禁让用户思考「这是什么」 —— 元素含义必须自明；图标必配文字标签。
  • 禁一屏多主任务 —— 一屏一个主行动；浏览列表页禁塞竞争性 CTA。
TOP 8 · 高频错误对照
DO ✓ 用语义 token
  • color: var(--color-text-primary)
DON'T ✕ 写裸色值
  • color: #18181B —— 改主题时必然漏改
DO ✓ 布局间距取 4 的倍数
  • 12 / 16 / 24，就近归档
DON'T ✕ 魔法间距
  • margin: 13px / 17px —— 无档可归
DO ✓ 状态多通道传达
  • 红色 + ✕ 图标 + 文字说明
DON'T ✕ 只用颜色
  • 仅变红传达错误 —— 色盲用户不可见
DO ✓ 一视图一主按钮
  • 主操作 1 个；行内 / 卡片内操作用文字按钮
DON'T ✕ 双主按钮
  • 「保存」「提交」同时高亮蓝 —— 用户失去焦点
DO ✓ 字号走阶梯
  • 16 / 14 / 12，层级靠档位差
DON'T ✕ 字号随手写
  • 15px、18px、19px 混排 —— 层级感被稀释
DO ✓ 动效有因
  • 弹层淡入 400ms，对应"出现"这一状态变化
DON'T ✕ 装饰动画
  • 静态元素循环漂浮 —— 抢注意力、耗性能
DO ✓ 图标同源同套
  • 全部取自 assets/icons，线性为默认
DON'T ✕ 图标混套
  • 页面里 3 种描边粗细的图标混排 —— 廉价感来源
DO ✓ 触控目标达标
  • 移动端可点区域 ≥ 44×44（含热区扩展）
DON'T ✕ 目标过小
  • 24px 的关闭按钮裸放在移动端 —— 误触率飙升
A11Y · 无障碍红线（自「无障碍」章归位）
  • 状态不只靠颜色 —— 信息不得仅靠颜色传达（状态配图标/文字）；自查：转灰度看信息是否完整。
  • 键盘可达 —— 可操作元素 Tab 可达、焦点可见（--focus-ring）、Modal 内 Esc 关闭；自查：拔鼠标走完流程。
  • 可读名称 —— 图标按钮必带 aria-label、图片有 alt、控件有 label；自查：开屏幕阅读器听一遍。
  • 禁 div 充当按钮 —— 无键盘语义；禁移除焦点描边而不提供替代。
