# GUI 风格 → 高保真设计项目

把一份风格提示词和业务材料，画成一包高保真设计稿：**一个风格一个目录**（`<风格id>/`：HTML+assets，相对引用离线可看）——每个页面都是能直接看、直接评的精修效果图，带页面列表导航。本技能沉淀的不是"写 HTML"，是一套**先立事再谈风格、页页过精修、感性自查守门**的绘制方法。集成度为零：精修、图标、硬检全部调外部技能。

## 铁律（always-on）

1. **第一性文档**：`intake/风格提示词.md` + `intake/用户输入.md` 在位才开工——主技能编排时已有则直接读，独立使用时由本技能落盘（风格提示词没给则按 references/prompt-protocol.md 起草，经用户确认）。两份是一切依据，禁转写禁派生；落盘后冻结；经用户裁决的修订直接修订并在 ledger.md 记一行（与主技能铁律 5 同口径）。
2. **风格提示词唯一视觉权威**，但页面功能的合理性才是设计稿更重要的。风格是服务于功能的。
3. **画布像真产品**：零"示例/未接入/示意"字样；不伪造业务成功、客户评价、产品指标；禁"合理最小值"式占位。**界面全部文案按性质三分类各自站得住**（界面文案可行动 / 动态输入内容像真实用户所填 / 数据规范互洽；装饰性废话砍）。**页面上每个字的读者都是终端用户**——产品上线后用户会看到的运作逻辑与提示才上屏；给评审/开发解释机制的话（白名单规则/平台建档/对账口径这类）不是产品内容，不上屏。操作口径见 style-selfcheck 文字层。
4. **图标**：调 solo-img-line-cy-icon-provisioner；禁 emoji 当图标；形态贴合风格族，一套一线宽。
5. **产物形态**：**一个风格一个目录**（`<风格id>/<风格id>.html` + `assets/`，画师直接产出，**不跑 build**）；产物运行期**零网络请求**，资产相对路径引用（图片/图标/字体细则、file:// 陷阱、图片供给链与生图兜底时机——全见 references/shell-draft-wiring.md）；**禁 base64 内嵌大资产**（小图标 sprite 内联除外）；禁灰块占位、禁 SVG 手绘充大图（图标按铁律 4 供给）。**交互结构标注规范**：弹层标 `data-sheet`、tab 分段标 `data-seg`/`data-panel`、跨页跳转标 `data-go`——**行为由壳标准 JS 统一接管（壳模板已预置），画师禁自造交互 JS**（定制行为登记交付说明；交互档位出处=开工文档 §5——a 档纯静态不写任何交互标注，b/c 档才按本条标注）；标注细则见 style-selfcheck 交互层。
6. **先落盘**：每页写完立即落盘，防上下文耗尽零产出。
7. **渲染实看每页 ≤3 次**；质量评审只有两道外部关：**风格盲测**（混图裁归属）+ **审美评审**（逐页裁观感差距，协议见 style-selfcheck）——都不替代实看。
8. **字体真装配**：品牌字体以真 woff2 装进 `<风格id>/assets/fonts/`（相对引用 @font-face，许可随包），**禁系统栈回退**——主代理开工前统一备好，画师只引用不下载；不可得时停下上报，禁静默回退。获取来源与独立使用口径见 references/shell-draft-wiring.md。零 CDN/外链字体引用。
9. **收口清账才交棒**：把产物交给下游环节（交互接线/旁批/铺量/转化）前，代表页收口欠账先清——四层自查、文字盲校、压力测试、审美评审+盲测，补完，或经用户明示跳过并在交付说明登记"跳过了什么"；静默跳段=违规。
10. **外部协议优先**：被主线 flow-ux-ui-line-cy-hifi-design 以任务书调起且任务书附**协议页**时，守门与登记口径以协议页为准（正本=主线 references/integration-contract.md，回执五项结构两侧同步）；无协议页按本文件原生流程。

## 工作流（设计师实践，不是状态机）

### 认材料
读风格提示词+**风格参照副本**（如有）+业务材料+**端型约束文件**（`references/端型约束/_共用.md` + 所做端型差异文件（微信小程序/iOS-App/安卓-App/平板/PC-Web）——宿主接管/原生组件规范/操作真实性三问，壳体与页面分工表也在里面）；缺关键信息集中问一次。**风格参照副本**=主代理提供的原样张去骨架版（只留卡头+载体样本条：色板真值/字体真渲染/组件形态/图标族）；画师**禁看原始骨架样张**——骨架区的布局结构/行高密度/槽位形态是三轮照抄事故的传染源（jiancewuyou 定案）。参照副本的合法用途=提**风格载体实值**（颜色怎么铺、字体怎么渲染、组件长什么形态、图标什么族），其布局一律不参考；布局由 Direction 的信息先行推导。**端型约束的合法用途**=宿主接管/原生组件规范/避让数值照办+操作真实性三问过筛；它不含任何视觉主张（收材标尺见 `_共用.md` 开头），页面长什么样仍归风格提示词。**端型按用户输入定，默认单端**（材料/收口确认单标了双端才双端做，且各端独立设计非缩放——代表页循环按端各跑一轮）。**多风格并行**（用户要 N 个风格各出代表页）：每风格独立一路代表页循环、**各自产出一个风格目录**（一风格一目录：`<风格id>/` 内含 `<风格id>.html`（左侧页面列表+手机框画布，壳用 templates/preview-shell.html——视觉对齐编辑器预览形态，转化时换编辑器壳观感延续）+ `assets/`，**全程不跑 build**）；聚合=一个**目录页**（静态 HTML，列出各风格目录链接）。页面互不混合，一风格一目录。本质是比稿，应提示用户先走 solo-ui-line-cy-gui-style-picker 样张收敛、对选中风格再画全精度代表页——用户坚持直接画则照办，交付说明里写明"样张收敛已跳过"。业务链路在心里过一遍：起点→终点→每个分支出口，哪些页面必须存在——这是页面生长的种子，不写成清单文档。

### Direction（动手前的内心锚，不产出文档）
**信息先行**：动笔前先答两问——这页的读者是谁、他打开这页要做什么决定；由决定倒推本页必须承载的信息清单，并给每项定呈现权重（主位正文/辅助行/折叠详情）。**易读优先于全面**：主视图只装高频决定所需的信息，低频内容（历史/日志/明细账）下沉到切换区、折叠或次级页——全面由功能覆盖审计兜底，主视图不背"全"的包袱。信息清单没定权重前禁进布局；不得因版面惯例有某个槽就臆造信息，也不得因空间不足就阉割决定所需的信息——空间不够调整结构，不砍内容。自查反向验一条：读者仅凭这一页，能否做出那个决定。
**形态先于槽位**：每个内容位置先答"这行字是谁写的、在业务里以什么形态写的"（与铁律 3 三分类同一问），由内容形态决定承载结构；禁止由版面槽位倒推内容形态——版面惯例有某个槽，不等于这段内容是那个形态。
**备选自问**：信息清单定完后问一句"这页有没有第二种画法"——没第二种（提现记录/登录这类怎么画都一样）直接画；有真分岔（如信息堆一页还是分标签切换）自己比较、拍板选优，交付说明记一行"选了什么、为什么"（不找用户审批，用户事后翻记录纠偏）；牵一发动全身的（首屏调子/整站信息组织基调）拿方案给用户挑。
从风格提示词推导：产品做什么给谁用；性格两三个具体词（禁"简洁/现代/高级/精致"万金油词）；属于哪个世界；哪 1-2 处允许撒丰富度；一个只有它有的 Signature 细节。提示词已声明的段逐段照办，未声明的段从这里推导。

### 角色与派工（要不要派看量，怎么拆看连续性）

- **量小**（一两张）：你自己画，单人循环直跑。
- **多张代表页**：**一个代理画全套**（或你自己画）——同风格的页设计判断必须连续，拆给多个代理=每页一个脑子，部件互斥、衔接断裂。**禁一页一个。**
- **没有任何场景是"一页一个"**：阶段 4 多张代表页→一个代理画全套；阶段 6 跑批→一个链路一个子代理（一代理负责一条完整链路的所有页面，见 batch-production.md）。

派工纪律只在**派出去**时生效——自己画时，任务书退化成动手前的范围划定，实看不需向谁存证（用户定调卡点把关）；一旦派出，全套上线。**派发模式（铁律）：子代理一律后台模式（run_in_background）派发——主会话保持可对话，用户插话不杀代理；回执靠完成通知回收，禁前台阻塞等待。**

**任务书只装四样**：①第一性文档路径（禁转写内容，画师自己读原文）；②本任务范围一句话（可以是一页，也可以是同风格的一组页）；③完成定义（含渲染实看、调哪些技能、**可用性优先口径**：内容完整性与可读性 > 制式符合——真实内容塞不进制式就改结构，禁删字迁就）；④回执要求。演示数据各代理自编（口径从开工文档/盘问记录自读：通用域、像真、页面内自洽），**禁建共享数据文件**。**任务书禁附 Direction 结论**——Direction 是画师动笔前自己从提示词推导的内心锚（见上节），主对话转写设计判断=替画师做题=透题；风格内多页一致性靠"一个代理画全套"，跑批一致性靠阶段4 冻结的设计资产规范，风格间无需一致。

**透题判据只约束派工的你，不约束画师：派出去的任务书里，每个设计决定必须指回源文档。** 来自开工文档信息架构、用户拍板（实体=盘问记录 `intake/用户输入.md`——0.1 正文没写的裁决原文在这，发路径让画师自己读）、参照卡的决定，合法（发路径让画师自己读）；源文档里没有的，你同样不许现场发明——要么提请用户补进源文档，要么留给画师判断。**样张以去骨架副本（卡头+载体条）进材料链，禁发原始骨架版、禁附加任何密度/结构/布局倾向语**（"可参考其内容密度口径"这类添头=把选型示意变成布局命令，jiancewuyou WeUI 事故定案）。卡里没写的构图、配色、细节，是画师的自由区（依据=prompt-protocol.md 的前言；参照卡自带前言时同样授权），自行推导，不许因找不到依据就不敢画。

**回执只认证据，不认动作**（五项结构，与主线 batch-production 任务书【回执】节同步，正本登记在主线 references/integration-contract.md）：渲染截图路径清单（每轮实看截图存工程目录 `shots/`）、自设参数清单（参照卡与硬约束没写、画师自己定的数值逐条报）、自查记录、**落盘清单（每页一行：路径+这是什么页）**、未决问题。禁写"我调了什么技能"。自查必须**指出成稿中具体的视觉不足并据此调整**——仍存在明显问题时，不得仅以步骤执行完毕为由回报完成；复核按同样标准真打开渲染图抽页看，不许清点汇报清单。

**画师工序白名单**：循环内定的动作（画→落盘→实看→走查→精修→自检）之外，禁自创工序（批量文本校对、额外审读代理等）——发现值得做的新工序，上报主对话由用户拍板转正，不自作主张、不静默扩权。

### 代表页（定调卡点）
按业务链路挑 1-3 页最能代表风格与主流程的页面，全精度画。此页**无旧图可看**——判断力全凭风格提示词内化（铁律 2）与 Direction 推导，第一张图就是设计师本人的出手。循环：写码 → 落盘 → **DOM 自查先跑**（自跑检查脚本：溢出/遮挡/字号/骨架零文字/跳转死链——每个 data-go 目标页存在，零截图，修到 DOM 层干净才许进下一层）→ **渲染实看抓视觉硬伤**（≤3 次——DOM 拦不住的形状崩坏/色调失衡/密度观感只在这层看）→ 修 → **调 solo-ui-line-cy-ui-walkthrough 走查**（布局/溢出/遮挡/字号，过）→ **调 solo-ui-line-X-unslop Polish 模式**（只修实看/走查发现的 AI 味项，禁九遍全屏遍历；方向从风格提示词推导，负面清单是硬边界；**动效本阶段不做，不加 solo-ux-line-X-add-motion-design**）→ 交稿自检（视觉/风格/文字/交互四层清单，见 references/style-selfcheck.md）→ **交用户定调**。不过不铺量；用户增删的代表页升级进本循环。形态按「角色与派工」：多张代表页由同一个代理连续画完（或你自己画）——部件/间距/衔接在同一双手下自然一致；若确需拆分，第一张用户定调通过后作为锚，后续以它的源码为底稿。

### 自由生长（只推演，不铺量）
从业务链路推演**全站页面结构（页面地图扩展）**：哪些页面必须存在、每个状态与异常分支（空态/错误态/详情配套）由哪页承载——这是本技能对全站页面结构的思考，随代表页一起产出。**页面地图补口规则**：地图可补业务/用户场景（"师傅需要知道这单为什么被驳回"），**界面元素不补**（控件语言归画师）。**铺量不归本技能**：其余页面由主技能阶段 6 吃本技能的惯性跑批（文档规范+设计资产+代表页旧图）。

### 产物清单（阶段 4 交付物，盲测通过后按此交付）
1. 代表页精修稿 = **一套风格一个目录**：`<风格id>/`（内含 `<风格id>.html`——壳 = 左侧页面列表+手机框画布——与 `assets/`（images/icons/fonts，相对路径按 html 同目录书写）），落工程根；**交付=整个 `<风格id>/` 目录打包**，交付说明列资产清单（来源+许可）。**壳与页面的尺寸/顶部避让/滚动范围必须一起查**：手机框外宽≠页面内容宽（边框占位），改画布宽度时内容区宽度、sticky 避让、滚动裁切逐项复验
2. 页面地图扩展 → `design/页面地图扩展.md`（文件名固定：0.1 §3 主线页+画师新增页，同格式逐步补全）
3. **设计资产与动效规范成文** → `design/设计资产与动效规范.md`（文件名固定；含 Direction 结论段——性格词/世界/Signature，批量代理的风格锚）
4. 交付说明（未验证项如实标；产物运行期零网络请求，无需"需联网"声明；图片/字体断链需在实看中排查）+ **每页一句"画了什么"设计要点登记**（下游旁批技能 solo-doc-line-cy-page-annotation 的喂料）

**复用基准链（样张→代表页→跑批，逐级传递）**：样张只供理解风格（结构示意不继承）；用户定调通过的正式代表页=后续跑批的唯一复用基准——跑批复用部件与样式，每页布局仍按本页业务组织。

后续管线：主技能阶段 5 完善整体文档 → 阶段 6 全量出图 → 附加环节（编辑版转化/旁批），均见主技能 V06 管线。

### 风格三方盲测 + 审美评审（交付前，两道独立的关）
**审美评审先行**（逐页诊断）：派没参与制作的独立评审，只看渲染截图不读代码，协议见 references/style-selfcheck.md 审美评审节——评审只出差距清单（位置+差在哪），不写修法；画师照单回改 → 复走查。
**风格盲测收口**（终门）：把代表页（含用户增删的）无壳渲染截图（口径同审美评审，细则见 style-selfcheck 盲测节）混入样张与其他风格的图，派不知情的独立评审，只回答"哪张和样张是同一个风格、哪张出戏"。出戏页回改 → 复走查 → 复测。不打分、不评布局——盲测只裁风格归属。
两道关的评审者不得是画师本人或参与验货的主对话。

### 收尾交付（盲测过后）
按上方产物清单交付：风格产物目录路径（`<风格id>/`）+ 页面地图扩展 + 资产 + 交付说明。**设计资产与动效规范此时成文定稿**（可复用部件/模式/动效用法+Direction 结论）——下游完善文档、批量惯性、回流接续的粮草。

> 注：本技能止于代表页+页面地图扩展+资产。全量铺量在主技能阶段 6，铺量页的收尾（走查/盲测抽样）也在主技能段定义。
