# 端型约束 · 共用层（所有端型通用的平台行为规则）

> 本目录 = 端型约束库。读法：`_共用.md` + 所做端型的差异文件，两个都读，合起来才是完整约束。
> 收材标尺：**这条约束离开视觉风格还成立吗？成立才进本库。** 视觉主张（涟漪/FAB/组件形态/动效曲线）归风格提示词，永不安置于此（安卓 App 可以不是 Material 长相，WeUI 明令排斥涟漪、别的风格要求按压下沉——端型文件若写视觉即打架）。

## 壳体/页面分工表（谁渲染什么，先读这个）

| 渲染方 | 内容 | 规则来源 |
|---|---|---|
| **壳体模板**（preview-shell，画师禁画禁改） | 状态栏时间、灵动岛/挖孔、手机边框、home indicator、桌面框 | 按端型出壳变体（手机-iOS 壳/桌面壳已有；安卓打孔壳、平板壳用到再建） |
| **页面**（画师画） | 宿主语义组件——真机上由系统渲染、效果图必须画出供开发参考的部分（如微信胶囊、导航标题+返回），按端型差异文件的规范画 | 端型差异文件 |
| **避让区**（页面禁入） | 壳装饰覆盖的安全区 | 数值以端型差异文件为准 |

分界自检：拿不准某装饰归谁，看真机——**系统/宿主渲染的归壳或标注，页面自己实现的归画师**。壳装饰区与页面内容重叠 = 壳模板 bug 或产物越界，先定位再修，禁混着改。

## 平台行为通则（跨端型成立）

1. **系统弹窗禁自绘**：权限授权（定位/通知/相机）、分享、客服会话、支付——真机上由系统/宿主渲染，开发不写这个界面。页面侧只画**触发入口**，弹窗位置标注"系统弹窗，形态由宿主渲染"并留出预期空间。自绘系统弹窗=误导开发（效果图画得出来，真机做不出来）。
2. **宿主接管类交互禁自绘**：下拉刷新指示器、启动页、通知推送（通知在系统通知中心，不在应用内复现）——框架管的不归页面画。
3. **安全区避让**：状态栏/刘海挖孔/底部手势区（home indicator）所覆盖的区域，页面内容禁入或按规则避让——具体数值看端型差异文件。状态栏/底部装饰区与内容重叠=硬伤。
4. **状态栏文字对比度跟随头部底色**：深底白字、浅底黑字（历史 bug：渐变蓝头部上白字不可见）。
5. **操作真实性三问**（每个用户操作必须过）：①这个操作在端型生态里存在吗？②操作者是谁（用户/平台/宿主）？③业务流哪一步有它的出处？三问有一个答不出=把平台侧能力画成了用户侧操作（实例：师傅小程序里画"微信已绑定"收款渠道——绑定是商户平台侧功能，提现到零钱走 openid 师傅零操作；开工文档写线下打款则连绑卡都只是登记）。
6. **交互形态按端型预期**：hover 在桌面是一等交互（漏 hover=可点性不可见），在移动端无意义；触控目标/手势按端型惯例，细节看差异文件。

## 维护规矩

- 新约束发现时先归类：跨端成立 → 进 `_共用.md`；本端独有 → 进对应差异文件。追加数据条目，技能条文零改动。
- 端型差异文件现有清单：微信小程序 / iOS-App / 安卓-App / 平板 / PC-Web。新端型开工 = 只建一个差异文件（共用层现成）。
- 视觉类"约束"（离开风格不成立的）禁入本库——那是风格提示词的辖区。
