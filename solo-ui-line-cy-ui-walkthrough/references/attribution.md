# 归因卡 · 症状→病因 · 禁改规矩

> 探针报的是**症状**，不是**结论**。修复前每条 finding 必须过归因卡：先定病因类，再动代码。
> **数据塌陷改 CSS = 掩盖，定性为违规。**

## 七类病因

| 类 | 特征 | 验证方法 | 典型案例 |
|---|---|---|---|
| 样式css | 样式值/选择器错误，改样式css即愈 | 改前改后几何对比 | 溢出由固定宽元素引起 |
| 数据 | 内容缺失/超长/空态导致塌陷或撑破 | 检查数据源与渲染条件；**清空数据复现=数据类** | 空数据容器塌陷 |
| 内容 | 文案本身问题（超长串/错字/占位） | 内容审查 | 长网址未断行撑破卡片 |
| 脚本js | 脚本错误中断渲染/交互无响应 | 控制台报错定位 | 渲染失败整段空白 |
| 资源 | 图挂/字体未加载/请求失败 | 请求监听 + 图片自然尺寸 | 断图占位塌陷 |
| 设计意图 | "看着怪"实为有意设计（空态/灰态/装饰） | 对照注解/需求/询问用户 | 黑名单灰态徽标（建议级，设计意图） |
| 误报 | 探针局限所致 | 对照校准规则（按规则名索引） | 渐变底对比度误报 |

## 归因卡格式（每条 finding 必填）

```
finding: <id>
症状: <探针实测值 + 选择器>
病因类: css|数据|内容|js|资源|设计意图|误报
根因: <file:line 或 数据源说明>
验证: <怎么证明是这个病因>
修法: <对应病因类的标准动作>
```

## 三条禁改规矩

1. **归因未完成，禁改样式**——先定位 file:line 并核对数据源，在归因卡标注病因类后才可动代码
2. **病因=数据 → 禁改 CSS**——给空数据容器加 min-height 撑起来 = 掩盖；修 mock/数据层
3. **CSS 修完症状仍复现 → 强制升级归因**（css→数据/js），禁止继续叠 CSS

## 模糊归因（第七类兜底）

设计意图无法判定的（灰态是有意还是缺陷、徽标该多大）→ **不修，列入"需人决策"清单**交用户。修复阶段只处理归因明确的项。

## 病因模式表（脚本先行部分）

已知病因模式可脚本直判（layout-inspector overflow.ts 模式）：transform 缩放越界 / 固定宽度超视口 / min-width 强撑 / 100vw 含滚动条 / flex 子元素缺 min-width:0 / 长串未断行——命中即出"病因+修法"对，无需模型。
