# Observation Rubric · 观感评审层任务书（AI 读图 · 仅 AI 职责项）

> **定位**：本任务书只含「必须看图 / 懂内容才能判」的项。可实测项（对比度比值、字号分布、行长、行高、间距刻度偏离、文本色种数、断图、CLS、z-index 档位）由**机检 13 组**负责（criteria.md §机械探针），观感层**不产出、不复述**——两账在仲裁层合并。文案与 mock 可信度（错别字、术语漂移、金额格式、业务自洽）归**场景 3「文字内容检查」**，不在本层。
> **署名与适配**：源自 [refactoring-ui-skill](https://github.com/edisonmbli/refactoring-ui-skill)（MIT）／原规则出自 *Refactoring UI*（Adam Wathan & Steve Schoger）。本地化条款：①项目设计契约永远优先，冲突记「契约冲突升级项」不判缺陷；②severity 对齐三轨映射（calibration.md）；③finding 字段映射台账（Lens→维度名、Rule→契约/规则条款、Now→实测、Proposed→修法、Effort→成本）；④像素证据按零截图铁律取证（`%TEMP%`，评审后即删）；⑤比对基线=项目契约+**原型既定配方**——契约未记档的原型造型（占位文案、示意配色、模板态结构）列「契约待记档」，不判缺陷；⑥本层产出仅为候选证据，须经主代理仲裁定性后方可谈修复——测试/试跑产出同样不作定案。
> **开查前置**：审美定调三立场（criteria.md 观感节：边界立场/色彩立场/密度立场）——写进报告头，判定全引用它；立场未提供时，依赖立场的项（如密度类）**存疑上交**，不得自行推定。
> **输入契约**：像素证据+页面源码+项目契约+原型既定配方均由派发方随任务书提供。仅截图无源码时，标注「需查源码」的条款降级为『图上可判为限』；契约/配方未提供时，相关项存疑上交。报告语言由派发方声明。
> **规则出处**：`§x.x` 编号指向 refactoring-ui-skill 上游对应章节（本包未含原文，仅争议裁决时需拉取上游）；`书外·` 前缀=原书没有的中文界面/原型语境扩展项。
> **派发形态**：页间并行 × 视角串行——子代理按 ≤30 页分片（一次性子代理），片内严格按 Sweep 顺序串行；禁止视角间并行（因果失效 → 假 finding，见 execution-pitfalls.md）。跨片一致性（同组件跨片漂移）由**仲裁层**汇总比对，单片只对自己片内负责。

## 扫描顺序（因果序，不可协商）

```
层级 → 布局间距 → 排版 → 色彩 → 深度 → 图像 → 收尾 → 界面自洽
```

因果理由：层级结论会改写"什么算间距问题"；间距没理顺，"要不要加边框"不存在；色彩没定，深度技法（多是色彩关系的伪装）无从判；结构没修好，收尾无意义。乱序扫会产出一堆"修一处就消解"的废 finding。

## 质量闸门

**每条 finding 必须挂规则 ID（§x.x 或 书外·xx）**。说不出违反哪条规则，那就是品味，不是 finding——要么找到规则，要么丢掉这条。

## AI 检查清单（按视角；可实测项已删，归机检）

### 层级 — hierarchy

1. 一眼能说出屏上最重要的元素吗？`2.1`
2. 有元素在堆强调手法、而它的竞争者还各自带着强调吗？`2.4`
3. 有 `label: value` 对可以删、合并或降级的吗？`2.5.1-2.5.3`
4. 图标颜色与相邻文字一致吗？（应继承文字色，**不一致才报**）`2.7.1`
5. 页面上有几个"看起来像主操作"的按钮？多于一个就是 finding。`2.8`
6. 破坏性操作是按严重度而非按等级设计的吗？`2.8.1`
7. （语义级）内容的主/次/三级分级成立吗？分级是内容理解，机器测不了

### 布局间距 — layout & spacing

1. 相对内容量，设计局促吗？`3.1`
2. 高密度是刻意的吗？（以密度立场为准，立场未提供则存疑上交）`3.1.2`
3. 内容是被拉伸填满视口，还是按自身尺寸定的？`3.3`
4. **每组间距分组：外侧间距 > 内侧间距吗？**（表单/标题/列表/横向组逐组看）`3.6`

**条件项**（仅当派发方提供了多视口截图对比时才判）：
- 更小断点下反而更宽的元素？`3.4.2`
- 大元素在移动端比小元素收缩得更快吗？`3.5`

### 排版 — typography

1. 字重层级是否够用、可辨？`4.2`
2. 同一行混排不同字号时，是基线对齐还是中心对齐？`4.4`
3. 链接密集区误用了散文链接样式吗？`4.6`
4. 有超过两三行的居中文本吗？`4.7.1`
5. 数字表列右对齐了吗？`4.7.2`
6. 两端对齐的文本犬牙差严重吗？（仅内嵌拉丁生效，中文两端对齐通常合法）`4.7.3`
7. 内嵌拉丁大写文本没配字距吗？（仅拉丁生效）`4.8.2`
8. 中文伪粗体发虚吗（字体栈无对应字重时的算法加粗）？`书外·CJK渲染`
9. 同页混用多套中文字体回退吗？`书外·CJK渲染`
10. 中英/数字与中文混排空隙生硬、全半角标点混用吗？`书外·CJK渲染`

### 色彩 — color

1. 语义色（成功/警告/危险）有成体系的色梯，还是临时抓的颜色？`5.2.3`
2. 灰阶是纯灰，还是刻意冷暖——两端温度守住了吗？`5.5`
3. 彩色面板里的次级文字可读且仍是次级吗？`5.6.2`
4. 有深色饱和色块在视觉上压过页面主操作吗？`5.6.1`
5. **有只靠颜色传递的信息吗？**`5.7`

### 深度 — depth

1. 光源统一从上来吗——阴影都在元素下方、无侧向偏移？`6.1.1`
2. 凸起元素有亮顶边 + 下方小阴影吗？`6.1.2`
3. 输入框/凹陷是上阴影下亮边吗？`6.1.3`
4. 阴影是大而虚，还是小而锐——与元素层级匹配吗？`6.1.2`
5. 双层阴影的两层各干各的活吗？`6.3`
6. 扁平/深色界面里，层次靠色彩关系扛住了吗？`6.4.1`
7. 扁平体系里混入了模糊阴影吗？`6.4.2`
8. 叠放图片有底色描边吗？`6.5.1`

### 图像 — images

（确认页面完全无图——含图标与头像——才跳过本组）

1. 摄影图配得上它占的空间吗？`7.1`
2. 图上文字在**整张图**范围都可读吗？`7.2`
3. 遮罩做的是最少必要的活吗？`7.2.2`
4. 有带偏移的文字阴影吗？`7.2.5`
5. 小图标/位图图渲染发糊吗？（按糊报，倍数是素材制作信息不究）`7.3.1`
6. 截图缩到看不清了吗？`7.3.2`
7. 白底上传/占位图会渗进背后的底面吗？`7.4.2`
8. 图标成套吗——线性/面性混用、视觉重量不一、同功能异形？`书外·成套性`
9. **AI 素材痕迹**：图内伪中文/乱码、畸形人物肢体、素材风格与产品调性冲突、同一素材跨页穿帮吗？`书外·AI素材`

**条件项**（仅当页面含上传图占位表面时才判）：图位有变形/裁切怪异吗？`7.4.1`

### 收尾 — finishing

（层级/间距/排版的 finding 消解后再跑本组）

1. 列表符号、引号、链接、表单控件还是浏览器默认样式吗？`8.1`
2. 一条强调边能让平淡的卡片/警告/导航项有身份吗？`8.2`
3. 页面有背景变化，还是从头到尾一个底？`8.3.1`
4. 渐变的色相偏移在 ~30° 以内吗？`8.3.1`
5. 背景纹理/形状保持低对比、避开文字了吗？`8.3.2`
6. **空态**：依赖内容的视图有设计过的空态吗？空态下无用的支撑 UI（页签/筛选）是隐藏而非置灰吗？——**判定前提：页面清单含空态态或截图本身为空列表；满数据页不得推定缺空态**`8.4`
7. 数一数边框——哪些可以换成阴影、底色变化或更多留白？`8.5`
8. 有元素同时带边框 + 阴影 + 底色变化吗？`8.5.1`

### 界面自洽 — 移动端原型专用（书外扩展）

1. 状态栏/底部安全区与内容关系——刘海、Home Indicator 区域被正文/操作占用了吗？`书外·表面语义`
2. 页面主操作（关键 CTA）落在拇指区吗（纵向位置单手可达）？`书外·拇指区`
3. 导航栏标题与页面内容匹配吗？`书外·身份自洽`
4. 当前 Tab 高亮与页面内容一致吗（高保真原型高发：详情页高亮着首页 Tab）？返回去路有暗示吗？`书外·身份自洽`

## 严重度

- **P0 可用性受影响**：层级崩塌用户看不懂屏 `2.1`｜只靠颜色传义 `5.7`｜图上文字部分不可读 `7.2`｜会造成录入错误的含混组间距 `3.6`｜破坏性动作长成页面主操作 `2.8.1`｜**空态缺失 `8.4`（按上述判定前提）**
  注：对比度 `5.6`、行长 `4.3`、视口布局破碎——**机检口径，此表仅供仲裁对账，观感层不产出**
- **P1 一致性受影响**：体系外值 `1.5 3.2`｜文字色 >3 或字重 >2 `2.2`｜彩底灰字/降透明度白字 `2.3`｜多主操作 `2.8`｜圆角跨组件不一致 `1.4.3`｜阴影逐组件手写 `6.2.1`｜深度线索违背光源 `6.1.1`｜行高全站一刀切 `4.5`｜**图标与相邻文字色不一致 `2.7.1`**
- **P2 打磨**：浏览器默认控件 `8.1`｜未开发的深度/强调机会 `8.2`｜该换阴影/底色/留白的冗余边框 `8.5`｜长页面缺背景变化 `8.3`
- **空态缺失是 P0 不是 P2**——它是每个用户必然看到的状态 `8.4`（按判定前提）

## 报告与裁剪

- 输出表：`| # | 视角 | 严重度 | 位置 | 规则§ | 现状 | 建议 | 工作量 |`，按严重度排序
- **工作量档位**：S=单行改动 · M=单组件 · L=系统性/跨页
- **合并同根**：一个根因五个症状 = 一条 finding 五个位置
- **说不出失败场景的，砍**——"这里可以更好"不是 finding
- 超过 ~15 条时，你多半在报症状——往下挖系统性病灶（通常是缺某个体系）
- **不报**：挂不上规则 ID 的｜项目刻意惯例与原型既定配方（记冲突不记分）｜该视角无对应表面时（先确认，图标头像也算图像）｜纯风格偏好 `1.4`｜同一问题第二十处（报模式一次 + 计数）
- 报告用派发方声明的语言写；规则 ID 原样保留
