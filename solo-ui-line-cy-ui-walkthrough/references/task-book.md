# 子代理任务书 · 模板与纪律

> 任务书是派发质量的决定项：任务书写得明白，子代理才能执行好；主代理必须验收并监督。

## 十字段模板

```markdown
# 走查任务书 · <编号>

## 1 范围
页面清单：<明确列出，排除已查页>
## 2 环境
服务：<静态服务地址或 file 约定>；视口：<档位视口>；主题：<浅/双>
query 约定：<按项目 config.query_convention 注入；无则留空>
## 3 探查层
探查层：脚本机检（探针组清单）+ 读证归因（覆盖面：<严重项/全量>）
[+ 观感评审：<抽样/逐屏>]
## 4 校准规则
引用 calibration.md 校准规则（按规则名索引）；本项目豁免白名单：<路径或内联>
## 5 契约引用
<system-rules.md 路径；无契约则声明"通用基线，立场推断">
## 6 禁改令
只查不修。禁动任何项目文件。发现即记录，修复归主代理。
## 7 台账 schema
按 templates/ledger-schema.json；每条 finding 必含 cause/cause_detail
## 8 对账等式
原始问题数 = 分级（阻断/严重/建议） + 豁免 + 备注；不平打回
## 9 异常处理
元素 <20 → 标记疑似空壳 + 读源码归因；单页 30s 超时 → 标记未完成
## 10 回报格式
统计摘要（页数/阻断/严重/建议）+ 前三严重项 + 报告路径 + 豁免要点（不超过 5 条）
```

## 对账与监督

- **对账等式**：原始 findings = 分级 + 豁免 + 备注；不平即打回重报
- **主代理抽查**：随机抽 2-3 页复跑探针，比对子代理结论——偏差 >阈值（漏报真问题/多报误报）打回
- **分片上限**：≤30 页/代理；超页数自动切分并行（页多只会更并行，不会堆积卡死）

2026-10-21 两条任务书（member 前半 40 页 / 后半+admin 35 页）即按此模板派发，双双对账闭合（A：333=332+1；B：278→122 校准+156 豁免）。模板本体在 references/task-book.md。

## 修复类任务书（问③=修复时；与扫描任务书并列）

修复派发按**三形状**排序，勿按页面竖切多代理（「≤30 页/代理」仅为扫描分片上限，不适用于修复）：

1. **脚本层**（主代理直接做，零 LLM）：确定性注入——sr-only h1、:focus-visible 焦点环、令牌增补等纯字符串操作，一个脚本全站跑完，一致性 100%
2. **判断代理**（1~2 个封顶）：需逐选择器甄别的活——信息/装饰灰字、语义色配方取舍、aria-label 语义、alt 描述
3. **专项微修**（主代理顺手）：个位数文件的定点修复，不值得派代理

与扫描任务书的差异：

- 发**成品改动清单**（精确到选择器：哪页哪个选择器改成什么）优先于修法配方——判断在仲裁层做完，执行零判断
- 下发**统一实现片段**（如焦点环：显式选择器 + `!important`，防页面内 `outline:none` 高特异性压制）；跨组实现必须同源，防分叉
- 镜像树同步（px×2）走**脚本变换**，禁手抄
- 回报模板加**跳过项及原因 / 契约缺口发现**字段，主代理逐条过账
- 验收链：归一化校验（统一实现形态）→ 同族一致性抽查 → 复验 `--compare` → 改动报告

## 观感子代理派发模板（AI 识图层；填空式，勿每次重写）

分片先行：`node scripts/shard-pages.mjs <页面根> <out目录> [片大小=30]` → shards.json（页面→片）+ shard-status.json（状态台账）。截图按 `shots/<片号>/<页面相对路径>.png` 落盘。

每片派发提示词（八字段填空）：

```markdown
你是 UI 走查的观感评审子代理。任务书：<技能根>/references/observation-rubric.md——先通读，严格按其规则执行（七视角因果序、finding 挂 § 规则 ID、职责分界、本地化条款）。

评审对象：
- 像素证据：<截图目录，本片 N 张，按 shards.json 对应页面>
- 页面源码（仅当图上判不了时查阅）：<源码根>/<页面相对路径>
- 项目设计契约（优先级压过量规通用数值；冲突记「契约冲突升级项」不判缺陷）：<契约路径>

要求：
1. 按 Sweep 顺序（层级→布局间距→排版→色彩→深度→图像→收尾）逐视角判
2. 只产出 AI 职责项——可实测项（对比度比值/字号/行长/行高/间距刻度偏离/文字色种数）不产出（归机检）
3. 输出 finding 表：| # | 视角 | 严重度 | 位置 | 规则§ | 现状 | 建议 | 工作量 |，中文，规则 ID 保留原编号
4. 契约既定配方如与量规冲突，记「契约冲突升级项」不判缺陷
5. 宁缺毋滥——说不出违反哪条规则的不要报
```

派发纪律：页间并行 × 视角串行；每片回报后更新 shard-status.json（未派发→派出→完成/中断）；**中断续跑只补非「完成」片**，截图已存在的片跳过重拍；跨片一致性（同组件跨片漂移）由**仲裁层**跨片汇总比对，单片只对自己片内负责。批量结束后按零截图铁律清理 shots 目录。
